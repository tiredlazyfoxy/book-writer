# Step 003 — step-specific context

D4 and the substrate contracts for `export_all` / `import_all` / `set_db_ready` are in
`context.md`.

Narrow to this step:

- **`import_all` already rebuilds the vector index** after UPSERT (per
  `docs/plans/001.backend-scaffold/004.import-export-mechanism.md`). `import_database` does
  not need to rebuild separately — do not double-call the rebuild path.
- **Validation is pre-mutation and non-destructive.** `validate_archive` reads the zip in
  memory / streams members to confirm gz + JSONL parseability; it must not touch the DB, so
  US-019.AC-3's "DB unchanged" holds by construction (refusal happens before `import_all`
  is ever reached).
- **Expected members come from `TABLE_REGISTRY`.** The validator checks the same per-table
  `<table>.jsonl.gz` names the export writes (currently `users`, `llm_servers`). Read the
  registry rather than hardcoding names, so it tracks any future model addition.
- **Do NOT reuse `services.setup.import_database`.** That function flips `set_db_ready`
  (first-run semantics). This step builds a parallel admin path over the same `import_all`.
  A future shared `validate_archive` could unify both refusal paths — recorded as a
  convergence observation in `outcome.md`, not built here.
- **Corrupt-bytes test** feeds obviously non-zip bytes (and/or a zip with a truncated
  member) and asserts `DbAdminError(invalid-archive)`; a round-trip test seeds a row,
  exports, wipes/re-imports, and asserts presence, then re-imports for idempotency.

# Step 001 — Schema introspection + drift report (read-only)

## Goal
Introspect the live database's actual structure and compute a per-table consistency
report (ok / drift / missing, with missing/extra column lists) against
`SQLModel.metadata`, exposed as typed report DTOs plus the feature's typed service error.

## Source files
backend/app/db/schema.py
backend/app/services/db_admin.py
backend/app/models/schemas/db_admin.py

## Test files
backend/tests/services/test_db_admin_report.py

## Interface intent
- **`app/db/schema.py` — `introspect()`** (net-new, session-free): opens an engine
  connection and runs SQLAlchemy `inspect()` under `run_sync` to return the **actual**
  structure — the set of table names present in the live DB and, per table, its column
  names (plus enough type info that step 002 can add columns later). Returns a typed
  internal shape (`TypedDict` or Pydantic — no free dict). Uses the engine primitive from
  `db/engine.py`; creates and closes its own connection (nothing leaks).
- **`app/models/schemas/db_admin.py` — report DTOs** (net-new, Pydantic `BaseModel`):
  a per-table entry carrying `name`, `status` (a `'ok' | 'drift' | 'missing'` literal
  union), `missing_columns` (list of str), `extra_columns` (list of str); and a report
  wrapper carrying the list of per-table entries. These are the wire shapes the route
  returns and the frontend mirrors 1:1.
- **`app/services/db_admin.py` — `DbAdminError`** (net-new typed exception): carries a
  `case` discriminator (e.g. `not-in-metadata`, `unknown-table`, `table-not-missing`,
  `invalid-archive`, plus a rebuild/no-provider case) and a human-readable message. Only
  the report-relevant cases need to be raisable in this step; the enum/set of cases is
  established here for later steps to reuse. No HTTP concerns.
- **`app/services/db_admin.py` — `build_consistency_report()`** (net-new): reads the
  **expected** structure from `SQLModel.metadata` (table names + column names per table —
  a models-layer read, not a session), calls `db.schema.introspect()` for the actual
  structure, and computes each expected table's status: `missing` if absent from the live
  DB; else `drift` if the expected and actual column-name sets differ; else `ok`. For a
  drifted table populates `missing_columns = expected − actual` and `extra_columns =
  actual − expected`; ok/missing tables carry empty lists. Returns the report DTO.

## Definition of done
1. `[test]` **US-015.AC-1** — given a database whose tables all match metadata,
   `build_consistency_report()` returns an entry for **every** expected table, each with
   status `ok`.
2. `[test]` **US-015.AC-1** — given a database missing an expected table (table not
   created / dropped), that table's entry reports status `missing`.
3. `[test]` **US-015.AC-1** — given a database whose table has a column set differing from
   metadata (e.g. an extra column added by raw `ALTER`), that table's entry reports status
   `drift`.
4. `[test]` **US-015.AC-2** — for a drifted table, the entry's `missing_columns` lists
   columns present in metadata but absent from the live table, and `extra_columns` lists
   columns present in the live table but absent from metadata (each list correct and
   disjoint).
5. `[manual/live]` **D1 (layer separation)** — `db/schema.py` holds the only `inspect()` /
   session/connection code; `services/db_admin.py` contains no `session` / `select()` /
   `session.exec()` / `session.add()` and reads expected structure only from
   `SQLModel.metadata`.

# Step 004 — Vector-index rebuild (operation + empty source registry seam)

## Goal
Implement the vector-index rebuild OPERATION — reset the LanceDB sidecar from an (empty in
Stage 1) source registry, wire the existing `run_vector_rebuild` stub to it, and add the
admin service action that resolves+validates the embedding designation before rebuilding.

## Source files
backend/app/db/vector.py
backend/app/db/import_export_queries.py
backend/app/services/db_admin.py

## Test files
backend/tests/services/test_db_admin_rebuild.py

## Interface intent
- **`app/db/vector.py` — `VECTOR_SOURCE_REGISTRY`** (net-new module-level list): an
  **empty list in Stage 1**, documented as the seam Stage-2 vector-backed domain features
  append `(model_class, text_extractor)` entries to. It defines what `rebuild_index`
  iterates.
- **`app/db/vector.py` — `rebuild_index()`** (net-new, replaces stub behavior): connects to
  the configured LanceDB directory (the `Settings` field frozen by the 001 skeleton — see
  `app/settings.py`), **drops/recreates the sidecar index tables** (reset), then iterates
  `VECTOR_SOURCE_REGISTRY`, embedding+writing each source's rows. With an empty registry it
  resets the index and returns a count of **0**. Returns the number of rows indexed.
- **`app/db/import_export_queries.py` — `run_vector_rebuild()`** (implement the existing
  NO-OP STUB): delegate to `db.vector.rebuild_index()` so the post-import rebuild and the
  admin rebuild button share one path. Preserve the existing call signature the stub froze.
- **`app/services/db_admin.py` — `rebuild_vector_index()`** (net-new): resolves the
  embedding provider via `db.llm_servers.get_embedding_server()` and **validates
  `embedding_model` is set** (006 does not guarantee it) — on no designated provider /
  unset model, surface a typed `DbAdminError` (no-provider case) **or** complete the reset
  and report a no-provider status, per the contract below. On a valid designation, calls the
  rebuild path and returns the indexed-row count. In Stage 1 (empty registry) this resets
  the index and returns 0.

## Definition of done
1. `[test]` **US-020.AC-1** — with a valid embedding designation present
   (`get_embedding_server()` returns a row whose `embedding_model` is set),
   `rebuild_vector_index()` completes, resets/recreates the sidecar index, and returns a
   count of `0` (Stage-1 empty `VECTOR_SOURCE_REGISTRY` — regenerated from current, zero,
   source rows).
2. `[test]` **US-020.AC-1 (idempotent reset)** — calling `rebuild_vector_index()` twice
   leaves the index in a consistent freshly-reset state without error (the reset is valid
   regardless of prior state).
3. `[test]` **D6 (no-provider contract)** — with no embedding provider designated
   (`get_embedding_server()` returns `None`) or a designated provider whose
   `embedding_model` is unset, the service behaves per the frozen contract: it never
   silently claims success against a missing provider — it either raises `DbAdminError`
   (no-provider) or completes the reset while surfacing a no-provider status (the skeleton
   freezes which; the test asserts the frozen behavior, and that the reset itself does not
   corrupt the index).
4. `[test]` **D6 (shared path)** — `run_vector_rebuild()` invokes
   `db.vector.rebuild_index()` (post-import rebuild and admin rebuild share one path);
   asserted via monkeypatching `db.vector.rebuild_index` and confirming `run_vector_rebuild`
   delegates to it.
5. `[manual/live]` **D6 (deferral)** — no `embed_texts`, no `services/embedding.py`, no
   vector-dimension detection/cache is added; `VECTOR_SOURCE_REGISTRY` ships empty.

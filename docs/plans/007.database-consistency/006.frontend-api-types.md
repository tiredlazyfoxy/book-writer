# Step 006 — Frontend db types + api (incl. blob-download & multipart plumbing)

## Goal
Add the Admin SPA's db-management wire types and its `api/db.ts` resource module, including
the frontend's first blob-download (export) and multipart-upload (import) helpers.

## Source files
frontend/src/types/db.d.ts
frontend/src/api/db.ts

## Test files
None — every DoD item is `[manual/live]` (no frontend test runner exists; see `context.md`).

## Interface intent
- **`src/types/db.d.ts`** — hand-written DTO `.d.ts` mirroring the backend report schemas
  1:1: a per-table consistency entry (`name`, `status: 'ok' | 'drift' | 'missing'`,
  `missing_columns: string[]`, `extra_columns: string[]`) and the report wrapper (list of
  entries), plus any request/response shapes the rebuild endpoint returns (e.g. a
  count/status result). No `any`, no zod.
- **`src/api/db.ts`** — one resource module for `/api/admin/db`, `signal?` last where
  applicable, imported in state files via `import * as dbApi from '../../api/db'`:
  - **`getConsistencyReport(signal?)`** — `GET /report` over the shared `request<T>` from
    `api/client.ts`, returns the report DTO.
  - **`createTable(name, signal?)`** — `POST /tables/{name}/create` over `request<T>`.
  - **`syncTable(name, signal?)`** — `POST /tables/{name}/sync` over `request<T>`.
  - **`rebuildIndex(signal?)`** — `POST /vector/rebuild` over `request<T>`, returns the
    count/status DTO.
  - **`exportDatabase()`** — **net-new blob-download plumbing**: a direct `fetch` to
    `GET /api/admin/db/export` with `Authorization: Bearer <token>` from the auth accessor
    (`auth.ts`), reads `res.blob()`, and triggers a browser save (object URL +
    programmatic anchor download, then revoke). Bypasses `request<T>` (which is JSON-only).
  - **`importDatabase(file)`** — **net-new multipart plumbing**: builds a `FormData` with
    field `file`, `POST`s to `/api/admin/db/import` with `Authorization: Bearer <token>`
    and **no** JSON content-type (let the browser set the multipart boundary). Mirrors
    003's `api/auth.ts::setupImport`. Surfaces a non-2xx as a rejected promise the page can
    catch (refusal → error).

## Definition of done
1. `[manual/live]` **US-015 (api)** — `getConsistencyReport` calls `GET /api/admin/db/report`
   with Bearer auth and returns the typed report; `types/db.d.ts` matches the backend report
   schema 1:1 (status union `'ok' | 'drift' | 'missing'`, `missing_columns`/`extra_columns`
   string arrays).
2. `[manual/live]` **US-016 / US-017 (api)** — `createTable(name)` and `syncTable(name)`
   POST to the correct per-table endpoints over the shared client.
3. `[manual/live]` **US-018.AC-1 (api, blob)** — `exportDatabase()` fetches the export with
   Bearer auth, reads the response as a blob, and triggers a browser file save (net-new
   download plumbing, not going through `request<T>`).
4. `[manual/live]` **US-019 (api, multipart)** — `importDatabase(file)` uploads the file as
   multipart field `file` with Bearer auth and no JSON content-type (mirroring 003's
   `setupImport`), and rejects on a non-2xx so a refusal (400) surfaces to the caller.
5. `[manual/live]` **US-020 (api)** — `rebuildIndex()` POSTs to `/vector/rebuild` and
   returns the count/status DTO.
6. `[manual/live]` **D7 (typing)** — `npm run build` (tsc + vite) passes with no `any`; all
   HTTP for this resource lives in `api/db.ts`; DTOs live in `types/db.d.ts`.

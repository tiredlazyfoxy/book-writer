# Step 002 — step-specific context

D2 and the layer rules are in `context.md`; the diff/report logic is from step 001.

Narrow to this step:

- **Reuse step-001 introspection for preconditions.** `create_missing_table` and
  `sync_table_schema` decide what to do from the same `db.schema.introspect()` +
  `SQLModel.metadata` comparison step 001 already computes — do not duplicate the diff;
  call into the shared helper the step-001 skeleton froze.
- **Compiled column types.** `add_columns` needs each column's SQL type text. Take it from
  `SQLModel.metadata.tables[name].columns[col].type` compiled against the SQLite dialect —
  the same metadata `introspect()`/the report read from. The exact compile call is the
  skeleton's to freeze.
- **Nullable-only ADD.** SQLite forbids `ADD COLUMN … NOT NULL` without a default. Emit the
  added column as nullable regardless of the metadata column's nullability; this is a
  storage-engine constraint, not a design choice, and is recorded for the architect in
  `outcome.md`.
- **DROP COLUMN availability.** `ALTER TABLE … DROP COLUMN` requires SQLite ≥3.35, which
  Python 3.13's bundled sqlite provides — no version guard needed, but note it in case a
  test environment surprises.
- **Test scenarios** mirror step 001's construction (temp DB, raw `ALTER` to seed drift,
  omit/drop a table to seed missing), then assert post-remediation reports via the
  step-001 report function.

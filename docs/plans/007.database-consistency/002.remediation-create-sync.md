# Step 002 — Remediation: create-missing-table + sync-schema (ALTER)

## Goal
Add the DDL operations and service actions that create a missing table and reconcile a
drifted table's columns (add missing, drop extra) so the table subsequently reports ok.

## Source files
backend/app/db/schema.py
backend/app/services/db_admin.py

## Test files
backend/tests/services/test_db_admin_remediation.py

## Interface intent
- **`app/db/schema.py` — `create_table(name)`** (net-new, session-free DDL): creates ONE
  table from `SQLModel.metadata.tables[name]` via `table.create(sync_conn)` under
  `engine.begin()`/`run_sync` (the single-table create `create_all` does not offer). No-op-
  safe or precondition-checked as the skeleton decides; the service guarantees the table is
  currently missing before calling.
- **`app/db/schema.py` — `add_columns(name, columns)`** (net-new): for each named column,
  runs `ALTER TABLE <name> ADD COLUMN <col> <compiled-type>` using the column's compiled
  SQL type taken from `SQLModel.metadata`. Columns are **added nullable** — SQLite cannot
  ADD a NOT NULL column without a default (a hard constraint; record it, do not fight it).
- **`app/db/schema.py` — `drop_columns(name, columns)`** (net-new): for each named column,
  runs `ALTER TABLE <name> DROP COLUMN <col>` (SQLite ≥3.35, satisfied by Python 3.13's
  bundled sqlite). Session-free, via `engine.begin()`/`run_sync`.
- **`app/services/db_admin.py` — `create_missing_table(name)`** (net-new): validates the
  name is in `SQLModel.metadata` **and** currently absent from the live DB (via the
  introspection from step 001) — otherwise raises `DbAdminError` (`not-in-metadata` for an
  unknown name, `table-not-missing` if it already exists); on success calls
  `db.schema.create_table(name)`. After the call the table exists and reports ok.
- **`app/services/db_admin.py` — `sync_table_schema(name)`** (net-new): recomputes the
  diff for `name` (reusing the step-001 report logic), then calls `db.schema.add_columns`
  for `missing_columns` and `db.schema.drop_columns` for `extra_columns`, so the table then
  reports ok. Raises `DbAdminError` (`unknown-table`) if the table is missing entirely or
  not in metadata.

## Definition of done
1. `[test]` **US-016.AC-1** — given a table reported `missing`, `create_missing_table(name)`
   creates it and a fresh consistency report then shows that table as `ok`.
2. `[test]` **US-016 (guard)** — `create_missing_table` on a name not in
   `SQLModel.metadata` raises `DbAdminError` (`not-in-metadata`); on a table that already
   exists raises `DbAdminError` (`table-not-missing`); the DB is unchanged in both cases.
3. `[test]` **US-017.AC-1** — given a table in `drift` with missing columns,
   `sync_table_schema(name)` adds the missing columns; a fresh report then lists no
   `missing_columns` for that table.
4. `[test]` **US-017.AC-2** — given a table in `drift` with extra columns,
   `sync_table_schema(name)` drops the extra columns and a fresh report shows the table as
   `ok`.
5. `[manual/live]` **D2 (nullable/ALTER constraint)** — added columns are nullable (no ADD
   NOT NULL); `db/schema.py` holds all DDL and `services/db_admin.py` stays session-free.

## Dependencies
Step 001 (`introspect`, report logic, `DbAdminError`, DTOs).

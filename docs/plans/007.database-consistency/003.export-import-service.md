# Step 003 — Admin export/import service + archive validation

## Goal
Add the service layer for admin database export and import: a passthrough to `export_all`,
an archive pre-validator that refuses corrupt/invalid exports before any mutation, and an
import that validates then UPSERTs via `import_all` **without** flipping the readiness flag.

## Source files
backend/app/services/db_admin.py

## Test files
backend/tests/services/test_db_admin_importexport.py

## Interface intent
- **`app/services/db_admin.py` — `export_database()`** (net-new): returns the export
  archive bytes by delegating to `services.db_import_export.export_all()` (a zip of
  per-table `.jsonl.gz`, per-row streamed). No transformation; the route adds download
  headers.
- **`app/services/db_admin.py` — `validate_archive(bytes)`** (net-new): pre-validates the
  raw archive **before any mutation**. Verifies the bytes open as a zip (`zipfile` —
  `zipfile.BadZipFile` → invalid) and that each expected `<table>.jsonl.gz` member (per the
  import/export `TABLE_REGISTRY`) is gz-decodable and its lines are JSONL-parseable. On any
  failure raises `DbAdminError(case=invalid-archive)`. Performs no writes.
- **`app/services/db_admin.py` — `import_database(bytes)`** (net-new): calls
  `validate_archive(bytes)` first (raising on failure, DB untouched), then on success calls
  `services.db_import_export.import_all(bytes)` (which runs `init_db()`, streams+UPSERTs per
  `TABLE_REGISTRY`, then rebuilds the vector index) — idempotent UPSERT. It **must NOT**
  call `set_db_ready` (that is first-run-only, owned by `services.setup`, and wrong for a
  configured instance). Returns nothing (or a minimal summary as the skeleton decides).

## Definition of done
1. `[test]` **US-018.AC-1 (service)** — `export_database()` returns non-empty bytes that
   open as a valid zip containing the expected per-table `.jsonl.gz` members.
2. `[test]` **US-019.AC-1** — importing a self-produced export (via `export_database()`
   after seeding rows) through `import_database(bytes)` restores those rows into the DB.
3. `[test]` **US-019.AC-2** — running `import_database(bytes)` twice with the same export
   yields no duplicate rows (idempotent UPSERT).
4. `[test]` **US-019.AC-3** — `import_database(corrupt_bytes)` raises
   `DbAdminError(invalid-archive)` and leaves the database unchanged (no partial write).
5. `[test]` **D4 (no readiness flip)** — `import_database` does not toggle the readiness
   flag: `is_db_ready()` is the same before and after a successful import (assert it stays
   at whatever the fixture set — the service never calls `set_db_ready`).

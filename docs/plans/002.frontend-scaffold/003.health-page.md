# Step 003 — Health-check page: MobX convention + end-to-end proof

## Goal
Bootstrap the MobX page-state convention on a trivial User-SPA health page that
fetches `GET /api/health` through `src/api/`, proving the full
browser → `api/` → Vite `/api` proxy → 001 backend wiring end to end.

## Source files

frontend/src/user/pages/healthPageState.ts

frontend/src/user/routes.tsx
frontend/src/user/App.tsx

## Interface intent

- **`src/types/health.d.ts`** — the `HealthResponse` DTO matching the 001
  backend `HealthResponse` 1:1: a `status` string and a `db` string (values
  `"ok"` / `"ready"` at runtime, but typed as `string`). Pure wire shape.
- **`src/api/health.ts`** — a resource module with a per-module `BASE` of
  `"/api/health"` and a REST-verb function `getHealth(signal?)` that calls
  `request<HealthResponse>` and returns the parsed `HealthResponse`. `signal?`
  is the last argument. Imported by state files via the `* as healthApi`
  namespace.
- **`src/user/pages/healthPageState.ts`** — the page state file, holding:
  - **`HealthPageState`** — a class using `makeAutoObservable(this)` with the
    async-resource **trio** (`health` / `healthStatus: 'idle'|'loading'|
    'ready'|'error'` / `healthError`) and NO effectful methods.
  - **`loadHealth(state, signal)`** — an external function that sets
    `healthStatus = 'loading'`, awaits `healthApi.getHealth(signal)`, and on
    success `runInAction`s `health` + `healthStatus = 'ready'`; on error it
    early-returns when `signal.aborted`, else `runInAction`s
    `healthStatus = 'error'` + `healthError`.
- **`src/user/pages/HealthPage.tsx`** — an `observer` component that owns a
  stable state instance via `const [state] = useState(() => new HealthPageState())`,
  runs a mount `useEffect` (empty deps) that creates an `AbortController`, calls
  `void loadHealth(state, controller.signal)`, and returns `() =>
  controller.abort()`; it renders directly from `state.*` — a loading indicator
  while `healthStatus === 'loading'`, the `status` / `db` values when `'ready'`,
  and the error when `'error'`.
- **`src/user/routes.tsx`** — the User SPA route table mapping the root path to
  `HealthPage` (replacing step 001's inline placeholder route).
- **`src/user/App.tsx`** — edited (from step 001) to render the `routes.tsx`
  route table inside the existing `<MantineProvider>` + `<BrowserRouter>` shell,
  in place of the placeholder route. No other change to the App shell.

## Definition of done
1. `[manual/live]` `cd frontend && npx tsc --noEmit` is clean.
2. `[manual/live]` `cd frontend && npm run build` (tsc + vite) stays clean.
3. `[manual/live]` `HealthPageState` holds only the observable trio + `get`
   computeds (if any) — no effectful methods; loading is done by the external
   `loadHealth(state, signal)` function using `runInAction` (per `frontend.md`
   MobX rules).
4. `[manual/live]` `HealthPage` is wrapped in `observer`, owns its state via
   `useState(() => new HealthPageState())`, and loads on mount / aborts on
   unmount via a single page-level `useEffect` with empty deps.
5. `[manual/live]` `getHealth` calls the backend through `src/api/`
   (`request<HealthResponse>` against `/api/health`), forwarding the optional
   `AbortSignal`; the page never calls `fetch` directly.
6. `[manual/live]` With the 001 backend running on `:8185`, `npm run dev` →
   loading the User page at `/` displays the fetched health result
   (`status: "ok"`, `db: "ready"`) obtained via the Vite `/api` proxy — proving
   browser → `api/` → proxy → backend → four-layer flow end to end.
7. `[manual/live]` `src/types/health.d.ts` matches the 001 `HealthResponse`
   shape 1:1 (`status: string; db: string`) with no runtime validation.

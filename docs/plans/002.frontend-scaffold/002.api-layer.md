# Step 002 — API layer + types seed

## Goal
Build the shared HTTP layer — `src/auth.ts` (token accessor + logout stub),
`src/api/client.ts` (`request<T>` + `ApiError` + auth headers), and
`src/api/sse.ts` (`streamPost`) — plus a common types seed, so state files and
resource modules have a typed, abort-aware fetch wrapper to build on.

## Source files
frontend/src/auth.ts
frontend/src/api/client.ts
frontend/src/api/sse.ts
frontend/src/types/common.d.ts

## Test files
_None — see decision 5 in `context.md`: no frontend test runner. All DoD items
are `[manual/live]`._

## Interface intent

- **`src/auth.ts`** — module-level, localStorage-backed (not a class, not a
  store). Exports `getToken()` returning the stored JWT string (or `null`) read
  from `localStorage` under the `"token"` key, and a minimal `logout()` stub
  that clears the stored token. `getCurrentUser()` / JWT-decode and the redirect
  flow are deferred to feature 004 (decision 3). This file must not import from
  `src/api/` — dependency direction is one-way (`api/` → `auth.ts`).
- **`src/api/client.ts`** — the single fetch wrapper:
  - `ApiError` — an `Error` subclass carrying the HTTP `status`, a `message`,
    and optional `details`.
  - `request<T>(url, options)` — calls `fetch(url, ...)` with the given method
    (default GET); sets `Content-Type: application/json`; injects
    `Authorization: Bearer <getToken()>` when a token is present; JSON-stringifies
    the `body` when defined; forwards an optional `AbortSignal`. On non-2xx it
    delegates to `throwApiError`. On `204` it returns `undefined`; otherwise it
    returns the parsed JSON typed as `T`.
  - `throwApiError(res)` — reads the error body (preferring a `{ detail }`
    field) for the message and throws an `ApiError` with the response status.
  - `authHeaders()` — returns the header object (including Bearer when present)
    for streaming/multipart callers that bypass `request`.
- **`src/api/sse.ts`** — `streamPost(url, body, handlers)` — a hand-rolled SSE
  reader over `fetch` POST (not `EventSource`): sends the JSON body with
  `authHeaders()`, reads `res.body.getReader()` through a `TextDecoder`, splits
  the stream on `"\n\n"`, parses `event:` / `data:` lines per frame, and
  dispatches to the typed `handlers`; it swallows `AbortError`. Returns an
  `AbortController` so the caller can cancel the stream.
- **`src/types/common.d.ts`** — a small seed of cross-resource DTO shapes (e.g.
  a generic error-detail shape and/or any shared primitive alias). Pure wire
  shapes only — no methods, no classes.

## Definition of done
1. `[manual/live]` `cd frontend && npx tsc --noEmit` is clean with all four
   files present (no `any`, no untyped data).
2. `[manual/live]` `cd frontend && npm run build` stays clean (tsc + vite).
3. `[manual/live]` `request<T>` injects `Authorization: Bearer <token>` from
   `getToken()` only when a token exists, sets `Content-Type: application/json`,
   and JSON-stringifies a defined body — confirmable by code inspection +
   typecheck.
4. `[manual/live]` A non-2xx response is normalized to a thrown `ApiError`
   carrying the response status and a message sourced from the `{ detail }`
   body; a `204` yields `undefined` — confirmable by code inspection.
5. `[manual/live]` `request<T>` and `streamPost` both accept and forward an
   `AbortSignal` (via the returned `AbortController` for `streamPost`).
6. `[manual/live]` `src/auth.ts` exports only `getToken()` and a `logout()`
   stub — no `getCurrentUser`, no JWT-decode, no redirect (decision 3) — and
   does not import from `src/api/`.
7. `[manual/live]` No `EventSource` is used; SSE is the `fetch`-POST reader
   (per `frontend.md`).

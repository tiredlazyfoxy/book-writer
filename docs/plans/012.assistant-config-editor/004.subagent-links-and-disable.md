# 004 — sub-agent tool set, accessible-modes set, and disable / enable

## Goal

Complete the sub-agent half: wire the tool selection and the accessible-modes selection into create
and update as replace-sets, and add the disable / enable operation whose disable detaches the
sub-agent from every mode.

## Interface intent

Prose only — the `skeleton` agent freezes the exact signatures.

### `models/schemas/assistant_config.py` — additions

- The sub-agent **create request** and **update request** each gain a list of `tool_name`s and a
  list of accessible `mode_key`s. Both **default to empty**, so step 003's tests and any caller that
  omits them keep working and get a sub-agent with no selections. The response DTO is unchanged — it
  already carries both lists (step 003).

### `services/assistant_config.py` — additions

- **New reason on the existing enum**: **mode-not-found** already exists from step 002 and is reused
  for an unknown `mode_key` in a sub-agent's mode selection. No other new reason is needed —
  **unknown-tool** and **sub-agent-not-found** are already defined.

- **A sub-agent tool replace-set** (internal) — validate every requested name against
  `TOOL_REGISTRY` (unknown → **unknown-tool**), then `subagent_tools.delete_by_sub_agent` followed by
  one `create` per distinct name.

- **A sub-agent mode replace-set** (internal) — validate every requested `mode_key` against the
  existing `AssistantMode` rows (unknown → **mode-not-found**), then
  `mode_subagents.delete_by_sub_agent` followed by one `create` per distinct key. **This writes the
  same `mode_subagent` rows step 002's mode saver writes** — one row set, two editors
  (US-112.AC-2, `context.md` → "Replace-set semantics").

- **Wire both into create and update.** In both paths every validation — name, model pair, tool
  names, mode keys — runs **before any write**, so a rejected save leaves the sub-agent and all its
  links untouched.

- **A disabled-sub-agent guard.** Applying a **non-empty** mode selection to a sub-agent that is
  currently `disabled` is refused with **sub-agent-disabled** (the reason step 002 introduced), for
  the reason recorded in `context.md` → "Planner-derived decisions": disabling is *defined* as being
  detached from every mode, so granting an attachment in the same breath contradicts the invariant.
  An **empty** mode selection on a disabled sub-agent is accepted (it is a no-op that agrees with the
  invariant), so a disabled sub-agent's name, prompt, tools and model remain editable.

- **A disable / enable setter** — takes a sub-agent id and the desired `disabled` value:
  - absent row → **sub-agent-not-found**;
  - **disabling** sets the flag, refreshes `modified_at`, **and deletes every `mode_subagent` row
    for that sub-agent** via `mode_subagents.delete_by_sub_agent`. Its `subagent_tool` rows are
    **kept** — the tool selection is the sub-agent's own configuration, not a mode's grant, and
    UC-097's disable flow speaks only of detaching from modes;
  - **enabling** sets the flag and refreshes `modified_at` and **nothing else** — the deleted links
    are not restored, because they were deleted rather than suppressed (US-114.AC-3);
  - returns the rebuilt sub-agent DTO.

  **There is no hard-delete function and no delete route anywhere in this feature**
  (`context.md` → scope decision 6).

## Definition of done

1. `[test]` Creating a sub-agent with a tool selection and a mode selection stores both, and the
   returned DTO carries them (UC-096 steps 4–5; US-113.AC-1).
2. `[test]` A sub-agent created as accessible from a mode **appears in that mode's accessible
   sub-agent set** when the mode is read back through the mode surface — the sub-agent-side write is
   visible from the mode-side read (US-113.AC-2, US-112.AC-2).
3. `[test]` A link written from the **mode** side is visible in that sub-agent's accessible-modes
   list, and re-saving from the **sub-agent** side replaces the whole set for that sub-agent while
   leaving other sub-agents' links to the same mode intact — one row set, two editors
   (US-112.AC-2).
4. `[test]` Updating a sub-agent's tool selection **replaces** it rather than merging: a tool present
   before and absent after is gone; the same for the mode selection (US-114.AC-1).
5. `[test]` An empty tool selection and an empty mode selection are both accepted and result in zero
   link rows of that kind (US-114.AC-1; `context.md` → scope decision 1 — empty means none).
6. `[test]` A selection naming a tool absent from `TOOL_REGISTRY` is refused with **unknown-tool**,
   and a selection naming a `mode_key` with no `AssistantMode` row is refused with
   **mode-not-found**; in both cases the sub-agent's stored scalars **and** its existing links are
   unchanged (US-113.AC-1, US-114.AC-1).
7. `[test]` A request repeating the same tool name or the same mode key twice produces one link row
   per distinct value — `uq_subagent_tool_sub_agent_id_tool_name` and
   `uq_mode_subagent_mode_key_sub_agent_id` are never violated (US-114.AC-1).
8. `[test]` Disabling a sub-agent that two modes reference sets `disabled` true **and removes its
   link rows from both modes** — neither mode lists it as accessible any more, and the sub-agent's
   own row still exists (UC-097 alternate flow; US-114.AC-2).
9. `[test]` Disabling **keeps** the sub-agent's `subagent_tool` rows — its own tool configuration
   survives so re-enabling restores a usable worker (UC-097 — disabling is reversible).
10. `[test]` Re-enabling a disabled sub-agent sets `disabled` false and leaves it **attached to no
    mode**; the links deleted at disable time are not restored (US-114.AC-3).
11. `[test]` After re-enabling, a mode may select it again and the link is stored — the sub-agent is
    usable once more (US-114.AC-3).
12. `[test]` Saving a **non-empty** mode selection onto a currently disabled sub-agent is refused
    with **sub-agent-disabled** and writes nothing, while saving that sub-agent's name, prompt,
    model and tools with an **empty** mode selection succeeds (US-114.AC-2, US-114.AC-1).
13. `[test]` Disabling or enabling a sub-agent id with no row is refused with
    **sub-agent-not-found** (UC-097 precondition).
14. `[manual/live]` `cd backend && .venv/Scripts/python -m pytest` green.

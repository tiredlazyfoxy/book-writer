# 005 — the admin route surface

## Goal

Expose the assistant-config service as `routes/admin/assistant_config.py` — the
`/api/admin/assistant-config` route family, every endpoint behind `require_role(admin)` — and mount
it in `main.py`.

## Interface intent

Prose only — the `skeleton` agent freezes the exact signatures. `routes/` is **HTTP only**: parse,
call a service, return. No business logic and no DB access in this module.

### `routes/admin/assistant_config.py` (new)

One `APIRouter` owning the prefix `/api/admin/assistant-config`, with its own tag, mirroring
`routes/admin/llm_servers.py:44` in every structural respect:

- **Response models are return annotations**, never `response_model=`.
- **Every handler** carries a caller dependency on `auth_service.require_role(UserRole.admin)`. 403
  for a non-admin comes from that dependency itself; no handler raises it.
- **Static segments are declared before `{param}` routes** within each family
  (the `llm_servers.py:12-15` rule).
- A module-level **reason → status dict** plus a `_map_*` helper turning the service exception into
  an `HTTPException` (`llm_servers.py:46-61`); every handler is a `try` / `except
  <AssistantConfigError>` → `raise _map_...(err)`.

Endpoints:

| Method + path | Body | Returns | Serves |
|---|---|---|---|
| `GET /tools` | — | the tool catalogue envelope | UC-095 step 3, UC-096 step 4 |
| `GET /modes` | — | the mode list envelope | UC-095 step 1 |
| `PUT /modes/{mode_key}` | the mode update request | the updated mode DTO | UC-095 steps 2–5 |
| `GET /sub-agents` | — | the sub-agent list envelope | UC-097 step 1 |
| `POST /sub-agents` | the create request | the created sub-agent DTO | UC-096 |
| `PUT /sub-agents/{sub_agent_id}` | the update request | the updated sub-agent DTO | UC-097 steps 2–3 |
| `POST /sub-agents/{sub_agent_id}/disable` | — | the updated sub-agent DTO | UC-097 alternate flow |
| `POST /sub-agents/{sub_agent_id}/enable` | — | the updated sub-agent DTO | UC-097 alternate flow |

**There is deliberately no single-mode GET** — there are five modes and the editor loads them all in
one call, so a per-mode read would be dead surface. **There is deliberately no DELETE** anywhere:
disable-not-delete (`context.md` → scope decision 6).

Reason → status map (every reason the service can raise must appear; an unmapped reason must not
fall through to a 500):

| Reason | Status |
|---|---|
| mode-not-found, sub-agent-not-found | **404** |
| name-taken | **409** |
| blank-name, invalid-model-pair, unknown-or-inactive-server, model-not-enabled, unknown-tool, unknown-sub-agent, sub-agent-disabled | **400** |

Path params: `mode_key` is a plain string; `sub_agent_id` is a **string** at the boundary and is
handed to the service as-is — the service owns the parse and answers **sub-agent-not-found** for a
value that is not an id (`context.md` → "Every id is a `str` at the JSON boundary").

### `main.py`

Import the new router module beside the existing admin routers and `include_router` it **bare** (the
router owns its own prefix), matching `main.py:31` / `main.py:82`.

## Definition of done

1. `[test]` `GET /modes` as an admin returns the five modes with their prompts and selections, and
   `PUT /modes/{mode_key}` stores a prompt, a tool set and a sub-agent set and returns the updated
   mode (UC-095; US-110.AC-1, US-111.AC-1, US-112.AC-1).
2. `[test]` **Every** endpoint in the family answers **403** to an authenticated non-admin (an
   `author`) — modes and sub-agents alike, reads as well as writes (US-110.AC-2, US-113.AC-4;
   `authorization.md` → "Global assistant configuration (FEAT-020) — admin only").
3. `[test]` Every endpoint answers **401** with no bearer token — there is no anonymous surface
   (US-110.AC-2, US-113.AC-4; `authorization.md` → "Failure modes").
4. `[test]` `POST /sub-agents` creates and returns a sub-agent with a string `id`, and
   `GET /sub-agents` lists it (UC-096; US-113.AC-1).
5. `[test]` A duplicate sub-agent name answers **409** on create and on update (US-113.AC-3).
6. `[test]` A blank name answers **400**, and a half-set model pair answers **400** (UC-096
   exception flow; US-113.AC-5).
7. `[test]` An unknown `mode_key` on `PUT /modes/{mode_key}`, and an unknown `sub_agent_id` on
   `PUT` / `disable` / `enable`, each answer **404** — including a `sub_agent_id` that is not a
   valid id at all, which must not surface as a 500 (UC-095 precondition, UC-097 precondition).
8. `[test]` An unknown tool name answers **400** on both the mode save and the sub-agent save
   (US-111.AC-1, US-113.AC-1).
9. `[test]` `POST /sub-agents/{id}/disable` returns the sub-agent with `disabled` true and an empty
   accessible-modes list, and the modes that referenced it no longer list it;
   `POST /sub-agents/{id}/enable` returns it with `disabled` false and still no modes
   (US-114.AC-2, US-114.AC-3).
10. `[test]` `GET /tools` returns the catalogue entries with `name` and `description` only, and is
    admin-gated like the rest of the family (UC-095 step 3).
11. `[test]` **No DELETE endpoint exists** in the family — a `DELETE` on a sub-agent path is not
    routed to a handler that removes the row (UC-097 — "No hard delete";
    `context.md` → scope decision 6).
12. `[test]` No response anywhere in the family contains an api key, raw or masked, or any field
    derived from `ToolDef.args_schema` / `ToolDef.callable` (FEAT-004 secret policy;
    `assistant-config.md` → "Tool registry").
13. `[manual/live]` `cd backend && .venv/Scripts/python -m pytest` green, and the app still starts
    (`cd backend && .venv/Scripts/uvicorn app.main:app --port 8185 --reload`) with the new router
    mounted.

# 002 — mode configuration service, DTOs and the tool catalogue

## Goal

Create `models/schemas/assistant_config.py` and `services/assistant_config.py` with the feature's
typed error, a read-only tool catalogue derived from `TOOL_REGISTRY`, and the **mode half** of the
service: list the fixed five with their current selections, and save one mode's prompt, tool set and
sub-agent set as a full replace.

## Interface intent

Prose only — the `skeleton` agent freezes the exact signatures.

### `models/schemas/assistant_config.py` (new) — DTOs only, no logic

- **A tool DTO** — one entry of the catalogue: the tool's stable registry `name` and its
  `description`. **Nothing else.** `args_schema` and `callable` from `ToolDef` are internal and must
  never reach the wire.
- **A tool list envelope** — `items`, per the codebase's list-envelope convention.
- **A mode DTO** — the mode's `key`, its nullable `system_prompt`, the list of `tool_name`s selected
  for it, the list of selected `sub_agent_id`s **as strings**, and both timestamps.
- **A mode list envelope** — `items`.
- **A mode update request** — the full replacement: nullable `system_prompt`, a list of tool names,
  a list of sub-agent ids as strings. All three fields are **required in the body** (they may be
  empty or null in value); this is a `PUT`-style full replace, per `context.md` → "Writes are
  full-replace".

### `services/assistant_config.py` (new)

- **A reason enum + a typed exception** for the whole feature, the
  `services/llm_servers.py:47/66` shape (`class …ErrorReason(str, enum.Enum)` with hyphenated
  string values; the exception carrying `reason` plus an optional message). Reasons this step
  introduces: **mode-not-found**, **unknown-tool**, **unknown-sub-agent**, **sub-agent-disabled**.
  Steps 003 and 004 extend the same enum; do not create a second error type.

- **A tool-catalogue reader** — maps every `ToolDef` in `services/tools.py:TOOL_REGISTRY` to the
  tool DTO and returns the envelope. Order follows the registry's declaration order. This is a pure
  read of a module-level literal: **no DB access, no `async` need beyond consistency with the rest
  of the service surface**, and it must be correct for a registry of zero, one or many entries.
  **It does not define, extend or re-declare the registry** (`context.md` → "Inbound dependency").

- **A mode-response builder** (internal) — given one `AssistantMode` row, load its `mode_tool` rows
  and its `mode_subagent` rows through the db namespace modules and hand-map them into the mode DTO,
  ids stringified. Used by both the list and the save path.

- **A mode lister** — reads every mode row and returns the envelope **ordered by
  `db.assistant_modes.DEFAULT_MODE_KEYS` position**. `db.assistant_modes.list_all` is unordered, so
  the fixed presentation order is imposed here; any row whose key is not in `DEFAULT_MODE_KEYS`
  (which seeding cannot produce, but an import could) sorts last, by key, rather than being dropped
  or raising.

- **A mode saver** — takes a mode key and the update request and performs, in this order:
  1. Load the mode; a key with no row raises **mode-not-found** (→ 404).
  2. Validate every requested tool name against `TOOL_REGISTRY`; the first unknown name raises
     **unknown-tool** (→ 400). See `context.md` → "Planner-derived decisions" for why unknown names
     are refused here even though the runtime skips-and-logs.
  3. Validate every requested sub-agent id: it must parse as an id, name an existing `SubAgent`
     (else **unknown-sub-agent**, → 400), and not be `disabled` (else **sub-agent-disabled**,
     → 400).
  4. Set `system_prompt` (a blank string is stored as-is — see DoD-3) and `modified_at`, then
     persist through `db.assistant_modes.update`.
  5. **Replace-set** the tool selection: `mode_tools.delete_by_mode` then one `create` per requested
     name, de-duplicated so a repeated name in the request cannot violate
     `uq_mode_tool_mode_key_tool_name`.
  6. **Replace-set** the sub-agent selection the same way via
     `mode_subagents.delete_by_mode` + one `create` per id, de-duplicated against
     `uq_mode_subagent_mode_key_sub_agent_id`.
  7. Return the freshly rebuilt mode DTO.

  **All validation happens before any write** so a rejected save leaves the mode's stored
  configuration untouched.

## Definition of done

1. `[test]` The mode lister returns exactly the five seeded modes, in `DEFAULT_MODE_KEYS` order,
   each carrying its `system_prompt`, its selected tool names and its selected sub-agent ids as
   strings (UC-095; US-110.AC-1).
2. `[test]` Saving a mode stores its `system_prompt` and reads it back on the next list
   (US-110.AC-1).
3. `[test]` A mode's prompt may be cleared: saving `null` and saving an empty string are both
   accepted and both round-trip as the stored value — an unset prompt is a valid configured state,
   not an error (US-110.AC-4, storage side; the runtime "adds nothing" half belongs to `013`, see
   `context.md`).
4. `[test]` Saving a tool selection stores exactly that set on the mode, and saving again with a
   different set **replaces** it rather than merging — a tool present before and absent after is
   gone (US-111.AC-1).
5. `[test]` Saving an **empty** tool list is accepted and results in a mode with zero `mode_tool`
   rows. An unconfigured mode likewise reports zero tools, never the whole registry — empty means
   *no tools*, and the two states are indistinguishable by design (US-111.AC-1;
   `context.md` → scope decision 1).
6. `[test]` Saving a sub-agent selection stores exactly that set as accessible from the mode, and a
   later save replaces it (US-112.AC-1).
7. `[test]` A save naming a tool absent from `TOOL_REGISTRY` is refused with the **unknown-tool**
   reason, and a save naming a non-existent sub-agent id with **unknown-sub-agent**; in both cases
   the mode's previously stored prompt, tool set and sub-agent set are **unchanged**
   (US-111.AC-1, US-112.AC-1).
8. `[test]` A save naming a `disabled` sub-agent is refused with the **sub-agent-disabled** reason
   and writes nothing (US-114.AC-2 — a disabled sub-agent is detached from every mode and cannot be
   re-attached while disabled).
9. `[test]` A save for a mode key that has no row is refused with the **mode-not-found** reason
   (UC-095 precondition — the mode is one of the fixed system set of five).
10. `[test]` A request repeating the same tool name, or the same sub-agent id, twice is accepted and
    produces one link row per distinct value — the unique constraints are never violated
    (US-111.AC-1, US-112.AC-1).
11. `[test]` The tool catalogue returns one entry per `TOOL_REGISTRY` `ToolDef`, in registry order,
    carrying only `name` and `description` — **no `args_schema`, no `callable`, and no key derived
    from either** appears anywhere in the payload (UC-095 step 3, the admin selects from the
    catalogue).
12. `[manual/live]` `cd backend && .venv/Scripts/python -m pytest` green.

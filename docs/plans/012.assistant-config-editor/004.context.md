# 004 — step context

Feature-wide facts (replace-set semantics, layer rules, the disabled-sub-agent decision and its
reasoning, the test harness) are in `context.md` and are not repeated here.

## The one table two steps write

`mode_subagent` is written from **both** sides and this step is the second writer:

| Writer | Clears with | Recreates |
|---|---|---|
| step 002, mode saver | `db.mode_subagents.delete_by_mode(key)` | one row per selected sub-agent id |
| step 004, sub-agent saver | `db.mode_subagents.delete_by_sub_agent(id)` | one row per selected mode key |

Both `delete_by_*` functions were added in step 001 and each removes **only its own slice** — that
property is pinned by step 001's DoD-7 and is what makes two editors over one row set safe. Neither
writer may clear the whole table.

`assistant-config.md` calls the sub-agent "the owning side" of the many-to-many; that phrase
describes *why disabling deletes the links*, **not** a direction of truth. There is no second table
and no precedence rule between the two editors — last write wins for the slice it owns.

## Which db functions this step calls

| Purpose | Call |
|---|---|
| replace a sub-agent's tools | `db.subagent_tools.delete_by_sub_agent` *(added in 001)* + `db.subagent_tools.create` |
| replace a sub-agent's modes | `db.mode_subagents.delete_by_sub_agent` *(added in 001)* + `db.mode_subagents.create` |
| validate a mode key | `db.assistant_modes.get_by_id` |
| set the disabled flag | `db.sub_agents.update` *(added in 001)* |

`TOOL_REGISTRY` membership is checked directly against the module-level list from
`services/tools.py`, exactly as step 002 does — not via `resolve_tools`, which skips unknown names
instead of refusing them (see `002.context.md`).

## Disable semantics — what is deleted and what is not

| On disable | Fate | Why |
|---|---|---|
| `mode_subagent` rows for this sub-agent | **deleted** | US-114.AC-2 — "detached from every mode"; deletion (not suppression) is what makes US-114.AC-3's "stays unattached" true without extra state |
| `subagent_tool` rows | **kept** | The sub-agent's own configuration; UC-097's disable flow mentions only modes |
| the `SubAgent` row | **kept**, `disabled = True` | Disable-not-delete (`context.md` → scope decision 6) |
| `llm_server_id` / `model_name` | **kept** | US-114.AC-4 concerns explicit model edits only |

There is **no** `db.sub_agents.delete`, no service delete, and no delete route. Do not add one.

## Interaction with step 002's mode saver

Step 002 already refuses attaching a `disabled` sub-agent from the **mode** side
(**sub-agent-disabled**). This step adds the symmetric refusal on the **sub-agent** side so the
invariant cannot be reached by either editor. The two guards share one reason value — do not
introduce a second.

The asymmetry to keep straight: an **empty** mode selection on a disabled sub-agent is fine (it
agrees with "attached to nothing"); a **non-empty** one is not. That is what keeps a disabled
sub-agent's name, prompt, tools and model editable, which UC-097 requires ("Admin opens an existing
sub-agent … edits its name, prompt, tools, accessible modes, or model") without exempting disabled
ones.

## Gotchas

- The create request's two new list fields **must default to empty**, or step 003's tests and any
  omitting caller break.
- De-duplicate before creating — both unique constraints are one duplicated checkbox away.
- `mode_key`s are strings and need no parsing; sub-agent ids do (see `002.context.md`).
- Validate **everything** before the first `delete_by_*` call. A replace-set that clears and then
  fails mid-recreate leaves the sub-agent with a partial selection, which DoD-6 forbids.
- Refresh `modified_at` on the `SubAgent` row for a links-only save too — the admin surface sorts
  and displays it, and a link change is a change to the sub-agent's configuration.

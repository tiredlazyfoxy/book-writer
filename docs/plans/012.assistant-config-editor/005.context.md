## Status taxonomy already in use (do not invent a new one)

`docs/architecture/backend/features.md`: missing-field / invalid-input → **400**, not-found →
**404**, probe-failed → **502**, delete / clear → **204**, non-admin → **403**.
`services/admin.py:109-113` → **409** for a taken name. This step adds no new status class.

## Path-shape notes

- Two static families under one prefix — `/tools`, `/modes…`, `/sub-agents…` — so there is no
  capture ambiguity **between** families. Within a family, declare `GET /modes` before
  `PUT /modes/{mode_key}` and `GET /sub-agents` + `POST /sub-agents` before
  `PUT /sub-agents/{sub_agent_id}`, per the standing rule.
- `/sub-agents/{sub_agent_id}/disable` and `/enable` put the static segment **after** the param, so
  they cannot be swallowed; they still must be declared before any hypothetical
  `/sub-agents/{sub_agent_id}/{anything}` route — there is none, and none should be added.
- The hyphenated `sub-agents` segment matches the codebase's existing `llm-servers` kebab-case URL
  style while the Python identifier stays `sub_agents`.

## Gotchas

- `main.py` currently has a stable import block and a mount block; add exactly one line to each and
  change nothing else. `main.py` is otherwise **not** this step's to edit.
- A `sub_agent_id` path param arrives as a string. Do **not** declare it `int` — FastAPI would
  answer 422 for a non-numeric value, but DoD-7 requires **404**, and the service already owns the
  defensive parse.
- No handler may touch `db/` or contain a conditional about configuration state; every decision
  belongs in `services/assistant_config.py`.
- Every reason the service can raise must have a map entry. As of step 004 the full set is:
  mode-not-found, sub-agent-not-found, name-taken, blank-name, invalid-model-pair,
  unknown-or-inactive-server, model-not-enabled, unknown-tool, unknown-sub-agent,
  sub-agent-disabled.

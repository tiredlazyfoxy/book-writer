## The full-set precedent to mirror

`db/llm_servers.py` is the only assistant-adjacent module with a complete function set — copy its
shapes rather than inventing new ones:

```
get_by_id:24   get_all:32   get_active:40   create:52   update(server) -> None:62   delete(server_id) -> bool:71
```

Note the two different delete shapes and why this step picks neither blindly: `llm_servers.delete`
returns `bool` ("did a row match"), which the route maps 204 vs 404. The three bulk deletes added
here return a **count**, because "no rows matched" is a normal, non-error state for an unconfigured
mode or a sub-agent with no tools.

## `seed_default_modes` and the gap being closed

`db/assistant_modes.py:58-69` — idempotent check-then-create, one row per `DEFAULT_MODE_KEYS` entry,
`system_prompt=None`.

Its **only** production call site today is `services/setup.py:57`, inside `create_database(...)`,
immediately after `await init_db()` and before the admin `User` row is created.
`services/setup.py:69-87 import_database` calls only `db_import_export.import_all` followed by
`set_db_ready` — it never seeds. That is the gap.

Both are **first-run bootstrap** paths owned by `services/setup.py`. Do not confuse either with the
**admin** import surface (`services/db_admin.py` → `routes/admin/db.py`), which deliberately does
**not** flip `set_db_ready` (`docs/architecture/backend/features.md` → "Admin export / import"). The
admin import path is **out of scope for this step** — it restores into an already-configured
instance whose modes were seeded at setup, so it has no gap to close.

## Gotchas

- `mode_tool`, `subagent_tool` and `mode_subagent` are **singular** `__tablename__`s while their
  `TABLE_REGISTRY` labels are plural. When writing a bulk delete, target the model class, never a
  literal table name.
- `SubAgent` is capital-A; `SubagentTool` and `ModeSubagent` are lowercase-a. A wrong import name
  fails at import time, not at test time.
- `AssistantMode.key` is the primary key and is a **`str`**. A bulk delete keyed on `mode_key`
  compares strings, not ints.
- `db/` never sets timestamps — `modified_at` is assigned by the caller before `update` is invoked
  (`context.md` → "Timestamps are set explicitly in the service"). The db test for DoD-1 therefore
  sets `modified_at` itself before calling `update`.
- `services/setup.py` is a **service**: it may not open a session, call `select()`, or touch the
  ORM. The seed call goes through the `db.assistant_modes` namespace import that `create_database`
  already uses.

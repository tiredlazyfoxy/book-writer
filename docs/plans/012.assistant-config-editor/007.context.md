# 007 — step context

Feature-wide frontend rules (MobX discipline, the page/draft/loader shapes, the multi-select idiom,
the test harness) are in `context.md` and are not repeated here. This file carries only what is
specific to the modes surface.

## Why a Table + Modal and not five inline cards

The five modes are edited through the **same page template as every other admin page** —
`LlmServersPage.tsx` + `llmServersPageState.ts` + `ServerFormModal.tsx` + `serverFormDraft.ts` —
because that template is fully established in this repo and needs no new component vocabulary. The
repo contains **no `Accordion`, `Tabs`, `Drawer`, `MultiSelect`, `Checkbox.Group` or `Chip` usage**
anywhere in `src/`, so an inline five-card editor would be inventing UI conventions in the same
step that ships the feature. UC-095 step 1 is literally *"Admin opens a mode"*, which the modal
matches.

The one genuinely new primitive is the **`Textarea`** — there is none in `src/` today. That is
unavoidable: a system prompt is multi-line by definition.

## Differences from the `LlmServersPage` template, and why

| Template feature | Here | Why |
|---|---|---|
| "Create" action button in the header | **absent** | The five modes are seeded and fixed; there is nothing to create (`assistant-config.md` → "the fixed five") |
| Row `Menu` with a destructive item | **a plain edit action** in the trailing 60px column | No delete exists for a mode |
| Modal target `useState<X \| null \| undefined>` where `null` = create | `undefined` = closed, a mode = editing; **no `null` case** | Same reason — no create path |
| One async trio in page state | **three** (modes, tools, sub-agents) | The picker needs the catalogue and the sub-agent names |

Everything else is copied verbatim in shape: `Container size="lg" py="md"`, header `Group`, error
`Text c="red"`, `Loader` or `Table striped highlightOnHover`, conditional modal mount, one
`AbortController` per handler, `void`ed calls.

## The sub-agent name problem

The mode DTO carries **`sub_agent_ids` only** — no names (a deliberate step-002 decision, see
`002.context.md`). The page therefore loads the sub-agent list alongside the modes and resolves
names locally. Consequences:

- the row's sub-agent **count** can be rendered from the mode alone;
- the picker's **labels** require the sub-agent list to be `ready`;
- a `sub_agent_id` on a mode with no matching entry in the loaded list should render as the raw id
  rather than disappearing, so a stale cache is visible instead of silently dropping a selection.

## Mode labels

Use the mode-label map exported from `src/api/assistantConfig.ts` (step 006). Do **not** re-declare
the five keys or their labels in this step, and do not derive a label by string-munging the key in
more than the one place the map's fallback already does.

## Selection state

Both pickers hold a **`Set`**. `modelsModalDraft.ts:12-13` records why: a `Set` mutated in place is
not observable to MobX, so every toggle **reassigns a fresh `Set`**. Copy
`components/llm-servers/ModelsModal.tsx:48-64` for the checkbox list itself
(`ScrollArea.Autosize mah={360}` → `Stack gap="xs"` → `Checkbox` with
`checked={draft.selected.has(x)}`).

Serialize to arrays only at submit time — the wire type is `string[]`, the draft type is `Set`.

## Error mapping for this modal

Richest precedent: `CreateUserModal.tsx:88-97` (`409 → {username}`, `400 → {password}`, else
`{form}`). This modal has **no field a server error maps onto**: the backend's 400s here mean
unknown-tool, unknown-sub-agent or sub-agent-disabled, all of which indicate the page's cached
catalogue or sub-agent list is stale — a whole-form condition, not a field one. So every status maps
to the `form` key, which `ServerFormModal.tsx:56` renders as an `<Alert color="red">` at the top of
the modal. Say so rather than leaving the mapping looking under-specified.

## Testing notes

- This is the **first admin page test in the repo** (`frontend/tests/admin/` holds only shell-level
  specs). Copy the idiom from `frontend/tests/user/BookshelfPage.test.tsx`.
- Mock `../../src/api/assistantConfig` with a **module factory**. The factory must supply **every**
  named export the rendered subtree touches — **including the mode-label map**, which is a runtime
  constant, not a function. Omitting it makes render throw; that exact caveat is recorded at
  `BookshelfPage.test.tsx:34-41`.
- `MantineProvider env="test"` (inside `renderWithProviders`) renders Modals inline and
  synchronously, so opening the editor needs no `waitFor`.
- `restoreMocks: true` wipes implementations between tests — set them in `beforeEach` via
  `vi.mocked(...)`.
- Use typed fixture factories for modes / tools / sub-agents, not partial objects cast to the type.
- Do **not** mock `fetch`, and do **not** mock `api/client`.

# 003 — sub-agent create / list / update, name uniqueness and the model-pair invariant

## Goal

Add the sub-agent half of the service: list every sub-agent, create one, and update one's scalar
fields — with a non-blank unique name (409 on collision) and the both-null-or-both-set
`(llm_server_id, model_name)` invariant enforced at the service edge.

## Interface intent

Prose only — the `skeleton` agent freezes the exact signatures. This step **extends** the two
modules step 002 created; it does not create new ones and does not alter the mode surface.

### `models/schemas/assistant_config.py` — additions

- **A sub-agent DTO** — `id` as a string, `name`, `system_prompt`, `disabled`, the nullable
  `llm_server_id` **as a string**, the nullable `model_name`, the list of selected `tool_name`s, the
  list of accessible `mode_key`s, and both timestamps. The two link lists are **read here from the
  start** (they are empty until step 004 supplies a write path) so the response shape never changes
  after this step.
- **A sub-agent list envelope** — `items`.
- **A create request** — `name`, `system_prompt`, and the nullable model pair. Step 004 adds the
  tool and mode selections to this same model.
- **An update request** — the same fields, full-replace semantics (`context.md` → "Writes are
  full-replace"). It carries **no `disabled` field**: enable/disable is its own operation in step
  004, because disabling has a cascade that a field assignment would hide.

Both request models and the response **must** set `model_config = ConfigDict(protected_namespaces=())`
— they carry a `model_name` field.

### `services/assistant_config.py` — additions

- **New reasons on the existing enum**: **sub-agent-not-found**, **name-taken**, **blank-name**,
  **invalid-model-pair**, **unknown-or-inactive-server**, **model-not-enabled**.

- **A model-pair validator** (internal) — mirrors `services/chats.py:142-177 _validate_model_pair`
  **exactly** in rule set and order:
  1. exactly one of the two set → **invalid-model-pair**;
  2. both `None` → the assignment is *inherit the main chat's model*, return "no server";
  3. the id fails to parse → **unknown-or-inactive-server**;
  4. no such `LlmServer`, or it exists but `is_active` is false → **unknown-or-inactive-server**;
  5. `model_name` not among that server's decoded `enabled_models` → **model-not-enabled**;
  6. otherwise return the parsed server id.

  The **accepted consequence** is recorded in `context.md` → scope decision 3: a server deactivated
  *after* an assignment was stored leaves that assignment unusable at runtime, and nothing here
  re-validates or rewrites it.

- **A sub-agent-response builder** (internal) — hand-maps one `SubAgent` row plus its
  `subagent_tool` rows and its `mode_subagent` rows into the DTO, ids stringified.

- **A sub-agent lister** — every sub-agent, ordered by name, **including disabled ones** (the admin
  must be able to find a disabled sub-agent to re-enable it, US-114.AC-3). Each entry carries its
  `disabled` flag so the surface can mark it.

- **A creator** — trims the name and refuses an empty result with **blank-name** (→ 400, UC-096
  exception flow); refuses a name already held by another sub-agent with **name-taken** (→ 409, the
  `services/admin.py:109-113 username_taken` precedent); validates the model pair; then stores the
  row with `disabled = False`, both timestamps set, and returns the DTO.

- **An updater** — loads the sub-agent (absent → **sub-agent-not-found**, → 404), applies the same
  name and model-pair validation, and persists. The name check must **exclude the row being
  updated**, so saving a sub-agent without renaming it is not a self-collision. `disabled` is not
  touched. `modified_at` is refreshed.

  **All validation happens before any write.**

## Definition of done

1. `[test]` Creating a sub-agent with a name, prompt and no model stores it and returns it with a
   string `id`, `disabled` false, both link lists empty, and both timestamps set (UC-096;
   US-113.AC-1).
2. `[test]` A created sub-agent with **no** model assignment stores `llm_server_id` and `model_name`
   as null — the recorded state for *re-use-the-main-chat's-model*, which is the default
   (US-113.AC-6).
3. `[test]` A created sub-agent naming an **active** server and a model listed in that server's
   `enabled_models` stores both fields, and the response returns `llm_server_id` as a **string**
   (US-113.AC-5).
4. `[test]` A half-set model pair — server without model, or model without server — is refused with
   the **invalid-model-pair** reason, on create and on update alike, and nothing is written
   (US-113.AC-5; `assistant-config.md` → "Model assignment is nullable, and the two model fields
   move together").
5. `[test]` A pair naming a non-existent server, or an existing server whose `is_active` is false,
   is refused with **unknown-or-inactive-server**; a pair naming an active server but a model absent
   from its `enabled_models` is refused with **model-not-enabled** (US-113.AC-5).
6. `[test]` A name already held by another sub-agent is refused with the **name-taken** reason on
   create **and** on update, and the existing rows are unchanged (US-113.AC-3; UC-097 exception
   flow).
7. `[test]` A blank or whitespace-only name is refused with **blank-name** on create and on update
   (UC-096 exception flow; US-113.AC-1).
8. `[test]` Updating a sub-agent **without** changing its name succeeds — the uniqueness check
   excludes the row being updated and does not self-collide (US-114.AC-1).
9. `[test]` Updating stores a changed name, prompt and model assignment, including switching a
   specific model **back to null/null** (inherit the main chat's) and from null/null to a specific
   pair; `modified_at` advances (US-114.AC-1, US-114.AC-4).
10. `[test]` Updating a sub-agent id with no row is refused with **sub-agent-not-found**
    (UC-097 precondition — the sub-agent exists).
11. `[test]` The lister returns every sub-agent ordered by name, **including disabled ones**, each
    carrying its `disabled` flag (US-114.AC-3 — a disabled sub-agent must remain findable to be
    re-enabled).
12. `[manual/live]` `cd backend && .venv/Scripts/python -m pytest` green.

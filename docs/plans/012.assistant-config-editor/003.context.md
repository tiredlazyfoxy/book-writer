## The model-pair invariant — the exact source to mirror

`backend/app/services/chats.py:142-177`:

```python
async def _validate_model_pair(llm_server_id: str | None, model_name: str | None) -> int | None
# 1. (a is None) != (b is None)                          -> invalid_model_pair          (400)
# 2. both None                                           -> return None
# 3. int(llm_server_id); ValueError/TypeError            -> unknown_or_inactive_server  (400)
# 4. server = await llm_servers.get_by_id(...)
#    server is None or not server.is_active              -> unknown_or_inactive_server  (400)
# 5. model_name not in json.loads(server.enabled_models) -> model_not_enabled           (400)
# 6. return server_id
```

Copy the **rule set and its order**, not the module. This step writes its own copy inside
`services/assistant_config.py` under this feature's own error enum — do **not** import a private
helper out of `services/chats.py` and do **not** refactor `chats.py` to share one. Two services
owning one small invariant each is the codebase's existing shape; a cross-service private import
would couple the chat feature to the admin feature for four lines.

**Deliberate divergence, recorded.** `services/chats.py:update_chat:276-280` re-validates the pair
only when at least one of the two fields is present, so a partial `PATCH` never wipes an existing
assignment. This step does **not** mirror that, because writes here are full-replace `PUT`s
(`context.md` → "Writes are full-replace"): both fields are always explicitly present, and
`null` + `null` is a meaningful value (*inherit the main chat's model*), not an omission. A verifier
should read the absence of the partial-patch branch as intentional.

**`enabled_models` is a JSON-encoded `list[str]` in a TEXT column.** It is decoded at the **service
edge** with `json.loads`, never in `db/` and never in the table
(`docs/architecture/backend/features.md` → `LlmServer`).

## Name uniqueness — the precedent and why it is a pre-check

`services/admin.py:109-113` raises `AdminError(AdminErrorReason.username_taken)` after an explicit
lookup, and the route maps it to **409**. Do the same: call `db.sub_agents.get_by_name` (added in
step 001) and raise **name-taken** before attempting the write.

`SubAgent.name` also carries `unique=True` at the DB level, so the pre-check is not the only
guard — but it is the one that produces a typed 409 instead of a raw `IntegrityError` surfacing as a
500. On **update**, compare the found row's `id` against the row being updated and treat a self-match
as *not* a collision.

## `SubAgent` field notes that shape this step

- `system_prompt: str` is **required and non-null** — unlike `AssistantMode.system_prompt`, which is
  nullable. A sub-agent has no "no prompt" state; an empty string is the closest thing and is
  accepted as-is (only the **name** is blank-checked).
- `disabled: bool = False`. There is no `disabled` field on the update request — enable/disable is
  step 004's own operation.
- **There is no `accessible_modes` column.** Mode access is the `mode_subagent` link table, read via
  `db.mode_subagents.list_by_sub_agent` (added in step 001).
- `models/sub_agent.py:35-37`'s docstring already states the model-pair invariant is a **service**
  rule, not a DB one. Nothing in `models/` enforces it and nothing should be added there.

## The model picker feed — no new endpoint

`context.md` → "Planner-derived decisions" settles this: the sub-agent model picker feeds off the
**existing** `GET /api/admin/llm-servers` surface (`services/llm_servers.py:102 get_all_servers()`),
whose `LlmServerResponse` already exposes decoded `enabled_models: list[str]` and `is_active`. This
step therefore adds **no** model-options DTO and **no** model-options service function — do not port
`services/chats.py:287-306 list_model_options` or `models/schemas/chats.py:146-162`
`ModelOptionResponse` / `ModelOptionListResponse`. Those exist for the author-facing chat surface,
which is not entitled to the admin payload; the admin already is.

## Gotchas

- `llm_server_id` is an **`int`** FK on the row and a **`str`** on the wire, both directions.
- The link lists on the sub-agent DTO will be **empty for every test in this step** — there is no
  write path for them until step 004. Assert they are present and empty; do not assert they are
  populated.
- Trim the name before the blank check *and* before the collision check, so `" x "` and `"x"` cannot
  both be stored.
- Set `created_at` **and** `modified_at` on create, and refresh `modified_at` on update, with
  `datetime.now(timezone.utc)`.
- `db.sub_agents.create` takes a constructed row; the snowflake `id` comes from
  `default_factory=generate_id` and must not be supplied.

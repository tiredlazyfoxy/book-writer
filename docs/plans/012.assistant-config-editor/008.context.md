# 008 — step context

Feature-wide frontend rules (MobX discipline, the page/draft/loader shapes, the multi-select idiom,
the test harness) are in `context.md` and are not repeated here. Facts about the modes page are in
`007.context.md` and are **not** needed here — the two steps share no file.

## The model picker's data source

Per `context.md` → "No new model-options endpoint", the picker feeds off the **existing**
`src/api/llmServers.ts:listServers()`, which already returns `LlmServer[]` unwrapped. The relevant
fields (`llmServers.d.ts:25`):

```ts
LlmServer { id, name, backend_type, base_url, has_api_key, enabled_models: string[],
            is_active, is_embedding, embedding_model, created_at, modified_at }
```

`enabled_models` is already a decoded `string[]` and `is_active` is already exposed, so the
`modelOptions` computed is a flatten-and-filter over data the admin SPA is already entitled to. This
step adds **no** new type and **no** new api function for models.

A `Select` needs `{ value, label }` data. The `value` must encode **both** the server id and the
model name (they move together — `assistant-config.md` → "Model assignment is nullable, and the two
model fields move together"); the draft splits it back into the two wire fields on change. Pick one
encoding and keep it inside the draft — it never reaches the wire.

## Disable/enable is a row action, not a form field

Reason, worth restating because the LLM-servers form does the opposite: `ServerFormModal.tsx:89-95`
puts an `is_active` `Switch` in the edit form, and `UsersPage.tsx:136-142` uses a row
`Menu.Item color="red"` → action → refresh. **Both precedents are valid**; this page uses the
**Users-page row-action** form because disabling a sub-agent has a **cascade** — it deletes every
`mode_subagent` row for it (US-114.AC-2) — and burying a cascading side effect inside a form save
would make it invisible at the moment the admin performs it. The form therefore has **no `disabled`
control**, and the wire update payload carries no `disabled` field (step 003).

## Draft coupling rules

- Both pickers hold a **`Set`** and every toggle **reassigns a fresh `Set`** — mutating in place is
  invisible to MobX (`modelsModalDraft.ts:12-13`). Copy `ModelsModal.tsx:48-64`.
- The model pair is two coupled draft fields, never one. Selecting "Inherit the main chat's model"
  sets **both** to `null`; selecting a concrete option sets **both**. There is no UI path to a
  half-set pair, which is why DoD-5 asserts the coupling rather than an error message.
- `clientErrors` keys are **wire** field names (`name`, not `subAgentName`) — that is what makes the
  server-error merge in `errors` work without a translation table (`serverFormDraft.ts:38-46`).

## Server-error mapping

`CreateUserModal.tsx:88-97` is the richest precedent (`409 → {username}`, `400 → {password}`, else
`{form}`). Here:

| Status | Key | Backend reason behind it |
|---|---|---|
| 409 | `name` | name-taken (US-113.AC-3) |
| 400 | `name` when the message identifies a blank name; otherwise `form` | blank-name; else invalid-model-pair / unknown-or-inactive-server / model-not-enabled / unknown-tool / mode-not-found / sub-agent-disabled |
| 404 | `form` | sub-agent-not-found — the row was removed under the admin |
| other | `form` | — |

A `form` key renders as an `<Alert color="red">` at the top of the modal
(`ServerFormModal.tsx:56`).

## Modal target typing

`LlmServersPage.tsx:50-54`: `useState<LlmServer | null | undefined>(undefined)` where `undefined` =
closed, `null` = create, a row = edit. This page uses the **full three-state** version (unlike the
modes page, which has no create path). The target lives in **component-local `useState`**, not in
page state — decision 9 of the frontend conventions.

There is a modal-to-modal hand-off precedent (`ServerFormModal.tsx:48-51`, `onSelectModels`) — it is
**not** used here. The tool and mode pickers live inline in this one modal.

## Mode labels

Use the mode-label map exported from `src/api/assistantConfig.ts` (step 006). Do not re-declare the
five keys.

## Testing notes

- Mock **two** api modules with module factories: `../../src/api/assistantConfig` and
  `../../src/api/llmServers`. Each factory must supply **every** named export the rendered subtree
  touches — including the **mode-label map** and any runtime `*_OPTIONS` constant `api/llmServers.ts`
  exports (`llmServers.ts:27-31`). Omitting one makes render throw; the caveat is recorded at
  `BookshelfPage.test.tsx:34-41`.
- `MantineProvider env="test"` renders Menus **and** Modals inline and synchronously — the row menu
  can be opened and its items asserted without `waitFor`. That is what makes DoD-12 ("no delete
  action exists") directly assertable.
- `restoreMocks: true` — set implementations in `beforeEach` via `vi.mocked(...)`.
- Typed fixture factories for sub-agents / tools / modes / servers, not partials.
- For DoD-6 the server fixture set must include at least one `is_active: false` server carrying
  `enabled_models`, so its absence from the picker is a real assertion.
- Do **not** mock `fetch`, and do **not** mock `api/client`.

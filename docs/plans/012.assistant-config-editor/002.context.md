## Gotchas

- **`sub_agent_id` is a snowflake `int` in the row and a `str` on the wire.** The update request
  carries strings; parse with `int(...)` inside a guard, and treat a `ValueError` / `TypeError` as
  **unknown-sub-agent** rather than letting it escape as a 500. This is the same defensive parse
  `services/chats.py:_validate_model_pair` step 3 uses for `llm_server_id`.
- **`mode_key` is already a string** — no conversion anywhere.
- The link tables carry snowflake `id` PKs with `default_factory=generate_id`; a `create` needs no
  explicit id.
- Set `modified_at` in the service with `datetime.now(timezone.utc)` before calling
  `db.assistant_modes.update`. There is no ORM `onupdate`.
- The service may not open a session, use `select()`, or call `session.add()`. Every read goes
  through a `db/` namespace module.
- De-duplicate requested tool names and sub-agent ids **before** issuing `create` calls — the
  unique constraints `uq_mode_tool_mode_key_tool_name` and
  `uq_mode_subagent_mode_key_sub_agent_id` would otherwise turn a duplicated checkbox value into an
  integrity error surfacing as a 500.
- This step writes **no sub-agent DTO**. The mode DTO carries sub-agent **ids only**; the editor
  resolves names from the separate sub-agent list (step 003). Keeping the mode payload id-only is
  what stops the two halves of the feature from importing each other's response shapes.

## Size note

This step is at the top of the 50–200-line band (~55 lines of DTOs, ~150 of service). It is not
split further because the mode saver, its validation and the response builder are one contract: a
save that validates in one place and writes in another cannot honour DoD-7 ("a rejected save leaves
the mode unchanged").

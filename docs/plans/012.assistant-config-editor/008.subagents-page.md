# 008 — the sub-agent management surface

## Goal

Turn the Sub-agents shell into the real surface: a table of every sub-agent, a create/edit modal
covering name, prompt, tools, accessible modes and the optional model assignment, and a
disable/enable action — with no delete anywhere.

## Interface intent

Prose only — the `skeleton` agent freezes the exact signatures. Every component is an `observer`.

### `subAgentsPageState.ts` (new)

- **A page-state class** — `makeAutoObservable`, no methods, no computeds
  (`llmServersPageState.ts:18-26`). **Four async trios**: sub-agents, the tool catalogue, the modes
  (for the accessible-modes picker), and the **LLM servers** (for the model picker, loaded through
  the existing `api/llmServers` module — `context.md` → "No new model-options endpoint").
- **One external loader** `(state, signal?)` loading all four in parallel, standard body shape.
- **Two external mutation actions** `(state, subAgentId, signal?)` — disable and enable — each
  calling the api then **re-running the loader**; no optimistic update. Modelled on
  `llmServersPageState.ts:67 deleteServerAction`, minus the deletion.

### `subAgentFormDraft.ts` (new)

Split-draft convention (`serverFormDraft.ts`), constructed from **a sub-agent or `null`** plus the
tool catalogue, the mode list and the server list:

- Fields: `name`, `systemPrompt`, a `Set` of selected tool names, a `Set` of selected mode keys, and
  the model assignment as **two coupled values** (`llmServerId: string | null`,
  `modelName: string | null`). On edit they seed from the row; on create they start empty/null.
  Plus `serverErrors: Record<string, string>` and `submitStatus`.
- **Computed `modelOptions`** — flattens the **active** servers' `enabled_models` into selectable
  `(server id, server name, model name)` entries, plus an explicit **"Inherit the main chat's
  model"** choice that maps to `null` + `null` (US-113.AC-6). Selecting a concrete option sets
  **both** fields together; selecting inherit clears **both**. The pair can therefore never reach a
  half-set state from this UI — the backend's 400 is a second line of defence, not the first.
  Inactive servers contribute nothing.
- **Computed `clientErrors`** with **wire** field names: a blank/whitespace `name` produces a `name`
  error. Nothing else is required — an empty tool set, an empty mode set and an empty prompt are all
  valid.
- **Computeds `errors`** (`{...clientErrors, ...serverErrors}`, server wins) and `canSubmit`.
- **A submit function** `(draft, subAgentId | null, onSaved, signal?)` — `null` means create — with
  the precedent's exact order: clear `serverErrors` + status loading → api create or update →
  `catch (err instanceof ApiError)` → map and **return** (non-`ApiError`: aborted-guard, status
  error, **rethrow**) → status ready → `onSaved()`.
- **Status → field mapping** (`CreateUserModal.tsx:88-97` precedent): **409** → `{ name: … }`
  (duplicate name, US-113.AC-3), **400** → `{ name: … }` when the message identifies a blank name,
  otherwise `{ form: … }` (a stale catalogue, a bad model pair, a disabled sub-agent), anything else
  → `{ form: … }`.

### `SubAgentFormModal.tsx` (new)

Props in the `ServerFormModal.tsx:17-25` shape: `opened`, `subAgent: SubAgent | null` (`null` =
create), the tool catalogue, the mode list, the server list, `onClose`, `onSaved`. Mounted
**conditionally** so each open builds a fresh draft. Body:

- `TextInput` for the name, bound to `draft.errors.name`;
- `Textarea` for the system prompt;
- a **model `Select`** driven by `draft.modelOptions`, with "Inherit the main chat's model" as the
  default choice;
- a **tool picker** — the multi-select idiom (`ScrollArea.Autosize` → `Stack` → one `Checkbox` per
  catalogue tool), with an explanatory empty state when the catalogue is empty;
- an **accessible-modes picker** — the same idiom, one `Checkbox` per mode, labelled from the api
  module's mode-label map (step 006). This is the **sub-agent-side editor of the same
  `mode_subagent` rows** the modes page writes (US-112.AC-2);
- the `form` alert, Cancel / Save wired to `canSubmit`.

**No `disabled` control in this form** — disable/enable is a row action, because it has a cascade
(detaching from every mode) that a checkbox would hide.

### `SubAgentsPage.tsx` (replaces the step-006 shell)

Standard template: `const [state] = useState(() => new …State())`; one page-level `useEffect` with
an `AbortController`, deps `[state]`; the modal target in **component-local `useState`** typed
`undefined` = closed / `null` = create / a sub-agent = edit (`LlmServersPage.tsx:50-54`).

Layout: `Container size="lg" py="md"` → header `Group` (Title + a **"New sub-agent"** `Button`) →
error `Text c="red"` → `Loader` or `Table striped highlightOnHover`. One row per sub-agent: name
(visibly marked when `disabled`), the model assignment rendered as `server / model` or "inherits
main chat", the tool count, the accessible-mode count, and a trailing 60px `Menu` /
`ActionIcon IconDots` column offering **Edit** and **Disable** or **Enable** — and **no Delete item
at all** (`context.md` → scope decision 6). Each handler spins its own `AbortController` and `void`s
the call; every mutation refreshes via the loader.

## Definition of done

1. `[test]` On mount the page loads sub-agents, tools, modes and servers and renders one row per
   sub-agent, including disabled ones, marked as disabled (UC-097 step 1; US-114.AC-3).
2. `[test]` A failing load renders an error message and no table, without throwing.
3. `[test]` "New sub-agent" opens an empty form; submitting a name, prompt, tool selection and mode
   selection calls the create api once with exactly those values and then refreshes the list
   (UC-096; US-113.AC-1).
4. `[test]` Creating **without** choosing a model sends `llm_server_id` and `model_name` as `null` —
   the inherit-the-main-chat's-model default (US-113.AC-6).
5. `[test]` Choosing a concrete model sets **both** wire fields together, and switching back to
   "Inherit" clears **both** — the UI cannot emit a half-set pair (US-113.AC-5, US-114.AC-4).
6. `[test]` The model picker offers models only from **active** servers; an inactive server's models
   are absent (US-113.AC-5).
7. `[test]` A create rejected with **409** shows the error on the **name** field, leaves the modal
   open with the admin's input intact, and does not refresh the list (US-113.AC-3; UC-096 exception
   flow).
8. `[test]` A blank name is blocked client-side — Save is disabled and no api call is made
   (UC-096 exception flow).
9. `[test]` Opening an existing sub-agent seeds the form with its name, prompt, model assignment,
   checked tools and checked modes; saving calls the update api with the edited values and refreshes
   (UC-097 steps 2–3; US-114.AC-1).
10. `[test]` The accessible-modes picker lists all five modes by label and reflects the sub-agent's
    stored `mode_keys` as checked — the same link the modes page edits, shown and editable from this
    view too (US-112.AC-2).
11. `[test]` The row menu's Disable action calls the disable api for that sub-agent and refreshes;
    for a disabled sub-agent the menu offers **Enable** instead, which calls the enable api
    (UC-097 alternate flow; US-114.AC-2, US-114.AC-3).
12. `[test]` **No delete action exists** anywhere on the page — the row menu offers no destructive
    removal and no delete api function is called under any interaction (UC-097 — "No hard delete";
    `context.md` → scope decision 6).
13. `[test]` An empty tool catalogue renders an explanatory empty state and the form still submits —
    nothing hard-codes a tool count (`context.md` → "Inbound dependency").
14. `[manual/live]` `cd frontend && npm run build`, `npm run test:types` and `npm test` all green.
15. `[manual/live]` Against a running backend: creating a sub-agent with modes selected makes it
    appear in those modes on the Assistant modes page, and disabling it removes it from them
    (UC-096 postcondition; US-113.AC-2, US-114.AC-2).

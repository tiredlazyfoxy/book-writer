# 007 — the five-mode editor surface

## Goal

Turn the Assistant modes shell into the real editor: a table of the five fixed modes and a per-mode
modal that saves its system prompt, its tool selection and its accessible-sub-agent selection in one
call.

## Interface intent

Prose only — the `skeleton` agent freezes the exact signatures. Every component is an `observer`.

### `assistantModesPageState.ts` (new)

- **A page-state class** — `makeAutoObservable` in the constructor, **no methods and no
  computeds**, exactly the `llmServersPageState.ts:18-26` shape. It holds **three async trios**
  (`data` / `dataStatus: "idle"|"loading"|"ready"|"error"` / `dataError`): the modes, the tool
  catalogue, and the sub-agent list. The sub-agent list is needed because the mode editor's
  sub-agent picker must show **names**, not the ids the mode DTO carries.
- **One external loader** `(state, signal?)` that loads all three in parallel and commits them,
  following the standard body shape (`context.md` → frontend constraints): set loading + clear
  errors, await, `if (signal?.aborted) return;`, commit in `runInAction`; on `ApiError` set the
  error, otherwise **rethrow**.
- **No mutation action lives here.** The save runs from the draft; the page re-calls the loader
  afterwards, per the no-optimistic-updates rule.

### `modeEditorDraft.ts` (new)

The split-draft convention (`components/llm-servers/serverFormDraft.ts`):

- **A draft class** constructed from **one mode** plus the tool catalogue and the sub-agent list.
  It seeds `systemPrompt` from the mode (null → empty string), a **`Set` of selected tool names**
  and a **`Set` of selected sub-agent ids**, and holds `serverErrors: Record<string, string>` and
  `submitStatus`. Selection toggles **reassign a fresh `Set`**; they never mutate in place.
- **Computeds** `clientErrors` (keys are **wire** field names), `errors`
  (`{...clientErrors, ...serverErrors}`, server wins) and `canSubmit`
  (`submitStatus !== "loading"` and no client errors). A mode has **no required field** — an empty
  prompt and empty selections are all valid (`context.md` → scope decision 1, US-110.AC-4), so
  `clientErrors` is normally empty; it exists to keep the shape uniform and to hold any future
  client-side rule.
- **A submit function** `(draft, modeKey, onSaved, signal?)` following the precedent's order
  exactly: clear `serverErrors` + status loading → call the api save with the prompt (**empty string
  sent as `null`**) and the two selections as arrays → `catch (err instanceof ApiError)` → map
  status to fields and **return** (non-`ApiError`: aborted-guard, status error, **rethrow**) →
  status ready → `onSaved()`.
- **Status → field mapping** (hand-written per modal, the `CreateUserModal.tsx:88-97` precedent):
  **400** → a `form`-keyed message (an unknown tool or a disabled sub-agent means the page's cached
  catalogue is stale), **404** → `form`, anything else → `form`. A `form` key renders as an
  `<Alert color="red">` at the modal top (`ServerFormModal.tsx:56`).

### `ModeEditorModal.tsx` (new)

Props in the `ServerFormModal.tsx:17-25` shape: `opened`, the mode being edited, the tool catalogue,
the sub-agent list, `onClose`, `onSaved`. Mounted **conditionally** by the page so each open builds
a fresh draft. Body:

- a read-only heading showing the mode's human label (from the api module's label map, step 006);
- a **`Textarea`** for the system prompt — the repo's **first**; autosized with a sensible minimum,
  described as optional;
- a **tool picker** using the established multi-select idiom: `ScrollArea.Autosize mah={360}` →
  `Stack gap="xs"` → one `Checkbox` per catalogue tool labelled with its `name` and `description`.
  With an empty catalogue it renders an explanatory empty state, not a blank box;
- a **sub-agent picker** with the same idiom, one `Checkbox` per sub-agent, showing the name;
  **`disabled` sub-agents are not offered** (the backend refuses them — step 002);
- the `form` alert, and Cancel / Save buttons wired to `canSubmit`.

### `AssistantModesPage.tsx` (replaces the step-006 shell)

The standard admin page template: `const [state] = useState(() => new …State())`; one page-level
`useEffect` with `new AbortController()`, deps `[state]`, aborting on unmount; the edit target held
in **component-local `useState`** (not page state), `undefined` = closed / a mode = editing —
matching `LlmServersPage.tsx:50-54` minus the create case, since modes are never created.

Layout: `Container size="lg" py="md"` → header `Group` with a `Title` **and no action button**
(there is nothing to add) → error `Text c="red"` → `Loader` or `Table striped highlightOnHover`.
One row per mode, in the order the api returns them: the mode's label, whether a prompt is set, the
number of selected tools, the number of selected sub-agents, and a trailing 60px action column
opening the editor. Saving closes the modal and re-runs the loader.

## Definition of done

1. `[test]` On mount the page loads modes, tools and sub-agents and renders one row per mode, in the
   order the api returned them, showing each mode's label and its tool and sub-agent counts
   (UC-095 step 1; US-110.AC-1).
2. `[test]` A failing load renders an error message and no table, and does not throw
   (UC-095 — the surface degrades rather than crashing).
3. `[test]` Opening a mode's editor shows its stored system prompt, its selected tools pre-checked
   and its selected sub-agents pre-checked, with unselected ones unchecked (UC-095 steps 2–4;
   US-110.AC-1, US-111.AC-1, US-112.AC-1).
4. `[test]` Editing the prompt and saving calls the mode-save api once with that mode's key and the
   new prompt, then refreshes the list; the modal closes (US-110.AC-1).
5. `[test]` Clearing the prompt entirely sends `null` — an empty prompt is a valid saved state and
   is not blocked client-side (US-110.AC-4, storage side).
6. `[test]` Toggling tool checkboxes and saving sends exactly the checked set, and **unchecking
   every tool sends an empty array** rather than omitting the field — empty means *no tools*
   (US-111.AC-1; `context.md` → scope decision 1).
7. `[test]` Toggling sub-agent checkboxes and saving sends exactly the checked set of sub-agent ids
   (US-112.AC-1).
8. `[test]` A **disabled** sub-agent is not offered in the picker (US-114.AC-2).
9. `[test]` A save that fails with an `ApiError` renders the error at the top of the modal, leaves
   the modal **open** with the admin's edits intact, and does not refresh the list
   (UC-095 exception handling).
10. `[test]` An empty tool catalogue renders an explanatory empty state and the modal still saves —
    nothing hard-codes a tool count (UC-095 step 3; `context.md` → "Inbound dependency", the
    registry has one entry today).
11. `[manual/live]` `cd frontend && npm run build`, `npm run test:types` and `npm test` all green.
12. `[manual/live]` Against a running backend, editing a mode's prompt, tools and sub-agents and
    reloading the page shows the saved configuration (UC-095 postcondition).

# 001 — step context

Feature-wide facts (the column list, the ordinal rules, layer rules, gates, test harness) are in
`context.md` and are not repeated here.

## The precedents to copy, named exactly

- **Row shape:** `backend/app/models/book_author_prompt.py` —
  `id: int = Field(default_factory=generate_id, primary_key=True)`,
  `book_id: int = Field(foreign_key="books.id")`, `user_id: int = Field(foreign_key="users.id")`,
  `created_at` / `modified_at` as `datetime | None = Field(default=None)`. Copy all of that. **Do not
  copy its `UniqueConstraint("book_id", "user_id")`** — see the step file's Interface intent.
- **`db/` module idiom:** `backend/app/db/book_author_prompts.py`. Every function opens its own session
  via `await get_standalone_session()` then `async with session:`. Copy the session, add/commit and
  refresh idiom verbatim rather than inventing one. Its own comment records the rule this step inherits:
  **timestamps are the service's policy, not this layer's.**
- **Codec pair:** `_book_author_prompt_to_dict` / `_dict_to_book_author_prompt` in
  `backend/app/services/db_import_export.py` — roughly 35 lines for the pair. Codec functions live in
  **that module**, not in `db/` and not in `models/`.

## `TABLE_REGISTRY` — the shape and the exact position

`TABLE_REGISTRY` is a `list[RegistryEntry]` where
`RegistryEntry = tuple[str, type[SQLModel], to_dict_fn, from_dict_fn]`. The order is **import order**.

The `memos` tuple goes **immediately after the `chapter_author_prompts` tuple and before
`("chapters", Chapter, …)`** — index 11 of 21. `backend/book-domain.md` → "`memos` sits immediately
after `chapter_author_prompts` (index 11)" states both grounds and, importantly, that this position is
**not** a second exception to FK ordering: here adjacency and FK order agree, where
`chapter_author_prompts` needed a sanctioned exception because they did not.

## `db/engine.py` — two seams, and only one applies

- **MODEL-REGISTRATION SEAM** — an explicit import list. A model absent from it is absent from
  `SQLModel.metadata` and its table is never created. **This is the seam this step uses**, and it is
  the only line this step changes in the file.
- **ADDITIVE MIGRATION SEAM** — currently `pass`. It exists for *columns added to existing tables*
  (`ChatMessage.tool_trace` is its only user). A brand-new table does not need it. **Leave it `pass`,
  and leave `ADDITIVE_COLUMNS` alone.**

There is no Alembic anywhere in the repository.

## Gotcha — `""` is a value, and so is `false`

Three columns have a falsy legal value and a codec or `db/` function that treats falsy as absent breaks
this step:

- `body = ""` — an empty memo is the **normal** state of a freshly created one (UC-103).
- `active = False` — a switched-off memo, still listed (US-127.AC-1).
- `archived = False` — the default, and the value the whole working-list read keys off.

Watch for `or ""` / `or False` / truthiness branches in the codec in particular.

## Gotcha — `ordinal` is not a primary key and not unique

It is a plain non-null int scoped per `(book, author)`. An **archived** row may legitimately share an
ordinal with a live one (`context.md` → decision 2). Do not add a unique constraint, a composite key or
an index-with-uniqueness to "fix" that; it is inert, because an archived row is never in the list.

## Test seeding

`backend/tests/db/` specs use the `db` fixture from `backend/tests/conftest.py` and insert supporting
rows through the sibling `db/` modules (`books`, `users`) — there is no HTTP in a db-layer spec.

Import/export specs live as flat `backend/tests/test_data_domain_*.py` modules, so **DoD-12, DoD-13 and
DoD-14 belong in `backend/tests/test_data_domain_memos.py`**, not in the db-layer spec.

DoD-1 (many rows per pair) must be asserted at the **database** level — two successful inserts, not a
Python-side assertion that no constraint object is declared. A later refactor that added a constraint
must fail this test.

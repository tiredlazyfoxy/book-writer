# 003 — step context

Feature-wide facts (the full route table, the status taxonomy, the DTO shapes) are in `context.md` and
are not repeated here.

## The precedent to copy, named exactly

`backend/app/routes/book_author_prompts.py`:

- `router = APIRouter(prefix="/api/books", tags=[...])`;
- a module-level `_<X>_ERROR_STATUS` dict, one entry per reason;
- a `_map_<x>_error` helper;
- handlers taking `access: authz.BookAccess = Depends(authz.book_access)` and nothing else from the
  path.

Registration in `backend/app/main.py` is an import plus `app.include_router(...)`, matching the
neighbouring routers.

## Route declaration order — set it up correctly now, even though nothing collides yet

At this step the three paths cannot collide. **Step 004 adds `PUT /{book_id}/memos/order`, which MUST
be declared before `PUT /{book_id}/memos/{memo_id}`** — FastAPI matches in declaration order, and
`/{memo_id}` would otherwise swallow the literal `order` segment. `routes/chapters.py` carries the same
constraint with a comment at the `PUT /{book_id}/chapters/order` declaration saying the ordering is
load-bearing.

Leave the `/{memo_id}` handler at the **end** of the module so step 004 has an obvious place to insert
ahead of it, and so step 005's four `/{memo_id}/<verb>` routes land beside it.

## What this step must NOT do

- **No re-derivation of `401` or the private-book `404`.** Both come from `Depends(authz.book_access)`.
  Producing them here would put existence hiding in a second place — the exact failure
  `authorization.md` → "Enforcement" is written to prevent.
- **No archived-book refusal.** `routes/chapters.py` refuses writes on an archived book; memos are the
  one named carve-out and must not copy it. DoD-11 is the test that catches a copy.
- **No `authz.require` call and no `Capability`.** Membership arrives with the access context and the
  service owns the rest.
- **No parsing of `memo_id`.** It is handed to the service as the wire string; the service owns the
  malformed-id decision (step 002's context).

## Test seeding

`backend/tests/routes/` specs define their own local `_seed_user` / `_seed_book` / `_auth_header`
helpers — there is no shared factory module; copy them from a sibling route spec. Auth is **real**:
seed a user row and mint a real JWT. Assertions read the parsed response body, and the envelope key for
the list is `items`.

For DoD-10 the three cases need three different fixtures: a request with no `Authorization` header; a
logged-in user with no relationship to a **private** book; and a logged-in user who can see the book
but is not a member (a reader on a **public** book).

For DoD-11 seed the book and then set its state to `archived` before calling — the carve-out is about
`BookAccess.book_state`, which the dependency resolves from the stored book.

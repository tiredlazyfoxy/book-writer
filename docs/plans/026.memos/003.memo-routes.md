# 003 — The memo routes: list, create, body update

## Goal

Expose the service behind three HTTP-only handlers — the include-archived list, the `201` create and
the body-only `PUT` — with the reason→status map that turns the service's typed refusals into `403`
and `404`, and register the router.

```
backend/app/routes/memos.py
backend/app/main.py
```

## Interface intent

**`backend/app/routes/memos.py`** (new) — HTTP only: parse, call a service, return. No business logic,
no DB queries. `backend/app/routes/book_author_prompts.py` is the shape precedent.

- A **router** with the `/api/books` prefix and this feature's tag.
- A **module-level reason→status dict** mapping the service's two reasons: not-a-member → **403**,
  memo-not-found → **404**. Step 004 adds the third entry.
- A **module-private mapper** turning a service error into the `HTTPException` the dict names, so every
  handler refuses identically.
- **A list handler** — `GET /{book_id}/memos`, taking an **include-archived query parameter that
  defaults to false** and the book-access dependency, returning the list envelope.
- **A create handler** — `POST /{book_id}/memos`, taking the create request, answering **`201`** with
  the memo response.
- **A body-update handler** — `PUT /{book_id}/memos/{memo_id}`, taking the wire **string** id verbatim
  and the update request, answering `200` with the memo response.

Every handler takes `access: authz.BookAccess = Depends(authz.book_access)` and does **not** re-declare
`book_id` as its own parameter — the dependency consumes it. Response models are declared as the
**return annotation**, never `response_model=`. `401` and the private-book `404` are produced by the
dependency and are **never re-derived here**.

**`backend/app/main.py`** — one import plus one `app.include_router(...)`, beside the other book-scoped
routers.

## Definition of done

1. `[test]` (US-124.AC-1, US-124.AC-2) `GET` returns only the caller's own memos: a second member of
   the same book — including when the caller is the owner — sees none of the other's.
2. `[test]` (US-128.AC-1) `GET` with no query parameter omits archived memos.
3. `[test]` (US-128.AC-2) `GET` with the include-archived parameter set returns archived memos too, so
   the archived set is reachable over HTTP.
4. `[test]` (US-131.AC-2) The returned list is ordinal-ordered.
5. `[test]` (US-123.AC-1) `POST` answers **`201`** and the created memo is last in the list.
6. `[test]` (US-123.AC-3) The created memo comes back active and not archived.
7. `[test]` (UC-103 postcondition — no separate AC) `POST` with `body: ""` succeeds; an empty body is
   not a `422`.
8. `[test]` (US-125.AC-1) `PUT` writes the body and answers the updated memo; it changes no other
   field.
9. `[test]` (US-124.AC-1) A memo id belonging to another author, to another book, or to nobody, and a
   non-numeric id, all answer **`404`** with the same body — no existence oracle.
10. `[test]` *(architecture — `authorization.md` → the memo status table)* A logged-in non-member of a
    book they can see gets **`403`**; a caller with no relationship to a **private** book gets **`404`**
    from the dependency; a request with no token gets **`401`**.
11. `[test]` *(architecture — `authorization.md` → the archived-book carve-out)* `POST` and `PUT` both
    succeed on a book whose state is `archived`. This is the carve-out's route-level proof, and the one
    behaviour a reader copying `routes/chapters.py` would get wrong.
12. `[test]` (US-128.AC-3) There is **no `DELETE`** on either path — the framework answers `405`.
13. `[test]` *(infrastructural)* The router is registered, so all three paths resolve on the live app.

# 006 — The `MEMOS` prompt layer: fourth position, rendered once

## Goal

Give the composer a fifth optional layer — the author's active memos, rendered into one `MEMOS` section
— inserted at **position 4** between `AUTHOR` and `CHAPTER`, and have the turn render that section once
from the chat's own author's memos.

## Source files

```
backend/app/services/prompt_composition.py
backend/app/services/chat_turn.py
```

## Test files

```
backend/tests/services/test_prompt_composition.py
backend/tests/services/test_chapter_prompt_composition.py
backend/tests/services/test_memo_prompt_composition.py
```

**Two of those three already exist, and this step *changes* their assertions rather than adding to
them.** `test_chapter_prompt_composition.py` pins the chapter prompt as the **fourth** layer and as
following base/mode/author; `test_prompt_composition.py` pins "all **four** layers in fixed order".
Both statements are now false — there are **five** layers and the chapter prompt is **fifth** — so both
files are in this step's scope for the test-coder to rewrite. **What must survive unchanged is that
`author` is still the third positional parameter**: the frozen-signature property those files also
assert is preserved by this feature, not broken (DoD-5).

## Interface intent

**`backend/app/services/prompt_composition.py`** — the module stays pure: no session, no clock, and no
knowledge of what a memo is.

- **The composer gains one more optional layer — a plain string — so the rendered order becomes
  `BASE`, `MODE`, `AUTHOR`, `MEMOS`, `CHAPTER`.** The section label is exactly **`MEMOS`**, rendered
  the way the existing labels are. The existing skip rule extends unchanged: a layer that is absent or
  blank after stripping contributes **no section, no separator and no blank block**.
- **`author` stays the third positional parameter.** The module docstring currently records that the
  signature is frozen with `author` third and that there is deliberately no compatibility alias; that
  statement survives, and the docstring is updated to describe **five** layers with memos fourth — and
  to say the composer receives an **already-rendered string** and never a list of memos.

**`backend/app/services/chat_turn.py`** — two responsibilities, both inside the turn's existing
prompt-composition path.

- **A module-level render function** turning an ordered sequence of the author's memos into the one
  section string the composer takes, or the no-layer value when there is nothing to render. It renders
  the bodies in the order given, separated so that two memos cannot read as one, and **skips a memo
  whose body is blank after stripping** — an empty memo is a legitimate row (UC-103) and must not
  contribute a stray separator. When nothing survives, the composer's empty-contributes-nothing rule
  does the rest.
- **The turn reads the memos itself**, through `db/memos.py` **directly** (`services → db`, the enforced
  direction) for `(the chat's book, the chat's own author)`, with **no `BookAccess` built** — the
  identical resolution the author and chapter layers already use, for the identical reason: the turn is
  already scoped to the chat's author by construction, so a second access resolution would re-derive an
  identity that cannot differ. It excludes archived rows at the read and **filters `active` in memory**,
  because context membership is a derived reading rule, not a stored state.
- **The section is rendered exactly once per turn** and held for the rest of it. Step 007 hands that
  same value to delegation, so this step must not leave a shape that would force a second read.

Nothing else in the turn changes: no new SSE frame, no change to `run_turn`'s signature, no change to
tool gating.

## Definition of done

1. `[test]` (US-131.AC-1) Every one of the author's active memos is present in the composed system
   prompt.
2. `[test]` (US-131.AC-2) They appear in ascending ordinal order — the author's order is the order the
   assistant receives them in.
3. `[test]` (US-131.AC-3, US-127.AC-3) An inactive memo and an archived memo each contribute nothing to
   the composed prompt.
4. `[test]` *(architecture — `assistant-runtime.md` → the five-layer table)* The rendered order is
   `BASE`, `MODE`, `AUTHOR`, `MEMOS`, `CHAPTER`: the memos section follows the author layer and precedes
   the chapter layer, and its label is exactly `MEMOS`.
5. `[test]` *(architecture — the frozen-signature note in the composer's docstring)* `author` is still
   the **third positional** parameter, and the positional contract for the layers before it is
   unchanged.
6. `[test]` (UC-109 postcondition — no separate AC) An author with **no active memos** contributes no
   section, no separator and no blank block — and the same holds when every active memo has a blank
   body.
7. `[test]` (US-132.AC-1) The memos layer is composed **independently of the mode**: with a mode prompt
   present and with none, and for a chapter subject as well as a codex one, the section is present
   whenever the author has active memos. No mode can be missing it.
8. `[test]` (US-124.AC-1) The turn resolves memos for **the chat's own author** and that chat's book —
   never another author's, never another book's.
9. `[test]` *(architecture — `assistant-runtime.md` → "the memo section is rendered once")* The turn
   performs **one** memos read and renders **one** section per turn.

# 001 — The `memos` table, its `db/` module, registration and JSONL codec

## Goal

Add the `memos` table that carries one author's standing notes for one book, its session-free `db/`
module, its model registration and its JSONL import/export codec — everything the row needs to exist
and to round-trip, and nothing that reads it through a service.

## Interface intent

**`backend/app/models/memo.py`** (new) — one SQLModel table, no logic.

- **`Memo`**, table name `memos`. Columns exactly as `context.md` → decision 1 lists them: a snowflake
  primary key generated the way every other table generates one, a book foreign key, a user foreign
  key (the memo's author), a **required** body (empty string is a valid value meaning "an empty memo"),
  a non-null integer ordinal, two independent booleans defaulting to active-and-not-archived, and
  created/modified timestamps. `backend/app/models/book_author_prompt.py` is the row-shape precedent
  for everything except the two things below.
- **No unique constraint of any kind.** The module docstring must state **why** — `BookAuthorPrompt`
  and `BookMember` both carry a unique `(book_id, user_id)` and this table's field list looks like
  theirs, but **an author has many memos per book**; this is the one thing a reader will get wrong
  from the field list.
- The docstring also records **two booleans, not one state enum** — the deliberate opposite of
  `Book.state` — and that context membership (`archived == false AND active == true`) is a **derived
  reading rule, not a constraint to enforce**: there is no invalid combination, only one with no effect
  on the prompt.

**`backend/app/db/memos.py`** (new) — session-free data access, one module per entity, following
`backend/app/db/book_author_prompts.py` for size and idiom: every function opens its own session via
`get_standalone_session()` then `async with session:`, no session parameter, detached rows returned, no
ORM type leaking out, **and no timestamp policy** (timestamps are the service's).

- **`create`** — persist a new row it is handed and return the stored row. The id comes from the
  model's `default_factory`; this layer never mints one.
- **`get_by_id`** — return one row by primary key, or nothing. It performs **no ownership check**:
  scoping to an author is the service's job (`context.md` → decision 3), and a `db/` module that
  silently filtered would put the privacy rule in two places.
- **`list_for_author`** — the read this whole feature is built on: every memo for a `(book_id,
  user_id)` pair, in **ascending `ordinal`** order, with an **include-archived flag** that defaults to
  excluding archived rows. It does **not** filter on `active` — inactive memos are still listed
  (US-127.AC-1), and the active rule is a derived reading applied by the caller.
- **`update`** — persist an already-mutated row and return the stored row.

**No delete function, ever** (`context.md` → decision 6). No `list_by_book`, no `get_by_book_and_user`
— nothing in this feature reads the table any other way, and `db/` modules are not speculatively
widened.

**`backend/app/db/engine.py`** — add the new model to the **MODEL-REGISTRATION SEAM** import list so
`init_db()`'s `create_all` creates the table. **Nothing else in this file changes:** the ADDITIVE
MIGRATION SEAM stays `pass` and `ADDITIVE_COLUMNS` is untouched — that seam is for a new *column on an
existing table*, which this is not.

**`backend/app/services/db_import_export.py`** — one codec pair and one registry entry.

- A **to-dict / from-dict pair** for the new table, copied in shape from `_book_author_prompt_to_dict`
  / `_dict_to_book_author_prompt`: snowflake ids emitted as **strings** and parsed
  string-or-legacy-number, timestamps `.isoformat()` / parsed back, both nullable. The booleans and the
  ordinal round-trip as themselves.
- One `TABLE_REGISTRY` entry named `memos`, placed **immediately after the `chapter_author_prompts`
  tuple and before `chapters`** — index 11. The position is FK-correct (`memos` references `books` and
  `users`, both already earlier) **and** keeps the three per-author tables adjacent, so it is **not** a
  second exception to FK ordering.

## Definition of done

1. `[test]` (US-123.AC-1) An author holds **many** memos in one book: several rows for the same
   `(book_id, user_id)` pair persist side by side, and the database refuses none of them — there is no
   unique constraint to violate.
2. `[test]` (US-123.AC-3) A created row defaults to `active` true and `archived` false, and every
   column survives the round trip through `create` → `get_by_id`.
3. `[test]` (UC-103 postcondition — no separate AC) A `body` of `""` is stored and returned as `""`,
   never coerced to null.
4. `[test]` (US-124.AC-1, US-124.AC-2) `list_for_author` returns only rows for the pair it was asked
   for — never another author's memos in the same book, never the same author's memos in another book.
5. `[test]` (US-128.AC-1) With the include-archived flag off (its default), archived rows are absent
   from the returned list.
6. `[test]` (US-128.AC-2) With the flag on, archived rows come back alongside the live ones, so the
   author's archived set is reachable at all.
7. `[test]` (US-127.AC-1) Inactive rows are listed exactly like active ones — `list_for_author` filters
   on `archived` only and never on `active`.
8. `[test]` (US-131.AC-2) The list comes back in ascending `ordinal` order.
9. `[test]` (US-125.AC-1) `update` persists a changed body and returns **stored** state rather than the
   in-memory argument; the `db/` layer sets **no timestamps** of its own.
10. `[test]` (US-127.AC-4, US-128.AC-2) `update` persists the two flags **independently** — writing
    `active` never rewrites `archived`, and the reverse.
11. `[test]` (US-128.AC-3) The module exposes **no delete function**: archive-not-delete is structural
    at the data layer, not merely an absent route.
12. `[test]` *(infrastructural — root `CLAUDE.md`'s same-change JSONL rule)* The codec pair round-trips
    a row through dict and back with every field preserved; ids emit as **strings**, and a dict
    carrying a **numeric** id still parses.
13. `[test]` *(infrastructural — `backend/book-domain.md` → registry order)* `TABLE_REGISTRY` contains
    exactly one `memos` entry, and it sits immediately after `chapter_author_prompts` and before
    `chapters`.
14. `[test]` *(infrastructural — additive-schema rule)* On a freshly initialised database the `memos`
    table exists and is queryable, and the consistency report comes back all-`ok` — the registration
    seam alone creates it, with no migration statement.

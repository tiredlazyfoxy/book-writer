# 005 — The two axes: activate / deactivate, archive / restore

## Goal

Add the everyday on/off switch and the archive axis as four no-body `POST` verbs, each writing exactly
one flag — with restore appending last, archive leaving its ordinal gap alone, and nothing anywhere
that deletes a memo.

## Source files

```
backend/app/services/memos.py
backend/app/routes/memos.py
```

## Interface intent

**`backend/app/services/memos.py`** — four added entry points, each taking the access context and the
wire **string** memo id, each resolving the row through the existing module-private resolver (so the
one `404`-shaped refusal covers them all) and each returning the memo response.

- **Activate** — sets `active` true. Leaves `archived`, `ordinal` and `body` untouched.
- **Deactivate** — sets `active` false. It refuses **nothing**: deactivating the author's last active
  memo is allowed, and there is no book-level memos-off switch to consult (US-127.AC-5).
- **Archive** — sets `archived` true. It **does not touch `ordinal`** (the gap is deliberate) and
  **does not touch `active`** — that flag is what lets a restore return the memo in the state its
  author chose, and it is the whole reason the model carries two booleans rather than one enum.
- **Restore** — sets `archived` false **and rewrites `ordinal` to one past the highest among the
  caller's non-archived memos**, i.e. appends it last, exactly as a fresh create does. It does not
  return to its old slot. Reuse step 002's next-ordinal computation rather than writing a second one:
  one rule covers every way a memo arrives in the list.

All four stamp `modified_at`. **All four are idempotent `200` no-ops** when the memo is already in the
requested state (`context.md` → "Planner-derived: repeat state calls are `200` no-ops, not `409`") —
the row is returned unchanged and no error reason is raised. No new error reason is added by this step.

**`backend/app/routes/memos.py`** — four added handlers, all `POST` with **no request body**, under
`/{book_id}/memos/{memo_id}/activate`, `/deactivate`, `/archive` and `/restore`, each answering `200`
with the memo response and each reusing the existing reason→status map. They are declared **after** the
`order` route, beside the `/{memo_id}` body-update handler.

**No `DELETE` handler is added, at any path.** Archive-not-delete is the requirement (US-128.AC-3), and
`db/memos.py` has no delete function to call even if one were wanted.

## Definition of done

1. `[test]` (US-127.AC-1) A deactivated memo **stays in the list** — it is still returned by the
   ordinary (non-archived) read.
2. `[test]` (US-127.AC-2) The deactivated memo comes back with `active` false, which is the state the
   client renders its visibly-off marking from.
3. `[test]` (US-127.AC-4) Activating an inactive memo sets `active` true again, making it eligible for
   context once more.
4. `[test]` (US-127.AC-5) Deactivating the caller's **only** active memo succeeds; the author is left
   with no active memo and nothing refuses.
5. `[test]` (US-128.AC-1) An archived memo leaves the working list: it is absent from the default read
   and present in the include-archived read.
6. `[test]` (US-128.AC-2) A restored memo returns to the working list **appended last**, at one past the
   current highest ordinal — never at the slot it held before.
7. `[test]` *(architecture — `domain-book.md` → the ordinal rules)* Archiving leaves a **gap**: the
   surviving memos' ordinals are untouched and nothing is renumbered.
8. `[test]` *(architecture — `domain-book.md` → two booleans, not one enum)* Archiving preserves the
   memo's `active` flag, so a memo archived while switched **off** comes back switched off, and one
   archived while **on** comes back on.
9. `[test]` (US-124.AC-1) Each of the four verbs answers **`404`** for a memo that does not exist,
   belongs to another author, or belongs to another book — the same single refusal the other routes
   produce.
10. `[test]` *(planner decision — `context.md` → repeat state calls)* Each verb applied to a memo
    already in that state answers **`200`** with the row unchanged; no `409` exists anywhere in this
    family.
11. `[test]` (US-128.AC-3) There is **no `DELETE`** on a memo path — the framework answers `405` — and
    a memo is never removed from the include-archived read by any call.
12. `[test]` *(architecture — the archived-book carve-out)* All four verbs succeed on a book whose state
    is `archived`.

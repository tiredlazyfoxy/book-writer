# 010 — The memos list page: create-and-focus, blur-save, the two axes

## Goal

Build the content pane's **first editable list** — the author's own memos, created empty and focused,
edited in place and saved when focus leaves, switched on and off, archived and restored, with a
client-side show-archived filter.

**Cohesion note (the step sits at the top of the size budget):** the list *is* the editor — there is no
memo page and no second write path — so create, edit, the on/off switch and archive/restore share one
state class and one row component. Splitting them would leave a half-wired list that satisfies no use
case and cannot be verified against one.

## Interface intent

**`memosListPageState.ts`** (new) — one `MemosListPageState` class plus external effectful functions.
`chatsListPageState.ts` is the precedent for every shape below.

- **One async-resource trio** for the memos themselves (`data` / `status` / `error`), loaded **once**
  with the include-archived flag **on**.
- **A show-archived flag and two `get` computeds** — the working list (non-archived, ordinal-ordered)
  and the archived list. The flag is a **pure client-side filter and never triggers a refetch**, copying
  `loadChats`'s shape exactly.
- **A body-draft map** keyed by memo id, holding what the author has typed but not yet blurred, plus a
  computed that resolves a row's displayed body to its draft when one exists and the server's value
  otherwise.
- **A focus target** — the id of the memo that should take focus on its next render, set by the create
  effect and cleared once consumed, so a newly created memo is focused **immediately** without an
  effect watching the list.
- **A per-row action status map**, written as a **whole new object** on every change
  (`{ ...state.actionStatus, [id]: "loading" }`), never mutated in place.
- **A per-row error surface** so a failed save or toggle is reported against the row it belongs to.
- **External effectful functions `(state, bookId, …, signal?)`** using `runInAction` before and after
  each await: load; create; save one memo's body; set one memo's active flag; archive one; restore one.
  Each reseeds the affected row (or the list) **from what the server returned**, swallows `ApiError`
  into the error field and rethrows anything else.

**`MemoRow.tsx`** (new) — an `observer` presentational row: the body field, the on/off control, the
archive control (and, in the archived view, the restore control), and the row's own error and busy
state. It owns **no effects and no `useEffect`**; it takes its handlers as props.

- **The body field saves on blur** — an ordinary `onBlur` event handler that calls the save effect when
  the draft differs from the server's value. **There is no Save button, anywhere.**
- **It takes an autofocus prop** driven by the state's focus target, so a created memo is focused
  without a hook.
- **Controls carry accessible names naming their memo**, because they are the only handle a spec has on
  an icon control (the chapter reorder precedent).

**`MemosListPage.tsx`** — an `observer` page with a stable state instance (`useState(() => new …)`), one
**page-level** `useEffect` owning the mount load and an `AbortController` cleanup, the show-archived
toggle, a create control, the working list of rows, the archived section when the toggle is on, and
labelled empty / loading / error states. It registers the page's subject the way every other
content-pane page does.

**Deliberately absent:** a Save control (US-125.AC-2), a delete control (US-128.AC-3), a memo detail
link, a restore-buffer write, and any `409` / divergence handling — memos carry no version token.

## Definition of done

1. `[test]` (US-123.AC-1) Creating a memo adds it **last** in the working list.
2. `[test]` (US-123.AC-2) The newly created memo's body field **receives focus immediately**, with no
   further author action.
3. `[test]` (US-123.AC-3) The newly created memo renders as **active**.
4. `[test]` (UC-103 postcondition — no separate AC) The new memo is **empty** and immediately typeable;
   an empty body is never reported as an error.
5. `[test]` (US-125.AC-1) Typing into a memo and **moving focus away** saves the edited body, and the
   row then shows what the server returned.
6. `[test]` (US-125.AC-2) **No save control is present** at any point — not while editing, not when the
   draft is dirty, nowhere in the list.
7. `[test]` (US-127.AC-1) Switching a memo off leaves it **in the list**.
8. `[test]` (US-127.AC-2) A switched-off memo is **visibly marked off** — its control reports the off
   state through its accessible name/role rather than through styling alone.
9. `[test]` (US-127.AC-4) Switching it back on returns it to the on state.
10. `[test]` (US-127.AC-5) Switching off the author's **only** active memo succeeds and the list renders
    with no active memo — nothing refuses and nothing is restored behind the author's back.
11. `[test]` (US-128.AC-1) Archiving a memo **removes it from the working list**.
12. `[test]` (US-128.AC-2) Revealing the archived memos and restoring one **returns it to the working
    list**, last.
13. `[test]` (US-128.AC-3) Each row offers **archive and no delete** — there is no delete control in the
    list at all.
14. `[test]` (UC-107 step 3 — no separate AC) The show-archived toggle is a **pure client-side filter**:
    the list is fetched **once**, with archived memos included, and toggling refetches nothing.
15. `[test]` (US-124.AC-1) The page requests only the caller's own memos — it sends no user id, and the
    only identity in the call is the book in the URL.
16. `[test]` (UC-104 exception handling — no separate AC) A failed save or toggle surfaces an
    author-facing message against that row, and the row falls back to **server truth** rather than
    keeping an unsaved optimistic value.

# 006 — step context

Feature-wide facts (the layer order and why, the render-once rule, the not-context-assembly boundary)
are in `context.md` → decisions 7 and 8, and are not repeated here.

## `prompt_composition.py` as it stands

A 74-line pure module. `BASE_SYSTEM_PROMPT` is a module constant. The composer takes four optional
layers (`base`, `mode`, `author`, `chapter`), builds a `layers: list[tuple[str, str | None]]` of
`("BASE", base), ("MODE", mode), ("AUTHOR", author), ("CHAPTER", chapter)`, skips any layer that is
`None` or blank after `.strip()`, renders each as `f"### {label}\n{text.strip()}"` and joins with
`"\n\n"`. **The labels are inline literals, not constants** — `MEMOS` joins them the same way.

The module docstring states the signature is frozen with `author` third and that there is deliberately
no compatibility alias. That statement is still true after this step and must stay in the docstring,
updated for five layers.

## `chat_turn.py` as it stands

`compose_turn_system_prompt(context: TurnContext) -> str` already does three direct `services → db`
reads with **no `BookAccess` built**:

- the mode prompt via `assistant_runtime.mode_system_prompt(...)`;
- the author row via `book_author_prompts.get_by_book_and_user(chat.book_id, chat.author_id)`;
- the chapter row via `chapter_author_prompts.get_by_chapter_and_user(...)`, **only** when
  `context.subject.chapter is not None`.

The turn's author is `context.chat.author_id`. **The memos read goes beside those three, unconditional
on the subject** — memos are not subject-scoped, which is the one way this layer differs from the
chapter layer's guarded read.

`run_turn` calls `compose_turn_system_prompt(context)` and then builds `tools_service.ToolContext(...)`
and `subagent_delegation.ParentTurn(...)`. **Where the rendered section is held matters to step 007**,
which needs the same value to reach `ParentTurn`; leave it reachable from `run_turn` rather than
private to the composition call.

## The `active` filter lives in Python, not in a query

`db/memos.py::list_for_author` takes an include-archived flag and **no `active` filter** (step 001).
The turn reads non-archived rows and drops the inactive ones in memory. This is deliberate on two
grounds: `domain-book.md` calls context membership a **derived reading rule, not a stored state**, and
every state filter in this codebase is service-side over the full row list rather than a scoped query.

## Gotcha — this is not context assembly, and the boundary is easy to blur

A reader seeing author-written material enter the prompt will conclude the deferred context-assembly
work shipped. It did not. Memos are **authored, standing, and selected by nobody** — no retrieval, no
ranking, no relevance question, no truncation. Nothing in this step may:

- read chapter text, summaries, state notes or codex entries into the prompt;
- introduce a budget, a cap, a truncation rule or an ordering heuristic over memos;
- decide where the memo block sits relative to chapter text — product explicitly leaves that open and
  this design answers only the narrower question of the layer's position **among the named prompts**.

## Test seeding

Composer tests are pure — no database. The chat-turn half needs the `db` fixture, a seeded book, two
users and memos in a known order, with at least one inactive and one archived row so DoD-3 has
something to exclude. **No network:** the LLM client is mocked, as in every existing turn spec.

For DoD-9, the cheapest honest signal is a counted/spied `db/memos` read across one turn, asserted to
happen once.

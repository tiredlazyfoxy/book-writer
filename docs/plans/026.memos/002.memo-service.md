# 002 — The memo schemas and the read / create / update service

## Goal

Add the memo DTOs and the service that lists, creates and body-edits **the caller's own** memos —
including the append-at-`max + 1` rule and the single `404`-shaped refusal that makes another author's
or another book's memo indistinguishable from one that does not exist.

```
backend/app/models/schemas/memos.py
backend/app/services/memos.py
```

## Interface intent

**`backend/app/models/schemas/memos.py`** (new) — Pydantic request/response models, no logic.

- **A create request** carrying a body string with **no constraint** — `""` is legitimate input, not a
  validation failure (UC-103). No ordinal: a new memo is appended, and the client never chooses a
  position.
- **An update request** carrying a body string and **nothing else** — no version token, no flags. The
  flags have their own verbs (step 005).
- **A memo response** with the fields `context.md` → "The wire contract" lists, ids as **strings**, and
  **no `user_id`**: the subject is always the caller, and echoing an id would invite the reading that
  another author's memo is addressable here (the `BookAuthorPromptResponse` rule).
- **A list envelope** holding the responses under `items`.

The reorder request DTO is **step 004's**, added to this same module when it has a caller.

**`backend/app/services/memos.py`** (new) — business logic and orchestration, no session and no
`select()`. `backend/app/services/book_author_prompts.py` is the shape precedent.

- **A module-level error reason enum plus one exception class** carrying a reason and a message. Two
  reasons at this step: *not a member*, and *memo not found*. Step 004 adds a third.
- **A module-private membership helper** that raises the not-a-member reason unless `access.role` is
  owner or co-author — copied from `book_author_prompts.py`'s `_require_member`. **No
  `authz.require` call and no `Capability`** (`context.md` → decision 3).
- **A module-private memo resolver** taking the access context and the wire **string** id, returning the
  row. It raises the **one** not-found reason for: a non-numeric id, an unknown id, a memo whose
  `user_id` is not `access.user_id`, and a memo whose `book_id` is not `access.book_id`. All four
  collapse into one refusal so there is no existence oracle; `services/chapters.py::_resolve_chapter`
  is the structural precedent for a single refusal site.
- **A list entry point** — the caller's own memos for the book, honouring an include-archived flag,
  returned as the list envelope in ordinal order.
- **A create entry point** — takes the access context and a body; computes the next ordinal as one past
  the highest among the caller's **non-archived** memos in that book (1 when there are none); creates
  the row **active and not archived**; stamps both timestamps; returns the memo response. This is the
  **single implementation of the append rule** — step 005's restore and step 008's tool both reach the
  list through it or through the same helper rather than recomputing it.
- **A body-update entry point** — resolves the memo, writes the new body and `modified_at`, and returns
  the memo response. It touches `ordinal`, `active` and `archived` **not at all**.
- **A module-private response mapper**, the single place a row becomes a DTO.

Every entry point takes the `BookAccess` as its first argument and scopes to `access.user_id` and
`access.book_id`; **no entry point takes a user id or a book id as a separate parameter**, because that
is the shape in which another author's row would become addressable.

**Nothing in this step consults `BookAccess.book_state`** — memos stay writable on an archived book
(`context.md` → decision 4).

## Definition of done

1. `[test]` (US-123.AC-1) Create appends: the first memo in a book gets ordinal 1, and each later one
   lands one past the highest ordinal among the caller's non-archived memos in that book.
2. `[test]` (US-123.AC-3) A created memo is **active** and **not archived**.
3. `[test]` (UC-103 postcondition — no separate AC) A create request with `body = ""` succeeds and
   stores `""`; an empty body is never a validation failure.
4. `[test]` (US-124.AC-1, US-124.AC-2) The list entry point returns only the caller's own memos — a
   second member's memos in the same book are absent, including when the caller is the book's owner.
5. `[test]` (US-128.AC-1, US-128.AC-2) The include-archived flag defaults to excluding archived memos
   and includes them when set.
6. `[test]` (US-131.AC-2) The list is ordinal-ordered.
7. `[test]` (US-125.AC-1) The body update writes the body and stamps `modified_at`, and leaves
   `ordinal`, `active` and `archived` exactly as they were.
8. `[test]` (US-124.AC-1) Every one of the four refusal sources — a non-numeric id, an unknown id,
   another author's memo, another book's memo — raises the **same** not-found reason with no
   distinguishable difference between them.
9. `[test]` *(architecture — `authorization.md` → the fourth row-ownership rule)* A caller who is
   neither owner nor co-author is refused with the not-a-member reason on every entry point; the
   refusal comes from the service's own helper, not from `authz.require`.
10. `[test]` *(architecture — `quick-reference.md` → the Memos DTO subsection)* The memo response
    carries no `user_id`, and every id on it is a string.
11. `[test]` *(architecture — `authorization.md` → the archived-book carve-out)* Create and body-update
    both succeed when `BookAccess.book_state` is `archived`.

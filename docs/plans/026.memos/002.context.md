# 002 — step context

Feature-wide facts (the wire contract, the status taxonomy, the ordinal rules, the layer rules) are in
`context.md` and are not repeated here.

## The precedent to copy, named exactly

`backend/app/services/book_author_prompts.py` — the whole shape:

- a module-level `<X>ErrorReason(str, enum.Enum)` and a `<X>Error(Exception)` pair;
- a `_require_member(access)` helper raising `not_a_member` when `access.role` is not owner or
  co-author;
- every read and write scoped to `access.user_id` — **never** to a path or body parameter.

`backend/app/services/chapters.py::_resolve_chapter` is the precedent for the **single refusal site**:
one module-private resolver that raises one not-found reason for every source, so the four sources
cannot drift apart into distinguishable answers.

## `BookAccess` — the fields available here

A frozen dataclass: `book_id`, `user_id`, `role`, `book_state`, `visibility`, `collaboration_mode`.
`AccessRole` is `owner | co_author | reader | none`.

Two of those fields are **deliberately not read by this service**:

- **`book_state`** — memos stay writable on an archived book (`context.md` → decision 4). A reader who
  copies `services/chapters.py`'s archived-book refusal into this module breaks the carve-out.
- **`collaboration_mode`** — a memo is never book content, so there is nothing for an owner to review
  and no proposal state to hold. The `(mode)` qualifier that `services/codex.py` and
  `services/continuity.py` layer on top of the matrix has **no counterpart here**.

## The service never opens a session

No `session`, `AsyncSession`, `select()`, `session.exec()` or `session.add()` may appear in this file.
Everything goes through `from app.db import memos` and `await memos.<fn>(...)`. The next-ordinal
computation is therefore done **in Python over the rows `list_for_author` returns**, not in a query —
which is also how every other state filter in the codebase is done (`authorization.md` → "The filter
lives in the service, over the full row list").

## Timestamps

`db/memos.py` sets none. This service stamps `datetime.now(timezone.utc)` inline: both `created_at` and
`modified_at` on create, `modified_at` only on update.

## Gotcha — which memos the next ordinal is computed over

**The caller's non-archived memos in that book**, and the reasoning is in `context.md` → decision 2.
Concretely: call the list read with the include-archived flag **off**, take the highest ordinal, add
one; an empty list gives 1.

Computing it over *all* rows including archived ones would also be safe, but it is not the rule this
plan chose, and steps 005 and 008 both reuse this one — three call sites converging on two different
readings is exactly the drift that makes ordinals unexplainable later.

## Gotcha — the id parses in the service, not in the route

`memo_id` crosses the wire as a **string** (snowflakes exceed the JS safe-integer range). The route
hands it over verbatim; this service parses it, and a non-numeric value is the **not-found** reason —
never FastAPI's `422`. This is the `services/codex.py` / `services/chapters.py` convention, a
deliberate override of the `routes/admin/llm_servers.py` `server_id: int` precedent, so that the
malformed-id decision stays out of `routes/`.

## Test seeding

`backend/tests/services/` specs use the `db` fixture and construct a `BookAccess` directly — there is no
HTTP here. Seed at least two users and two books so DoD-8's four refusal sources are each reachable,
and remember the owner case for DoD-4: the book's **owner** must be shown to see none of a co-author's
memos, which is US-124.AC-2 and is the half a test written only from the co-author's side would miss.

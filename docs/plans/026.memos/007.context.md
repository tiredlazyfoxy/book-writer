# 007 — step context

Feature-wide facts (the render-once rule and its reasoning, the layer order) are in `context.md` →
decision 7. Step 006's context carries the composer's internals; this file does not repeat either.

## The call chain, as it stands

```
chat_turn.run_turn
  → assistant_runtime.resolve_turn_tools(mode_key, parent_turn)
      → subagent_delegation.build_delegation_tools(...)
          → run_delegation(...)
              → _delegate(...)        # system = sub_agent.system_prompt   ← the only uncomposed value
```

`ParentTurn` is a **frozen dataclass** carrying `server`, `resolved_key`, `model` and `tool_context`,
constructed in `chat_turn.run_turn` and threaded unchanged through the chain. **`chat_turn.py` never
calls `run_delegation` or `build_delegation_tools` directly** — which is exactly why `ParentTurn` is the
carrier: it is the one value that already travels the whole way.

## Why the section is carried rather than re-read

`assistant-runtime.md` → "The parked question is answered, narrowly" gives both reasons, and the second
is the load-bearing one:

- one DB read per turn;
- **it guarantees the parent and every sub-agent see the identical set.** A second read could pick up a
  memo `create_memo` added mid-turn, and parent and child would then disagree about what the author
  asked to be remembered.

So the prohibition is concrete: `subagent_delegation.py` imports no memo module and calls no memo
function. DoD-5 is the test that keeps it that way.

## What the narrowing is, and what stays open

This section of `assistant-runtime.md` used to give a sub-agent its **own `system_prompt` alone** and
explicitly parked "whether the author's voice should thread into delegated work" as a later question.
US-132.AC-2 forces it open, and the answer is deliberately **narrow**: the sub-agent's own prompt plus
the `MEMOS` section, nothing more.

- Threading the whole composition would end the sub-agent's **self-contained admin-configured worker**
  property.
- Threading memos alone keeps that property for **behaviour** — how the worker works is still the
  admin's alone — while honouring the author's standing **facts**.
- The broader parked question — whether the author's *voice* belongs in delegated work — **stays open**.
  Do not resolve it here, in either direction.

**US-132.AC-1 is not this step's.** It falls out of the composition itself (step 006, DoD-7): every mode
composes the same five layers, so no mode can be missing the memos layer.

## The existing test this step rewrites — named exactly

`backend/tests/services/test_subagent_delegation.py::test_nested_system_is_the_subagent_prompt_alone__DoD5`.

Its intent survives in DoD-2 (no mode/author/chapter layer threads through); its literal assertion — the
prompt **alone** — does not.

## Gotcha — compose, do not concatenate

Use the composer step 006 changed, so the child's `MEMOS` section is byte-identical in shape to the
parent's. A hand-rolled `f"{prompt}\n\n### MEMOS\n{section}"` would work today and drift the first time
the composer's separator or label rendering changes — and it would duplicate the empty-layer skip rule
that has already been written once.

## Test seeding

`backend/tests/services/test_subagent_delegation.py` is the shape to follow for the nested-call harness
— the LLM client is mocked and **no network is opened**. Assert on the `system` argument the nested call
received.

DoD-6 needs one turn in which a memo is created between the parent's composition and the delegated
call; the honest way to stage it is to add a memo row through the `db/` layer at that point and assert
the child's `system` still matches the parent's section.

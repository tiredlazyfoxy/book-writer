## Interface intent

**`frontend/src/types/memos.d.ts`** (new) — hand-written, wire-exact `snake_case`, **ids typed
`string`**, no `any`:

- a **memo** interface matching `MemoResponse` field for field — id, book id, body, ordinal, the two
  booleans, both timestamps — and **no `user_id`**, because the backend does not send one;
- the **create**, **update** and **reorder** request interfaces matching their backend twins.

The `{ items: [...] }` list envelope is deliberately **not** modelled; it is unwrapped at the call site,
as every other resource module does.

**`frontend/src/api/memos.ts`** (new) — one function per endpoint, each forwarding through
`client.ts`'s `request<T>` with a trailing optional `AbortSignal`: list (taking an include-archived
flag), create, update-body, reorder, activate, deactivate, archive, restore. The list function unwraps
the envelope and returns the memos array. No state, no MobX, no error swallowing — `ApiError` propagates
to the caller.

**`frontend/src/work/components/shell/navItems.ts`** — an **eighth** `WORK_NAV_ITEMS` entry, labelled
**Memos**, after Chats, with the `/memos` path segment, an icon reference from `@tabler/icons-react`
(`IconNotes` unless a clearly better fit exists) and `paneTarget: "content"`. It is an **ordinary router
link** like every other entry — **no pane-control exception**, which is the whole point of having
removed the last one. No `extraActiveSegments`: there is no item route to light up for.

**`frontend/src/work/routes.tsx`** — one added route for the `memos` segment, mounted **directly**, with
**no `key={id}` wrapper** (that is for item routes, and there is no memo id in any URL). **No
`/memos/:id` and no `/memos/new` route exists or is to be added.**

**`frontend/src/work/subject.ts`** — two additions:

- **`SubjectKind` gains `"memos"`**, value-for-value with the backend `Literal` and with the
  `types/chats.d.ts` twin;
- **`resolveEditability` gains a memos branch returning a constant editable verdict** using the
  **existing `"whole"` region** and no read-only reason. **No new `EditableRegion` member and no
  `WriteRegion` widening.** The branch decides nothing — the memos list has no state machine, no
  collaboration-mode gate and no archived-book gate — and exists so this file stays the single
  enforcement point the editability table names. There is **no author/assistant symmetry to enforce**:
  `create_memo` creates a new row and never writes into a displayed memo.

**`frontend/src/types/chats.d.ts`** — the wire-exact `SubjectKind` twin gains `"memos"` too. A comment
in that file says the two must stay structurally identical; keep it true.

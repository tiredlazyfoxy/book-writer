# 004 — Reorder: the whole-set service rule and `PUT …/memos/order`

## Goal

Let an author set the order their memos reach the assistant in: one bulk endpoint taking the **full**
id list of their non-archived memos, validated whole before any write, then ordinals rewritten `1..N`.

## Source files

```
backend/app/models/schemas/memos.py

backend/app/routes/memos.py
```

## Interface intent

**`backend/app/models/schemas/memos.py`** — one added DTO: a **reorder request** carrying a list of
memo ids as **strings**, the full ordered set. No ordinals, no partial moves.

**`backend/app/services/memos.py`** — one added entry point plus one added error reason.

- **A reorder entry point** taking the access context and the submitted id list. It loads the caller's
  current **non-archived** memos, builds an id→row lookup, and **refuses the whole request before any
  write** when the submitted list is not exactly that set: a different length, a duplicate id, or an id
  that is not in the set (which covers an unknown id, an archived memo's id, another author's memo and
  another book's memo alike). On success it walks the list in order, setting each row's `ordinal` to its
  1-based position and stamping `modified_at`, calling the ordinary per-row `db/` update. It returns the
  refreshed list envelope.
- **One added error reason** for the invalid set. Deliberately **not** the not-found reason: the caller
  is being told their *set* is wrong, not that a resource is missing.
- **There is deliberately no bulk `db/` writer.** A bulk update would move the `1..N` rule out of the
  service, which is where the rule belongs; `services/chapters.py::reorder_chapters` makes the same
  choice for the same reason.

**`backend/app/routes/memos.py`** — one added handler and one added map entry.

- **`PUT /{book_id}/memos/order`**, taking the reorder request, answering `200` with the list envelope.
- The handler is declared **before** the `/{memo_id}` routes. FastAPI matches in declaration order, so
  a later declaration would let `/{memo_id}` swallow the literal `order` segment. Carry a comment
  saying so, as `routes/chapters.py` does.
- The invalid-set reason maps to **`400`, not `422`**: the body is structurally valid and the refusal
  is a business-rule one, so `422` would misreport where validation happened.

## Definition of done

1. `[test]` (US-126.AC-2) Submitting the caller's full memo id list in a new order rewrites ordinals
   `1..N` in that order, and the returned list reflects the new order. Both the arrow controls and the
   drag gesture funnel into this one call (step 011), so this is the persistence contract for both.
2. `[test]` (US-131.AC-2) After a reorder, the ordinal-ordered read returns the memos in exactly the
   submitted order — the author's order **is** the order the assistant will receive them in.
3. `[test]` *(business-rule refusal — no separate AC)* Each invalid set is refused with the invalid-set
   reason → **`400`**, and **nothing is written**: a list that is too short, one that is too long, one
   with a duplicate id, and one containing an id that is not in the caller's non-archived set.
4. `[test]` (US-124.AC-1) An id belonging to **another author** or **another book** is refused as an
   invalid set — it is simply not in the caller's set — and the response reveals nothing about whether
   that id exists.
5. `[test]` (US-128.AC-1) Archived memos are **not** part of the submitted set: including one is
   refused, and a successful reorder leaves every archived memo's ordinal untouched — archiving left a
   gap and reorder does not reclaim it.
6. `[test]` *(architecture — `quick-reference.md` → the memos route table)* `PUT …/memos/order` resolves
   to the reorder handler and is never captured by the `/{memo_id}` route; a memo whose id happens to be
   passed to the `/{memo_id}` path still resolves to the body-update handler.
7. `[test]` *(architecture — `authorization.md` → the memo status table)* A non-member of a visible book
   gets **`403`**; a caller with no relationship to a private book gets **`404`**; no token gets `401`.
8. `[test]` *(architecture — the archived-book carve-out)* A reorder succeeds on a book whose state is
   `archived`.

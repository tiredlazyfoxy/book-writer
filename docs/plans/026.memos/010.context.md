# 010 — step context

Feature-wide facts (the MobX rules, the api module, the restore-buffer exclusion, the blur-save
decision) are in `context.md` → decisions 12 and 13, and are not repeated here.

## The page precedent, named exactly

`frontend/src/work/pages/ChatsListPage.tsx` + `chatsListPageState.ts` is the closest shape in the repo:

- `observer(function …)`; `const [state] = useState(() => new XState())`;
- one **page-level** `useEffect` with an `AbortController`;
- a state class using `makeAutoObservable(this)`, an async trio plus `get` computeds;
- external effectful functions `(state, bookId, …, signal?)` using `runInAction` before **and** after
  each await, swallowing `ApiError` into the error field and rethrowing anything else;
- per-row action status tracked as a **whole new object**
  (`state.actionStatus = { ...state.actionStatus, [id]: "loading" }`), never a mutation;
- **`loadChats` fetches the archived set too and `showArchived` is a pure client-side filter, never a
  refetch** — copy that exactly: one load with the include-archived flag on, and a computed that filters.

## Save on blur — the SPA's first, and why it is sanctioned

An exhaustive grep of `frontend/src` found **zero `onBlur` handlers**: every editable field today uses
an explicit Save button bound to a `canSaveX` computed. This page departs from that, and the departure
is required rather than chosen:

- UC-104 / **US-125.AC-1** require the body to save when focus leaves;
- **US-125.AC-2** requires that **no explicit save control exist** — so the house shape is not merely
  unnecessary here, it is forbidden;
- `frontend-workspace.md` fixes the mechanism: **"an ordinary event handler, not a `useEffect` watching
  the draft."**

Consequences to keep straight: a draft that is identical to the server's value saves nothing (no
pointless write on every focus change); a failed save leaves the row showing server truth with an
author-facing message (DoD-16); and there is **no debounce, no autosave timer and no beforeunload
flush** — none is specified, and inventing one would add a second write path to a feature whose whole
claim is that it has one.

## Create-and-focus without a hook

The state holds the id of the memo that should take focus next; the create effect sets it from the
server's returned row and the row consumes it through an **autofocus prop**, clearing it. No
`useEffect` in the row, no ref-chasing, no `useCallback` — all three are banned by `frontend.md` and
none is needed.

## What must NOT appear on this page

- **No Save button, no "unsaved changes" badge, no dirty indicator that implies a save action.**
- **No delete control** — archive-not-delete (US-128.AC-3). `db/memos.py` has no delete function and no
  route exists, so a delete control could not work even if added.
- **No restore-buffer write, no `baseVersion`, no divergence view, no `409` path.**
  `frontend-work-drafts.md` → "Memos are outside the buffer too": short, saved on focus loss, one
  writer, and **no version token to compare a `baseVersion` against**.
- **No reorder controls.** Drag and arrows are step 011's; leaving hooks for them is fine, building them
  here is scope creep the verifier will read as an unplanned change.
- **No `useCallback` / `useMemo` / `useReducer`, no React context, no Mantine `useForm`, no custom
  `useX` hook.**

## Accessible names are a test contract

Icon-only controls (the on/off switch, archive, restore) have **no other handle** — specs query by role
and accessible name and never by test id. Name them with the memo they act on, the way
`ChapterOrderList.tsx` names its arrows (`Move "<title>" up`). A memo has **no title** — body text only
— so the name must be derived from something stable: the memo's position in the list and/or a truncated
body are both acceptable; whichever is chosen, it must be stable enough for a spec to address a row and
must not break on an **empty** body, which is a legitimate state.

## Test harness facts

`frontend/tests/work/*.test.tsx`, mocking the api module wholesale —
`vi.mock("../../src/api/memos", () => ({ <every export>: vi.fn() }))` — and rendering via
`renderWithProviders` from `frontend/tests/support/render.tsx` with a `route` option. `globals: false`,
so every primitive is imported from `"vitest"`. `ApiError` is imported real from
`../../src/api/client`.

Focus assertions (DoD-2) and blur assertions (DoD-5) are ordinary jsdom — no live browser needed; the
`[manual/live]` tag is reserved for step 011's drag gesture, which jsdom genuinely cannot drive.

# 005 — step context

Feature-wide facts (the ordinal rules, the two-axes model, the status taxonomy, the repeat-call
decision) are in `context.md` and are not repeated here.

## The precedent to copy — `Book`, not the codex

**Codex archive/restore routes do not exist yet** (FEAT-017's archive half is unbuilt, owned by
`017.codex-archive-restore`). Do not go looking for them and do not model this step on
`domain-codex.md`.

The shipped precedent for a no-body state verb pair is `backend/app/routes/books.py`:
`POST /{book_id}/archive` and `POST /{book_id}/unarchive`, both taking no body and returning the row.

**Two differences, both deliberate:**

- The verb is **`restore`**, not `unarchive` (`quick-reference.md` → the memos route table).
- `books.py` answers **`409`** when the book is already archived. **Memos answer `200`** — the memo
  taxonomy names no `409` at all, and these four verbs are idempotent state assertions rather than
  lifecycle transitions with a state machine behind them. The nearest shipped precedent for that
  reading is `POST …/close/cancel`'s deliberate `200` no-op.

`SubAgent`'s `disable` / `enable` pair is the precedent for **why there are two verb pairs rather than
one `PATCH`**: each axis gets its own verb so the wire says the two axes are independent, and so the
focus-loss `PUT` never carries state it did not mean to write.

## The flag each verb writes, and the flags it must leave alone

| Verb | Writes | Must not touch |
|---|---|---|
| activate | `active = true` | `archived`, `ordinal`, `body` |
| deactivate | `active = false` | `archived`, `ordinal`, `body` |
| archive | `archived = true` | **`active`**, **`ordinal`**, `body` |
| restore | `archived = false`, `ordinal = max + 1` | **`active`**, `body` |

The two bolded cells are the ones a reader will get wrong:

- **Archive must not clear `active`.** Two booleans exist precisely so a restored memo comes back in
  the state its author chose; clearing `active` on archive would collapse the model back into the
  three-value enum `domain-book.md` rejects.
- **Archive must not renumber.** The gap is the design (the `chapters` DELETE precedent). Restore is
  where the ordinal moves, and it moves to the **end**.

## The next-ordinal computation is step 002's, reused

Restore must call the same helper create uses — one past the highest ordinal among the caller's
**non-archived** memos, 1 when there are none. Writing a second implementation here is how the two
drift; `domain-book.md` states the point of the rule outright: one rule covers every way a memo arrives
in the list — manual create, assistant create, restore.

## What this step must NOT do

- **No `DELETE` route**, and no "hard delete for archived memos" convenience. `db/memos.py` has no
  delete function; keep it that way.
- **No archived-book refusal** — the carve-out covers these four verbs explicitly
  (`authorization.md` → "The one named exception").
- **No refusal on deactivating the last active memo.** US-127.AC-5 makes the empty active set a
  legitimate end state, and product's alternate flow says so in as many words.
- **No re-derivation of `401` / the private-book `404`** — both come from the access dependency.

## Test seeding

Service specs build a `BookAccess` directly; route specs use their own `_seed_user` / `_seed_book` /
`_auth_header` helpers and a real JWT.

DoD-8 needs four memos to be unambiguous: one archived while active, one archived while inactive, then
both restored — each must come back with the flag it went in with. DoD-7 needs at least three memos so
that the gap left by archiving the middle one is visible in the survivors' ordinals.

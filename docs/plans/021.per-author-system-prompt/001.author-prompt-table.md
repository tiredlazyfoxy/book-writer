# 001 — The `BookAuthorPrompt` table, its `db/` module, registration and JSONL codec

## Goal

Add the `book_author_prompts` table that carries one system prompt per `(book, author)` pair, its
session-free `db/` module, its model registration, and its JSONL import/export codec — everything the
row needs to exist and to round-trip, and nothing that reads it.

## Interface intent

**`backend/app/models/book_author_prompt.py`** (new) — one SQLModel table, no logic.

- **`BookAuthorPrompt`**, table name `book_author_prompts`. Columns exactly as `context.md` → decision
  1 lists them: a snowflake primary key generated the way every other table generates one, a book
  foreign key, a user foreign key, a **required** prompt text (empty string is a valid value meaning
  "no prompt"), and created/modified timestamps. A **unique constraint on the `(book_id, user_id)`
  pair**, declared the way `backend/app/models/book_member.py` declares its own — that file is the
  row-shape precedent for the whole model.
- The module docstring states **why the table exists rather than a column on `BookMember`** (the owner
  has no membership row) and that it **supersedes `Book.system_prompt`**, which step 004 marks
  dormant.

**`backend/app/db/book_author_prompts.py`** (new) — session-free data access, one module per entity,
following `backend/app/db/chapters.py` for size and idiom (sessions created internally, detached rows
returned, no ORM type leaking out, no timestamp policy).

- **`create`** — persist a new row it is handed and return the stored row.
- **`get_by_book_and_user`** — the single lookup this whole feature is built on: return the row for a
  `(book_id, user_id)` pair, or nothing when there is none.
- **`update`** — persist an already-mutated row and return the stored row.

No list function, no delete function, no `get_by_id` — nothing in this feature reads the table any
other way, and `db/` modules are not speculatively widened.

**`backend/app/db/engine.py`** — add the new model to the **MODEL-REGISTRATION SEAM** import list so
`init_db()`'s `SQLModel.metadata.create_all` creates the table. **Nothing else in this file changes**;
in particular the ADDITIVE MIGRATION SEAM stays `pass` — a brand-new table needs no migration
statement.

**`backend/app/services/db_import_export.py`** — one codec pair and one registry entry.

- A **to-dict / from-dict pair** for the new table, copied in shape from
  `_book_member_to_dict` / `_dict_to_book_member`: snowflake ids emitted as **strings** and parsed
  **string-or-legacy-number**, timestamps handled the way the sibling codecs handle them.
- One `TABLE_REGISTRY` entry, `book_author_prompts`, placed **immediately after `book_members`** —
  `TABLE_REGISTRY` is FK dependency (import) order and the row references both `books` and `users`,
  which are already earlier.
- **`Book`'s existing codec is not touched.** It round-trips `system_prompt` today and keeps doing so
  (`context.md` → decision 2).

## Definition of done

1. `[test]` A row created for a `(book, user)` pair is returned intact by `get_by_book_and_user` —
   every column, including an empty-string prompt, survives the round trip.
2. `[test]` `get_by_book_and_user` returns nothing when the pair has no row, and never returns a row
   belonging to a different book or a different user.
3. `[test]` A second row for the same `(book_id, user_id)` pair is refused by the database — the
   unique constraint is real, not advisory.
4. `[test]` Two different users in the same book hold independent rows, and the same user in two books
   holds independent rows; writing one never changes the other.
5. `[test]` `update` persists changed prompt text, and the returned row reflects stored state rather
   than the in-memory argument.
6. `[test]` On a freshly initialised database the `book_author_prompts` table exists and is queryable
   — the registration seam alone creates it, with no migration statement.
7. `[test]` The codec pair round-trips a row through dict and back with every field preserved; ids
   emit as strings, and a dict carrying a **numeric** id still parses.
8. `[test]` `TABLE_REGISTRY` contains exactly one `book_author_prompts` entry and it sits after
   `book_members`.
9. `[test]` `Book`'s codec still round-trips `system_prompt` unchanged — the dormant column stays
   exportable and importable.

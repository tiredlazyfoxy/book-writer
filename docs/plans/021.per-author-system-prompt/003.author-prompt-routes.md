# 003 — The `/api/books/{book_id}/system-prompt` route pair

## Goal

Expose the per-author prompt over HTTP as a `GET` + `PUT` pair on the book route family, mapping the
service's typed refusal onto the status taxonomy and inheriting existence hiding from the `book_access`
dependency.

## Source files

```
backend/app/routes/book_author_prompts.py
backend/app/main.py
```

## Test files

```
backend/tests/routes/test_book_author_prompts.py
```

## Interface intent

**`backend/app/routes/book_author_prompts.py`** (new) — HTTP only: parse, call one service entry
point, return. No business logic, no capability check, no database access.

- A router owning the path `/api/books/{book_id}/system-prompt`, following the existing book-scoped
  route family: the `{book_id}` segment is consumed entirely by `Depends(book_access)` and is **not**
  re-declared by either handler; response models are declared as the **return annotation**, never
  `response_model=`.
- **A read handler** — returns the caller's own prompt response. `200` always, for a member; the
  "no row yet" case is an ordinary success carrying an empty prompt.
- **A write handler** — takes the update request body, calls the service's upsert, returns the stored
  response. `200`, not `201`: the resource addressed is "this caller's prompt for this book", which
  exists conceptually from the moment the caller is a member, and the same URL answers before and
  after.
- **A module-level reason → status map plus one mapper function**, following the shape the sibling
  book-scoped routers already use, translating the service's single typed reason to **`403`**.
- **No DELETE handler**, per `context.md` → decision 6.

**`backend/app/main.py`** — mount the router alongside the other book-scoped routers. Nothing else in
this file changes.

## Definition of done

1. `[test]` `GET` returns `200` and the caller's own stored prompt.
2. `[test]` `GET` on a book where the caller has no row returns `200` with an empty prompt and a null
   modified timestamp — **not** `404`.
3. `[test]` `PUT` stores the body's text, the response echoes what was stored, and a following `GET`
   returns the same value.
4. `[test]` Two members of one book `PUT` different prompts; each one's `GET` returns their own text
   and never the other's. *(This is the behaviour that replaces UC-093's single book-wide prompt.)*
5. `[test]` `PUT` a second time updates rather than duplicating — the value changes and the response
   still describes one prompt.
6. `[test]` A user with no relationship to a **private** book gets `404` from both verbs — existence
   hiding, inherited from the dependency.
7. `[test]` A logged-in non-member reading a **public** book gets `403` from both verbs.
8. `[test]` A request with no token gets `401` from both verbs.
9. `[test]` The path answers no `DELETE` — a delete attempt is refused by the framework rather than
   silently accepted.
10. `[test]` A malformed `PUT` body (missing the prompt field) is refused as a validation error, and
    nothing is stored.

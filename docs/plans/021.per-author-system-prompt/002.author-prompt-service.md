# 002 — Prompt DTOs and the per-author service

## Goal

Add the request/response DTOs and the service that reads and upserts **the caller's own** prompt for a
book, guarded by row ownership over `BookAccess` rather than by a capability.

## Source files

```
backend/app/models/schemas/book_author_prompts.py
backend/app/services/book_author_prompts.py
```

## Test files

```
backend/tests/services/test_book_author_prompts.py
```

## Interface intent

**`backend/app/models/schemas/book_author_prompts.py`** (new) — two Pydantic DTOs, declarative, no
logic. Field sets are fixed by `context.md` → "The wire contract".

- **An update-request DTO** carrying one field: the prompt text. Empty string is valid input.
- **A prompt-response DTO** carrying the book id (as a **string**), the prompt text, and the
  last-modified timestamp (nullable — `null` when the author has no row yet). **No `user_id` field**,
  for the reason `context.md` gives.

**`backend/app/services/book_author_prompts.py`** (new) — business logic and the ownership guard.

- **A reason enum plus one exception class**, following `services/chats.py`'s typed-error shape. It
  needs exactly **one** reason: the caller is not a member of this book. Do not invent more; every
  other refusal on this path (no token, an invisible book, a book in a hidden state) is produced
  upstream by the `book_access` dependency and never reaches this service.
- **A private membership guard** taking the access context: an `owner` or a `co_author` passes;
  anything else (a `reader`, or no relationship) raises the typed error. It makes **no** capability
  check and adds **no** matrix row — see `context.md` → decision 4.
- **A read entry point** — given the access context, guard, then look up the row for
  `(access.book_id, access.user_id)` through step 001's `db/` module and map it to the response DTO.
  **No row is not an error**: the response carries an empty prompt and a null timestamp.
- **A write entry point** — given the access context and the update request, guard, then **upsert**:
  create the row when absent (setting both timestamps), update the text and the modified timestamp
  when present. Returns the same response DTO, built from what was stored. Empty text is stored as-is;
  there is no deletion path.
- **A private response mapper** — the single place a row (or its absence) becomes the DTO, so both
  entry points cannot drift.

The service never receives, and cannot be asked for, another user's prompt: the user id comes from the
access context, never from an argument.

## Definition of done

1. `[test]` An owner reads back the prompt they stored, and a co-author reads back the prompt they
   stored — in the **same** book, each seeing only their own text.
2. `[test]` A caller with no row reads an empty prompt and a null timestamp, and no error is raised.
3. `[test]` The write entry point creates a row when none exists, and a subsequent read returns it.
4. `[test]` The write entry point updates in place when a row exists: the pair still has exactly one
   row, its creation timestamp is preserved, and its modified timestamp advances.
5. `[test]` Writing an empty string is accepted and read back as an empty prompt — clearing a prompt
   needs no delete verb.
6. `[test]` A `reader` is refused with the service's typed reason on **both** entry points, and a
   caller with no relationship to the book is refused the same way.
7. `[test]` A **co-author is not refused** on the write path. *(This deliberately reverses
   US-108.AC-2, which required refusing a co-author who edits the book prompt — there is no book
   prompt any more, and each author owns their own. See `context.md` → "Product situation".)*
8. `[test]` The response DTO exposes no user identifier and no field a caller could vary to reach
   another author's prompt.
9. `[test]` Writing one author's prompt leaves every other author's row in that book, and the same
   author's row in other books, untouched.

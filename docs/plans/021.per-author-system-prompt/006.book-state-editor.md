# 006 — The working page's Book-state prompt editor

## Goal

Give the working page's Book-state view a writable editor for the caller's own system prompt, so every
member of a book — not only whoever can reach the settings page — can set the prompt their assistant
turns compose.

## Source files

```
frontend/src/work/pages/bookStatePageState.ts
frontend/src/work/pages/BookStatePage.tsx
```

## Test files

```
frontend/tests/work/BookStatePage.test.tsx
```

## Interface intent

**`frontend/src/work/pages/bookStatePageState.ts`** — additions only; the existing book-state trio,
its computeds and its loader are untouched.

- An **async trio** for the prompt (value / status / error), named in this file's existing trio style.
- A **draft field**, a **server-error** holder and a **submit status**, held separately as step 005's
  page state holds them.
- Pure `get` computeds: whether the draft differs from the last value the server returned, and whether
  submitting is currently allowed.
- Two **external effect functions** `(state, bookId, signal?)` in the same file — one loading the
  prompt and seeding the draft, one saving and re-seeding from the response. Both call the api
  functions step 005 added; **no new api function and no new DTO is introduced here.**

**`frontend/src/work/pages/BookStatePage.tsx`** — render the editor as its own section of the Book
state view: the trio's loading and error branches, a multi-line editor bound to the draft, a save
control gated on the computed, a server-error surface, and one line of copy stating the prompt is the
caller's own and invisible to co-authors. The prompt load is triggered from the page's **existing**
mount effect and aborted by its existing cleanup — no second `useEffect`. Handlers are inner functions
closing over the state.

The page's existing read-only book-state content keeps rendering exactly as it does today; the prompt
section is the **only** editable region this step introduces.

## Definition of done

1. `[test]` On mount the page loads the caller's own prompt alongside the book state it already loads,
   and shows the text in the editor.
2. `[test]` A member with no stored prompt sees an empty, editable field — not an error and not a
   read-only placeholder.
3. `[test]` Editing and saving sends the draft and the editor then shows what the **server returned**.
4. `[test]` The save control is unavailable while the draft matches the loaded value and while a save
   is in flight.
5. `[test]` Saving an empty editor is allowed and clears the prompt; there is no delete control.
6. `[test]` A refused save surfaces the server's message and leaves the draft intact.
7. `[test]` A failed prompt load renders its own error branch **without** breaking the rest of the Book
   state view — the two trios fail independently.
8. `[test]` The section states the prompt is the caller's own and not shared with co-authors.
9. `[test]` The rest of the Book-state view remains read-only — this step adds exactly one editable
   region.
   *(This changes `frontend-workspace.md`'s content-pane editability table, whose Book-state row today
   reads "state notes editable; everything else read-only"; the change is carried in `outcome.md`.)*
10. `[manual/live]` Two authors opening the same book's working page each see and edit their own
    prompt, and neither sees the other's.

# 001 — step context

Feature-wide facts (the table's column list, layer rules, gates, test harness) are in `context.md`
and are not repeated here.

## The precedents to copy, named exactly

- **Row shape:** `backend/app/models/book_member.py`. It is the system's `(book_id, user_id)` link
  row — surrogate snowflake PK **plus** a unique constraint on the natural pair. `domain-book.md` →
  "BookMember" carries the reasoning (the id convention is system-wide with no permanent exceptions,
  and a surrogate id keeps the import/export codec identical in shape to every other table). The new
  table is that shape with a text column added.
- **`db/` module size and idiom:** `backend/app/db/chapters.py` — 46 lines holding
  `create` / `get_by_id` / `list_by_book`, session-free via `get_standalone_session`. Copy the session
  and refresh idiom verbatim rather than inventing one.
- **Codec pair:** `backend/app/services/db_import_export.py:410-443` —
  `_book_member_to_dict` / `_dict_to_book_member`, roughly 35 lines for the pair.

## `db/engine.py` — the two seams, and which one applies

- **`db/engine.py:55-82` — MODEL-REGISTRATION SEAM.** An explicit import list. A model absent from it
  is absent from `SQLModel.metadata` and its table is never created. **This is the seam this step
  uses.**
- **`db/engine.py:101-124` — `init_db()`** runs `SQLModel.metadata.create_all`, which is **additive**:
  it creates missing tables and never alters existing ones.
- **`db/engine.py:119-124` — ADDITIVE MIGRATION SEAM**, currently `pass`. It exists for *columns added
  to existing tables*. A brand-new table does not need it. **Leave it `pass`.**

There is **no Alembic anywhere in the repository**. This is also why step 004 keeps `Book.system_prompt`
rather than dropping it.

## `TABLE_REGISTRY` — the shape and the position

`backend/app/services/db_import_export.py:958-1002` holds `TABLE_REGISTRY` as an FK-ordered list of
`(name, Model, to_dict, from_dict)` tuples. The order is **import order**: a table appears after every
table it references.

`book_author_prompts` references `books` and `users`, both of which are already earlier in the list
(`users` sits in the global-config block; `books` opens the book-domain block). Placing the new entry
**immediately after `book_members`** keeps the two `(book_id, user_id)` link tables adjacent, which is
where a reader will look for it.

## `Book`'s codec is untouched

`backend/app/services/db_import_export.py:369` and `:403` already round-trip `Book.system_prompt`.
**Do not remove either line.** Decision 2 in `context.md` keeps the column exportable so archives
written before this feature still import; step 004 only stops *reading* it and documents that it is
dormant.

## Gotcha — the prompt column is required, and `""` is a value

`system_prompt` is a **required** text column, not nullable. The absence of a prompt is expressed two
ways in this system and both must survive:

- **no row at all** for the pair — the ordinary state before an author writes one;
- **a row holding `""`** — the state after an author clears one (there is no DELETE, `context.md` →
  decision 6).

A codec or a db function that coerces `""` to `None` (or the reverse) breaks DoD-1 and DoD-7. The
composer already skips blank layers, so both states behave identically at runtime — but they are
distinct rows and must round-trip distinctly.

## Test seeding

`backend/tests/db/` specs use the `db` fixture from `backend/tests/conftest.py` and insert supporting
rows through the sibling `db/` modules (`books`, `users`) — there is no HTTP in a db-layer spec.
Import/export specs in this repo live as flat `backend/tests/test_data_domain_*.py` modules; the codec
and registry assertions belong there rather than in the db-layer spec.

DoD-3 (the unique constraint) is asserted at the **database** level: the second insert must be refused
by SQLite, not by a Python-side check the module could later drop.

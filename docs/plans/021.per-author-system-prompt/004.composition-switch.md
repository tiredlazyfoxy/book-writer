# 004 — The composition switch: `BOOK` becomes `AUTHOR`

## Goal

Repoint the assistant's prompt composition off `Book.system_prompt` and onto the prompt of the author
whose chat is running — renaming the layer, retiring the column in place, and revising the three
backend docstrings that explain why the field is absent from the book DTOs.

**This step is deliberately kept small and separate rather than merged into 003.** It is the step that
actually delivers "replace"; burying it inside the route work would hide the one change that makes the
old model stop applying.

## Interface intent

**`backend/app/services/prompt_composition.py`** — `compose_system_prompt` keeps its name, its purity,
its blank-skipping rule and its rendering, and changes in exactly two ways:

- its **book parameter is renamed to name the author**, and
- its **section label changes from `BOOK` to `AUTHOR`**.

The resulting layer order is **base → mode → author → chapter**. The base, mode and chapter parameters
are untouched; the chapter layer stays in place and stays optional.

**`backend/app/services/chat_turn.py`** — the sole production call site. Today it passes the book row's
prompt. It must instead pass **the prompt belonging to the author on whose behalf the turn is running**
— the chat's author, the same identity `services/chats.py`'s ownership guard already scopes every chat
read and write to.

- The row is read through step 001's `db/` module (`services → db` is the sanctioned edge; see
  `context.md` → "Planner-derived decisions").
- **No row, or a blank prompt, contributes nothing** — the composer already skips blank layers, so the
  turn passes the stored text through as-is and does not special-case it.
- `chapter=` is still **not** passed. Nothing else about the turn changes.

**`backend/app/models/book.py`** — the `system_prompt` column keeps its type and its required-ness;
only its docstring changes. It must state that the field is **superseded by `BookAuthorPrompt` and
read by nothing**, that it is retained rather than dropped because the schema layer offers only an
additive migration seam and there is no Alembic, and that it is still written `""` at book creation
and still exported.

**`backend/app/models/schemas/books.py`** — the **three** docstrings that currently declare
`system_prompt` deliberately omitted from the book DTOs are **revised, not deleted**. The new reason
is that the prompt is **per-author and served by its own endpoint**, so a book-shaped DTO cannot carry
it honestly — two authors reading the same book would need different bytes in the same field.

## Definition of done

1. `[test]` A composed prompt renders the author's text under an `AUTHOR` heading, positioned after
   the mode layer and before the chapter layer.
2. `[test]` A blank, whitespace-only or absent author prompt contributes no heading, no section and no
   extra separator — the surrounding layers render exactly as they would with the argument omitted.
3. `[test]` The parameter is named for the author: calling `compose_system_prompt` with the old
   keyword fails rather than silently binding, so a half-finished rename cannot ship.
4. `[test]` A turn composes the prompt belonging to **the chat's own author**. Two authors in one
   book, each with a different stored prompt, produce two different composed prompts.
   *(This deliberately reverses UC-093 / US-108's "the book prompt is applied to every chat in the
   book"; see `context.md` → "Product situation".)*
5. `[test]` A turn whose author has no prompt row composes with no author layer at all, and every
   other layer is unaffected.
6. `[test]` `Book.system_prompt` no longer influences composition: setting it to a distinctive value
   changes nothing in the composed prompt.
7. `[test]` The column is nevertheless still alive — a book created through the ordinary path still
   carries it, and it still round-trips through export and import.
8. `[manual/live]` The three `models/schemas/books.py` docstrings state the new reason (per-author,
   own endpoint) rather than the old book-wide one, and none of them was deleted.
9. `[manual/live]` A live chat turn against a configured LLM server, in a book where two authors hold
   different prompts, reflects each author's own instruction in their own chat.

## Dependencies

- **001** — the `db/` module the turn reads.
- **002** — not strictly required by the code path (the turn reads `db/` directly), but the write path
  must exist for DoD-4 to be reachable end to end.

## Out of scope

`backend/app/services/books.py` is **not** touched. It still writes `""` into `Book.system_prompt` at
creation, and must keep doing so — the column is required and has no default.

# 004 context — Book read projections

The taxonomy (401/404/403), the reader-is-access-control-only decision, and the
UC-029 exclusion list are in `context.md`. Narrow facts for this step:

- **Two projections, deliberately different shapes.** `BookDetailResponse` is the
  members-only view feeding step 7's settings page (needs owner id, visibility,
  state, mode, members). `ReaderBookResponse` is the UC-029 reader view: table of
  contents + chapter text **only** — and since chapters don't exist yet, the
  TOC/chapters field is an empty placeholder. Keeping them separate DTOs is what
  enforces the exclusion at build time.
- **Where each status comes from:**
  - 401 (no token) — the `book_access` dependency via `get_current_user`.
  - 404 (missing book, or private + non-member) — `resolve_book_access` inside the
    dependency; the service never sees these callers.
  - 403 (member detail requested by a public-book reader) — `authz.require(access,
    view_book_detail)` in `get_book_detail`, mapped by the route.
- A reader of a **public** book resolves to `role == reader`, so
  `GET /{book_id}` (member detail) reaches the service and is refused 403 by
  `require`, while `GET /{book_id}/read` is permitted by `read_book`. A non-member of
  a **private** book never reaches either service — the resolver 404s first.
- `GET /{book_id}` and `GET /{book_id}/read` are added to the router **after** the
  static `GET /api/books/shared` from step 3 (ordering constraint in `context.md`).
- Route tests seed owner, co-author (a `BookMember` row), and a third non-member
  author; flip `Book.visibility` between `private`/`public` by seeding the row with
  the desired value. The anonymous case sends no `Authorization` header.

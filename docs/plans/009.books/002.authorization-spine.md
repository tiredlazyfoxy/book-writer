# 002 — Authorization spine

## Goal

Build the book-scoped authorization spine: a `BookAccess` typed context resolved by
a FastAPI `book_access(book_id)` dependency (existence hiding = 404), plus a
`services/authz.py` capability × role matrix with a `require(access, capability)`
decision point (denial = 403).

## Source files

backend/app/services/authz.py

## Test files

backend/tests/services/test_authz.py

## Interface intent

Everything lives in one new module, `services/authz.py` (the spine consumed by
steps 3–5). It exposes:

- **`AccessRole` enum** — `owner`, `co_author`, `reader`, `none`. (`admin` as a
  book-access role is deferred to FEAT-011's moderation view — not populated here;
  an admin calling an authoring endpoint is resolved by the ordinary rules and
  refused exactly as a stranger, per `authorization.md` → "The admin boundary".)
- **`BookAccess`** — a typed structure (not a dict) carrying `book_id`, `user_id`,
  `role` (`AccessRole`), `book_state`, `visibility`, `collaboration_mode`. This is
  identity relative to one book and nothing else.
- **`resolve_book_access(book_id, user)`** — the resolution logic, pure of HTTP
  beyond the raised status: reads `db/books.get_by_id` and
  `db/book_members.get_by_book_and_user`; determines role (owner if
  `owner_id == user.id`; else co-author if a membership row exists; else reader if
  `visibility == public`; else none); raises **404** when the book is missing **or**
  the resolved role is `none` (existence hiding); otherwise returns `BookAccess`.
  Returning a testable function (not only a dependency) is deliberate so the resolver
  is exercised without HTTP.
- **`book_access(book_id)`** — the thin FastAPI dependency wrapper: pulls the
  current user via the existing `get_current_user` dependency (which raises **401**
  when there is no valid token) and delegates to `resolve_book_access`. This is what
  routes declare as `Depends(...)`.
- **`Capability` enum** — the 009 capabilities: `read_book`, `view_book_detail`,
  `archive_book`, `transfer_ownership`, `add_member`, `remove_member`,
  `set_visibility`.
- **The capability × role matrix** — a table mapping each `Capability` to the set of
  `AccessRole`s allowed it: `read_book` → {owner, co_author, reader};
  `view_book_detail` → {owner, co_author}; every mutation
  (`archive_book`, `transfer_ownership`, `add_member`, `remove_member`,
  `set_visibility`) → {owner} only. (Straight from `authorization.md` → "Book
  lifecycle and settings — owner only".)
- **`BookAuthorizationError`** — the typed exception `require` raises on denial,
  carrying enough context for a route to map it to **403**.
- **`require(access, capability)`** — raises `BookAuthorizationError` when
  `access.role` is not in the matrix's allowed set for `capability`; returns
  normally otherwise. The single guard every book service calls.

No write-refusal / archived-state capability is built (deferred — see `context.md`).
The resolver still populates `book_state` for future use and the read gates.

## Definition of done

1. **[test]** `resolve_book_access` returns `role == owner` for the book's owner and
   `role == co_author` for a co-author, on a private book. *(US-029.AC-2 — a private
   book is openable by owner and co-authors.)*
2. **[test]** `resolve_book_access` returns `role == reader` for a logged-in
   non-member on a **public** book. *(US-030.AC-1.)*
3. **[test]** `resolve_book_access` raises **404** for a logged-in non-member on a
   **private** book. *(US-030.AC-3 — existence hiding, not 403.)*
4. **[test]** `resolve_book_access` raises **404** for a non-existent `book_id`.
   *(authorization.md → "Failure modes"; existence hiding; no dedicated US-AC.)*
5. **[test]** `resolve_book_access` populates `book_state`, `visibility`,
   `collaboration_mode` on the returned `BookAccess` from the book row. *(Supports
   the read/state gates; no dedicated US-AC.)*
6. **[test]** `require` returns normally when the role is permitted (owner for a
   mutation capability; reader for `read_book`) and raises `BookAuthorizationError`
   when it is not (co-author or reader for an owner-only capability). *(Guards the
   owner-only rows: US-024.AC-1, US-025.AC-1, US-027.AC-1, US-028.AC-1,
   US-029.AC-1.)*
7. **[test]** `require(access, Capability.view_book_detail)` denies a `reader`
   (members-only detail) and permits owner/co_author. *(US-030.AC-2 — a reader is
   given no members/settings surface; members-only exclusion.)*
8. **[manual/live]** `resolve_book_access` reads only through `db/`; `require`
   contains no DB/session access and no HTTP framework types beyond its raised
   exception (layer separation, verified by reading).

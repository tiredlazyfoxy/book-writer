# 004 — Book read projections

## Goal

Add the two book read paths — the member detail view (owner/co-author, includes the
member list, feeds the settings page) and the reader access-controlled projection
(logged-in reader of a public book, reader-safe placeholder content) — both gated by
`BookAccess`.

## Source files

backend/app/models/schemas/books.py
backend/app/services/books.py
backend/app/routes/books.py

## Test files

backend/tests/routes/test_book_read.py

## Interface intent

- **Schemas (extend `models/schemas/books.py`)**:
  - **`BookMemberResponse`** — one co-author: member `user_id` as **string**, plus
    the role marker and the membership timestamp.
  - **`BookDetailResponse`** — the members-only detail: everything in
    `BookResponse` plus `owner_id`, the full field set the settings page needs
    (`collaboration_mode`, `visibility`, `state`, `description`, `system_prompt`
    inclusion is a skeleton call — expose what settings renders) and a `members`
    list of `BookMemberResponse`.
  - **`ReaderBookResponse`** — the reader-safe projection: `title` and a **table of
    contents** / chapters field that is an **empty placeholder** (no chapters exist
    until Stage 5). It carries **none** of the members-only surface — no members,
    owner id, codex, notes, flags, book state, settings or system prompt (UC-029
    exclusion list). No mutation-bearing fields.
- **Service (extend `services/books.py`)**:
  - **`get_book_detail(access)`** — takes the resolved `BookAccess`, calls
    `authz.require(access, Capability.view_book_detail)` (owner/co-author only),
    loads the book via `db/books.get_by_id` and members via
    `db/book_members.list_by_book`, returns `BookDetailResponse`.
  - **`get_reader_book(access)`** — calls `authz.require(access,
    Capability.read_book)` (owner/co-author/reader), loads the book, returns a
    `ReaderBookResponse` with placeholder TOC/chapters. Realizes UC-029.
- **Routes (extend `routes/books.py`)** — both take `Depends(book_access(book_id))`;
  the resolver already yields 401 (no token) and 404 (missing / private non-member);
  the service `require` yields 403; both map `BookAuthorizationError` to 403 via the
  step-3 error helper:
  - **`GET /api/books/{book_id}`** — member detail; returns `BookDetailResponse`.
  - **`GET /api/books/{book_id}/read`** — reader projection; returns
    `ReaderBookResponse`.

## Definition of done

1. **[test]** `GET /api/books/{book_id}` returns 200 with the book fields and its
   `members` list for the owner and for a co-author of a **private** book.
   *(US-029.AC-2 — a private book is openable by owner and co-authors.)*
2. **[test]** `GET /api/books/{book_id}` → **404** for a logged-in non-member of a
   private book. *(US-030.AC-3 — existence hiding.)*
3. **[test]** `GET /api/books/{book_id}` → **403** for a logged-in non-member reader
   of a **public** book (member detail is members-only). *(US-030.AC-2 — the reader
   gets no members/settings surface.)*
4. **[test]** `GET /api/books/{book_id}/read` returns **200** with a reader-safe
   projection for a logged-in non-member of a **public** book. *(US-030.AC-1.)*
5. **[test]** The `ReaderBookResponse` exposes no members, owner id, codex, notes,
   book state, settings or mutation fields — only title + placeholder TOC/chapters.
   *(US-030.AC-2 — no edit action / members-only exclusion, UC-029 exclusion list.)*
6. **[test]** `GET /api/books/{book_id}/read` → **404** for a logged-in non-member of
   a **private** book. *(US-030.AC-3.)*
7. **[test]** `GET /api/books/{book_id}/read` without a valid token → **401**.
   *(US-030.AC-4 — anonymous refused.)*
8. **[manual/live]** The reader projection's TOC/chapter content is an empty
   placeholder; real chapter/TOC content arrives with Stage 5 (no automated content
   assertion beyond the placeholder shape).

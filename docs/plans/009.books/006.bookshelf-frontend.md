# 006 — Bookshelf frontend

## Goal

Build the Shell bookshelf at `/`: the API/type layer for books, a page showing owned
and shared books via the async-resource trio, and a create-book form (draft class, no
Mantine `useForm`) wired to the step-3 endpoints.

## Interface intent

- **Types (`types/books.d.ts`)** — hand-written interfaces mirroring the step-3
  Pydantic DTOs exactly: a book summary (`id`/`owner_id` as `string`, title,
  description, collaboration mode, visibility, state, timestamps), the list envelope
  (`{ items: [...] }`), and the create-request body. Doc comment cites the backend
  schema source (`models/schemas/books.py`).
- **API module (`api/books.ts`)** — mirrors `api/admin.ts` (`const BASE =
  "/api/books"`, `signal?` trailing, namespace-imported): `listOwnedBooks(signal?)`
  → `GET /api/books`; `listSharedBooks(signal?)` → `GET /api/books/shared`;
  `createBook(body, signal?)` → `POST /api/books`. All via the shared
  `request<T>` client.
- **Page state (`bookshelfPageState.ts`)** — a `BookshelfPageState` class with two
  async-resource trios (owned + shared: `data` / `dataStatus` / `dataError` each) and
  `makeAutoObservable`. External `loadBookshelf(state, signal?)` loads both lists
  (runInAction loading→ready/error, guards `signal?.aborted`, maps `ApiError` to the
  error trio else rethrows). External `createBookAction(state, body, signal?)` awaits
  the create then re-loads (mirrors `disableUserAction` re-load pattern).
- **Create draft (`createBookDraft.ts`)** — a `CreateBookDraft` class: observable
  fields (title, description, collaboration mode, visibility), `serverErrors`,
  `submitStatus`; `get clientErrors` / `get errors` / `get canSubmit`; external
  `submitCreateBook(draft, onCreated, signal?)` mapping `ApiError` by status into
  `draft.serverErrors`, calling `onCreated` on success. (Template =
  `CreateUserDraft`.)
- **Create modal (`CreateBookModal.tsx`)** — `observer`, holds the draft via
  `useState(() => new CreateBookDraft())`; inputs bound `value`/`onChange`, `error`
  from `draft.errors`; open/target flags are component-local `useState`.
- **Page (`BookshelfPage.tsx`)** — `observer`; `useState(() => new
  BookshelfPageState())`; one page-level `useEffect([state])` spinning an
  `AbortController`, calling `void loadBookshelf(state, ctrl.signal)`, cleanup
  `ctrl.abort()`. Renders the two lists (owned / shared) and the create modal;
  successful create re-loads.
- **Routes (`routes/user routes.tsx`)** — set `/` to `BookshelfPage`; relocate the
  existing `HealthPage` route to `/health` so it is preserved.

## Definition of done

1. **[manual/live]** `/` shows the books the caller owns (owned list, from `GET
   /api/books`). *(US-023.AC-1 — covered `[test]` at backend step 3.)*
2. **[manual/live]** `/` shows the books shared with the caller (shared list, from
   `GET /api/books/shared`). *(US-031.AC-1 — backend step 3.)*
3. **[manual/live]** The create-book form submits `title`, `description`,
   `collaboration_mode`, `visibility` to `POST /api/books` and the new book appears
   in the owned list on success. *(US-022.AC-1 / AC-2 — backend step 3.)*
4. **[manual/live]** Server validation errors map into the draft's field errors (not
   a raw throw); the form follows the draft-class pattern with no Mantine `useForm`.
5. **[manual/live]** `types/books.d.ts` matches the backend DTOs and `cd frontend &&
   npm run build` typechecks clean (no `any`). *(API-typing convention.)*
6. **[manual/live]** Every component is an `observer`; loads/creates run through
   external `(state, args, signal)` functions with a page-level `useEffect` +
   `AbortController` (MobX conventions).

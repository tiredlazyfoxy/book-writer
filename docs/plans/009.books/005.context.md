# 005 context — Book settings mutations

Owner-only matrix, the transfer-to-non-member REFUSE decision, and the deferred ACs
are in `context.md`. Narrow facts for this step:

- **All six are owner-only.** Each service function's first act is
  `authz.require(access, <its capability>)` — `archive_book` / `unarchive_book` share
  `Capability.archive_book`; the rest use their own-named capability. A co-author or
  reader is denied 403; a private non-member never reaches the service (resolver 404).
- **Transfer target must be a current co-author.** Check `db/book_members`
  (`get_by_book_and_user`) for the target on this book; missing → `BookError`
  (refuse), do **not** implicitly add them. This is the resolved UC-024 `_TBD_`.
- **Archive is state-only.** `state = BookState.archived`, everything else preserved;
  no chapter interaction (no `Chapter` entity). Unarchive → `state = active`. Guard
  unarchive against a book that is not archived, and archive against one already
  archived, via `BookError` rather than a silent no-op (skeleton's call on exact
  reasons).
- **Add/remove key on `(book_id, user_id)`.** Add creates a `BookMember(role =
  MemberRole.co_author)`; the unique constraint makes a duplicate add a `BookError`
  rather than a DB 500. Remove uses `db/book_members.delete` and 404s a non-member
  target.
- **Verifying visibility flips** uses the step-4 `GET /{book_id}/read` endpoint: after
  `→ public`, a seeded non-member gets 200; after `→ private`, the same non-member
  gets 404. Verifying add/remove uses the step-4 `GET /{book_id}` detail `members`
  list and the removed user's subsequent 404.
- New routes are added to the same `routes/books.py` router after the step-3/4
  routes; keep `POST/DELETE/PATCH` handlers consistent with the existing
  `try/except` + `_map_book_error` shape. `modified_at` set via
  `datetime.now(timezone.utc)` on every mutation.

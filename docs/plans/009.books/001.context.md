# 001 context — DB-layer extensions

Feature-wide facts (data layer delivered by 008, enum names, layer rules, test
harness) are in `context.md`. Narrow facts for this step:

- The existing `db/books.py` has `create` and `get_by_id` only; `db/book_members.py`
  has `create`, `get_by_id`, `list_by_book`. Add alongside them following the same
  session-free, internally-managed-session pattern (template = `db/llm_servers.py`:
  `get_by_id`, `get_all`, `create`, `update`, `delete`, add/commit/refresh).
- `BookMember` has a **unique `(book_id, user_id)`** constraint — so
  `get_by_book_and_user` and `delete` key on that pair, not the surrogate `id`.
- `list_shared` semantics: "co-author, not owner". A user could theoretically own a
  book *and* be listed nowhere as a member (owner is never a member row), so the
  owner-exclusion is about not double-counting — a book must not appear in both a
  user's owned list and their shared list.
- `MemberRole` mirrors the existing `(str, Enum)` book enums in `models/book.py`
  (`CollaborationMode`, `Visibility`, `BookState`) — same style, single value
  `co_author`.
- JSONL codec functions to check for round-trip: `_book_member_to_dict` /
  `_dict_to_book_member` in `services/db_import_export.py`. Only edit if the retype
  breaks round-trip (a `(str, Enum)` value is itself a `str`, so `json.dumps` and
  Pydantic coercion may already round-trip unchanged — verify, don't assume).
- Test seeding: reuse the 008 `test_data_domain_*` seeding style for `db/` tests
  (construct `Book` / `BookMember` rows directly and call the `db/` functions
  against the temp-DB `db` fixture).

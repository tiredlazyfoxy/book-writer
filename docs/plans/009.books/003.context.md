# 003 context — Book create + list

Slice conventions (llm_servers template, error-mapping pattern, DTO-id-as-string,
router registration, static-before-param ordering) are in `context.md` → "Backend
vertical-slice conventions". Narrow facts for this step:

- **Create and both lists are gated by `get_current_user` only** — they are not
  book-scoped (there is no single book to resolve for a create or a list), so they do
  **not** use the `book_access` dependency from step 2. `services/authz` is imported
  by later steps, not this one.
- `create_book` mirrors `llm_servers` create: construct the `Book` model (id assigned
  by the model's `default_factory=generate_id`), set timestamps via
  `datetime.now(timezone.utc)`, persist with `db/books.create`, hand-map to
  `BookResponse`. Owner is a scalar field (`owner_id`), **not** a `BookMember` row.
- Defaults on create: `state = BookState.active`, `system_prompt = ""`,
  `active_notes = ""`, `moderation_reason/moderated_by/moderated_at = None`. The
  request supplies only `title`, `description`, `collaboration_mode`, `visibility`.
- **Route ordering is load-bearing:** `GET /api/books/shared` is a static path that
  must be declared before the `GET /api/books/{book_id}` route step 4 adds to the
  same router file, or FastAPI matches `shared` as a `book_id`.
- `routes/books.py`, `services/books.py`, `models/schemas/books.py` are **created
  here and extended by steps 4 and 5** — keep the module structure open for those
  additions (shared error enum, shared `_to_response`, shared router).
- Route tests seed authors inline with `_seed_user(...)` + `auth.create_access_token`
  + `_auth_header` (no prebuilt authed fixture). Exercising the shared list needs a
  `BookMember` row created directly (via `db/book_members.create` or a seeded row)
  linking a second author to a book owned by a first.

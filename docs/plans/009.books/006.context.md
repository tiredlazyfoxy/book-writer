# 006 context — Bookshelf frontend

MobX/API/forms conventions and the frontend-test-runner situation are in `context.md`
→ "Frontend conventions". Narrow facts for this step:

- **Templates to copy shape from:** page + state = admin Users page
  (`admin/pages/UsersPage.tsx` + `usersPageState.ts`); create form = admin
  `CreateUserModal.tsx` + `CreateUserDraft`; API module = `api/admin.ts`; types =
  `types/admin.d.ts`. The book slice is greenfield under `src/user/` — only the
  health page exists there today.
- **Two trios on one page:** the bookshelf shows owned **and** shared lists, so
  `BookshelfPageState` carries two independent async-resource trios (no aggregation
  type — `frontend.md` rule). `loadBookshelf` populates both.
- **`routes.tsx` currently has one route** (`/` → `HealthPage`) and **no path
  params**. This step only touches the top-level `/` route (bookshelf); the
  URL-param `/books/:bookId/settings` route is step 7. Preserve `HealthPage` by
  moving it to `/health`.
- `api/books.ts` created here is **extended in step 7** with the settings-mutation
  calls — keep it open for those additions. `routes.tsx` is likewise edited again in
  step 7.
- New directory `src/user/components/books/` holds the create form (and step 7's
  settings sub-forms). The `App.tsx` token gate already redirects unauthenticated
  users to `/login/` — no auth handling needed on the page.
- DTO ids are `string` everywhere; the collaboration-mode and visibility values are
  the same string literals as the backend enums (`free`/`proposal`,
  `private`/`public`).

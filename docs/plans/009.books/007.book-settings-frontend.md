# 007 — Book settings frontend

## Goal

Build the `/books/:bookId/settings` Shell page (the codebase's first URL-param
route → apply the `key` remount rule): load book detail + members, and wire
archive/unarchive, transfer, co-author add/remove, and visibility toggle to the
step-4/5 endpoints.

## Interface intent

- **Types (extend `types/books.d.ts`)** — add the detail DTO (book fields + a
  `members` list of member DTOs, `user_id` as `string`) and the mutation request
  bodies (transfer target id, add-member target id, set-visibility value), mirroring
  the step-4/5 Pydantic exactly.
- **API module (extend `api/books.ts`)** — add: `getBookDetail(bookId, signal?)` →
  `GET /api/books/{id}`; `archiveBook` / `unarchiveBook` → the archive/unarchive
  POSTs; `transferOwnership(bookId, body, signal?)`; `addMember(bookId, body,
  signal?)`; `removeMember(bookId, userId, signal?)` → the DELETE;
  `setVisibility(bookId, body, signal?)` → the PATCH. Ids interpolated into paths,
  `signal?` trailing.
- **Page state (`bookSettingsPageState.ts`)** — a `BookSettingsPageState` class
  holding the book-detail async-resource trio (`data` / `dataStatus` / `dataError`);
  `makeAutoObservable`. External `loadBookSettings(state, bookId, signal?)` loads the
  detail. External action functions — `archiveAction` / `unarchiveAction` /
  `transferAction` / `removeMemberAction` / `setVisibilityAction` — each `(state,
  bookId, args..., signal?)`, awaiting the mutation then re-loading the detail
  (mirrors `disableUserAction`). Errors map to the trio / surfaced state.
- **Drafts** — `addCoAuthorDraft.ts` (`AddCoAuthorDraft`: target-account field,
  `serverErrors`, validation computeds, `submitAddCoAuthor(draft, bookId, onDone,
  signal?)`) and `transferOwnershipDraft.ts` (`TransferOwnershipDraft`: target
  co-author selection, same shape). Template = `CreateUserDraft` /
  `serverFormDraft.ts`.
- **Page (`BookSettingsPage.tsx`)** — `observer`; `useState(() => new
  BookSettingsPageState())`; page-level `useEffect([state])` with an
  `AbortController` calling `void loadBookSettings(state, bookId, ctrl.signal)`.
  Reads `bookId` from the route param. Renders: current visibility with a toggle,
  archive/unarchive control keyed on current state, the members list with
  remove controls, an add-co-author form, and a transfer-ownership form. Each action
  spins a fresh `AbortController` and re-loads on success.
- **Routes (extend `routes.tsx`)** — add `/books/:bookId/settings` →
  `BookSettingsPage`, applying the documented **`key={bookId}` remount rule** so the
  page is a fresh state instance per book id.

## Definition of done

1. **[manual/live]** `/books/:bookId/settings` loads and shows the book's detail +
   members list (from `GET /api/books/{id}`); the route uses `key={bookId}` so
   changing book id remounts a fresh page. *(US-029.AC-2 detail access — backend
   step 4.)*
2. **[manual/live]** The archive control archives the book and unarchive reverses it;
   the control reflects the current `state`. *(US-024.AC-1 / AC-2 — backend step 5.)*
3. **[manual/live]** The transfer-ownership form transfers to a selected co-author;
   selecting a non-co-author is not offered / a refusal surfaces as a field error.
   *(US-025.AC-1 — backend step 5.)*
4. **[manual/live]** The add-co-author form grants access and the new member appears
   in the members list after re-load. *(US-027.AC-1 — backend step 5.)*
5. **[manual/live]** The remove control removes a co-author and the members list
   updates after re-load. *(US-028.AC-1 — backend step 5.)*
6. **[manual/live]** The visibility toggle switches the book between private and
   public. *(US-029.AC-1 / AC-2 — backend step 5.)*
7. **[manual/live]** `cd frontend && npm run build` typechecks clean (DTOs match the
   backend; no `any`); every component is an `observer`; all mutations run through
   external `(state, args, signal)` functions (MobX conventions).

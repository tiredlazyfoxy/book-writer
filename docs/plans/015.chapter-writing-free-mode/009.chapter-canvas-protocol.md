# 009 — The chapter canvas protocol: a frame operation, the selection on the wire, and the chapter branch of `determine_mode`

## Goal

Widen the `canvas` frame with an operation discriminator defaulted to the codex's current behaviour,
carry the author's selection on the turn request into the per-turn tool context, and **add the chapter
branch `determine_mode` does not have** — the three pieces the chapter tools need before they exist.

*This step has no product id: FEAT-013 / UC-054 / UC-055 are parked under "Mapped later" by the
roadmap, so its criteria are self-contained and cite none (`context.md` → "Known product gaps").*

## Interface intent

- **`CanvasFrame` (`models/schemas/chats.py:260-295`) gains an operation field** — a three-valued
  discriminator: replace the whole field, append to it, or replace the author's current selection —
  **defaulted to replace** (`context.md` → **D17**). The default is the entire reason this is cheap:
  the **single** existing emission, at `codex_tools.py:689-706`, is unchanged and is not edited. The
  frame keeps `subject_kind`, `subject_id`, `field` and `text`, and `routes/chats.py:224-231`
  serializes generically over `frame.event`, so **no route changes**.
- **`CanvasField` (`chats.py:257`) is NOT widened.** It stays `Literal["name", "body"]`; a chapter's
  body **is** the `"body"` field. `context.md` → D17 carries the reasoning.
- **`TurnRequest` (`chats.py:187-216`) gains an optional selection text** — a **fourth flat field**
  beside `subject_kind`, `subject_id` and `codex_kind`. There is no subject object on the backend
  request and none is introduced. It is **client-supplied turn context, never persisted**
  (`context.md` → **D5**), and it is **text only: no offsets, no line numbers, no anchors.**
- **`ToolContext` (`tools.py:93-139`, a frozen dataclass) gains the selection text** as a fifth field
  beside `book_id`, `access`, `subject` and `emit_frame`, so a bound tool can read it without the turn
  re-deriving anything. **`chat_turn.py` populates it** where it already builds the context for the
  codex tools.
- **`ResolvedSubject` gains a resolved-chapter member** beside its existing `entry`, and the subject
  resolution that today loads a codex entry also loads a chapter row when the request's subject kind is
  a chapter. A `subject_id` naming a chapter in **another book** resolves to **no subject** — the same
  rule `013.codex` fixed for codex entries, implemented by the same resolution step rather than by a
  later check.
- **`determine_mode` (`assistant_runtime.py:195-218`) gains its chapter branch.** Today its whole body
  is `if subject.entry is None: return None` / `return _mode_for_codex_kind(subject.entry.kind)` —
  there is **no chapter handling at all**, and its own docstring says the two chapter modes belong to
  `015` / `016`. The branch maps a resolved chapter **by state**: `open` → `write-chapter`; `closing` →
  `close-chapter`; `planned` and `closed` → **no mode**, because neither is an activity FEAT-020 names.
  A **mode-key constant** sits beside `_CODEX_KIND_MODES` (`:104-108`) rather than inlining the two
  strings.
- **Tool gating is not changed.** `allowed_tool_names` (`:247-274`) already returns `BASE_TOOL_NAMES`
  for a null mode and the mode's `mode_tool` rows otherwise, and `resolve_turn_tools` (`:277-305`)
  already concatenates delegation tools. **No `mode_tool` row and no `AssistantMode` row is seeded**
  (`context.md` → D4 and "Mode seeding").

## Definition of done

1. `[test]` A canvas frame constructed without an operation carries the replace operation, and one
   constructed with append or replace-selection carries what it was given — the default is what keeps
   every existing emitter correct.
2. `[test]` The existing codex canvas emission still produces a frame identical to today's apart from
   the defaulted operation field — same subject kind, same subject id, same field, same text — and the
   codex tools' behaviour and refusal strings are unchanged. (`services/codex_tools.py` is **not** in
   this step's source list; this is a pure regression assertion over a file the step does not touch.)
3. `[test]` `CanvasField` still admits exactly `"name"` and `"body"` — no `"text"` member was added.
4. `[test]` A turn request carrying no selection is valid, and one carrying selection text makes that
   text readable from the per-turn tool context.
5. `[test]` The selection is never written anywhere: a turn carrying selection text leaves no row that
   holds it, and creates no chapter change and no revision.
6. `[test]` `determine_mode` resolves a chapter subject in state `open` to **`write-chapter`** — a
   branch that does not exist before this step.
7. `[test]` `determine_mode` resolves a chapter subject in state `closing` to **`close-chapter`**.
8. `[test]` `determine_mode` resolves a chapter subject in `planned` or `closed` to **no mode**, and
   `allowed_tool_names` therefore returns the base allowlist — concretely, exactly `web_search` — not
   an empty list and not the whole registry.
9. `[test]` A `subject_id` naming a chapter in **another book** resolves to **no subject**, and
   therefore to no mode — the cross-book read is refused by resolution, not by a later check.
10. `[test]` Codex subject resolution and codex mode determination are unchanged: a codex entry of each
    kind still resolves to the mode it resolves to today.
11. `[test]` A turn with no subject at all is unaffected by every change in this step.
12. `[test]` A freshly initialised database has an `AssistantMode` row keyed **`write-chapter`** and one
    keyed **`close-chapter`** — the two keys the branch above returns. **Nothing in this step seeds
    them**; the assertion exists because a mode key with no row fails *silently* (empty mode prompt,
    empty tool allowlist, no error anywhere). See `context.md` → "Mode seeding".

## Dependencies

None within this feature. It touches only the assistant runtime, which exists as of `013.codex`.

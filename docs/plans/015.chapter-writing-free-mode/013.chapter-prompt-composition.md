# 013 — The caller's own chapter prompt as composition layer 4

## Goal

Wire 014's per-author chapter prompt into the assistant's existing fourth prompt layer for turns whose
subject is a chapter — the one thing 014's `outcome.md` handed forward, and the blocker 015 dissolved.

**This step is deliberately small and deliberately last.** It is the feature's only dependency on 014's
`ChapterAuthorPrompt` half; if that half slips, every other step of 015 stands without it
(`context.md` → **D12**). It stays a step of its own rather than merging into 009 precisely so it can be
dropped without unpicking anything.

*This step has no product id: FEAT-019's UC-094 and every criterion of US-109 describe a chapter prompt
that narrows a book-wide prompt feature `021` removed, and 014 deliberately cites none of them. Its
criteria are self-contained, the same convention `014` and `021` used.*

## Interface intent

**`backend/app/services/chat_turn.py`** — one addition to the composition call it already makes.

`services/prompt_composition.py` is a **pure function taking four optional layers** — base, mode,
author, chapter — and it already has a chapter slot that nothing has ever filled. **That module is not
touched**: no signature change, no new layer, no reordering.

When the turn's resolved subject is a **chapter**, `chat_turn` reads the `(chapter_id, author_id)` row
through `db/chapter_author_prompts.py` — `services → db`, the enforced direction — and passes its text
as the fourth layer. The identity is **the chat's own author**, the same identity that already scopes
layer 3 and every chat read and write; **no `BookAccess` is built for this**, for the reason
`assistant-runtime.md` states about layer 3: the turn is already scoped to the chat's author by
construction, so a second access resolution would re-derive an identity that cannot differ.

- **No row, or an empty prompt, contributes nothing** — no section, no separator, no blank block. That
  is the composer's existing rule for every layer and it needs no new code.
- **`Chapter.system_prompt` is not read.** It is dormant and superseded (014's D1). Nothing in this step
  touches it.
- The layer applies whatever the chapter's state is — a prompt is the author's instruction to their own
  assistant, not chapter content, so the state machine does not gate it (014's authorization decision).

## Definition of done

1. `[test]` A turn whose subject is a chapter composes the **caller's own** chapter prompt as the fourth
   layer, after the base, mode and author layers, in that order.
2. `[test]` Another member's chapter prompt for the same chapter is **never** read into the turn —
   including when the caller is the book's owner.
3. `[test]` A chapter with **no** prompt row for the caller, and a row whose prompt is the empty string,
   both contribute nothing: no section, no separator, no blank block.
4. `[test]` A turn whose subject is **not** a chapter — a codex entry, a list, book state, or no subject
   — composes exactly what it composes today, with no fourth layer.
5. `[test]` The prompt is read for a chapter in **every** state, including `planned` and `closed` — the
   chapter state machine does not gate it.
6. `[test]` **`Chapter.system_prompt` is not read** by the turn: a chapter whose dormant column holds
   text contributes nothing to the composed prompt.
7. `[test]` `services/prompt_composition.py`'s signature and behaviour are unchanged — the fourth layer
   was already there and this step only fills it.

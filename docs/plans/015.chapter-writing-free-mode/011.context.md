## `contentSubject.ts` as it stands, and exactly what is wrong with it for chapters

Harvested: `registerContentSubject(source, applyDraft?)`, `unregisterContentSubject(source)`,
`currentContentSubject()`, `dispatchCanvasFrame(bookId, frame)`.

`dispatchCanvasFrame` is codex-shaped in **one** place that matters: the fallback buffers a dropped
frame under `restoreBufferKey(bookId, "codex-entry", frame.subject_id)`. **That literal is the change.**

It also gates the fallback on the `"body"` field — and that condition **stays exactly as it is**.
`CanvasField` is `Literal["name", "body"]` (`frontend/src/types/chats.d.ts:172`, mirroring
`backend/app/models/schemas/chats.py:257`) and a chapter's body **is** the `"body"` field
(`context.md` → D17). There is no `"text"` member and none is added, on either side of the wire.

Generalizing means routing on the frame's own `subject_kind`. It does **not** mean building a registry
of per-kind handlers — there are two kinds and a third is not on the roadmap.

`frontend/src/types/chats.d.ts` carries four relevant declarations:

## The registration discipline is already written and must be preserved

`frontend-work-drafts.md`: *"The open page registers both in its existing page-level mount `useEffect`
and unregisters them in the same cleanup; registration overwrites outright (newest wins) and
unregistration clears **only** when the caller is still the registered owner, so a late unmount from a
superseded page is a no-op."*

The selection registry inherits that discipline verbatim — DoD-9 pins it. This matters more for
selection than for the subject, because a selection setter fires constantly and a stale page's final
setter call must not win.

## Why the applier's type widens rather than the callback being replaced

`context.md` → D17. The TypeScript fact this leans on: a function of two parameters is assignable to a
type of three. So widening the registry's callback **type** with a third optional parameter leaves
`CodexEntryPage`'s existing two-parameter applier valid, unedited, and correctly ignoring an operation
it will only ever receive as the default.

DoD-6 and DoD-13 together are what prove the codex path paid nothing. **`CodexEntryPage.tsx` and
`codexEntryPageState.ts` are in no step's source list in this entire feature** (`context.md` → D2), and
neither is `services/codex_tools.py`.

## Why undo is in memory and why it only covers assistant writes

`context.md` → D6, both halves:

- **not `localStorage`** — 20 chapter bodies against a few-megabyte origin quota, competing with the
  restore buffer that already has an eviction policy and already reports evictions as data loss. An undo
  stack that evicts other items' unsaved drafts is strictly worse than an undo stack that does not
  survive a reload.
- **assistant writes only** — ProseMirror ships a real history plugin, and the author's typing already
  has undo inside the editor. A second stack over the same keystrokes would give the author two undo
  affordances that disagree about what "one step back" means.

`frontend-work-drafts.md` → "The module tier — three members": *"Each needed the same explicit sanction,
because each is an exception to 'state lives in a `<Page>State`'. They are recorded together so a fourth
is added on purpose rather than by precedent."* This is the fourth. The sanction is carried in
`outcome.md`.

The stack is **not** cleared on save. An author may want to undo an assistant write after saving; the
pop just sets the draft, and re-saving is an ordinary save against the current version.

## `subject.ts` and the shape 014 leaves behind

014 step 008 amends `resolveEditability`'s chapter branch from a whole-subject verdict to a per-region
one, and may widen the `EditableRegion` / `WriteRegion` unions to name the sketch and the prompt. **The
harvest did not record those unions' members**, and 014's own step context says the member names are the
skeleton agent's to freeze.

So this step states only the **behaviour**: `open` → body editable, sketch not; the other three states
unchanged, reasons preserved verbatim. Bind to whatever 014 shipped; if the region vocabulary cannot
express "body editable, sketch not" on `open`, widening it is in scope here — `subject.ts` is in this
step's source list. Do not add members for anything this feature does not ship.

`frontend/src/work/restoreBuffer.ts` is **not** in the source list — it is called, not changed.

- `frontend/tests/work/subject.test.ts` — **may already exist** (014 step 008 creates or extends it).
  **Extend it; do not restructure or rename anything already there.** Touch only the chapter cases for
  DoD-1/2/3.
- `frontend/tests/work/contentSubjectChapter.test.ts` — new. It uses the **real** `restoreBuffer.ts`

  state rather than a mock's call log. DoD-12's DTO assertion also lives here.
- `frontend/tests/work/chapterUndo.test.ts` — new. Pure module tests, no rendering.

These are module tests, not component tests: no `renderWithProviders`, no api mocks. `globals: false`,
so import from `"vitest"`.

DoD-12 is a **type-level** claim about a `.d.ts`; assert it the way a DTO is asserted here — construct
frame literals of each operation and one with the operation omitted, and let `npm run test:types` be the
gate that they compile. Do not import runtime values from a declaration file.

DoD-13's "was not modified" half is a **verifier** observation, not something a spec asserts — it is
listed as `[manual/live]` for that reason.

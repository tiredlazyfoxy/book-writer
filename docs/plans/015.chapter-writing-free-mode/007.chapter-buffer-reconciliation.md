# 007 — The chapter body's restore buffer and both reconciliation entrances

## Goal

Wire the chapter body into the device-local restore buffer keyed on `Chapter.version`, and turn both a
`409` on save and a base-version mismatch at load into the divergence view where the author takes one
side whole.

## Source files

```
frontend/src/work/pages/chapterPageState.ts
frontend/src/work/pages/ChapterPage.tsx
```

## Test files

frontend/tests/work/ChapterPageReconcile.test.tsx

## Interface intent

**`frontend/src/work/pages/chapterPageState.ts`** — buffer and reconciliation state on top of step
006's body region.

- **Buffer wiring**, consuming `frontend/src/work/restoreBuffer.ts` unmodified:
  - the key is `(bookId, "chapter", chapterId)` — the `"chapter"` `SubjectKind` member already exists;
  - the base version written into the buffer is the **numeric `Chapter.version`** the body response
    carried. `BufferBaseVersion` is `number | string` for exactly this;
  - **on every body draft change**, the buffer is written and the write result is inspected;
  - **on a successful save**, the buffer is cleared;
  - an **evicted-keys** holder records a `saved-after-eviction` outcome so the page can tell the author
    which other items' drafts were lost. An eviction is data loss on some other item and is never
    silent.
- **Reconciliation state** — the server's current body, re-fetched and held **beside** the author's
  draft, plus a flag that makes the page render the divergence view instead of the editor.
- **Load-time entrance (the load-bearing one)** — after the body loads, read the buffer at the key:
  - no buffer → seed the draft from the server's body (step 006's behaviour, unchanged);
  - buffer whose base version **equals** the server's version → restore the buffered draft and bump the
    editor generation counter;
  - buffer whose base version **differs** → open the divergence view directly, **with no save
    attempted**.
- **Save-time entrance** — a `409` from the save re-fetches the body and opens the same divergence
  view. Never an auto-merge, never a silent overwrite.
- **A resolution effect** `(state, side, …, signal?)` taking **one side whole**:
  - *keep the server's* → discard the draft, clear the buffer, re-seed everything from the server's
    body, bump the generation counter, leave the view;
  - *keep the draft* → adopt the server's **version** first (so the base version becomes the current
    one), leave the view, and re-save the draft against it.
  There is **no third, merged outcome** produced by the system; a merged body is something the author
  types.

**`frontend/src/work/pages/ChapterPage.tsx`** — the divergence view and the eviction notice.

The divergence view renders the **server's current body** against the **author's draft**, side by side
and readable, with one explicit control per side and no default selection. It replaces the editor while
it is open and offers no save control of its own beyond the two side choices.

The eviction notice names the evicted buffer keys when a buffer write reports one.

**The divergence view is a normal landing, not an error state** (`frontend-work-drafts.md`): it must not
be a modal, must not be styled as a failure, and must not block the rest of the page.

## Definition of done

1. `[test]` Editing the body writes the restore buffer under the `(bookId, "chapter", chapterId)` key
   with the body response's **version** as its base version — UC-092 / **US-107.AC-1**.
2. `[test]` Returning to a chapter whose buffer's base version **matches** the server's version restores
   the **buffered draft** rather than the server's body — **US-107.AC-1**, **US-107.AC-2**.
3. `[test]` Nothing reaches the server as a result of buffering — editing and navigating away issues no
   write call — **US-107.AC-4**, **US-103.AC-3**.
4. `[test]` A successful save **clears** the buffer, so a later return shows the server's body with no
   restore.
5. `[test]` Loading a chapter whose buffer's base version **no longer matches** the server's version
   opens the divergence view **directly**, with no save attempted — the load-time entrance.
6. `[test]` A `409` from the save re-fetches the server's body and opens the divergence view showing it
   against the author's draft, with no auto-merge and no silent overwrite — **US-041.AC-1**,
   **UC-039**.
7. `[test]` Taking the **server's** side discards the draft, clears the buffer and leaves the chapter
   showing the server's body — nothing of the abandoning author's text is written — **US-041.AC-3**.
8. `[test]` Taking the **draft's** side re-saves it against the **new** version and succeeds, and the
   chapter then shows the reconciled text — **US-041.AC-2**.
9. `[test]` A draft that contains both members' text, reconciled by keeping the draft, lands as the
   chapter's body — **US-040.AC-4** through the flow `context.md` → "Known product gaps" describes.
10. `[test]` A buffer write reporting `saved-after-eviction` tells the author which keys were evicted,
    and the **current** chapter's buffer is never the victim.
11. `[test]` The divergence view is rendered inline in place of the editor, is not a modal, and offers
    exactly two choices with neither pre-selected.
12. `[manual/live]` `cd frontend && npm run build`, `cd frontend && npm test` and
    `cd frontend && npm run test:types` all pass.

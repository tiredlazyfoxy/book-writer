# 013 — step context

Feature-wide facts (D12, the layer rules, the test harness) are in `context.md` and are not repeated
here.

## The blocker 014 recorded, and why it is gone

014's `outcome.md` → "`015.chapter-writing-free-mode` inherits one thing explicitly":

> **Composition of the chapter system prompt.** This feature stores and serves it; nothing reads it.
> Wiring it into `services/prompt_composition.py` / `services/chat_turn.py` needs an answer to "which
> chapter is this turn about", which is undesigned FEAT-013 context assembly.

The answer arrived from a different direction: `013.codex` shipped `subject_kind` / `subject_id` on the
turn request, and **this feature registers the open chapter as the content-pane subject** (step 012). So
"which chapter is this turn about" is answered by the **request**, not by context assembly.

**Context assembly itself is still undesigned and still out of scope** — building, ordering, ranking and
truncating retrieved book/chapter/codex material into the prompt (US-057, UC-085/086/078) is untouched.
Only the *named system prompts* are composed, which is exactly the boundary `assistant-runtime.md`
already draws. `outcome.md` records the distinction so nobody reads this step as context assembly having
shipped.

## The composer already has the slot

`assistant-runtime.md`: composition is *"a **pure function** in `backend/app/services/prompt_composition.py`
taking four optional layers, with the base layer as a module constant"*, in the order base / mode /
author / chapter, and *"an empty or absent prompt contributes nothing — no section, no separator, no
blank block"*.

Feature `021` renamed layer 3 from `BOOK` to `AUTHOR` and left layer 4 *"in place, untouched and
unpassed"*. This step passes it. **`prompt_composition.py` is in no source list** — DoD-7 pins that.

## The layer-4 caveat in the architecture is what this step resolves in practice

`assistant-runtime.md` → "Layer 4 caveat": *"`Chapter.system_prompt` now has nothing to append to. What
a chapter prompt narrows is an open question, and it is `014.chapter-skeleton`'s to answer."*

014 answered it: the chapter prompt is a **per-author** row in `ChapterAuthorPrompt`, and
`Chapter.system_prompt` is dormant and read by nothing. This step consumes that answer; it does not
re-open it, and it does not read the dormant column (DoD-6).

## Whose prompt, and why no `BookAccess`

`assistant-runtime.md`, on layer 3: *"`services/chat_turn.py` reads the `(book_id, author_id)` row
through the `db/` module **directly**, using **the chat's own author** … **No `BookAccess` is built for
this**, and the reason matters: the turn is already scoped to the chat's author by construction, so a
second access resolution would re-derive an identity that cannot differ. 'Whose prompt?' is now a real
question with a non-obvious answer, and this is the answer every future runtime slice must reuse."*

This is that future slice. Reuse the answer exactly — same identity, same direct `db/` read, same
absence of an access resolution. DoD-2 is what proves it.

## Severability, concretely

If 014's step 001 has not shipped, `db/chapter_author_prompts.py` does not exist and this step cannot
run. That is the whole of its coupling. Steps 001–012 of this feature do not import it, do not reference
the table, and do not degrade without it — the chapter is writable, the tools work, the editor works,
and the composed prompt simply has three layers instead of four, exactly as it does today.

Marking the step `blocked` and shipping the rest is a legitimate outcome. Do not fold any part of this
step into another one to avoid that.

## Testing

`backend/tests/services/test_chapter_prompt_composition.py` is created from scratch.

**No LLM server is contacted.** Exercise the composition path as a function and assert on the composed
string; `chat_with_tools` is not called. Seed chapters, prompt rows and chats through the sibling `db/`
modules with the `db` fixture.

DoD-1 asserts **order** as well as presence — the four layers are ordered base, mode, author, chapter,
and an assertion that only checks the chapter text is present would pass on a wrong order.

DoD-2 needs two members with different prompt rows on the same chapter, and needs the **owner** as the
non-reader in one direction, because "nobody, including the owner, reads another author's" is the rule
014 established.

DoD-6 needs a chapter whose dormant `system_prompt` column is non-empty and whose
`ChapterAuthorPrompt` row is absent — the composed prompt must contain neither.

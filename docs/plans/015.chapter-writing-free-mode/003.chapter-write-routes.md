# 003 — The body and transition handlers on the chapter router

## Goal

Expose the chapter body read/save and the three state transitions as five handlers on 014's existing
book-scoped chapter router, extending its reason→status map with the six new reasons.

## Source files

```
backend/app/routes/chapters.py
```

## Test files

```
backend/tests/routes/test_chapter_text.py
backend/tests/routes/test_chapter_states.py
```

## Interface intent

**`backend/app/routes/chapters.py`** — five new handlers on the router 014 already declares and
`main.py` already mounts. HTTP only: parse, call one service entry point, return. No business logic, no
capability check, no database access. **`main.py` is not touched** — the router is already included.

- **A body read handler** — `GET` on the chapter's `/text` sub-path, returns the body response. `200`.
- **A body save handler** — `PUT` on the same sub-path, takes the whole-body request, returns the
  stored body response. `200`. `PUT` because the request replaces the whole resource
  (`context.md` → D1).
- **Three transition handlers** — `POST` on `/open`, `/close` and `/reopen` under the chapter id, each
  taking **no request body** and returning 014's chapter response. `200` each.
- **Six new rows on the module's existing reason→status map**: not-open, not-closed,
  another-chapter-open and stale-version → **`409`**; archived and proposal-mode → **`403`**. 014's
  three existing rows are unchanged.
- Every handler wraps its single service call in the two-`except` idiom the module already uses: the
  authorization error first, mapped by the existing shared helper; then the chapter error, mapped by
  this module's existing helper.
- Response models are the **return annotation**; the `{book_id}` path parameter is consumed entirely by
  `Depends(book_access)` and is not re-declared.

**Declaration order.** All five paths carry a literal segment after `/{chapter_id}`, so none of them
collides with 014's parameterised `/{chapter_id}` handlers, and 014's `/order` rule is untouched. Keep
the new handlers grouped after 014's, in the order body-read, body-save, open, close, reopen, so the
module reads as skeleton-then-writing.

## Definition of done

1. `[test]` `GET` on the body path returns `200` with the chapter's text, state, version and its id as
   a string; a book whose state is `archived` still serves it — **D10**.
2. `[test]` `PUT` on the body path with the current version returns `200` and the new body, and a
   following `GET` returns the same text with the version incremented by one — **US-040.AC-1**,
   **UC-038**.
3. `[test]` `PUT` carrying a stale version returns **`409`** and a following `GET` shows the body
   unchanged — **US-041.AC-1**, **UC-039**.
4. `[test]` After that `409`, a `PUT` carrying a body with **both** members' text and the **current**
   version returns `200` and that body is what a following `GET` returns — **US-041.AC-2**,
   **US-040.AC-4**.
5. `[test]` `PUT` on a chapter that is `planned`, `closing` or `closed` returns **`409`** and the body
   is unchanged — **US-040.AC-3**, and the "no longer editable" half of **US-038.AC-1**.
6. `[test]` A **co-author** `PUT` in a free-mode book returns `200`; the same call in a
   **proposal**-mode book returns **`403`** with a reason naming FEAT-010, while the **owner**'s
   returns `200` — **D11**.
7. `[test]` `PUT` and all three transitions return **`403`** on a book whose state is `archived` —
   **D10**.
8. `[test]` `POST /open` as the **owner** on a `planned` chapter returns `200` with state `open` —
   **US-036.AC-1**; as a **co-author** it returns **`403`** and the state is unchanged —
   **US-036.AC-2**.
9. `[test]` `POST /open` while another chapter is `open` or `closing` returns **`409`** and both
   chapters keep their states — **US-037.AC-2**, **US-038.AC-4**.
10. `[test]` `POST /close` as the **owner** on the `open` chapter returns `200` with state **`closed`**
    — **US-038.AC-1**; as a **co-author** it returns **`403`** — **US-038.AC-2**.
11. `[test]` `POST /reopen` as the **owner** on a `closed` chapter with nothing else open returns `200`
    with state `open` — **US-039.AC-1**; with a different chapter `open` it returns **`409`** and that
    chapter is unaffected — **US-039.AC-2**.
12. `[test]` `POST /reopen` on a chapter that is not `closed`, and `POST /close` on a chapter that is
    not `open`, both return **`409`**.
13. `[test]` A logged-in non-member of a **public** book gets `403` from the body `PUT` and from all
    three transitions, and `200` from the body `GET`.
14. `[test]` A user with no relationship to a **private** book gets `404` from all five routes —
    existence hiding, inherited from the dependency, not re-derived.
15. `[test]` A request with no token gets `401` from all five routes.
16. `[test]` Addressing a chapter id that belongs to **another book** returns `404` — not `403`, not
    `200` — on all five routes.
17. `[test]` A malformed body on the body `PUT` (missing text, missing version, wrong type) returns
    `422` and nothing is stored; the three transitions accept a request with **no body at all**.

## Dependencies

- **001** — the body DTOs, the two capabilities and the read/save service.
- **002** — the three transition entry points and their two reasons.
- **014** — the router, its prefix, its `_map_*_error` helper and its existing status map.

# 005 — The `@mantine/tiptap` dependency set and the `ChapterBodyEditor` component

## Goal

Add the rich-text editor dependency set at the majors `@mantine/tiptap` actually declares, and build
the one component that turns Markdown into an editable document and back — the frozen prop seam every
later chapter step binds to.

## Source files

```
frontend/package.json
frontend/src/work/components/chapter/ChapterBodyEditor.tsx
```

## Test files

```
frontend/tests/work/ChapterBodyEditor.test.tsx
```

## Interface intent

**`frontend/package.json`** — add the editor dependency set: `@mantine/tiptap`, the TipTap React
packages it requires (its React binding, its ProseMirror bundle and a starter extension set), and
**`tiptap-markdown`** for serialize/parse.

**The versions are not stated here on purpose.** `@mantine/tiptap` at the Mantine major already in this
file declares a peer range for TipTap; **read that range and pin inside it**, and pin `tiptap-markdown`
to a release that targets the same TipTap major. DoD-1 makes this a checked criterion rather than an
assumption. Nothing else in `package.json` changes — no script, no dev dependency, no engine field.

**`frontend/src/work/components/chapter/ChapterBodyEditor.tsx`** (new) — one `observer` component and
nothing else. It is a **leaf**: it owns no page state, runs no `useEffect`, performs no HTTP, and knows
nothing about chapters, books, saving or the assistant.

Its props are the seam steps 006, 007 and 012 mock, so they are deliberately small:

- **the initial Markdown** — read **once, at mount**. The component never watches it for changes;
  external writes remount the component instead (`context.md` → **D15**), which is the page's job, not
  this component's.
- **a change callback** — invoked with the document serialized back to **Markdown** whenever the
  author edits. Not HTML, not JSON: the page stores Markdown and the server stores Markdown.
- **a selection-change callback** — invoked with the currently selected text, and with an empty
  selection expressed as such, whenever the selection moves. This is what feeds `context.md` → D5.
- **an accessible label** — so the editable region is reachable by role/label in tests and by a screen
  reader in life. Queries are by role or label only; an unlabelled editor is untestable here.

It renders Mantine's `RichTextEditor` over a TipTap instance built with the library's own hook,
configured with the starter extension set plus the Markdown extension, and a small formatting toolbar
using Mantine's own control components. **Consuming a library's hook is not a breach of the
no-custom-`useX` rule** — the rule forbids authoring hooks; 014 recorded the same reading for
`@dnd-kit`.

**The component imports `@mantine/tiptap`'s stylesheet itself**, rather than the entry's `main.tsx`
importing it. The style then ships with the only bundle that uses it, and no unharvested entry file
enters this feature's scope.

**It has no read-only mode.** A read-only chapter body renders through `react-markdown` on the page
(`context.md` → **D16**), so this component is mounted only when the body is editable and never has an
`editable` flag to toggle.

## Definition of done

1. `[manual/live]` The installed TipTap major matches the peer range `@mantine/tiptap` declares for the
   Mantine version in `frontend/package.json`, and `tiptap-markdown` targets that same major — verified
   by reading the declared ranges, not assumed. `cd frontend && npm run build` passes.
2. `[test]` The component mounts and exposes an editable region reachable by its accessible label,
   containing the initial Markdown's rendered content.
3. `[test]` The formatting toolbar renders its controls with accessible names, so a later surface can
   assert against them by role.
4. `[test]` The component runs no network call and holds no state beyond the editor instance — mounting
   it with a stub change callback triggers neither.
5. `[manual/live]` Typing into the editor invokes the change callback with **Markdown**, not HTML or
   JSON, and the emitted string round-trips: feeding it back as the initial Markdown produces the same
   rendered document.
6. `[manual/live]` Selecting text invokes the selection callback with the selected text, and clearing
   the selection invokes it with an empty selection.
7. `[manual/live]` The editor inherits the app theme (dark by default) with no local styling beyond the
   library's own stylesheet — no CSS module, no styled-component, no Tailwind.
8. `[manual/live]` `cd frontend && npm run test:types` passes.

## Dependencies

None. This step is independent of the backend and of 014; only its consumers (006 onward) depend on it.

# 007 — step context

Feature-wide facts (D1, D15, the restore-buffer facts, the mock-the-editor testing decision, the build
gates) are in `context.md` and are not repeated here.

## `restoreBuffer.ts` is consumed, never modified

Harvested and complete: `restoreBufferKey(bookId, subjectKind, subjectId)`, `readBuffer(key)`,
`writeBuffer(key, draft, baseVersion)`, `clearBuffer(key)`; `BufferBaseVersion = number | string`;
`WriteResult` is `saved` / `saved-after-eviction` (with `evictedKeys`) / `failed`. Reads are **total** —
an absent, non-JSON or wrong-shaped entry returns `null` rather than throwing.

`frontend/src/work/restoreBuffer.ts` is in **no** step's source list. If the chapter needs something it
does not offer, that is a blocker to route back, not a local widening — `frontend-work-drafts.md` says
015 "adopts this tier rather than extending it".

**This is the buffer's declared reason for existing.** `frontend-work-drafts.md` → "Out of scope":
*"Chapter bodies. The buffer's design covers them (`BufferBaseVersion` carries the numeric
`Chapter.version` for exactly this reason)."* The number branch of that union has had no writer until
now.

## The principal-text-field rule already answers "what gets buffered"

`frontend-work-drafts.md`: *"A multi-field subject buffers its principal text field."* The chapter page
has three editable regions — the body, the sketch, and the caller's own prompt — and buffers **only the
body**. The sketch is `planned`-only and last-write-wins with no version token (014's D6), and the
prompt row has exactly one writer; 014 explicitly excluded both from the buffer. Do not widen
`BufferedDraft` to a multi-field shape.

Consequence, accepted and already sanctioned: an unsaved **sketch** is lost on an unload, and the
divergence view **compares bodies only**.

## Both entrances, and which one is load-bearing

`frontend-work-drafts.md` → "Two entrances, not one": *"The load-time entrance is the load-bearing one.
Entrance 1 protects the author who tries to save; entrance 2 protects the author who simply comes back
to the page, which is the far commoner case and the one a save-centred design misses."*

DoD-5 is that entrance. It must assert that **no save call was made** — the whole point is that the
mismatch is detected before anything is attempted.

## The resolution takes one side whole — copy codex's exact sequencing

`013.codex`'s realization, harvested: *"Keeping the server version clears the buffer and reseeds from
the server's entry; keeping the draft adopts the server's entry **first** — so `baseVersion` becomes the
server's new `modified_at` — leaves the view, and re-saves."*

The chapter equivalent replaces `modified_at` with `version`. The ordering matters: adopting the
server's version **before** re-saving is what makes the second save non-stale. Getting it backwards
produces an infinite 409 loop that looks like a server bug.

`resolveCodexConflict(state, side, signal?)` is the signature shape to mirror.

## The divergence view's tone is a design requirement, not a preference

`frontend-work-drafts.md`: *"The divergence view is the normal landing for the navigated-away-mid-turn
path, not an edge case. Anything that treats the divergence view as a rare error condition (a scary
color, a modal, a log line) is mis-sized for how often it will be seen."*

That is DoD-11. It is also why step 012's canvas fallback (a buffered assistant draft with an inherited
or empty base version) reads as stale on return **by construction** — the author lands here on the
ordinary path, not on a failure.

## No LLM-assisted merge, no diff algorithm

`frontend-work-drafts.md`: reconciliation takes one side whole; an LLM-assisted merge is a **Stage-5**
capability and is not this feature's. Render the two bodies **side by side and readable** — no diff
library, no character-level highlighting, no third merged pane. `domain-chapter.md`: *"There is no
automatic merge at MVP — no rebase, no three-way reconcile, no heuristic re-anchoring."*

## Testing

`frontend/tests/work/ChapterPageReconcile.test.tsx` is created from scratch. Same two module mocks as
step 006 (the whole `api/chapters` module and the `ChapterBodyEditor` component), plus real access to
`restoreBuffer.ts` — **the buffer is not mocked**; jsdom provides `localStorage` and the buffer's own
unit behaviour is already covered elsewhere. Clear it between tests.

`ApiError` is imported real; DoD-6 needs a genuine `409`.

DoD-10 needs a `writeBuffer` that reports an eviction. Fill `localStorage` with oversized sibling
entries rather than stubbing the module, so the assertion exercises the real eviction policy — including
that the current key is never the victim.

DoD-2 and DoD-5 need the buffer seeded **before** the page mounts, with a base version that matches and
one that does not.

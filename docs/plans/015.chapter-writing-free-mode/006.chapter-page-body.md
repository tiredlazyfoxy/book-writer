# 006 — The chapter page's body region: load, edit, save

## Goal

Give `ChapterPage` a third trio for the chapter body, a Markdown draft, and an explicit save carrying
the loaded version — with the editor mounted only for the `open` chapter and the body rendered
read-only otherwise.

## Interface intent

**`frontend/src/work/pages/chapterPageState.ts`** — extends 014's `ChapterPageState`. Its chapter trio,
its prompt trio, its sketch editor state and their external effects are untouched.

- **A third async trio** for the chapter body, holding the body response. It loads and fails
  **independently** of the other two.
- **Body draft state** — the Markdown draft, a save status, a `…ServerErrors` map, and the **base
  version** the draft was composed against, taken from the body response and from nowhere else. There
  is **no `clientErrors` and no `errors` union**: every string, `""` included, is a valid body
  (`context.md` → the form-state shape).
- **An editor generation counter** — a plain observable number the view keys the editor on. It is
  bumped by every **external** draft write and never by a keystroke (`context.md` → **D15**). This step
  bumps it in exactly one place, when the body loads and seeds the draft; steps 007 and 012 bump it
  from theirs.
- **Pure `get` computeds** — whether the body draft differs from the loaded body; whether the body is
  editable at all (true only when the loaded body response's state is `open`); whether a save may be
  issued right now.
- **External effect functions** `(state, bookId, chapterId, …, signal?)` using `runInAction`:
  - **load the body** — fetch it, seed the draft and the base version from the response, bump the
    generation counter;
  - **edit the body draft** — the single entry point every draft change goes through, so that steps 007
    and 012 have one place to hook. A keystroke does **not** bump the generation counter;
  - **save the body** — send the draft with the **loaded base version**, then re-seed the draft, the
    base version and the trio **from the response**; a refused save stores the server's message and
    **leaves the draft intact**. A `409` is recognised and left in a state step 007 takes over — this
    step surfaces it as a refusal like any other and adds no reconciliation.

**`frontend/src/work/pages/ChapterPage.tsx`** — extends 014's page component. Its existing sections,
its `useState` instance and its single mount `useEffect` are kept; the effect starts the third load and
aborts it on unmount alongside the other two.

It gains **one body section**, rendered as:

- the body trio's loading and error branches;
- when the chapter is **`open`**: the `ChapterBodyEditor` from step 005, keyed on the generation
  counter, given the draft as its initial Markdown and wired to the draft-edit effect; plus a save
  control gated on the computed and a server-error surface;
- when the chapter is **not `open`**: the body rendered with `react-markdown`, read-only, with the
  author-facing reason from `resolveEditability` and **no save control** (`context.md` → **D16**).

The chapter's `sketch` and prompt sections keep the behaviour 014 gives them.

## Definition of done

1. `[test]` On mount the page loads the chapter body and shows it; the body trio loads and fails
   **independently** of the chapter trio and the prompt trio, in both directions.
2. `[test]` On an **`open`** chapter the editor is mounted, seeded with the stored body, and a save
   control is present.
3. `[test]` Saving sends the draft together with the **version the body response carried**, and the
   surface afterwards shows the text the **server returned**, not the local draft — **US-040.AC-1**.
4. `[test]` After a successful save the base version the next save would send is the **new** version
   from the response, so two sequential saves both succeed.
5. `[test]` The save control is unavailable while the draft matches the loaded body and while a save is
   in flight; saving an **empty** body is allowed.
6. `[test]` Nothing reaches the server until the save control is used — editing the body issues no
   write call.
7. `[test]` A refused save surfaces the server's message and leaves the draft **intact** — including a
   `403` carrying the proposal-mode refusal that names FEAT-010, and a `403` carrying the archived-book
   refusal — **D10**, **D11**.
8. `[test]` On a chapter that is `planned`, `closing` or `closed` the body renders **read-only** with a
   stated reason and offers **no** save control and **no** editor — **US-038.AC-1**'s "no longer
   editable" half, client affordance.
9. `[test]` A `409` from the save leaves the stored body untouched on screen and surfaces a refusal
   rather than silently overwriting anything — **US-041.AC-1**, client half. (Step 007 turns this into
   the divergence view.)
10. `[test]` The editor's generation counter changes when the body loads and does **not** change on a
    keystroke — **D15**.
11. `[manual/live]` `cd frontend && npm run build`, `cd frontend && npm test` and
    `cd frontend && npm run test:types` all pass.

# 011 — The working page's module tier learns about chapters

## Goal

Widen the pane model so an `open` chapter is editable in its body, generalize the canvas dispatcher off
its hardcoded codex key, add a selection registry beside the subject registry, add the fourth
module-tier member — an in-memory undo stack for assistant writes — and mirror the frame's new
operation field in the frontend DTO.

*The dispatcher, selection, undo and DTO halves have no product id (FEAT-013 / UC-055, parked); the
editability half is `frontend-workspace.md`'s content-pane rule.*

## Interface intent

**`frontend/src/types/chats.d.ts`** — the **frame** twin only. `CanvasFrame` (`:191-196`) gains the
optional operation field step 009 added to the backend model, with the same three values and the same
replace default. **`CanvasField` (`:172`) is not touched** — a chapter's body is the `"body"` field
(`context.md` → D17). The `TurnRequest` twin at `:159-164` and the frontend-only `TurnSubject` helper at
`:144-148` are **step 012's** and are not touched here.

**`frontend/src/work/subject.ts`** — amend `resolveEditability`'s `"chapter"` branch and nothing else in
the file.

After 014, that branch answers by **region**: a `planned` chapter is editable in its sketch and in the
caller's own prompt and read-only in its body; `open` is editable; `closing` and `closed` are read-only
with their own author-facing reasons.

This step makes the **`open`** case explicit in the same region vocabulary: the chapter's **body text**
is editable (and the caller's own prompt stays editable, as it is in every state); the **sketch is not**
— UC-033 confines sketch edits to `planned`, which is the exact opposite window from the body.
`closing`, `closed` and `planned` keep the answers 014 gives them, and their reason strings are author-
facing copy that must be preserved verbatim.

`checkWritePermission` must **allow** a body write on an `open` chapter and keep refusing one on
`planned`, `closing` and `closed` — the assistant and the author are refused by the same rule
(`frontend-workspace.md`).

**`frontend/src/work/contentSubject.ts`** — three changes, none of which may cost the codex path a line.

- **The registered apply-draft callback's type widens by one optional parameter** — the frame's
  operation. A two-parameter implementation is assignable to a three-parameter type, so
  **`CodexEntryPage`'s existing applier satisfies the widened type unchanged** (`context.md` → D17).
- **A selection registry beside the subject registry** — a setter the open page calls whenever the
  author's selection moves, and a reader the chat pane calls at send time. Same ownership discipline as
  the subject registry: newest registration wins, and a clear only takes effect when the caller is still
  the registered owner, so a late unmount from a superseded page is a no-op. Unregistering the subject
  clears the selection too.
- **`dispatchCanvasFrame` stops assuming codex.** It routes on the frame's own `subject_kind`:
  - a **registered target matching the frame's subject** receives the text, the field and the operation;
  - **no registered target** and the operation is replace → the text is written into the restore buffer
    under `restoreBufferKey(bookId, frame.subject_kind, frame.subject_id)`, inheriting whatever base
    version already sits at that key and the empty string when there is none. **This is the one
    hardcoded thing that has to change** — the key's `"codex-entry"` literal becomes the frame's own
    kind. The existing `"body"`-field condition **stays as it is**: a chapter's body is also the
    `"body"` field, so it needs no widening;
  - **no registered target** and the operation is append or replace-selection → **dropped and logged**
    (`context.md` → **D18**): both are relative to a draft this module does not have;
  - a frame naming **no subject at all** with no registered target stays dropped, as today.

**`frontend/src/work/chapterUndo.ts`** (new) — the tier's **fourth** member, sanctioned deliberately
(`context.md` → **D6**; `frontend-work-drafts.md` requires the sanction). Plain module functions, not a
reactive store, matching its three siblings.

- Push a body snapshot for a `(book, chapter)` pair, keeping at most **20**, dropping the oldest.
- Pop the most recent snapshot for a pair, or nothing when the stack is empty.
- Report the depth for a pair, so a control can enable itself.
- Clear a pair's stack.
- **In memory only** — nothing is written to `localStorage`, nothing survives a reload. Stacks for
  different `(book, chapter)` pairs are independent, and the module survives page navigation because it
  is module-level, which is the point.

## Definition of done

1. `[test]` `resolveEditability` reports an **`open`** chapter as editable in its **body text**; the
   `planned`, `closing` and `closed` answers 014 gives — including their author-facing reason strings —
   are unchanged.
2. `[test]` `resolveEditability` does **not** report an `open` chapter's **sketch** as editable —
   UC-033's window is `planned` only.
3. `[test]` `checkWritePermission` allows a body write on an `open` chapter and refuses one on
   `planned`, `closing` and `closed`.
4. `[test]` A canvas frame for a chapter with a **matching registered target** is delivered to that
   target's applier with its text, its field and its operation.
5. `[test]` A canvas frame whose subject does **not** match the registered target is not delivered to
   it.
6. `[test]` A **codex** frame still behaves exactly as it does today — delivered to a matching registered
   target, and buffered under the `"codex-entry"` key when there is none — and an applier taking only
   two parameters still satisfies the registry.
7. `[test]` A chapter frame with the **replace** operation and no registered target is written to the
   restore buffer under the **chapter's** key, inheriting the base version already at that key and the
   empty string when there is none — **D18**.
8. `[test]` A chapter frame with the **append** or **replace-selection** operation and no registered
   target is **dropped**: nothing is written to any buffer key — **D18**.
9. `[test]` The selection registry returns what the current owner set, returns nothing after that owner
   unregisters, and ignores a clear from a superseded owner.
10. `[test]` The undo stack keeps at most 20 snapshots per `(book, chapter)`, dropping the oldest;
    popping returns them most-recent-first and returns nothing when empty.
11. `[test]` Undo stacks for different chapters and different books are independent, and nothing the
    module holds is written to `localStorage`.
12. `[test]` The frontend `CanvasFrame` DTO carries the operation field with the same three values and
    the same replace default as the backend model, and `CanvasField` still admits exactly `"name"` and
    `"body"`.
13. `[manual/live]` `cd frontend && npm run build` and `cd frontend && npm run test:types` pass, and
    `frontend/src/work/pages/CodexEntryPage.tsx` and `codexEntryPageState.ts` were **not modified** by
    this step.

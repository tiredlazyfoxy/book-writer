# 006 — step context

Feature-wide facts (D13, D14, D15, D16, the form-state shape, the MobX rules, the mock-the-editor
testing decision, the build gates) are in `context.md` and are not repeated here.

## The page already has two trios; this makes three

014 step 008 ships `ChapterPageState` with a chapter trio and a chapter-prompt trio, a sketch editor
(draft + `…ServerErrors` + submit status + computeds) and external effects
`(state, bookId, chapterId, signal?)`. `frontend.md` is explicit that a page with three loadables has
**three trios and no aggregation type** — do not introduce one.

Do not fold the body into the chapter trio. They come from **different endpoints** (`context.md` → D13)
and must fail independently — DoD-1 pins it in both directions.

## Where the version comes from, and why only from there

The chapter response (014's) also carries a `version`. **Ignore it for the save.** The base version is
the one the **body response** carried, because the body and its version arrive together and a save
composed against a version that came with a different payload is exactly the stale-write bug the
contract exists to prevent. One field, one source. Step 007's buffer records the same value.

## `codexEntryPageState.ts` is the template, with two deliberate differences

Harvested shape to copy: the async trio, a **separate** `saveStatus` / `saveError` beside the trio's
own status, a bound `applyDraft` **excluded from `makeAutoObservable`**, `evictedBufferKeys`, and
external effects `loadCodexEntry` / `editCodexDraft` / `saveCodexEntry` / `discardCodexDraft` /
`resolveCodexConflict(state, side, signal?)`.

Two differences:

- the base version is a **number** (`Chapter.version`), not a `modified_at` ISO string;
- the page is **not** a create surface — there is no blank-chapter path, no `/new` route and no
  post-save navigation. A chapter body always has a row behind it.

`conflictEntry` / `isReconciling` / `resolveCodexConflict`'s equivalents and `applyDraft` are **step
007's and step 012's**, not this step's. Leave the hooks where they naturally fall — a single
draft-edit effect every change routes through — but ship no reconciliation and no canvas wiring here.

## Why the editor is keyed and the read-only branch is a different component

`context.md` → D15 and D16. Two consequences for this file:

- the view reads the generation counter **only** to build the editor's `key`. It is not rendered, not
  compared, and not persisted;
- `react-markdown` is already a dependency and already the repo's markdown renderer, used with **no
  plugins configured** (`frontend.md`). Inherit that default; do not add a plugin here.

`resolveEditability`'s author-facing read-only reason is the copy for DoD-8. 014 step 008 preserves the
`closing` and `closed` reasons verbatim and keeps the `planned` one for the body; step 011 of this
feature widens the `open` case. This step **consumes** `subject.ts` and does not modify it —
`frontend/src/work/subject.ts` is **not** in this step's source list.

## The 409 is deliberately half-built here

DoD-9 asserts only that a `409` refuses visibly and overwrites nothing. The divergence view, the
re-fetch of the server's body and the take-one-side resolution are **step 007's**. Splitting them keeps
both steps inside the size budget and keeps this step's spec free of buffer state.

Do not pre-build a `conflict` field here and leave it unused; step 007 adds it with its consumer.

## Testing

`frontend/tests/work/ChapterPageBody.test.tsx` is created from scratch, beside 014's
`frontend/tests/work/ChapterPage.test.tsx`. **Do not modify 014's spec.**

Two module mocks are needed:

- `vi.mock("../../src/api/chapters", () => ({ … }))` enumerating **every** export the page imports,
  including 014's skeleton and prompt functions the body region never calls — a missing export strips
  the mock and the page fails for the wrong reason;
- `vi.mock` over `../../src/work/components/chapter/ChapterBodyEditor`, substituting a stub that renders
  a labelled control and calls the change callback with a string. This is the decision recorded in
  `context.md`; ProseMirror is not driven in jsdom.

`ApiError` is imported real from `../../src/api/client`; DoD-7 and DoD-9 both need real `403` and `409`
instances carrying a server message.

Render through a local `renderPage(route)` wrapper with a
`<Routes><Route path="/:bookId/chapter/:id" …/></Routes>` shim so the page receives both path params.

Queries are by **role or label only**. The save control, the read-only reason and the server-error
surface must therefore all be readable text or accessibly-named controls.

DoD-1 needs the three api calls armed independently — one rejecting while the others resolve, in each
direction.

DoD-10 needs the generation counter observable from the spec; the simplest honest assertion is that the
stubbed editor **remounts** (its initial-Markdown prop is re-read) on load and does **not** remount on a
keystroke. Bind to the observable behaviour, not to the counter's name.

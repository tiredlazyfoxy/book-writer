# Step 005 — Frontend login form + protected-route gates

## Goal
Replace the login entry's "proceed to login" placeholder with the real login
form (when the instance is configured), migrate create-token storage to the
pair, and add the mount-time token gate the 002 scaffold deferred to both SPAs.

## Source files
frontend/login/loginState.ts
frontend/login/Login.tsx
frontend/src/user/App.tsx
frontend/src/admin/App.tsx

## Test files
_None — no frontend test runner is configured (root `CLAUDE.md`; 002 decision 5).
All DoD items are `[manual/live]`._

## Interface intent
The login entry keeps its exemption (no React Router / no `<Page>State`) but
binds the rest of the MobX rules (`observer`, `<Component>State` class,
external `(state, args, signal)` effect fns, no Mantine `useForm`) — see
`context.md` and 003 decision 9.

- **`login/loginState.ts`** (amend) — add the login-form slice to the existing
  `LoginState`:
  - observable fields: login drafts (`loginUsername`, `loginPassword`) and a
    login submit status trio (`loginStatus: 'idle'|'loading'|'ready'|'error'` /
    `loginError`);
  - pure `get` computeds: `canSubmitLogin` (both fields non-empty);
  - external **handleLogin(state, signal)** — calls `authApi.login(...)`; on
    success stores **both** tokens via the `auth.ts` pair setter then navigates
    to `/` (`window.location.href`); on `ApiError` records the generic refusal
    into the login trio (no navigation);
  - **migrate `submitCreate`** — the create flow already stored a single token
    via `setToken`; update it to store the `TokenResponse` pair (step 004's
    `auth.ts` pair setter). This is the 003→004 create-path amendment.
- **`login/Login.tsx`** (amend) — when `needs_setup === false`, render the real
  **login form** (username + password bound to `loginState`, submit disabled
  until `canSubmitLogin`, server/refusal error surfaced) instead of the 003
  "instance configured — proceed to login" placeholder; the submit handler is an
  inner function calling `handleLogin`. The `needs_setup === true` first-run
  wizard (003) is unchanged. `observer`-wrapped; no plain-`useState` fields; no
  Mantine `useForm`.
- **`src/user/App.tsx`** (amend) — add a mount-time gate: if there is no token
  (`getToken()` is null), redirect to `/login/` via `window.location.href`
  before rendering the SPA. This is the gate 002 deferred.
- **`src/admin/App.tsx`** (amend) — the same mount-time token gate for the Admin
  SPA.

## Definition of done
1. `[manual/live]` `US-003.AC-1` — on a configured instance (`npm run dev`),
   submitting valid credentials in the login form authenticates and lands the
   user in the SPA at `/` (both tokens stored).
2. `[manual/live]` `US-003.AC-2` — submitting invalid credentials surfaces the
   generic refusal and does not navigate (no session).
3. `[manual/live]` `US-004.AC-1` — invoking `logout()` (from the SPA) returns the
   browser to `/login/` and blocks the SPA (client side of log-out).
4. `[manual/live]` `US-004.AC-1` — loading a protected SPA (`/` or `/admin`) with
   no token redirects to `/login/` on mount (further access requires
   authentication).
5. `[manual/live]` `cd frontend && npm run build` (tsc + vite) is clean; the
   login form and SPAs honor the conventions — `observer`-wrapped, a
   `<Component>State` class with observable fields + `get` computeds only,
   external `(state, args, signal)` effect fns, **no** Mantine `useForm`,
   navigation via `window.location.href` — confirmable by inspection.

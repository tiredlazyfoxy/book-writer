## Route → service wiring (thin routes)
- `POST /login` → `auth_service.authenticate_user(username, password)` → then
  `auth_service.create_access_token` + `create_refresh_token` → `TokenResponse`.
- `POST /refresh` → `auth_service.refresh_access_token(refresh_token)` → new
  access → `TokenResponse(access_token=new, refresh_token=<incoming>)`.
- `GET /me` → `Depends(auth_service.get_current_user)` → `MeResponse` from the
  `User`.
All auth business logic is in the service (steps 001–002). The route only maps
`AuthError` → `HTTPException(401, <generic message>)` and shapes responses.
Import services as `from app.services import auth as auth_service` (namespace
style, `backend.md`). The router already owns `prefix="/api/auth"`; do not
re-mount it (mounted by 003 in `main.py`).

## Test harness reminders
In-process `httpx.AsyncClient` over `ASGITransport` with the temp-SQLite
`DbConfig` fixture and `http_client` fixture (001/002 harness). Tests that need a
logged-in user create one via the db/service layer (a `User` with a bcrypt
`pwdhash` and a signing key) then exercise the endpoints. The expired-access and
disabled-user cases mint/craft tokens the same way step 001's tests do
(PyJWT-crafted expired token; a user with `pwdhash` set to `None`). The
rate-limit case must reset `rate_limit` state between tests (see step 002 note).

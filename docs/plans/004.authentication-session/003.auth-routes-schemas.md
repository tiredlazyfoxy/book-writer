# Step 003 — Auth routes + schemas (HTTP surface)

## Goal
Expose the thin HTTP surface — `login`, `refresh`, `me` under `/api/auth` — with
typed schemas and a single `AuthError`→401 mapping, and re-point 003's
`setup/create` to the new token pair.

backend/app/routes/auth.py
backend/app/models/schemas/auth.py

## Test files

backend/tests/routes/test_setup.py

## Interface intent
Routes are HTTP-only (parse → call one service fn → map error → return schema),
per decision 4. Token shapes/echo rules are in `context.md` → "Token model".

- **`TokenResponse`** (in `models/schemas/auth.py`) — a Pydantic response schema
  carrying `access_token` and `refresh_token` (both non-empty JWT strings).
  Replaces 003's `LoginResponse{token}`.
- **`RefreshRequest`** (in `models/schemas/auth.py`) — request schema carrying
  `refresh_token`.
- **`MeResponse`** (in `models/schemas/auth.py`) — response schema carrying `id`,
  `username`, `role`.
- **`POST /api/auth/login`** (in `routes/auth.py`) — body `LoginRequest`
  (`username`, `password`); calls `authenticate_user`, then mints
  `create_access_token(user)` + `create_refresh_token(user)`, returns
  `TokenResponse`. `AuthError` → **401** with the single generic message. (Add
  `LoginRequest` to `models/schemas/auth.py` if 003 did not — it is the
  login body.)
- **`POST /api/auth/refresh`** (in `routes/auth.py`) — body `RefreshRequest`;
  calls `refresh_access_token(refresh_token)`, returns `TokenResponse` with the
  new `access_token` and the **incoming** `refresh_token` echoed. `AuthError` →
  **401**.
- **`GET /api/auth/me`** (in `routes/auth.py`) — behind
  `Depends(get_current_user)`; returns `MeResponse` built from the resolved
  `User`. Missing/expired/invalid access token → **401** (from the dependency).
- **`POST /api/auth/setup/create`** (amend) — its handler now mints
  `create_access_token(admin)` + `create_refresh_token(admin)` and returns
  `TokenResponse` instead of `LoginResponse{token}`; the auto-sign-in yields the
  token pair. `SetupError`→400 mapping (from 003) is unchanged.
- Retire **`LoginResponse`** from `models/schemas/auth.py` once no route
  references it. `AuthStatusResponse` / `CreateDBRequest` are unchanged.

## Definition of done
1. `[test]` `US-003.AC-1` — `POST /api/auth/login` with valid credentials → HTTP
   200 and a `TokenResponse` carrying non-empty `access_token` and
   `refresh_token`.
2. `[test]` `US-003.AC-2` — `POST /api/auth/login` with invalid credentials →
   HTTP 401 and no tokens in the body.
3. `[test]` `US-003.AC-3` — after the rate-limit threshold is exceeded,
   `POST /api/auth/login` is refused with HTTP 401 **even with valid
   credentials**, and with the same generic message as bad creds.
4. `[test]` `US-003.AC-1` — `GET /api/auth/me` with a valid access token → HTTP
   200 and a `MeResponse` carrying the caller's `id`, `username`, `role`.
5. `[test]` `US-004.AC-2` — `GET /api/auth/me` with an **expired** access token →
   HTTP 401 (re-authentication required).
6. `[test]` `US-004.AC-1` — `GET /api/auth/me` with **no** `Authorization` header
   → HTTP 401 (a logged-out client's requests require re-auth).
7. `[test]` `US-003.AC-1` — `POST /api/auth/refresh` with a valid refresh token →
   HTTP 200 and a `TokenResponse` with a fresh `access_token` (session renewed).
8. `[test]` `US-004.AC-1` — `POST /api/auth/refresh` for a **disabled** user →
   HTTP 401.
9. `[test]` `US-001.AC-1` — `POST /api/auth/setup/create` with valid credentials
   now returns HTTP 200 and a `TokenResponse` (both `access_token` and
   `refresh_token` present) — the auto-sign-in yields the token pair.
   (Cross-feature amendment to 003.)

## Import-cycle avoidance for the interceptor
`api/auth.ts` imports `client.ts`. If `client.ts` imported `api/auth.ts` for
refresh, that is a cycle. `frontend.md` allows `fetch` **inside `client.ts`**, so
the interceptor performs its refresh with a direct `fetch` to `/api/auth/refresh`
using `getRefreshToken()` (read from `auth.ts`, which `client.ts` already
imports). `api/auth.refresh()` still exists as the public function; the
interceptor does not call it. Dependency direction stays one-way:
`api/ → auth.ts`, `auth.ts` imports nothing from `api/`.

## Backend contract consumed (from step 003)
- `POST /api/auth/login` `{username,password}` → `TokenResponse{access_token,
  refresh_token}` (200) / 401 generic refusal.
- `POST /api/auth/refresh` `{refresh_token}` → `TokenResponse` (200) / 401.
- `GET /api/auth/me` (Bearer access) → `MeResponse{id,username,role}` / 401.
- `POST /api/auth/setup/create` → `TokenResponse` (200) — the amended 003 shape.
DTOs in `src/types/auth.d.ts` must match these 1:1.

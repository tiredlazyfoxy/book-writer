# Step 002 — step-specific context

Frozen design in `context.md`: D2 (bare-str backend_type validated in the service
against the module constant), D3 (`$ENV` resolver + masking), D5 (embedding
clear-all-then-set). The db surface (`get_by_id`/`get_all`/`get_active`/`create`/
`update`/`delete`/`clear_all_embedding`/`get_embedding_server`) is step 001's and is
consumed here.

Step-local notes:

- **Layer discipline:** this service must not import `session`/`AsyncSession` or use
  `select()`/`session.exec()`/`session.add()` — all persistence goes through
  `db.llm_servers` (namespace import `from app.db import llm_servers`). Import the
  secrets helper as `from app.services import secrets`.
- **The backend-type constant** (`{"llama-swap", "openai"}`) is a module-level
  constant in this service file (D2), not an enum, not in the schema. Frontend mirrors
  it as a TS union (step 005) — keep the two lists in agreement.
- **`enabled_models` is the JSON-string ⇄ `list[str]` boundary.** The db layer keeps
  the raw string; `set_enabled_models` does `json.dumps`; `_to_response` does the
  decode. Nowhere else decodes it.
- **`api_key` partial-update rule** (D-locked in the briefing): `None`/omitted →
  leave stored key unchanged; `""` → clear to `None`. This is the only place the
  distinction between "absent" and "empty" matters — the `UpdateLlmServerRequest`
  makes `api_key` optional so "absent" is representable.
- **`LlmServerError` case set** is shared with step 003 (which adds `probe-failed`)
  and step 004 (which maps every case to a status). Freeze the discriminator values
  here so the skeleton records them once: invalid-backend-type, missing-field,
  not-found, env-not-set, probe-failed.
- **`resolve_env_ref` is not called by this step's own functions** — it exists here
  so step 003's probe can call it at use time (D3 "resolution only at use time").
  This step only builds and unit-tests the resolver.
- **`EmbeddingConfigResponse`** carries `has_api_key` (masked), never the key.

Frozen design in `context.md`: D5 (route paths + the **static `/embedding` before
`/{server_id}` ordering rule**), D7 (admin gating, router wiring, error→status
taxonomy), D8 (probe-failed → 502).

Step-local notes:

- **Route ordering is load-bearing (D5):** FastAPI matches routes in declaration
  order, so `GET/DELETE "/embedding"` MUST be declared before `GET/PUT/DELETE
  "/{server_id}"`; otherwise `embedding` is captured as a `server_id`. The skeleton
  and coder must preserve this ordering — DoD-10 exercises it.
- **`require_role` and the caller `User`** come from `services/auth.py` (005).
  Import as `from app.services import auth as auth_service` and gate each endpoint
  with `Depends(auth_service.require_role(admin))` (the same pattern as 005's
  `routes/admin/users.py`). This feature does **not** thread the caller into the
  service (no self-guards here) — the guard alone provides gating.
- **Routes stay HTTP-only** — no business logic, no `session`/`select()`; each handler
  calls exactly one `services.llm_servers` function and maps `LlmServerError.case` to
  a status. The case→status map is D7: missing-field / invalid-backend-type /
  env-not-set → 400; not-found → 404; probe-failed → 502.
- **`main.py` is the composition root** (005 file) — add one
  `app.include_router(...)` for the new router next to the existing includes; no other
  change. `routes/admin/__init__.py` is 005's — touch it only if the admin package
  aggregates routers for mounting (otherwise leave it).
- **Test air-gap:** the probe endpoint tests monkeypatch `_create_client`
  (step 003's frozen seam) — same fake-client approach as step 003; no live server /
  network. The 502 assertion (DoD-9) comes from the fake raising `aiohttp.ClientError`.
- **US-010.AC-3 at HTTP level:** an *empty* required field is refused by the service
  as missing-field → 400 (deterministic). A truly-absent required field is a Pydantic
  422; the DoD asserts the service's 400 path via empty values.

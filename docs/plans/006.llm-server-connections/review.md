### R1 — LlmServer uses snowflake ids (mirror User)   [target: 001.model-db-importexport.md + 002/004/005/006 stack]
- Concern: `LlmServer.id` is a DB **autoincrement int** (`id: int | None = Field(default=None, primary_key=True)`), diverging from `User`'s **snowflake** PK and unsafe for cross-instance import (an autoincrement id like `7` can collide with an unrelated row on import into a different DB; `session.merge` would then silently overwrite it). This reverses the plan's locked **D1** (which chose autoincrement and flagged it for `/architect`). Aligning `LlmServer` to `User`'s existing snowflake standard removes the inconsistency.
- Files:
  - `backend/app/models/llm_server.py` — change PK to `id: int = Field(default_factory=generate_id, primary_key=True)`; add `from app.ids import generate_id` (mirror `models/user.py` exactly).
  - `backend/app/models/schemas/llm_servers.py` — `LlmServerResponse.id: str` (was `int`); `EmbeddingConfigResponse.server_id: str | None` (was `int | None`). **Wire type is `str`** because 64-bit snowflake ids exceed JS safe-integer range — this is exactly why `AdminUserResponse.id` is `str`.
  - `backend/app/services/llm_servers.py` — `_to_response` sets `id=str(server.id)`; `get_embedding_config` sets `server_id=str(server.id)` (mirror `admin.py::_to_response`, which does `id=str(user.id)`). Internal param types (`server_id: int`) stay `int`.
  - `backend/app/routes/admin/llm_servers.py` — **keep `server_id: int` path params** (FastAPI coerces the stringified id in the URL back to `int`, exactly as the users router does). Likely no change; confirm.
  - `backend/tests/{db,services,routes/admin}/…` — update assertions that expect an integer DTO `id` to expect the stringified id; tests seeding explicit ids (e.g. `id=7`) remain valid. The import/export codec already does `str(id)`/`int(raw_id)`, so codec tests are unaffected.
  - `frontend/src/types/llmServers.d.ts` — `LlmServer.id: string` (was `number`); `EmbeddingConfig.server_id: string | null`.
  - `frontend/src/api/llmServers.ts` — id params `string` (was `number`) on `updateServer`/`deleteServer`/`probeModels`/`setEnabledModels`/`setEmbedding`.
  - `frontend/src/admin/pages/llmServersPageState.ts` — `deleteServerAction(state, id: string, …)`.
  - `frontend/src/admin/pages/LlmServersPage.tsx` — modal targets hold whole `LlmServer` objects (transparent); handlers pass `server.id` (now string).
  - `frontend/src/admin/components/llm-servers/{serverFormDraft.ts,modelsModalDraft.ts,embeddingModalDraft.ts}` — `serverId: string` (was `number`) on `submitServerForm`/`probeModelsAction`/`submitEnabledModels`/`submitEmbedding`.
- Constraints: preserve observable behavior — register/edit/delete/probe/enable/embedding all still work end-to-end. **Mirror the `User` id pattern exactly**: snowflake `int` internally (model/db/service/route param types stay `int`), serialized as `str` only at the DTO edge and on the frontend. The import/export codec is already id-strategy-agnostic (`str(id)` / `int(raw_id)`) — **no codec change for this item**.
- Out of scope: `User`'s id handling (already snowflake); the internal `int` typing of db/service/route params; any broader system-wide id-strategy doc reconciliation (that remains an `/architect` finalization task).
- STATUS: DONE

### R2 — Export redacts raw-literal LLM api keys (keeps $ENV tokens)   [target: 001.model-db-importexport.md]
- Concern: the JSONL export writes `LlmServer.api_key` **verbatim in cleartext** (`"api_key": server.api_key`), bypassing the HTTP masking (`LlmServerResponse` exposes only `has_api_key`). A raw literal secret (e.g. `sk-...`) lands in the export file. This reverses the plan's locked **D6** (which chose verbatim export and flagged redaction for `/architect` / feature 007).
- Decision (user-selected): a `$ENV_VAR` token is a *pointer*, not a secret, so **keep `$`-prefixed tokens verbatim**; **replace a raw literal key with `null`**; `None` stays `None`. Scope is **`LlmServer.api_key` only** — `User.pwdhash` / `User.jwt_signing_key` continue to export as-is (needed so restored accounts can authenticate).
- Files:
  - `backend/app/services/db_import_export.py` — in `_llm_server_to_dict`, redact `api_key`: emit the value when it is `None` or starts with `$`; otherwise emit `None`. (Reuse the `$`-prefix distinction that `services/secrets.py::resolve_env_ref` already relies on — inline or a tiny helper; do **not** import the resolver into the codec if it risks a cycle.) `_dict_to_llm_server` is unchanged (`api_key=data.get("api_key")` — reads whatever survived: a `$ENV` token or `None`). Do **not** touch `_user_to_dict`/`_dict_to_user`.
  - `backend/tests/services/test_db_import_export_llm_servers.py` — invert `test_api_key_exported_verbatim_not_masked__DoD5`: assert a **raw literal** `api_key` is redacted to `None` on export, AND assert a **`$ENV` token** api_key is preserved verbatim. Update the all-fields round-trip test so its seeded `api_key` is a `$ENV` token (which survives) — or split it — so round-trip coverage stays intact.
- Constraints: preserve observable behavior for `$ENV`-token servers (they restore fully and can still probe); a raw-literal-key server restores with `api_key = None` (operator re-enters). This **intentionally supersedes** step-001 **DoD-5**'s "`api_key` preserved verbatim … not masked on export" clause and **D6** — coverage is not weakened (the inverted test still fully exercises the export codec's api_key handling, now asserting the *new* redaction policy plus `$ENV` preservation). User-credential export is unchanged.
- Out of scope: `User` credential redaction (`pwdhash`/`jwt_signing_key`); the deferred feature-007 two-mode (sanitized vs. backup) export system; `run_vector_rebuild()` (unrelated no-op stub).

# Step 003 — App factory, lifespan & health end-to-end

## Goal
Wire the FastAPI app singleton with logging, dotenv, and a startup lifespan (engine + DB + vector init), then prove the walking skeleton with a `GET /api/health` that flows routes → services → db → schema.

## Interface intent
- **`app`** (in `app/main.py`) — the module-level FastAPI application singleton. At import it runs `logging.basicConfig(level=DEBUG, ...)` and quiets noisy third-party loggers (aiosqlite, httpx, httpcore) to WARNING; modules use `logging.getLogger(__name__)`. It loads `.env.local` (dotenv / via `Settings`) and mounts routers with bare `app.include_router(...)` (each router owns its `/api/...` prefix).
- **lifespan** — an async startup/shutdown context on the app that, on startup, builds a `DbConfig` from `Settings` and calls `init_engine` → `init_db` → the vector init stub. **`init_db` runs `create_all` here** — this is the recorded seam that feature 003.first-run-bootstrap will later amend (see `context.md`). No teardown logic needed beyond what the engine requires.
- **health router** (in `routes/health.py`) — an `APIRouter` with `prefix="/api"` (or `/api/health` per the reference's per-router convention; see `003.context.md`) exposing `GET /api/health`. HTTP only: calls the health service and returns its result as the response model. No business logic, no DB access here.
- **health service** (in `services/health.py`) — orchestrates the readiness check by calling `db.health.ping()` and assembling the response data. No `session`/`select()` here.
- **`HealthResponse`** (in `models/schemas/health.py`) — a Pydantic `BaseModel` response schema: a `status` field (`"ok"`) and a `db` field (`"ready"`). The typed contract the route returns.
- **`http_client` fixture (extend `conftest.py`)** — wraps `app.main.app` in `httpx.ASGITransport` and yields an `httpx.AsyncClient(base_url="http://test")` — in-process, no network. Added alongside the existing temp-DB fixture from step 002.

## Definition of done
1. `[test]` `GET /api/health` returns HTTP 200 with body `{"status": "ok", "db": "ready"}`, exercised in-process via the `http_client` fixture.
2. `[test]` The 200/ready result proves the full flow: the route delegates to the health service, which calls `db.health.ping()`, and the response is the `HealthResponse` schema (readiness reflects the initialized DB, not a hardcoded literal in the route).
3. `[manual/live]` `cd backend && .venv/Scripts/uvicorn app.main:app --port 8185 --reload` boots the app without error and the lifespan initializes engine + DB + vector stub.

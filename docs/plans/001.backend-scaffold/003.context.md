# 003.context — App factory, lifespan & health end-to-end

## Lifespan wiring order
On startup: build a `DbConfig` from `Settings` (`db_path` from `Settings`), then `init_engine(config)` → `init_db()` → vector init stub. `init_db()` runs `create_all` for this greenfield scaffold — this is the **known seam** (Decision 6) that feature `003.first-run-bootstrap` (FEAT-001) will amend to defer table creation to a first-run wizard. See the "Known seam" section of `context.md`. Do not build any bootstrap logic here.

## Router mount convention (Decision 7)
Each `APIRouter` owns its own `prefix="/api/..."`, mounted with a bare `app.include_router(health.router)`. Mirror the reference's per-router prefix style (`D:/GitRoot/_TextGens/LLMRPTextOnlyProject/backend/app/main.py` and `.../app/routes/health.py`). Reference divergence: the reference `/api/health` is liveness-only; BookWriter's is **DB-readiness through all four layers** (routes → services → db.health.ping → HealthResponse).

## HealthResponse shape
Pydantic `BaseModel` in `models/schemas/health.py`: `status: str` = `"ok"`, `db: str` = `"ready"`. This is the typed response the route returns. Readiness must originate from `db.health.ping()`, not a route-level constant.

## Logging setup (mirror the reference)
`logging.basicConfig(level=DEBUG, ...)` at import in `main.py`; quiet aiosqlite/httpx/httpcore loggers to WARNING; modules use `logging.getLogger(__name__)`.

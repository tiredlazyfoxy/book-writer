# Step 004 — JSONL import/export mechanism hook

## Goal
Stand up the streaming gzip-JSONL import/export *mechanism* — the session-free db primitives and the service-layer registry-driven zip round-trip — with an **empty** table registry, so the machinery exists and round-trips an empty archive.

backend/app/db/import_export_queries.py
backend/app/services/db_import_export.py

## Test files
backend/tests/services/test_db_import_export.py

## Interface intent
- **`export_table(model_class, callback)`** (in `db/import_export_queries.py`) — generic, session-free per-row export: opens its own session, iterates rows of `model_class`, invokes `callback(row)` per row. **No serialization in db/** — the callback (owned by the service) does that. Streaming; no bulk `SELECT *` into memory.
- **`upsert_batch(items)`** (in `db/import_export_queries.py`) — the streaming UPSERT primitive: `session.merge` per item and a single commit for the batch. Idempotent.
- **`run_vector_rebuild()`** (in `db/import_export_queries.py`) — stub for rebuilding the LanceDB sidecar index from SQLite source rows after import. No-op / minimal for now (no models, no vector-backed data).
- **`TABLE_REGISTRY`** (in `services/db_import_export.py`) — an **ordered list** of `(zip_filename, model_class, to_dict_fn, from_dict_fn)` tuples; order = FK dependency order. **Empty for now** (no models). Adding a model later = add its codec pair + one ordered tuple here.
- **`BATCH_SIZE`** — module constant `= 100`.
- **`export_all()`** (in `services/db_import_export.py`) — returns `bytes`: a zip archive containing one `<table>.jsonl.gz` per registry entry, each streamed per-row through gzip via `export_table` + a serializing callback. Over an empty registry, yields a valid empty zip.
- **`import_all(zip_bytes)`** (in `services/db_import_export.py`) — calls `init_db()` first (creates/reshapes tables), then for each registry entry streams JSONL lines, accumulates up to `BATCH_SIZE`, and flushes via `upsert_batch`; triggers `run_vector_rebuild()` after. UPSERT — idempotent. Over an empty registry / empty archive, an idempotent no-op that still runs `init_db()`.

## Definition of done
1. `[test]` `export_all()` over the empty registry returns `bytes` that parse as a valid (empty) zip archive.
2. `[test]` `import_all(export_all())` completes without error as an idempotent no-op over the empty registry, and it invokes `init_db()` as part of the flow.
3. `[test]` The import/export mechanism round-trips the empty archive: `import_all(export_all())` leaves the DB usable (readiness still holds) and can be re-run safely (idempotent).
4. `[manual/live]` Documented extension contract: adding a persistent model = add its `to_dict`/`from_dict` codec pair plus one ordered `TABLE_REGISTRY` tuple in FK order — recorded in `outcome.md` Observations for the architect.

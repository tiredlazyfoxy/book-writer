# 003 — step context

Feature-wide facts (route map, the `BookResponse` wire gap, the deferral table, MobX rules, test
setup, gates) are in `context.md`. Only what this step alone needs is below.

## Why this page loads the book again

The shell (002) already loaded the book, but this page loads it again by URL id, and that is
deliberate:

- `frontend.md`: "Each page loads its own data by URL id — no warm start from a parent's data; every
  page is deep-linkable."
- The alternative for passing the shell's book down is react-router's `useOutletContext`, which is
  React context — **banned** by `frontend.md` ("No Redux, Zustand, React-Query, React-Context").
- The shell's copy exists for header/navigator chrome; this page's copy is the subject's own data.

One extra `GET /api/books/{id}` per landing is the accepted cost. Recorded for the architect in
`outcome.md`.

## Exactly what is on the wire

`src/types/books.d.ts`:

- `BookResponse { id, owner_id, title, description, collaboration_mode, visibility, state,
  created_at, modified_at }`
- `BookDetailResponse extends BookResponse { members: BookMemberResponse[] }`
- Unions: `CollaborationMode = "free" | "proposal"`, `Visibility = "private" | "public"`,
  `BookState = "active" | "archived" | "quarantined" | "destroyed"`, `MemberRole = "co_author"`.
- `src/types/common.d.ts` has `type ISODateString = string` and `interface ApiErrorBody { detail?: string }`.

`src/api/books.ts` already exports `COLLABORATION_MODE_OPTIONS` and `VISIBILITY_OPTIONS` — reuse them
for the author-facing labels rather than minting a second label map. There is **no** exported label
map for `BookState`; derive those labels in this page's state file.

**Not on the wire, though `domain-book.md` lists them on the entity:** `system_prompt` and
`active_notes`, plus the moderation fields (`moderation_reason`, `moderated_by`, `moderated_at`).
Render nothing for the moderation fields (a `quarantined` book never reaches this page — the API
refuses it), and render the state-notes empty state for `active_notes`. Do **not** add a field to
`types/books.d.ts` or call a new endpoint: this feature touches no backend file.

## Date formatting

`src/utils/` contains only `navigate.ts` — there is no shared date formatter in the repo. Format the
two timestamps inline in this page; do **not** add a `src/utils/formatDate.ts` (out of scope, and a
shared helper is a decision for whichever feature needs it twice).

## Ownership label for the deferred region

Use the literal `016.chapter-close-continuity`. The per-chapter region covers, per UC-091 /
`frontend-workspace.md` → "Navigator": per chapter its title, its summary (UC-089), the after-chapter
note changeset (UC-049 / UC-051) and any active **warnings** in context (FEAT-016). None of those has
a backing endpoint — the mounted routers are `health, auth, books, admin_users, admin_llm_servers,
admin_db`, and `backend/app/routes/books.py` exposes no continuity route.

## Test notes specific to this page

`renderWithProviders` strips the basename, so the redirect case is exercised by rendering the work
route table at `/:bookId` and asserting the Book-state view appears; assert the redirect is a replace
where the harness allows it. `api/books` is mocked as a module (the convention established in step
001 — see `001.context.md`), never `fetch`.

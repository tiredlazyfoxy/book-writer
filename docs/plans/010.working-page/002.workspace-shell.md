# 002 — workspace shell

## Goal

Build the three-region working page — navigator · content pane · empty chat-pane slot — as a route
element keyed on `:bookId` that loads the book once and renders the subject route through the repo's
first `<Outlet/>`.

## Interface intent

- **`navItems.ts`** — mirrors `src/admin/components/shell/navItems.ts`.
  - A *work nav item* shape: the path segment under `/work/:bookId`, the author-facing label, a
    `@tabler/icons-react` icon, an optional list of additional segments that also mark the item
    active, and a **pane target** discriminator distinguishing an entry that renders into the content
    pane from the one that renders into the chat pane.
  - The ordered, `readonly` list of the **seven** entries in UC-090 order: Book state · Characters ·
    Locations · Facts · Chapters · Variants · Chats. Chapters also matches the single-chapter
    segment; Chats is the one entry whose target is the chat pane.
  - A helper building an item's href for a given book id.
  - An active-match predicate taking the current pathname, the book id and the item: true for the
    item's own path and for `/`-delimited descendant paths, and for the item's extra segments; false
    for a sibling entry's path.
- **`WorkNavigator.tsx`** — an `observer` component taking the book id and rendering the seven entries
  as in-SPA react-router links, marking the active one via the predicate. No data loading.
- **`ChatPaneSlot.tsx`** — an `observer` placeholder for the right-hand region, rendering a short
  notice that the chat pane is owned by `011.chat-panel`. No chat behaviour, no state.
- **`workspaceShellState.ts`** — a shell state class holding the book **async trio** (book detail /
  status / error) plus a navbar-open flag, alongside an external
  `(state, bookId, signal)` loader that calls `getBookDetail` from `src/api/books.ts`, writes results
  through `runInAction`, returns silently when the signal aborted, and turns an `ApiError` into an
  author-facing message (the 403/404 a non-member gets).
- **`WorkspaceShell.tsx`** — an `observer` component that reads `:bookId` from the router, owns its
  state instance via `useState`, runs a single mount-only `useEffect` that starts the load and aborts
  on unmount, and lays out the three regions with Mantine `AppShell`: navigator on the left, the
  content pane in the centre containing **`<Outlet/>`**, and the chat-pane slot on the right. It
  renders the book title plus the loading and error states of its own trio.
- **`routes.tsx`** — a small `WorkspaceRoute` wrapper reading `:bookId` and rendering the shell with
  `key={bookId}` (mirrors the existing `BookSettingsRoute` wrapper in `src/user/routes.tsx`); a
  `/:bookId` route using it, with a nested catch-all so an unknown subject path renders the
  not-found page **inside** the content pane; the terminal top-level catch-all from 001 is preserved.

## Definition of done

1. `[test]` The navigator renders exactly seven entries, in the order Book state · Characters ·
   Locations · Facts · Chapters · Variants · Chats, with the author-facing labels (UC-090 / US-105).
2. `[test]` Each entry links to its own subject path under the current book id, as an in-SPA router
   link (basename-stripped in tests).
3. `[test]` The active-match predicate marks an item active for its own path and for a descendant
   path, not for a sibling entry's path; the Chapters entry is active for a single-chapter path and
   the Variants entry for a per-chapter variants path (UC-090 / US-105.AC-1).
4. `[test]` The shell renders all three regions: the navigator, a content-pane region containing the
   nested-route outlet, and the chat-pane slot whose placeholder names `011.chat-panel` as its owner
   (`frontend-workspace.md` → "The working page").
5. `[test]` The shell loads the book exactly once through the mocked `api/books.getBookDetail` and
   renders its title; the loading state renders while pending.
6. `[test]` A failed book load — the 403/404 a non-member receives — surfaces an author-facing
   message in place of the workspace content rather than crashing or rendering blank.
7. `[test]` Navigating between two subject paths under the same `:bookId` does **not** remount the
   shell: `getBookDetail` is called exactly once across the navigation
   (`frontend-workspace.md` → "Keying the shell on `:bookId`").
8. `[manual/live]` `cd frontend && npm run build` clean, `npm test` green, `npm run test:types` clean.

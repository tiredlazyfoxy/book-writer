# 003 — Book-state landing view

## Goal

Make Book state the landing view of the working page (US-106.AC-1): redirect `/work/:bookId` to
`/work/:bookId/state` and render the book's own fields from `BookDetailResponse`, with the per-chapter
continuity region shipped as a labelled empty state owned by `016.chapter-close-continuity`.

## Interface intent

- **`bookStatePageState.ts`** — a page state class holding a book-detail **async trio** (book detail /
  status / error), plus an external `(state, bookId, signal)` loader calling `getBookDetail`, writing
  through `runInAction`, returning silently on abort and storing an author-facing message on
  `ApiError`. Derivations are `get` computeds only: the author-facing labels for collaboration mode,
  visibility and lifecycle state, the member list to render, and the member count. No setters, no
  methods that fetch.
- **`BookStatePage.tsx`** — an `observer` page reading `:bookId` from the router, owning its state via
  `useState`, with one mount-only `useEffect` that loads and aborts on unmount. It renders four
  regions:
  1. **the book's own fields** — everything `BookDetailResponse` actually carries;
  2. **members** — the owner and the co-author list;
  3. **state notes** — a labelled empty state stating the book's state notes are not yet exposed by
     the API (the `BookResponse` gap in `context.md`), not an error state;
  4. **per-chapter continuity** — a labelled empty state naming `016.chapter-close-continuity` as its
     owner, using the author-facing word *warning* (never *flag*), covering the deferred per-chapter
     title + summary + after-chapter notes + active warnings.
  It also renders the trio's loading and error states.
- **`routes.tsx`** — under the `/:bookId` shell route: an index route redirecting (replace) to
  `state`, and a `state` child rendering the page.

## Definition of done

1. `[test]` Opening the working page at `/work/:bookId` lands on Book state — the index route
   redirects to `/work/:bookId/state` (replace, so it does not trap the back button) and the
   Book-state view renders (UC-091 / US-106.AC-1).
2. `[test]` The Book-state view renders the fields `BookDetailResponse` carries: title, description,
   collaboration mode, visibility, lifecycle state, created and modified timestamps, the owner and
   the co-author members (UC-091 / US-106.AC-1; field list per `domain-book.md`, minus the wire gap).
3. `[test]` The state-notes region renders as a labelled empty state saying the book's state notes are
   not yet available from the API — it is not rendered as a load failure and not omitted silently.
4. `[test]` The per-chapter continuity region renders as a labelled empty state naming
   `016.chapter-close-continuity` as its owner, and every author-facing string in the page says
   *warning*, never *flag* (US-106.AC-2 / US-106.AC-3 deferred; `frontend-workspace.md` →
   "Warning is the author-facing word for a flag").
5. `[test]` The page's own async trio renders correctly: a pending load shows the loading state, and
   a failed load shows an author-facing error rather than a blank pane.
6. `[manual/live]` `cd frontend && npm run build` clean, `npm test` green, `npm run test:types` clean.

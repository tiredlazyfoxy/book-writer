# 002 — step context

Feature-wide facts (route map, the `<Outlet/>` decision and why, MobX rules, link rules, test setup,
gates) are in `context.md`. Only what this step alone needs is below.

## `AdminShell` — the layout precedent

`src/admin/components/shell/AdminShell.tsx`:

- `class AdminShellState { navbarOpened = false }` — `makeAutoObservable`, no methods.
- `interface AdminShellProps { children: ReactNode }`.
- Mantine `AppShell` with `header={{ height: 56 }}` and
  `navbar={{ width: 220, breakpoint: "sm", collapsed: { mobile: !opened } }}`.

Two differences here: the shell state grows an **async trio** for the book, so it lives in its own
`workspaceShellState.ts` file beside the component (matching the `<page>PageState.ts` convention)
rather than inline; and the shell takes **no `children`** — it renders `<Outlet/>`, per `context.md`.

## `navItems.ts` — the precedent to mirror

`src/admin/components/shell/navItems.ts` exports
`interface AdminNavItem { path; label; icon: Icon; exact?: boolean }`,
`const ADMIN_NAV_ITEMS: readonly AdminNavItem[]`, and
`isNavItemActive(pathname: string, item: AdminNavItem): boolean` — exact match for `/`, `/`-delimited
descendant match otherwise. The work version drops `exact` (there is no root entry: Book state is
`/state`) and adds a book id parameter, extra active segments, and the pane-target discriminator.

**Known limitation, accept it:** `/work/:bookId/codex/:id` cannot be attributed to Characters,
Locations or Facts from the URL alone — the entry's `kind` is not in the path. No navigator entry
highlights for a single codex entry until the feature that loads the entry supplies its kind. Do not
invent a scheme for it here.

## The book load

`src/api/books.ts` (`const BASE = "/api/books"`) exports
`getBookDetail(bookId, signal?) => Promise<BookDetailResponse>`. `src/types/books.d.ts` declares
`BookDetailResponse extends BookResponse { members: BookMemberResponse[] }` with `BookResponse`
carrying `id, owner_id, title, description, collaboration_mode, visibility, state, created_at,
modified_at`. Errors arrive as `ApiError` from `src/api/client.ts` (`status`, `message`, `details?`).

The shell needs the title (and the load's status) for its header chrome only. Each subject page loads
its own data by URL id — see `003.context.md` for why that duplicate fetch is correct and why
`useOutletContext` is not an option.

**`useEffect` placement.** `frontend.md` permits `useEffect` at the page level only. The shell keyed
on `:bookId` **is** the page-level mount for the workspace — the subject routes are nested views
inside a single mount — so the book load's mount effect belongs there, with empty deps and an abort
on unmount. This reading is recorded for the architect in `outcome.md`.

## Route wiring

catch-all — the work entry's does, from step 001.)

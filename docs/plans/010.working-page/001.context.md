# 001 — step context

Feature-wide facts (route map, admin-vs-user pattern, link rules, test setup, gates) are in
`context.md`. Only what this step alone needs is below.

## `frontend/vite.config.ts` as it stands

- `appType: "mpa"`, `plugins: [react(), spaFallback()]`, `server.port` 8194 with `/api` proxied to
  `http://localhost:8185`.
- `build.rollupOptions.input` has exactly three keys: `user` → `index.html`, `admin` →
  `admin/index.html`, `login` → `login/index.html`.
- **`spaFallback()`** is a local dev plugin implemented as a `configureServer` middleware. It skips
  `/api`, `/src`, `/@`, `/node_modules` and any url containing a `.`, then branches:
  `url.startsWith("/admin")` → `/admin/index.html`; `url.startsWith("/login")` →
  `/login/index.html`; **else → `/index.html`**, a catch-all. The new `/work` and `/read` branches
  **must be inserted before that `else`** or they will never be reached.

## Entry HTML shape

`frontend/index.html`, `frontend/admin/index.html` and `frontend/login/index.html` are identical
except for `<title>` and the script src (`/src/user/main.tsx`, `/src/admin/main.tsx`,
`/src/login/main.tsx`). The body is `<div id="root"></div>` plus the module script. Note
`frontend/tsconfig.json` has `include: ["src"]`, so the HTML files are outside the typecheck program;
the new `src/work/` and `src/read/` sources are inside it.

## The admin bootstrap to mirror

- `src/admin/main.tsx` calls `enforceAdminAccess()` **outside React**, and only then
  `createRoot(...).render(<StrictMode><App /></StrictMode>)`.
- `src/admin/App.tsx` is
  `<MantineProvider theme={theme} defaultColorScheme="dark"><BrowserRouter basename="/admin"><AdminShell><AdminRoutes /></AdminShell></BrowserRouter></MantineProvider>`.
  The `work` App has **no shell at this step** — step 002 adds the shell as a route element, not as a
  wrapper around the route table.
- `src/admin/routes.tsx` is `observer`-wrapped and ends with `<Route path="*" element={<NotFoundPage />} />`.

## `src/admin/adminGate.ts` — the shape to mirror

`type AdminAccessDecision = { allowed: true } | { allowed: false; redirectTo: string }`, a pure
`resolveAdminAccess(): AdminAccessDecision`, and `enforceAdminAccess(): boolean` which calls
`navigateTo` once on deny. It documents its rejection of `useEffect` gates and `<AdminGate>`
components — carry the equivalent note across.

The work gate differs in exactly one way: it checks **authentication only**, not a role. Admin's
role check has no analogue here because book membership is not in the JWT.

## Available seams

- `src/auth.ts` — exported key constants (`ACCESS_TOKEN_KEY`, `REFRESH_TOKEN_KEY`) and plain
  functions `setTokens` / `setAccessToken` / `getToken` / `getRefreshToken` / `getCurrentUser` /
  `logout`, plus `interface CurrentUser { user_id; username; role }`. Module-level state, no class,
  no MobX. It must not import from `src/api/`.
- `src/utils/navigate.ts` — `export function navigateTo(href: string): void { window.location.href = href; }`,
  documented as the mockable seam for cross-SPA navigation. It is the only file in `src/utils/`.
- `src/components/` is empty but for `.gitkeep`; no shared component exists, and this step adds none.

## Bookshelf page today

`src/user/pages/BookshelfPage.tsx` + `bookshelfPageState.ts` render owned and shared books through
`listOwnedBooks` / `listSharedBooks` from `src/api/books.ts`. **Table rows are plain `<Text>`: there
is currently no navigation from the bookshelf into any book at all**, not even to settings, and
nothing anywhere in the repo references `/work` or `/read`. This step adds the first such link.

The link crosses Vite entries, so it must be a plain `<a href="/work/<id>">`: a react-router `<Link>`
would resolve through the user SPA's router, and `navigateTo` is for programmatic cross-SPA redirects,
not for rendered links.

## Intermediate state — accepted

Until step 002 wires the `/:bookId` shell route, following the new bookshelf link lands on the work
entry's not-found page. That is an intra-feature intermediate state, not a defect; step 002 closes it.
Because any single-segment path matches `:bookId` once 002 lands, the durable catch-all cases to
assert are the entry root and an unmatched deep path.

## First `src/api/*` mock in the repo

`tests/user/BookshelfPage.test.tsx` is the first spec anywhere to mock an `api/` resource module
(`../../src/api/books`), establishing the convention the later steps reuse. Follow the existing
`vi.mock` style used for `../../src/auth`: module-factory form with `vi.fn()` members, then
`vi.mocked(...).mockResolvedValue(...)` per case. Mock the **`api/` module, never `fetch`**
(`frontend.md` → Testing). `tests/admin/routes.test.tsx` deliberately avoids navigating to fetching
pages rather than mocking them — that avoidance ends here.

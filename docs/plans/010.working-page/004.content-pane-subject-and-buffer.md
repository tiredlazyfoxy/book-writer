# 004 — content-pane subject model and restore buffer

## Goal

Ship the content pane's subject model — the single enforcement point for the editable-vs-read-only
rule — the remaining subject routes as read-only empty states naming their owning feature, and the
per-item `localStorage` restore buffer. This step deliberately carries both the subject model and the
buffer and may run slightly past the 200-line band: the buffer's key scheme is expressed in the
subject vocabulary, so splitting them would break one contract across two steps (user's explicit
call).

## Interface intent

- **`subject.ts`** — the one place the editability rule lives.
  - A **subject-kind** vocabulary covering: book state, the chapter list, one chapter, each of the
    three codex lists (characters / locations / facts), one codex entry, the variants list, one
    chapter's variants, and the chat list.
  - A **loaded-subject descriptor**: the kind, the entity id where the kind has one, and the facts
    editability depends on — a chapter's `planned | open | closing | closed` state, and whether a
    codex entry is archived.
  - A **pane-target resolver**: chat list → the chat pane; every other kind → the content pane.
  - An **editability resolver** implementing `frontend-workspace.md`'s table exactly, returning what
    is editable — nothing, the whole subject, or the book's state notes only — together with an
    author-facing read-only reason.
  - A **write-permission check** taking a subject and the region being written and returning
    allow/deny with that reason. Document it as the single gate that both the author's save path and
    (at Stage 5) the assistant's write path must call — that symmetry is US-097.AC-2 / US-059.AC-3
    and is why the module exists before either writer does. Nothing calls it yet in this feature.
- **`restoreBuffer.ts`** — module-level plain functions, `auth.ts`-style: no class, no MobX, no
  reactivity, no import from `src/api/`.
  - A shared storage-key prefix constant and a **key builder** from `(bookId, subjectKind, subjectId)`.
  - A **buffered draft record**: the draft text, the base version it forked from (a chapter's
    `version`, or a codex entry's `modified_at`), and when it was written.
  - **read** — returns the record for a key, or nothing when the entry is absent, unparseable or
    shaped wrong; never throws.
  - **write** — stores the record under the key, stamping the written-at, and returns a result saying
    whether it was saved outright, saved after evicting other buffers (naming what was evicted, so
    the caller can tell the author), or failed.
  - **clear** — removes exactly that key's entry.
  - **Quota handling** — on a quota error, evict this module's own buffers (never other
    `localStorage` keys) **oldest-written-first**, retrying between evictions, and **never evict the
    key currently being written**.
- **`SubjectPlaceholderPage.tsx`** — one `observer` placeholder taking a heading and an owner label,
  rendering a read-only empty state. Used by every list route and every item route this step adds.
- **`routes.tsx`** — the remaining children under the `/:bookId` shell route: `chapters`,
  `chapter/:id`, `characters`, `locations`, `facts`, `codex/:id`, `variants`, `variants/:chapterId`,
  `chats`. Each renders the placeholder with its owner label. **No route carries a chat id.** Item
  routes get the `key` remount treatment their path param implies.

Owner labels, verbatim: chapters and one chapter → `014.chapter-skeleton`; characters, locations,
facts and one codex entry → `013.codex`; variants and one chapter's variants →
`018.chapter-history-variants`; chats → `011.chat-panel`.

## Definition of done

1. `[test]` A chapter in `open` state resolves as fully editable; a chapter in `closing`, `planned` or
   `closed` resolves as read-only with a stated reason (US-097.AC-1, US-097.AC-3).
2. `[test]` A non-archived codex entry resolves as editable and an archived one as read-only; Book
   state resolves as state-notes-only editable; every list kind resolves as read-only
   (`frontend-workspace.md` → "Content pane — subject and editability").
3. `[test]` The write check denies a write into a read-only subject through the same call and with the
   same denial regardless of the writer — the author's path and the assistant's path get identical
   answers (US-097.AC-2).
4. `[test]` The chat list resolves to the chat pane while every other subject kind resolves to the
   content pane, and no route carries a chat id: a path of the form `/work/:bookId/chat/<id>` falls
   through to the not-found page (US-105.AC-3).
5. `[test]` Each list route renders, inside the content pane, a read-only empty state naming its
   owning feature with the labels listed above (US-105.AC-1 — the pane switches per navigator kind;
   list content itself is deferred).
6. `[test]` The item routes `/chapter/:id`, `/codex/:id` and `/variants/:chapterId` resolve into the
   content pane rather than the catch-all (US-105.AC-2 routing; US-105.AC-4's variant/revision content
   deferred to `018.chapter-history-variants`).
7. `[test]` A draft written to the buffer is readable again after navigating away and back — reading
   the same key returns the draft text, its base version and its written-at (US-107.AC-1).
8. `[test]` A buffer survives a full reload — re-reading the key from a freshly initialised module
   returns the same record (US-107.AC-2).
9. `[test]` Buffers are keyed per item: writing under one `(bookId, kind, id)` triple leaves another
   triple's buffer untouched, and clearing one removes only that key
   (`frontend-workspace.md` → "Keyed per item, not per pane").
10. `[test]` The buffer is device-local and never server-side: a write touches `localStorage` only and
    issues no HTTP, so a buffered draft is invisible to co-authors and leaves the item unpersisted
    (US-107.AC-3, US-107.AC-4).
11. `[test]` On a quota error the write evicts this module's buffers oldest-written-first, retries,
    never evicts the key being written, and reports the eviction in its result so the author can be
    told (`frontend-workspace.md` → "Accepted limitation — quota").
12. `[test]` Reading a missing, unparseable or wrongly shaped entry returns nothing rather than
    throwing.
13. `[manual/live]` `cd frontend && npm run build` clean, `npm test` green, `npm run test:types` clean.

# Step 003 — AssistantMode seed at first-run setup

## Goal

Seed the fixed five `AssistantMode` rows idempotently at instance setup: add a
session-free `seed_default_modes()` to `db/assistant_modes.py` and call it from
`services/setup.py::create_database` after `init_db()` and before
`set_db_ready(True)`.

## Source files

backend/app/db/assistant_modes.py
backend/app/services/setup.py

## Test files

backend/tests/test_data_domain_mode_seed.py

## Interface intent

- **`seed_default_modes()`** in `db/assistant_modes.py`: session-free;
  idempotently ensures a row exists for each of the fixed five keys
  (`edit-character`, `edit-location`, `edit-fact`, `write-chapter`,
  `close-chapter`). A key already present is left untouched (do not clobber an
  admin-edited `system_prompt`); a missing key is created with `system_prompt =
  None`. Safe to call any number of times.
- **`services/setup.py::create_database`**: after the existing `init_db()` call
  and before `set_db_ready(True)`, invoke `seed_default_modes()` so a fresh
  instance comes up with the five modes present. No other change to the setup
  flow; the seed is the only addition.

## Definition of done

1. **[test]** On a fresh throwaway DB, calling `seed_default_modes()` (after
   `init_db()`) creates exactly five `AssistantMode` rows, whose keys are
   exactly the fixed five.
2. **[test]** Idempotent: calling `seed_default_modes()` a second time leaves
   exactly five rows (no duplicates, no error).
3. **[test]** Wiring: after `create_database` completes on a fresh instance, the
   five `AssistantMode` rows exist — the seed is reachable through the setup
   path.
4. **[manual/live]** `import_database` converges seeded + imported modes: because
   the `assistant_modes` codec is an idempotent UPSERT keyed on `key`, a fresh
   instance that seeds its own five modes and then imports an archive containing
   the same keys reconciles rather than colliding. (No new import code — this is
   an existing-mechanism confirmation; recorded requires-live-run.)

## Dependencies

001 (the `assistant_modes` table, its `create` / `get_by_id` / `list_all` db
functions, and its codec).

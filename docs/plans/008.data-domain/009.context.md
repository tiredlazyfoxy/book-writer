# Step 009 — step-specific context

Field specs from `domain-chat.md`. Shared conventions in `context.md`.

**Realizes:** FEAT-013 **entities only** — UC-053, UC-081, UC-082; US-061,
US-095, US-096. **Not** the assistant subsystem — these two tables exist so the
schema is drawn whole; nothing that makes them useful is built here.

## `Chat` (table `chats`)

| Field | Type / notes |
|---|---|
| `id` | snowflake PK |
| `book_id` | FK → `books.id` — chats are per book |
| `author_id` | FK → `users.id` — private to that author (a plain FK; privacy is a service rule, not modelled here) |
| `title` | display label |
| `archived` | `bool = False` — archived, not destroyed (UC-082) |
| `created_at` / `modified_at` | timestamps |

**No subject FK** (no chapter / codex / content-pane binding) — a deliberate
absence per `domain-chat.md`, not an omission.

## `ChatMessage` (table `chat_messages`)

| Field | Type / notes |
|---|---|
| `id` | snowflake PK |
| `chat_id` | FK → `chats.id` |
| `role` | who spoke (free string; no enum specified) |
| `content` | the message body |
| `position` | non-null `int` — the message number / order of the message within its chat (explicit ordinal, alongside `created_at`) |
| `created_at` | timestamp (single timestamp) |

Both classes live in one model module `models/chat.py`, so a single
`_register_models()` import registers both tables.

# Step 006 — step-specific context

Field specs from `domain-chapter.md`. Shared conventions in `context.md`.

## `ChapterChange` (table `chapter_changes`) — "ChapterChange — the unified write record"

**Realizes:** FEAT-009, FEAT-010 (UC-040/041), FEAT-013 (UC-055 save path),
FEAT-014; US-040, US-041.

| Field | Type / notes |
|---|---|
| `id` | snowflake PK |
| `chapter_id` | FK → `chapters.id` |
| `author_id` | FK → `users.id` (attribution, US-040.AC-2) |
| `placement_kind` | enum {`append`, `range`} |
| `line_from` / `line_to` | nullable ints; set only when `placement_kind = range` |
| `base_version` | int — the `Chapter.version` this change was composed against |
| `text` | the change's text |
| `status` | enum {`pending`, `applied`, `rejected`} |
| `applied_at` | nullable datetime; null until applied |
| `applied_by` | nullable FK → `users.id`; null until applied |
| `created_at` | timestamp |

Placement is a discriminator plus two nullable ints, not a union column. All
lifecycle behaviour (the one write path, 409, stale-refusal) is feature 015's —
this step only lands the table shape.

## `ChapterTextRevision` (table `chapter_text_revisions`) — "ChapterTextRevision"

**Realizes:** FEAT-014 (UC-058..060), challenge C20.

| Field | Type / notes |
|---|---|
| `id` | snowflake PK |
| `chapter_id` | FK → `chapters.id` |
| `applied_change_id` | FK → `chapter_changes.id` — the change this snapshot precedes |
| `text_before` | the **full** chapter body before that change |
| `applied_by` | FK → `users.id` (non-null) |
| `applied_at` | datetime (this entity's single timestamp) |

Full snapshots, not reverse patches. First *built* at Stage 3, drawn now.

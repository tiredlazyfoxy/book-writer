# Step 005 — step-specific context

Field specs from `domain-chapter.md` → "Chapter". Shared conventions in
`context.md`.

**Realizes:** FEAT-008 (UC-031..034), FEAT-009 (UC-035..039), FEAT-012
(UC-047/048 states), FEAT-014.

| Field | Type / notes |
|---|---|
| `id` | snowflake PK |
| `book_id` | FK → `books.id` |
| `ordinal` | int — position in the skeleton |
| `title` | chapter title |
| `state` | enum {`planned`, `open`, `closing`, `closed`} |
| `sketch` | forward-looking outline (named `sketch`, product's word) |
| `text` | the single main body (one `text`, not a block table) |
| `summary` | nullable — backward-looking summary |
| `summary_status` | nullable enum {`draft`, `approved`, `stale`} |
| `system_prompt` | nullable — appends to the book's (no product requirement — divergence 3) |
| `version` | int, **default 1**; bumped on every applied change |
| `created_at` / `modified_at` | timestamps |

- `state = closing` and `summary_status` **land now, nullable/unused** —
  Stage-4 behaviour, per the Stage-4-columns rule in `context.md`. Nothing in
  this feature reads them; they exist so Stage 4 is pure behaviour.
- **`version` default is 1** (a freshly created chapter is version 1). This is
  the value `ChapterChange.base_version` is composed against and
  `Chapter.version` bumps from (feature 015's concern, not this one) — fixing it
  now keeps the codec round-trip deterministic.

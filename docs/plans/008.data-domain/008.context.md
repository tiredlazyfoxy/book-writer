# Step 008 — step-specific context

Field specs from `domain-codex.md`. Shared conventions in `context.md`.

## `CodexEntry` (table `codex_entries`) — "CodexEntry"

**Realizes:** FEAT-017 (UC-069..075), FEAT-018 (save path); US-078..085.

| Field | Type / notes |
|---|---|
| `id` | snowflake PK |
| `book_id` | FK → `books.id`. One codex per book |
| `kind` | enum {`character`, `location`, `fact`} |
| `name` | nullable str — set for character/location, **null for fact** (US-078.AC-2) |
| `body` | the entry's content |
| `archived` | `bool = False` — archived, never deleted (UC-072) |
| `author_id` | FK → `users.id` — the entry's original creator. **Required** (non-null) |
| `modified_by` | FK → `users.id` — author of the last version (most recent editor). **Nullable** (`int | None`); maintained by the feature-013 service on edit, round-tripped only here |
| `created_at` / `modified_at` | timestamps |

Three kinds, one table (a fixed taxonomy, not three entities). `name` is
nullable because a fact has no name.

## `CodexEntryVersion` (table `codex_entry_versions`) — "CodexEntryVersion"

| Field | Type / notes |
|---|---|
| `id` | snowflake PK |
| `entry_id` | FK → `codex_entries.id` |
| `name` | nullable — the entry's name as it stood |
| `body` | content as it stood |
| `kind` | enum {`character`, `location`, `fact`} as it stood |
| `author_id` | FK → `users.id` |
| `generation` | non-null `int` — 1-based sequence/generation number of this version within its entry; maintained by the service when a version is written, round-tripped only here |
| `created_at` | timestamp (single timestamp) |

Full prior content per version (same reasoning as `ChapterTextRevision`). First
*built* at Stage 5; drawn now.

## Vector deferral — authoritative

`CodexEntry` is the architecture's "first vector-backed model", but the user's
decision **defers all vector work to `013.codex`**. In this feature
`codex_entries` is an ordinary data table only: **no `VECTOR_SOURCE_REGISTRY`
entry, no `db/vector.py` change, no chunker, no `services/embedding.py`.** DoD-5
guards this — the registry must stay codex-free. `outcome.md` records the
deferral so the architecture stays honest.

## Registry position — slot codex before `flags`

The canonical order is `chapter_note_changesets, codex_entries,
codex_entry_versions, flags`. Step 007 registered `flags` immediately after
`chapter_note_changesets` (codex was absent). This step inserts
`("codex_entries", ...)` then `("codex_entry_versions", ...)` **between**
`chapter_note_changesets` and `flags` — not after `flags`. After this step the
registry matches the full canonical order through `flags`.

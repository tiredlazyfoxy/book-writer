# Step 009 — Chat + ChatMessage

## Goal

Add the final two book-domain entities — `Chat` (per book, private to its
author) and `ChatMessage` — each with its session-free `db/` module, JSONL codec
pair, `TABLE_REGISTRY` tuple, and model registration; then assert the completed
registry matches the full canonical order.

## Source files

backend/app/models/chat.py
backend/app/db/chats.py
backend/app/db/chat_messages.py
backend/app/services/db_import_export.py
backend/app/db/engine.py

## Test files

backend/tests/test_data_domain_chat.py

## Interface intent

- **`Chat` model** (`models/chat.py`, table `chats`): snowflake PK `id`;
  `book_id` FK → `books.id`; `author_id` FK → `users.id`; `title`; `archived`
  bool default false; `created_at` / `modified_at`.
- **`ChatMessage` model** (same file `models/chat.py`, table `chat_messages`):
  snowflake PK `id`; `chat_id` FK → `chats.id`; `role`; `content`; `position`
  non-null int (the message number / order of the message within its chat, an
  explicit ordinal alongside `created_at`); `created_at`.
- **`db/chats.py`**: `create`, `get_by_id`, `list_by_book(book_id)`.
- **`db/chat_messages.py`**: `create`, `get_by_id`, `list_by_chat(chat_id)`.
- **Codecs** in `db_import_export.py`: a `Chat` pair (`archived` bool) and a
  `ChatMessage` pair (`position` a plain int emitted/parsed as-is). Register
  `("chats", ...)` then `("chat_messages", ...)` as the final two entries, after
  `flags`.
- **`_register_models()`**: add a single import for `app.models.chat` (it
  declares both `Chat` and `ChatMessage`).

## Definition of done

1. **[test]** `Chat` codec round-trip: `id` / `book_id` / `author_id`
   string↔int; `title`; `archived` bool; isoformat timestamps preserved.
2. **[test]** `ChatMessage` codec round-trip: `id` / `chat_id` string↔int;
   `role`; `content`; `position` int round-trips; isoformat `created_at`
   preserved.
3. **[test]** DB round-trip: `create` then `get_by_id` returns an equal row for
   both tables; `list_by_book(book_id)` returns exactly a book's chats;
   `list_by_chat(chat_id)` returns exactly a chat's messages.
4. **[test]** Full registry equality: the complete `TABLE_REGISTRY` tablename
   sequence equals the full canonical order exactly —
   `users, llm_servers, assistant_modes, sub_agents, mode_tools, subagent_tools,
   mode_subagents, books, book_members, chapters, chapter_changes,
   chapter_text_revisions, chapter_note_changesets, codex_entries,
   codex_entry_versions, flags, chats, chat_messages` — with no duplicates and
   no extras. This is the final FK-order guard for the whole feature.
5. **[test]** Schema present / drift-clean: after `init_db()`, `chats` and
   `chat_messages` exist in `SQLModel.metadata` and the FEAT-005 consistency
   report is clean.

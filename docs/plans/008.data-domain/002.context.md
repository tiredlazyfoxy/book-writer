## `assistant-config.md` → "The three link tables"

**Realizes:** FEAT-020, UC-096, US-111, US-112. Each link table follows
`BookMember`'s reasoning: a surrogate snowflake `id` PK plus a unique constraint
on the natural columns, so the codec has the same shape as every other table
while the natural pair carries the "one selection" semantics.

| Table (`__tablename__`) | Fields | Unique |
|---|---|---|
| `mode_tool` | `id` snowflake PK; `mode_key` FK→`assistant_modes.key`; `tool_name` str | `(mode_key, tool_name)` |
| `subagent_tool` | `id` snowflake PK; `sub_agent_id` FK→`sub_agents.id`; `tool_name` str | `(sub_agent_id, tool_name)` |
| `mode_subagent` | `id` snowflake PK; `mode_key` FK→`assistant_modes.key`; `sub_agent_id` FK→`sub_agents.id` | `(mode_key, sub_agent_id)` |

- `tool_name` references the code-defined `TOOL_REGISTRY` **by string, not FK** —
  no FK, no table (`TOOL_REGISTRY` is out of scope for this feature).
- `mode_key` is a string FK to the natural-key PK of `assistant_modes`; its
  codec passes it through verbatim (same rule as `AssistantMode.key` in
  step 001).
- Composite unique via
  `__table_args__ = (UniqueConstraint(...),)` (`from sqlalchemy import
  UniqueConstraint`) — first-of-kind; name each constraint (e.g.
  `uq_mode_tool_mode_key_tool_name`).

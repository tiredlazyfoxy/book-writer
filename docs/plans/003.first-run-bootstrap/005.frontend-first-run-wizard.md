## Interface intent
- **`src/types/auth.d.ts`** — hand-written DTO shapes mirroring the step-004
  backend schemas 1:1 (pure wire shapes, no methods): the auth-status shape
  (`needs_setup: boolean`), the create-DB request shape (`admin_username`,
  `password`, `password_confirm`), and the login-response shape (`token`).
- **`src/api/auth.ts`** — the setup resource module (all HTTP stays in `src/api/`):
  - **getAuthStatus** — GET `/api/auth/status` via `client.request`, returns the
    auth-status DTO. (No token exists on a cold instance; `request` omits Bearer
    when none is present, so no special no-auth variant is needed.)
  - **setupCreate** — POST `/api/auth/setup/create` with the create-DB body via
    `client.request`, returns the login-response DTO (`{token}`).
  - **setupImport** — POST `/api/auth/setup/import` as **multipart**: builds a
    `FormData` with the archive under field `file`, and **must not** set a JSON
    `Content-Type` (let the browser supply the multipart boundary); attaches
    `Authorization` from the token accessor only when a token is present.
    Returns the auth-status DTO. This is the sanctioned multipart bypass of
    `request` (like `sse.ts`), using the auth accessor for the header.
  - Each function takes an optional trailing `AbortSignal`.
- **`src/auth.ts`** (amend) — add **setToken** — writes a JWT string to
  `localStorage["token"]` (the counterpart to the existing `getToken`). Keep the
  file free of any `src/api/` import (one-way direction holds).
- **`login/loginState.ts`** — a `<Component>State` class + external effect
  functions (decision 9; the login entry is exempt from `<Page>State`/router
  machinery but binds the rest of the MobX rules):
  - observable fields: a mode/tab selector (`create` | `import`); the create
    drafts (`username`, `password`, `passwordConfirm`); the selected import file;
    a startup readiness field and its status; and a submit status trio
    (`submitStatus: 'idle'|'loading'|'ready'|'error'` / `submitError`).
  - pure `get` computeds only (no effectful methods): password-too-short
    (min length 8), passwords-match, and per-tab can-submit derivations.
  - external `(state, args, signal)` functions using `runInAction`:
    **loadStatus** (calls `getAuthStatus`, records `needs_setup`),
    **submitCreate** (calls `setupCreate`; on success `setToken(token)` then
    navigates to `/` via `window.location.href`; on refusal records the server
    error into the trio), and **submitImport** (calls `setupImport`; on success
    records the now-configured state; on refusal records the error and stays on
    setup).
- **`login/Login.tsx`** (rebuild) — an `observer` component owning a stable
  `loginState` instance (`useState(() => new LoginState())`); a mount `useEffect`
  runs `loadStatus`. When `needs_setup` is true it renders the create/import
  wizard (tabbed): the Create form (username + password + confirm, drafts bound
  to state, submit disabled until the `get` validation passes, server/validation
  errors shown) and the Import form (file picker + submit). When `needs_setup`
  is false it renders a minimal "instance configured — proceed to login"
  placeholder (the real login form is feature 004's). Handlers are inner
  functions closing over `state`. No Mantine `useForm`; no plain-`useState` form
  fields.

## Definition of done
1. `[manual/live]` `US-001.AC-1` — against a cold 001-backend (`npm run dev`),
   the login entry shows the setup wizard; submitting valid create credentials
   stores the returned token and lands the operator signed-in at `/`.
2. `[manual/live]` `US-001.AC-3` — submitting a password shorter than 8
   characters is refused (submit blocked and/or server 400 surfaced); no
   navigation occurs.
3. `[manual/live]` `US-001.AC-4` — submitting mismatched password/confirmation is
   refused (submit blocked and/or server error surfaced); no navigation occurs.
4. `[manual/live]` `US-002.AC-2` — importing a corrupt file surfaces an error and
   leaves the operator on the setup screen (instance still unconfigured).
5. `[manual/live]` `US-002.AC-1` — importing a valid export transitions the UI to
   the configured/"proceed to login" state (no token stored).
6. `[manual/live]` `cd frontend && npm run build` (tsc + vite) is clean; no `any`,
   no zod; DTOs live in `src/types/`.
7. `[manual/live]` The component honors the conventions: `observer`-wrapped, a
   `<Component>State` class with observable fields + `get` computeds only,
   external `(state, args, signal)` effect functions, **no** Mantine `useForm`,
   navigation via `window.location.href` — confirmable by inspection.

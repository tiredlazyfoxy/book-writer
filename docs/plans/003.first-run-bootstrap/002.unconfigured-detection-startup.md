# Step 002 — Unconfigured detection + startup lifespan amendment

## Goal
Add the process-level readiness flag to `db/engine.py` and amend the 001-scaffold
startup lifespan so a cold instance boots with an engine and **zero tables**,
detecting "unconfigured" from admin-existence rather than eagerly creating the
schema.

## Source files
backend/app/db/engine.py
backend/app/main.py

## Test files
backend/tests/test_startup_detection.py
backend/tests/conftest.py

## Interface intent
- **readiness flag** (in `db/engine.py`) — a module-level boolean, default
  `False`, exposed through:
  - **is_db_ready** — returns the current flag value.
  - **set_db_ready** — sets the flag to a given boolean.
  The flag is the single source of truth for `needs_setup = not is_db_ready()`.
- **model-registration hook** (in `db/engine.py`) — extend the existing (empty)
  hook to import the `app.models.user` module (`# noqa: F401`) so the `User`
  table is registered on `SQLModel.metadata` before any `create_all`, without
  relying on incidental imports. `init_db()` itself is **unchanged** and remains
  callable on demand (the setup flows call it) — this step does **not** make it
  run eagerly.
- **lifespan amendment** (in `app/main.py`) — the startup lifespan:
  1. calls `init_engine` (opens the engine + `data/` dir) and the vector-init
     stub, **as before**;
  2. **removes the eager `init_db`/`create_all` call** (the recorded 001 seam) —
     a cold instance now boots with zero tables, serving only status/setup/
     health;
  3. performs **startup readiness detection**: queries `db.users.admin_exists()`
     (which returns `False` gracefully on a missing table) and calls
     `set_db_ready(...)` with the result. As the composition root, the lifespan
     may call the `db/` layer directly (see `context.md`).
  The health readiness probe (`db.health.ping()` → `SELECT 1`) still succeeds on
  an open engine with no tables, so the 001 health contract is preserved.
- **conftest readiness reset** (extend `tests/conftest.py`) — an autouse fixture
  that resets the process-level readiness flag (via `set_db_ready(False)`) before
  each test, so the module-global flag does not leak state across tests. Added
  alongside the existing temp-DB and `http_client` fixtures from 001.

## Definition of done
1. `[test]` On a cold instance (engine initialized, no `init_db`/tables),
   `is_db_ready()` is `False` and `admin_exists()` is `False` — i.e. the instance
   reports itself unconfigured (`needs_setup` true). (Backs `US-001.AC-1`/
   `US-002.AC-1` preconditions.)
2. `[test]` After tables are created and an admin user exists, `is_db_ready()`
   becomes `True` once `set_db_ready(True)` is called — the detection state
   machine reflects admin presence. (Backs `US-001.AC-1`/`US-002.AC-1`
   postconditions.)
3. `[test]` The startup lifespan does **not** create tables: after the lifespan
   runs against a cold temp DB, the `users` table is absent (schema creation is
   deferred to the setup flows). (Backs the deferral required by `UC-001`/
   `UC-002`.)
4. `[manual/live]` `cd backend && .venv/Scripts/uvicorn app.main:app --port 8185
   --reload` boots a cold instance without error; `GET /api/health` still returns
   ready (open engine, zero tables); no schema is created at startup.

# Step 001 — User model, db/users layer, auth primitives

## Goal
Introduce the first persistent entity — the `User` model — its session-free
`db/users` access module, and the minimal bcrypt + per-user-JWT auth primitives
needed to hash the first admin's password and mint its first token.

## Source files
backend/app/models/user.py
backend/app/db/users.py
backend/app/services/auth.py

## Test files
backend/tests/db/test_users.py

## Interface intent
- **`UserRole`** (in `models/user.py`) — a string enum with exactly two members,
  `admin` and `author` (decision 5). No editor/player.
- **`User`** (in `models/user.py`) — a SQLModel table (`table=True`), the first
  persistent entity. Carries: an autoincrement integer primary key (decision 6);
  a unique, indexed `username`; a **nullable** password hash (`pwdhash`) where
  **null means the account is disabled** (keep this convention — feature 005
  relies on it; do **not** add a separate `disabled` boolean); a `role`
  (`UserRole`); a **nullable** per-user JWT signing key; and the two auth
  timestamps `last_login` and `last_key_update` (both nullable). **No `salt`
  column** (decision 2 — bcrypt embeds its own salt). No logic on the model.
- **`db/users` module** (in `db/users.py`) — the session-free access layer for
  the `users` table; opens/closes its own sessions internally via
  `get_standalone_session()`; never leaks ORM/session types. Provides:
  - **create** — persists a supplied `User` and returns it with its generated id
    populated.
  - **get_by_username** — returns the `User` with a given username, or `None`.
  - **get_by_id** — returns the `User` with a given id, or `None`.
  - **admin_exists** — returns whether ≥1 user with the `admin` role exists.
    **Must return `False` gracefully** when the `users` table does not yet exist
    (cold instance) — catch the missing-table error rather than propagating it.
- **auth primitives** (in `services/auth.py`) — no `session`/`select()` here:
  - **hash_password** — bcrypt-hashes a plaintext password, returns the hash
    string.
  - **verify_password** — checks a plaintext password against a stored bcrypt
    hash, returns a bool.
  - **generate_signing_key** — returns a fresh random per-user signing key
    (e.g. `secrets.token_hex(32)`).
  - **create_token** — mints a stateless JWT (HS256) for a given `User`, signed
    with **that user's** `jwt_signing_key`; the payload carries `user_id`,
    `username`, `role`, and an `exp` ~30 days out. Returns the token string.
    (Token *verification*, rotation-on-login, and logout are feature 004's — do
    not build them here.)

## Definition of done
1. `[test]` `hash_password` then `verify_password` returns `True` for the correct
   password and `False` for a wrong one. (Backs `US-001.AC-1`'s credential
   storage.)
2. `[test]` `create_token(user)` produces a JWT that decodes with the user's own
   `jwt_signing_key` to a payload carrying that user's `user_id` and `role`.
   (Backs `US-001.AC-1` sign-in.)
3. `[test]` `users.create` followed by `users.get_by_username` round-trips the
   stored user (same username and role). (Backs `US-001.AC-1`.)
4. `[test]` `users.admin_exists` returns `False` when no admin is present and
   `True` after an admin user is created. (Backs the readiness detection of
   `US-001.AC-1`/`US-002.AC-1`.)
5. `[test]` `users.admin_exists` returns `False` gracefully (no unhandled error)
   when the `users` table has not been created. (Backs `US-001.AC-1` cold-start
   detection.)

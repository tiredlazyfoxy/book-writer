# Step 003 — Setup service + User import/export codec

## Goal
Add the setup service that orchestrates create-DB-and-first-admin and
import-DB-to-bootstrap (with service-side validation and graceful import
rejection), and register the first persistent model's codec in the import/export
registry so a `users` archive round-trips.

## Source files
backend/app/services/setup.py
backend/app/services/db_import_export.py

## Test files
backend/tests/services/test_setup.py

## Interface intent
- **`SetupError`** (in `services/setup.py`) — a typed exception raised for every
  setup refusal (already-configured, password too short, password mismatch,
  corrupt import). Carries a human-readable message the route layer maps to an
  HTTP 4xx (step 004). No HTTP concerns in the service.
- **create_database** (in `services/setup.py`) — orchestrates first-admin
  creation. Given an admin username, password, and password confirmation:
  1. **refuses** (raises `SetupError`) if the instance is already configured
     (`is_db_ready()` true) — `US-001.AC-2`;
  2. **refuses** if the password is shorter than the **minimum length 8** —
     `US-001.AC-3`;
  3. **refuses** if password and confirmation differ — `US-001.AC-4`;
  4. otherwise calls `init_db()` (creates the schema), then via the auth
     primitives hashes the password and generates a signing key, builds an
     `admin`-role `User`, persists it through `db.users.create`, calls
     `set_db_ready(True)`, and returns the created admin `User`.
  No `session`/`select()` here — persistence goes through `db.users`; the token
  is minted at the route (step 004), not here.
- **import_database** (in `services/setup.py`) — bootstraps from an export.
  Given the raw archive bytes:
  1. wraps the import in error handling; on a corrupt/invalid archive or parse
     failure raises `SetupError` and **does not** call `set_db_ready` — the
     instance remains unconfigured (`US-002.AC-2`, decision 4);
  2. on success runs the import (via `db_import_export.import_all`, which itself
     calls `init_db()` first and rebuilds the vector index after), then calls
     `set_db_ready(True)` — the instance is configured (`US-002.AC-1`).
  Full transactional rollback of a partial import is **not** required (noted as a
  possible enhancement in `outcome.md`).
- **User codec** (in `services/db_import_export.py`) — a `to_dict`/`from_dict`
  pair for `User`: serialize the enum via its `.value` and restore via
  `UserRole(...)`; serialize datetimes via isoformat and restore them; treat
  nullable fields with a `.get`-style lookup. The codec **includes credentials**
  (`pwdhash` and `jwt_signing_key`) so restored accounts can authenticate —
  flag the security consideration in `outcome.md`.
- **`TABLE_REGISTRY` entry** (in `services/db_import_export.py`) — add the
  `("users", User, <to_dict>, <from_dict>)` tuple as the **first** entry (FK
  order — `users` before any dependent entity), extending the empty registry
  from 001. This is the "add a model = add its codec + one ordered registry
  tuple in the same change" contract.

## Definition of done
1. `[test]` `US-001.AC-1` — given an unconfigured instance, `create_database`
   with valid credentials creates the schema, persists exactly one `admin`-role
   user, and leaves the instance configured (`is_db_ready()` true); the returned
   admin has an id and a signing key.
2. `[test]` `US-001.AC-2` — given an already-configured instance
   (`is_db_ready()` true), `create_database` raises `SetupError` and does not
   create a second admin.
3. `[test]` `US-001.AC-3` — `create_database` with a password shorter than 8
   characters raises `SetupError` and leaves the instance unconfigured.
4. `[test]` `US-001.AC-4` — `create_database` with password ≠ confirmation
   raises `SetupError` and leaves the instance unconfigured.
5. `[test]` `US-002.AC-1` — `import_database` given a valid `users` archive
   (produced by `export_all` after seeding a user) restores the user(s) and
   leaves the instance configured (`is_db_ready()` true).
6. `[test]` `US-002.AC-2` — `import_database` given corrupt/invalid bytes raises
   `SetupError` and leaves the instance unconfigured (`set_db_ready` not called).
7. `[test]` The `users` codec round-trips through `export_all`/`import_all`:
   a user upserts back with the same username, role, and credential fields
   (`pwdhash`, `jwt_signing_key`) — idempotent on re-import. (Backs `US-002.AC-1`.)

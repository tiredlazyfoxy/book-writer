## Substrate this step binds to (from 002-scaffold — see `context.md`)
- `src/api/client.ts` `request<T>(url, {method?, body?, signal?})` — used for the
  JSON `getAuthStatus`/`setupCreate` calls. It injects Bearer **only when a token
  exists**, so the cold-instance setup calls carry no Authorization automatically
  — no separate no-auth variant is required.
- The multipart `setupImport` bypasses `request` (which forces JSON
  `Content-Type`): build `FormData`, POST via `fetch`, and set `Authorization`
  from the `getToken` accessor **only when present** — do **not** set
  `Content-Type` (the browser sets the multipart boundary). This mirrors how
  `sse.ts` bypasses `request` for a non-JSON body; `api/` may import `getToken`
  from `src/auth.ts` (one-way `api/` → `auth.ts`).
- `src/auth.ts` `getToken()` reads / `setToken()` writes `localStorage["token"]`.
- Navigation from the login entry uses `window.location.href` (the entry is
  outside React Router — sanctioned by `frontend.md`).

## Backend contract this step consumes (from step 004)
- `GET /api/auth/status` → `{ needs_setup: boolean }`.
- `POST /api/auth/setup/create` (JSON `{admin_username, password,
  password_confirm}`) → `{ token: string }` (auto-sign-in); refusals are HTTP 400
  with a `{detail}` message (normalized to `ApiError` by `client.ts`).
- `POST /api/auth/setup/import` (multipart field `file`) → `{ needs_setup:
  boolean }` (no token); corrupt archive → HTTP 400.
The `src/types/auth.d.ts` DTOs must match these shapes 1:1.

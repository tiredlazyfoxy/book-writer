## The composition-root exemption
`app/main.py` is not a route — it is the app composition/lifespan root. Its
calling `db.users.admin_exists()` + `set_db_ready(...)` directly at startup is
**not** a routes-layer violation. Routes and services keep their normal
boundaries; only the lifespan gets this latitude (matches the reference, which
does readiness detection in the engine layer).

## Readiness flag is process-global — test isolation
The flag lives at module scope in `db/engine.py`, so a `set_db_ready(True)` in
one test leaks into the next within a process. The conftest autouse reset
(`set_db_ready(False)` before each test) keeps steps 002–004 isolated. The
cold-instance detection tests (DoD-1/3) initialize the engine on a temp
`DbConfig` **without** calling `init_db` — the test-coder wires that directly
(the standard 001 temp-DB fixture *does* call `init_db`, so it is unsuitable for
the zero-tables cases).

## Health contract survives the deferral
`db.health.ping()` runs `SELECT 1`, which succeeds on an open engine even with no
tables — so removing eager `create_all` does not break `GET /api/health`. Note
this reconciliation for `outcome.md`.

See `context.md` for the readiness-flag definition and the feature-wide layering
rules.

# 006 — step context

Feature-wide facts (layer rules, the never-block-the-save rule, test harness) are in `context.md`.
The embedding surface is step 004's; the chunker, upsert/delete helpers and table-dimension accessor
are step 005's.

## Why a separate module rather than code inside `services/codex.py`

`services/codex.py` is already at the top of its size band after step 002, and the composition is a
different concern with a different failure contract (never-raise, best-effort) from the codex
service's (typed raises the route maps to statuses). Keeping them apart means the codex service's
call sites are two lines each and the index rules have one home that `017` and later corpora can
reuse.

## The maintenance table this step implements (`retrieval.md`)

| Event | Index action | Owner |
|---|---|---|
| Codex entry created / edited | delete this `source_id`'s chunks, re-chunk, re-embed, insert | **this step** |
| Codex entry archived | delete this `source_id`'s chunks | `017`, calling this module's drop operation |
| Chapter change applied | same delete-then-reinsert for that chapter | later stage |
| Book destroyed | delete by `book_id` | later stage |

Only row 1 is wired here. Row 2's operation is *exposed* here so `017` does not re-derive it.

## The failure taxonomy to catch

Step 004's error type covers no-provider, unreachable and dimension mismatch. Catch that type plus
whatever the sidecar can raise, and log at warning level with the entry id and the reason. Do **not**
catch bare `Exception` around the whole body — a programming error in the chunker should still fail
loudly in tests; catch the typed families.

`retrieval.md`'s reasoning for swallowing, worth keeping in the log message's framing: "Refusing an
author's save because an embedding server is unreachable would make writing a book depend on an
optional subsystem — and the index is derived, so the failure is recoverable by definition."

## Ordering inside `services/codex.py`

The call goes **after** the db-layer write returns, in both create and update. In `update` that means
after the version row and the entry mutation have both committed, so the entry the indexer reads
carries the new content and its `modified_at`.

The indexer takes the **entry row** (or the data it needs), not an entry id it must re-read — the
codex service already holds the freshly stored row.

## Avoiding a circular import

`services/codex.py` importing `services/codex_index.py` is a one-way edge and is fine. `codex_index`
must **not** import `services/codex.py`. If a shared helper is ever needed, it belongs in the db
layer or in `codex_index`, not back-imported.

## Test approach

Mock step 004's embed and dimension functions and drive step 005's sidecar for real against a
`tmp_path` vector dir (LanceDB runs locally; only the model call is fake). For DoD-3, assert the
entry's stored content is visible from the db at the moment the indexer's mock is invoked. For DoD-9,
assert no `asyncio` task remains pending after the service call returns.

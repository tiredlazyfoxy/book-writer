## The `llm` client's tool contract — verified in feature 011, all of it binding here

- `chat_with_tools(messages, *, tools_definitions, tools, system=None, max_loops=5, options=None,
  stream=False, on_delta=None, response_format=None) -> str` — a **client method**, returning the
  final assistant string only.
- **Pre-flight:** every name in `tools_definitions` must have a key in `tools`, or it raises
  `ValueError`. Build the two maps together, always.
- Tool callables may be sync or async. Arguments are JSON-decoded and applied as `func(**kwargs)` and
  validated against `inspect.signature(func).parameters`, so **a tool callable must accept exactly
  the JSON-schema field names as keyword parameters**. There is **no per-request context argument** —
  anything a delegation needs (the sub-agent row, the parent turn's server/key/model) must be closed
  over or bound with `functools.partial`.
- **A tool that raises aborts the whole loop** (wrapped as `RuntimeError`) and the error is *not* fed
  back to the model. Exhausting `max_loops` also raises `RuntimeError`. This is why the delegation
  callable returns error strings.
- `pydantic_to_openai_tool(name, description, schema)` is a sync module function returning
  `{"type":"function","function":{…,"parameters": schema.model_json_schema()}}`.
- `LLMClient` has `__aenter__` / `__aexit__` and **no standalone `close()`**; connection failures are
  **not** wrapped in `LLMError` — raw `aiohttp.ClientError` subclasses propagate.

## The never-raise pattern to copy

`backend/app/services/web_search.py:39 async def web_search(query: str, num_results: int = 5) -> str`
never raises; it returns an error string. Every tool in this feature copies that contract exactly.

## Tool-name derivation

OpenAI-style function names are conventionally `^[a-zA-Z0-9_-]{1,64}$`. A sub-agent's `name` is a
free admin-entered string, so the derived name must be sanitised, not passed through. Deriving rather
than storing keeps `SubAgent` unchanged (no schema, no codec, no `012` coordination) at the cost of
possible collisions — which DoD-12 and DoD-13 make explicit and observable instead of silent.

## Structural bound, restated

There is **no `subagent_subagent` table**: modes select sub-agents, sub-agents select tools only. The
one-level bound is therefore unrepresentable-otherwise, not merely enforced — the nested call's tool
list comes from `subagent_tool` rows resolved against `TOOL_REGISTRY`, and nothing else can enter it.

## Size note

This is one of the feature's three heavy steps (roughly 150 lines of source change across the new
module and two small call-site edits). It is one contract — build the synthetic tools, run the nested
loop — and splitting the builder from the callable would freeze a tool list nothing can invoke.

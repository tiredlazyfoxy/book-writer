`run_turn`'s current order: persist the user message → `books.get_by_id` →
`compose_system_prompt(...)` (349) → `build_tool_bindings(resolve_tools(None))` (355) → history →
sampling → an inner `drive()` doing `async with create_model_client(...) as client: await
client.chat_with_tools(...)` → frames pumped over an `asyncio.Queue` → persist one assistant
`ChatMessage` → `done`.

**`run_turn` currently takes only `(context, prompt)`.** The subject fields arrive on `TurnRequest`,
so either they are threaded through `prepare_turn`/`TurnContext` or `run_turn` gains a parameter —
the skeleton agent picks the exact shape; the constraint is that
`backend/app/routes/chats.py:194`'s handler already has the parsed `TurnRequest` in hand and needs no
new path parameter.

## Backward compatibility gotcha

Feature `011`'s turn tests exercise a turn with a bare `TurnRequest`. Under decision 6 that path now
resolves `BASE_TOOL_NAMES` instead of the whole registry — which is the **same set** today, because
`TOOL_REGISTRY` holds only `web_search`. The behaviour therefore does not change until step 009 adds
registry entries, and `011`'s tests must keep passing unmodified.

# 009 — Codex assistant tools: semantic search and entry read

## Goal

Give the assistant the codex: a semantic `codex_search` over the sidecar and a read tool for one
entry, registered into `TOOL_REGISTRY` as the **first mode-gated tools** and bound per turn to a tool
context carrying the turn's book. Delivers UC-078 pull-only — the relevance `_TBD:` stays open.

## Interface intent

**`backend/app/services/tools.py`** — two additive changes and two registry entries.

- **a tool-context value** — a frozen dataclass carrying what a bound tool needs from the turn it
  runs inside. In this step it carries the turn's **book id**. (Step 010 extends it with the
  content-pane subject and the frame emitter.)
- **`ToolDef` gains an optional binder** — a callable that, given the tool context, returns the
  callable to dispatch. When a `ToolDef` has a binder, `build_tool_bindings` calls it; when it does
  not, the existing `callable` field is used unchanged, so `web_search`'s context-free entry is
  untouched. Reason: the `llm` client dispatches `func(**kwargs)` with no context argument, so a
  per-turn value must be closed over.
- **`build_tool_bindings` takes the tool context** as an argument and uses it for bound tools. This
  is a signature change with exactly one caller (`chat_turn.run_turn`).
- **two new `TOOL_REGISTRY` entries** — `codex_search` and the entry-read tool, both bound. They are
  the first entries that a mode must *select* to reach; under step 007's gating a mode with no
  `mode_tool` row for them cannot see them.

**`backend/app/services/codex_tools.py`** — new module holding the two callables and their arg
schemas.

- **`codex_search`** — arguments: a free-text query and an optional result limit. It embeds the query
  through `services/embedding.py`, searches the sidecar restricted to the **`codex_entry` source
  kind** and to the **turn's book id as a hard filter**, and returns a compact text block listing each
  hit's entry id, kind, name (when present) and matched chunk text, ordered nearest first. The book
  scope comes from the tool context, never from a model-supplied argument — the model cannot ask for
  another book's codex because there is no parameter through which to ask.
- **the entry-read tool** — arguments: one entry id. It loads the entry, refuses an id that is
  unknown or belongs to another book, refuses an **archived** entry (the index drops archived entries,
  so the two tools present the same world), and otherwise returns the entry's kind, name and body as
  text.
- **both never raise.** No embedding provider, an empty index, a transport failure, a bad id — each
  returns an informative string the model can act on. `retrieval.md`'s degrade rule: "the assistant
  loses pulled context, it does not fail."

**`backend/app/services/chat_turn.py`** — construct the tool context for the turn (the book is
already resolved there for prompt composition) and pass it to `build_tool_bindings`.

## Definition of done

1. `[test]` `codex_search` embeds the query text and searches the sidecar with the **turn's** book id;
   an entry in another book that is the nearest neighbour of the query is never returned.
   (`retrieval.md` → hard filter; US-085.AC-1)
2. `[test]` `codex_search` restricts to the `codex_entry` source kind, so a future corpus in the same
   table cannot leak into a codex answer. (`retrieval.md` → Query surface)
3. `[test]` The result text carries each hit's **entry id** alongside its snippet, so the model can
   follow up with the read tool. (UC-078)
4. `[test]` `codex_search` honours its result limit and returns hits nearest-first.
5. `[test]` With **no embedding provider configured**, `codex_search` returns an informative string
   and does not raise. (`retrieval.md` → Failure modes; `web_search` contract)
6. `[test]` With an empty or stale index, `codex_search` returns a "nothing found" string rather than
   an error. (`retrieval.md` → Failure modes, row 4)
7. `[test]` An embedding transport failure returns an error string and does not raise. (`web_search`
   contract — a raising tool aborts the parent loop)
8. `[test]` The read tool returns the kind, name and body of an entry in the turn's book.
   (UC-078 follow-up)
9. `[test]` The read tool given an entry id from **another** book returns an error string and leaks
   no content of that entry. (US-085.AC-1)
10. `[test]` The read tool given an unknown or malformed id returns an error string and does not
    raise.
11. `[test]` The read tool refuses an **archived** entry with an informative string. (consistency
    with the index, which drops archived entries)
12. `[test]` Both tools are present in `TOOL_REGISTRY` and are bound with the turn's context at
    binding time; a mode whose `mode_tool` rows do not select them builds neither into the
    definitions. (US-111.AC-2)
13. `[test]` `web_search`'s existing context-free entry still binds and dispatches unchanged through
    the widened `build_tool_bindings`. (regression guard on `011`'s shipped tool)
14. `[manual/live]` With a live embedding server and an indexed codex, a chat in `edit-character` mode
    with `codex_search` selected returns entries relevant to the prompt. (UC-078 / US-089.AC-1)

# 004 — step context

Feature-wide facts (layer rules, typed-error convention, test harness, no-network rule) are in
`context.md`.

## The pieces this module composes — all already shipped

**Designated server lookup.** `backend/app/db/llm_servers.py` exposes
`async def get_embedding_server() -> LlmServer | None` (around line 103) beside `get_by_id` and
`get_active`. At most one row may hold the designation; `FEAT-004 / UC-014` enforces that
clear-all-then-set. The row carries `embedding_model` (may be null or blank), `base_url`,
`backend_type` and `api_key`.

**Key resolution.** `backend/app/services/secrets.py` exposes
`def resolve_env_ref(value: str | None) -> str | None` (line 24): a stored `"$NAME"` is looked up in
the environment, and a missing variable raises
`LlmServerError(LlmServerErrorReason.env_not_set, …)`. A non-`$` value passes through.

**The import-direction rule this module must respect.** `services/llm_servers.py` reaches
`services/secrets.py` only through a **function-local import** (see `llm_servers.py:351`) to keep the
service graph acyclic. The canonical use-time pattern — resolve the ref, then construct the client —
is at `llm_servers.py:345-363`. Copy that pattern; if a module-level import of `secrets` creates a
cycle, use the same function-local form and say so in a comment.

**Client construction.** `backend/app/services/llm_servers.py` exposes
`def create_model_client(server: LlmServer, resolved_key: str | None, model: str) -> LLMClient`
(line 307). It branches through `_construct_client` (line 272) on `backend_type`: `"openai"` →
`OpenAIAPIClient`, otherwise `LlamaSwapAPIClient`. `_VALID_BACKEND_TYPES = {"llama-swap", "openai"}`.
**It must be used as `async with`** — `LLMClient` implements `__aenter__` / `__aexit__` and has **no
standalone `close()`**. Do **not** use `_create_client` (line 294): it hardcodes `model=""` and is a
frozen test seam for `list_models()`.

**The client's embedding surface.** The `llm` package's clients expose
`async def embed(self, text, *, options=None) -> List[float]` and
`async def embed_batch(self, texts, *, options=None) -> List[List[float]]`, implemented on
`OpenAIAPIClient` and `LlamaSwapAPIClient` (and ollama, which this repo does not support).

**Error types that must not escape.** Connection failures are **not** wrapped by the `llm` library —
raw `aiohttp.ClientError` subclasses propagate, alongside `LLMError`. `services/chat_turn.py`
already treats `(aiohttp.ClientError, LLMError, ValueError, RuntimeError)` as its turn-failure set;
mirror that breadth when converting to the unreachable reason.

## Who consumes what, later

- **Step 005** calls the dimension probe before creating the sidecar table, and the batch embed
  during a full rebuild — but it reaches them through an **injected callable** set at
  `init_vector`, because `db → services` is forbidden. This module does not know about `db/vector.py`
  and must not import it.
- **Step 006** calls the batch embed and the dimension check on every codex save, wrapping every
  error so the author's save is never blocked.
- **Step 009** calls the single-text embed to turn a `codex_search` query into a vector.

## Already-shipped gate that becomes load-bearing

`backend/app/services/db_admin.py:250 rebuild_vector_index()` already validates that
`llm_servers.get_embedding_server()` is not `None` **and** that `server.embedding_model` is truthy,
raising `DbAdminError(DbAdminErrorCase.no_embedding_provider)` → **400** at
`backend/app/routes/admin/db.py:51`. That validation stays exactly where it is; this module's
no-provider reason is the *service-side* equivalent for callers that are not the admin rebuild
endpoint. Do not move, duplicate or weaken the admin gate.

`backend/app/db/import_export_queries.py:62 run_vector_rebuild()` deliberately **bypasses** that
gate at the tail of `import_all` — which is why the no-provider path must be a clean typed raise that
a caller can swallow, not a crash.

## Test approach

No network. Mock `app.db.llm_servers.get_embedding_server`, and mock the client factory so the
returned object is an async-context-manager double whose `embed` / `embed_batch` are controllable and
whose `__aexit__` can be asserted. For DoD-4/5, drive `resolve_env_ref` through
`monkeypatch.setenv` / `delenv` rather than mocking it, so the real `$ENV` semantics are exercised.

# 006 — Incremental index maintenance on codex writes

## Goal

Keep the sidecar current as the author writes: a codex create or edit re-chunks, re-embeds and
replaces that entry's chunks, **after** the SQLite commit and **best-effort**, so a missing or broken
embedding server can never block a save.

## Interface intent

**`backend/app/services/codex_index.py`** — new module, the service that composes step 004's embedder
with step 005's sidecar. `retrieval.md` puts exactly this composition in `services/`: "the LanceDB
session and table handles live in `db/vector.py`; `services/embedding.py` owns the model call; a
service composes the two."

- **an index-entry operation** — takes one codex entry, runs step 005's chunker over it, embeds the
  chunks in one batch, checks the returned vectors against the live table's dimension, and replaces
  that entry's chunks through the sidecar's upsert. Reports success or failure as a **return value**;
  it **never raises**. Every failure — no provider, unreachable, dimension mismatch, a sidecar error —
  is caught and logged with the entry id and the reason, and the index is left stale until the next
  rebuild.
- **a drop-entry operation** — removes one entry's chunks, same never-raise contract. Used
  internally when an entry becomes unindexable, and exposed for `017.codex-archive-restore` to call
  on archive without re-deriving the rule.
- **an archived-entry rule** — an archived entry is never indexed; if the operation is called on one
  it drops the entry's chunks instead of inserting. `retrieval.md`: archived entries leave the index
  rather than being filtered at query time.

**`backend/app/services/codex.py`** — two call sites added, nothing else changed.

- After a **create** commits, index the new entry.
- After an **update** commits, index the updated entry.
- Both calls are **awaited inside the request**, after the db write returns and before the service
  returns its DTO. No background task, no queue: `retrieval.md` rejects a queue explicitly for a
  single-instance app over local SQLite.
- Neither call may change what the service returns or raises. A failed index leaves a successful
  save.

## Definition of done

1. `[test]` Creating an entry results in that entry's chunks being written to the sidecar with the
   `codex_entry` source kind and the entry's book id and (stringified) id. (`retrieval.md` →
   Incremental maintenance; supports UC-078 / US-089.AC-1)
2. `[test]` Editing an entry deletes the previous chunks and inserts the new ones, so shortening a
   body leaves no orphan chunk from the longer version. (`retrieval.md` → delete-then-reinsert)
3. `[test]` The index write happens **after** the SQLite write: at the moment the indexer is invoked,
   the entry is already readable from the db with its new content. (ordering is load-bearing)
4. `[test]` When no embedding provider is configured, the create and the update both **succeed** and
   return their DTOs; the index is simply not updated. (`retrieval.md` → "Index maintenance never
   blocks the author's save"; US-079.AC-1)
5. `[test]` When the embedding server is unreachable, the save still succeeds and the failure is
   logged rather than raised. (`retrieval.md` → Failure modes, row 2)
6. `[test]` When the embedder returns vectors of a different length than the live table's dimension,
   the **index write** is refused, the save still succeeds, and nothing malformed is inserted.
   (`retrieval.md` → Failure modes, row 3)
7. `[test]` A sidecar error (the table missing or the write failing) is likewise caught, logged, and
   does not surface to the caller. (`retrieval.md` → recoverable by rebuild)
8. `[test]` Indexing an archived entry drops its chunks instead of inserting any. (`retrieval.md` →
   archived entries leave the index)
9. `[test]` The index operation completes before the codex service returns — no task is scheduled and
   nothing is left pending after the call. (`retrieval.md` → "No background job queue is
   introduced")
10. `[test]` Neither index operation ever raises, for any of the failure modes above. (never-raise
    contract)
11. `[manual/live]` With a live embedding server, saving a codex entry makes its content reachable
    through the sidecar search immediately, with no admin rebuild. (UC-078)

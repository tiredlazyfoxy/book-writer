## `routes.tsx` today

- `/characters`, `/locations` and `/facts` each render
  `<SubjectPlaceholderPage heading=… owner="013.codex"/>`, where
  `SubjectPlaceholderPageProps = { heading: string; owner: string }`.
- `/codex/:id` renders `<CodexEntryItemRoute/>` — keyed `key={id}` — which today renders the same
  placeholder with `owner="013.codex"`.

This step replaces the three list placeholders and adds `/codex/new`. **`/codex/:id`'s element stays
the placeholder until step 012** — do not change it here, and do not delete `SubjectPlaceholderPage`
(the other placeholder routes still use it).

React Router 7 ranks a static segment above a dynamic one automatically, but declare `/codex/new`
before `/codex/:id` anyway for readability and to match the backend convention.

## `navItems.ts` — read-only in this step

`WorkPaneTarget = "content" | "chat"`;
`interface WorkNavItem { path; label; icon; extraActiveSegments?; paneTarget }`;
`WORK_NAV_ITEMS` holds seven entries, of which Characters (`/characters`, `IconUsers`), Locations
(`/locations`, `IconMapPin`) and Facts (`/facts`, `IconInfoCircle`) all carry
`paneTarget: "content"`. Also `workNavHref(bookId, item)` and
`isWorkNavItemActive(pathname, bookId, item)`.

The navigator entries already exist with their paths and icons. **Add no nav item.**

## `src/api/` conventions to copy

`frontend/src/api/client.ts`:

- `class ApiError extends Error { constructor(public status: number, message: string, public
  details?: unknown) }`
- `interface RequestOptions { method?; body?; signal? }`
- `async function request<T>(url, opts): Promise<T>` — on 401 with a token it performs **one** silent
  refresh and retries; a 204 resolves to `undefined`.
- plus `authHeaders()`, `refreshAuthToken()`, `throwApiError(res)`.

`frontend/src/api/chats.ts` is the shape to mirror: `const BASE = "/api/books"`, string ids
interpolated, trailing `signal?: AbortSignal`, `{items: […]}` unwrapped in the module and **not**
modelled in the `.d.ts`.

## `src/types/` today

`admin, auth, books, chats, common, db, health, llmServers` — **no codex types**.
`common.d.ts` holds `ApiErrorBody` and `ISODateString`. The convention: hand-written, wire-exact
`snake_case`, **ids are `string`**, unions written as the backend's enum literals.

## Query params — the repo's first use

`useSearchParams` / `URLSearchParams` return **zero matches anywhere in the frontend today**. This
step is the first consumer, so there is no precedent to copy and `frontend.md`:192 is the governing
rule: the query string is written **in the event handler that changed it**, never by a `useEffect`
watching it. Reading it once on mount to seed the initial load is fine — that is the mount effect, not
a watcher.

## Test gotchas

- `frontend/vitest.config.ts` sets `globals: false`, so every spec imports `describe` / `it` /
  `expect` / `vi` from `"vitest"`.
- `frontend/tests/support/render.tsx` exposes `renderWithProviders(ui, { route? })`; routes passed in
  are **basename-stripped**.
- Specs mock the `api/` module in module-factory form (`vi.mock("../../src/api/codex", () => ({…}))`),
  never `fetch`; `ApiError` is imported **real** from `../../src/api/client`.
- **Any spec that mounts `WorkRoutes` or `WorkspaceShell` must also mock `../../src/api/chats`**
  (`listChats` / `listModelOptions` → `[]`), re-armed in `beforeEach`, or the chat pane's own load
  will throw.

## Size note

This step runs to roughly 200–230 lines of source across five files. The three list routes share one
parameterized page deliberately: splitting by kind would produce three near-identical steps whose only
difference is a literal, and the DTO module has no other consumer until it lands.

# 003 — step context

Feature-wide route conventions (prefix ownership, return-annotation response models, the 401/404/403
taxonomy, `book_id` consumed by the dependency) are in `context.md`. The service's reason enum and
error class are step 002's, described in `002.codex-schemas-service.md`.

## The two routers to copy from

- **`backend/app/routes/chats.py`** — the closest analogue: `APIRouter(prefix="/api/books",
  tags=["chats"])`, every path starting `/{book_id}/…`, handlers taking `access: authz.BookAccess =
  Depends(authz.book_access)` and **never declaring `book_id`**, payload parameter first when there
  is a body.
- **`backend/app/routes/admin/db.py`** — the error-mapping shape: a module-level
  `_<X>_ERROR_STATUS: dict[ReasonEnum, int]` and a `_map_<x>_error(err) -> HTTPException`, one
  `try/except` per handler.

`backend/app/routes/books.py` carries the in-code note that **static path segments must be declared
before `/{param}` routes** — it is load-bearing in FastAPI's matcher, not style.

## Response-model convention

Response models are declared as the handler's **return annotation**. Do not pass `response_model=`
to the decorator — no router in this repo does.

## Existing status precedents

- **409** already exists in the repo for a duplicate username (`services/admin.py` →
  `username_taken`); this feature adds the second 409, for a stale `modified_at`.
- **403** is produced today only by `authz.BookAuthorizationError` mapping. This step adds a second
  producer — the proposal-mode refusal — through the reason→status dict, so both paths land on the
  same status with different detail bodies.

## `main.py` wiring

`backend/app/main.py` includes routers bare (`app.include_router(chats.router)`); it also calls
`await vector.init_vector(settings.lancedb_dir)` at line ~65 during startup. **Step 005 changes that
call**; this step must not touch it — restrict the edit to the router include.

## Route-test seeding

`backend/tests/routes/test_chats.py` holds the helpers to copy verbatim: `_now()`,
`_auth_header(token)`, `_seed_user`, `_seed_author`, `_seed_private_book`, `_add_co_author`. Auth is
real — mint a JWT with `auth.create_access_token(user)`.

For DoD-13 (a reader on a public book) there is no existing `_seed_public_book` helper in
`test_chats.py`; seed a book with `visibility = public` alongside the private one. For DoD-11 seed a
book with `collaboration_mode = proposal`.

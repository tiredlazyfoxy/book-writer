## The two db modules as they stand today

`backend/app/db/codex_entries.py` contains **exactly three** functions and nothing else:

- `create(row: CodexEntry) -> CodexEntry`
- `get_by_id(entry_id: int) -> CodexEntry | None`
- `list_by_book(book_id: int) -> list[CodexEntry]` — **no ordering, no filters**

`backend/app/db/codex_entry_versions.py` contains exactly:

- `create(row: CodexEntryVersion) -> CodexEntryVersion`
- `get_by_id(version_id: int) -> CodexEntryVersion | None`
- `list_by_entry(entry_id: int) -> list[CodexEntryVersion]` — **unordered**

Both modules are session-free: sessions are created internally and detached rows are returned. Copy
the surrounding module's existing session/refresh idiom rather than inventing one.

## The two table models (feature 008, unchanged by this step)

`backend/app/models/codex_entry.py`

- `CodexKind(str, enum.Enum)` = `character` | `location` | `fact`
- `CodexEntry`, `__tablename__ = "codex_entries"`:
  `id` (snowflake PK via `generate_id`), `book_id` FK `books.id`, `kind: CodexKind` (required),
  `name: str | None = None`, `body: str`, `archived: bool = False`,
  `author_id: int` FK `users.id` (non-null, the **original creator**),
  `modified_by: int | None` FK `users.id`, `created_at: datetime | None`,
  `modified_at: datetime | None`.
- Module docstring: "No vector / LanceDB registration here — codex vector indexing defers to
  `013.codex`" (step 005 acts on that, not this step).

`backend/app/models/codex_entry_version.py`

- `CodexEntryVersion`, `__tablename__ = "codex_entry_versions"`:
  `id`, `entry_id` FK `codex_entries.id`, `name: str | None`, `body: str`, `kind: CodexKind`,
  `author_id: int`, `generation: int` (**required**, 1-based), `created_at`.
- Docstring: `CodexEntry.modified_by` and `CodexEntryVersion.generation` are "maintained by the
  feature-013 service, round-tripped only here" — step 002 is that service; this step only supplies
  the `next_generation` lookup it needs.

**No column is added by this step**, so no JSONL codec changes: `_codex_entry_to_dict` /
`_dict_to_codex_entry` / `_codex_entry_version_to_dict` / `_dict_to_codex_entry_version` and both
`TABLE_REGISTRY` entries stay exactly as they are.

## `services/authz.py` as it stands today

- `@dataclass(frozen=True) class BookAccess` with fields
  `book_id, user_id, role, book_state, visibility, collaboration_mode`.
- `AccessRole` = `owner` | `co_author` | `reader` | `none`.
- `Capability` currently holds **seven** members and **no codex entry**:
  `read_book, view_book_detail, archive_book, transfer_ownership, add_member, remove_member,
  set_visibility`.
- `_CAPABILITY_MATRIX: dict[Capability, frozenset[AccessRole]]`.
- `resolve_book_access(book_id: int, user: User) -> BookAccess` — raises 404 for a missing book or a
  caller with no relationship to a private one.
- `book_access(book_id: int, user: User = Depends(auth_service.get_current_user)) -> BookAccess` —
  **the** route dependency.
- `require(access: BookAccess, capability: Capability) -> None` — raises
  `BookAuthorizationError(capability, role)`.

Add enum members and matrix rows only. Do **not** add a `(mode)` notion to the matrix: it maps
capability → `frozenset[AccessRole]` and has no vocabulary for "and the book is in free mode". That
rule belongs to step 002's service, the same way `011` put chat row-ownership in `services/chats.py`
rather than inventing a matrix concept for it.

## Ordering gotcha

SQLite sorts `NULL` **before** non-null values by default in `ORDER BY name ASC`. The required order
is name-ascending with **null-named rows last** (facts have no name), so the ordering expression must
say so explicitly rather than relying on the default.

## Test seeding

`backend/tests/db/` specs use the `db` fixture from `backend/tests/conftest.py` and insert rows
through the module under test plus the sibling `db/` modules (`books`, `users`) — there is no HTTP in
a db-layer spec. For the authz spec, construct `BookAccess` instances directly; it is a frozen
dataclass and needs no database.

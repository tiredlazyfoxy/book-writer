# 012 — The codex entry page: draft-until-saved, restore buffer, 409 reconciliation

## Goal

Build the content-pane page for one codex entry — load, edit, save, the per-item restore buffer keyed
on `modified_at`, the blank/create path, and the stale-buffer reconciliation view a 409 turns into.
Delivers UC-069 / UC-070 on the surface plus UC-092 / US-107.

## Interface intent

**`frontend/src/work/pages/codexEntryPageState.ts`** — a `CodexEntryPageState` class plus external
effect functions.

- **Mode**: the page serves both an existing entry (an id from the route) and a **blank** one
  (`/codex/new` with the kind in a query param). The state carries which, and the blank case has no
  loaded server entry and no buffer base version until the first save.
- **Async trio** for the loaded entry (`entry` / `entryStatus` / `entryError`), plus a separate
  status for the save.
- **Draft fields** — the name draft and the body draft, plus a `get` computed for dirtiness against
  the loaded entry.
- **Validation as `get` computeds** — a character or location needs a non-blank name; a fact must have
  none. No Mantine `useForm`. Server errors are merged separately from local validation.
- **Reconciliation state** — after a 409: the server's current entry (re-fetched) held beside the
  author's draft, plus a flag that the page renders the reconciliation view instead of the editor.
- **An apply-draft entry point** — a method that sets one field's draft text from an external source
  and runs the same dirty/buffer path a keystroke does. It exists here so **step 013** can hand the
  assistant's canvas draft to the page without the page knowing where it came from.
- **External functions** `(state, args, signal)`: load the entry (and restore a matching buffer),
  edit a field (updates the draft and writes the buffer), save (create or update), discard the buffer,
  and resolve a reconciliation by taking one side.

**Restore-buffer behaviour** (`frontend/src/work/restoreBuffer.ts`, already complete and unit-tested —
consumed, not modified):

- key `(bookId, "codex-entry", entryId)`; `baseVersion` is the entry's **`modified_at` ISO string**;
- on load: read the buffer; if its `baseVersion` matches the server's `modified_at`, restore the
  draft; if it does **not** match, that is a stale buffer — go straight to the reconciliation view
  without a save attempt;
- on every draft change: write the buffer, surfacing the eviction outcome to the author when the
  write reports one;
- on a successful save: clear the buffer.

**Save behaviour**:

- an existing entry saves through the update endpoint carrying the **loaded** `modified_at` as the
  expected version;
- a blank entry saves through the create endpoint with the kind from the query param, then navigates
  to the created entry's route;
- a **409** re-fetches the server entry and switches to the reconciliation view — never an
  auto-merge;
- a **403** (the proposal-mode refusal from decision 3, or a lost capability) surfaces the server's
  reason text to the author and leaves the draft and its buffer intact.

**`frontend/src/work/pages/CodexEntryPage.tsx`** — one `observer` component. Renders the name field
(hidden for facts), the body editor, save / discard actions, the validation and server-error
surfaces, the read-only banner for an archived entry using `resolveEditability`'s `readOnlyReason`
from `frontend/src/work/subject.ts` (consumed, not modified), and the reconciliation view: the
server's current text **against** the buffered draft with an explicit per-side choice. `useState`
holds the state instance; the page-level `useEffect` loads on mount and aborts on unmount.

**`frontend/src/work/routes.tsx`** — point `/codex/:id` (already keyed `key={id}`) and the
`/codex/new` route reserved in step 011 at this page.

## Definition of done

1. `[test]` Mounting on `/codex/:id` loads the entry and renders its name and body. (UC-070 step 1;
   US-105.AC-2)
2. `[test]` Editing the body marks the page dirty and writes the restore buffer under the
   `(bookId, "codex-entry", id)` key with the entry's `modified_at` as `baseVersion`. (UC-092 /
   US-107.AC-1)
3. `[test]` Returning to an entry whose buffer's `baseVersion` matches the server's `modified_at`
   restores the buffered draft rather than the server text. (US-107.AC-1, US-107.AC-2)
4. `[test]` Nothing reaches the server until Save is pressed — editing and navigating away makes no
   write call. (US-107.AC-4, US-088.AC-2, US-103.AC-3)
5. `[test]` Save on an existing entry calls the update endpoint with the loaded `modified_at` and
   clears the buffer on success. (UC-070 / US-079.AC-1)
6. `[test]` A 409 from Save renders the **reconciliation view** showing the server's current text
   beside the buffered draft, with no auto-merge and no silent overwrite.
   (`frontend-workspace.md` → "Returning to a stale buffer")
7. `[test]` Loading an entry whose buffer's `baseVersion` no longer matches the server's
   `modified_at` opens the reconciliation view directly, without attempting a save.
   (`frontend-workspace.md`)
8. `[test]` Taking the server's side in the reconciliation view discards the draft and clears the
   buffer; taking the draft's side re-saves it against the **new** `modified_at` and succeeds.
   (`frontend-workspace.md` — the author reconciles manually)
9. `[test]` An **archived** entry renders read-only with the reason text from
   `subject.ts:resolveEditability`, and the save action is unavailable. (`frontend-workspace.md` →
   editability table)
10. `[test]` A `fact` entry renders no name field and saves with no name; a `character` or `location`
    keeps Save disabled until a non-blank name is present. (US-078.AC-1, US-078.AC-2)
11. `[test]` The blank route creates a new entry on Save with the kind from the query param and then
    navigates to the created entry's route. (UC-069, UC-076 precondition)
12. `[test]` A 403 from Save surfaces the server's reason text — including the proposal-mode
    refusal naming FEAT-010 — and leaves the draft and the buffer intact. (decision 3; US-079.AC-2
    knowingly unmet)
13. `[test]` A buffer write that reports an eviction tells the author which buffers were evicted, and
    the **current** item's buffer is never the victim. (`frontend-workspace.md` → quota limitation)

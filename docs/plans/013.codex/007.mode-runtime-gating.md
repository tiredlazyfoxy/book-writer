# 007 — Mode determination, the mode prompt layer, and real tool gating

## Goal

Make the turn subject-aware: `TurnRequest` carries the content-pane subject, a new
`services/assistant_runtime.py` resolves it to one of FEAT-020's five modes, `run_turn` finally passes
the mode's prompt into `compose_system_prompt`, and `011`'s `resolve_tools(None)` seam is replaced by
real `mode_tool` gating plus the `BASE_TOOL_NAMES` rule for a subject with no mode.

## Interface intent

**`backend/app/models/schemas/chats.py`** — `TurnRequest` gains three **optional** fields beside its
existing `prompt`: the subject kind, the subject id (a string, null for a blank entry that has no row
yet), and the codex kind. All three default to absent, so `011`'s existing callers and tests keep
working unchanged. The subject-kind field is a **literal union**, not a free string, mirroring the
frontend's `SubjectKind` values in `frontend/src/work/subject.ts`.

**`backend/app/services/assistant_runtime.py`** — new module. Pure runtime policy; it reads the
FEAT-020 `db/` modules directly and never touches `services/assistant_config.py` (that is `012`'s).

- **a base tool-name constant** — `BASE_TOOL_NAMES`, holding exactly `web_search`. This is the
  allowlist for a subject that has **no** mode (book state, any list, the chats view). See
  `context.md` decision 6 for why a null mode does not mean "the whole registry".
- **a resolved-subject value** — the subject kind, the loaded codex entry if there is one, and the
  resolved mode key (or none). Frozen dataclass, per the no-free-dictionaries rule.
- **subject resolution** — takes the access context and the three request fields. When the subject is
  a codex entry **with** an id, it loads the row and treats an entry belonging to a different book as
  no subject at all. When the subject is a codex entry with **no** id (UC-076's blank entry), it uses
  the request's codex kind. For an existing entry, the **row's** kind wins and the request's codex
  kind is ignored.
- **mode determination** — maps the resolved subject to a mode key per `assistant-config.md`'s table:
  codex entry of kind `character` → `edit-character`, `location` → `edit-location`, `fact` →
  `edit-fact`. Every other subject, and the absence of a subject, resolves to **no mode**. Chapter
  subjects are `015`/`016`'s and resolve to no mode here.
- **mode prompt lookup** — given a mode key, returns that `AssistantMode`'s `system_prompt`, or none
  when the key is absent, the row is missing, or the prompt is null/blank (US-110.AC-4: an empty
  prompt contributes nothing).
- **allowed tool names** — given a mode key: with a mode, exactly that mode's `mode_tool` rows'
  `tool_name` values, **including the empty case** (zero rows ⇒ zero tools, per `012`'s settled
  rule); with no mode, `BASE_TOOL_NAMES`.

**`backend/app/services/chat_turn.py`** — three edits inside `run_turn`, no restructuring.

- Resolve the subject and mode from the `TurnRequest` fields near the top of the turn, before the
  prompt is composed.
- Pass the mode prompt as the `mode=` layer of `compose_system_prompt`, joining the `base=` and
  `book=` layers it already passes (line ~349). The composer already implements the
  `base → mode → book → chapter` order and drops empty layers — no change to
  `services/prompt_composition.py`.
- Replace `resolve_tools(None)` (line ~355, the documented `013.codex` seam) with `resolve_tools`
  over the resolved allowlist. `services/tools.py` itself is **not** modified in this step: its
  `None ⇒ whole registry` branch stays, unused by the turn, and its skip-and-log behaviour for an
  unknown name is what `assistant-config.md` already prescribes.

## Definition of done

1. `[test]` A turn whose subject is a codex entry of kind `character` resolves mode `edit-character`;
   `location` resolves `edit-location`; `fact` resolves `edit-fact`. (`assistant-config.md` → Mode
   determination; UC-095 runtime half)
2. `[test]` A turn with a codex-entry subject and **no** id resolves the mode from the request's
   codex kind. (UC-076 — a blank entry has no row yet)
3. `[test]` For an existing entry the row's kind decides the mode and a conflicting codex kind in the
   request is ignored. (`context.md` → shared-canvas design point 1)
4. `[test]` A subject id naming an entry in **another** book resolves to no subject and no mode — no
   cross-book content is loaded. (US-085.AC-1)
5. `[test]` A book-state subject, a list subject, the chats subject and an absent subject all resolve
   to **no mode**. (`assistant-config.md`: subjects outside the five fall outside the mode set)
6. `[test]` A chapter subject resolves to no mode in this feature. (`write-chapter` / `close-chapter`
   are `015`/`016`'s)
7. `[test]` A resolved mode's `system_prompt` reaches `compose_system_prompt` as its **mode** layer,
   and the composed prompt carries base, then mode, then book, in that order. (US-110.AC-3;
   `assistant-config.md` → composition order)
8. `[test]` A mode whose `system_prompt` is null, empty or whitespace contributes **no section** to
   the composed prompt — no header, no blank block. (US-110.AC-4)
9. `[test]` With a mode, only that mode's `mode_tool` rows are built into the tool definitions; a
   registry tool the mode did not select is absent from both the definitions and the callable map.
   (US-111.AC-2)
10. `[test]` A mode with **zero** `mode_tool` rows yields zero tools — an empty allowlist, not the
    whole registry. (`012` settled rule)
11. `[test]` With **no** mode, exactly `BASE_TOOL_NAMES` is allowed, so `web_search` is still
    available on the chats view and the book-state view. (decision 6 — `011`'s shipped behaviour is
    not silently lost)
12. `[test]` A `mode_tool` row naming a tool absent from `TOOL_REGISTRY` is skipped and logged, and
    the turn still runs with the remaining tools. (`assistant-config.md` → the catalogue is the
    source of truth)
13. `[test]` A turn sent with no subject fields at all behaves exactly as `011` shipped it, except
    for the allowlist rule above — the existing turn tests still pass unmodified. (backward
    compatibility)

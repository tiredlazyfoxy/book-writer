# 001 — Codex db layer + authz capabilities

## Goal

Widen the two codex `db/` modules from feature `008`'s bare create/get/list into the query surface the
codex service needs (kind / archived / substring filters, deterministic ordering, update,
next-generation lookup, ordered version list), and add the members-only codex capabilities and their
matrix rows to `services/authz.py`.

## Interface intent

**`backend/app/db/codex_entries.py`** — keeps `create`, `get_by_id` and `list_by_book` as they are
named; `list_by_book` is widened and one function is added.

- **`list_by_book`** — widened to accept, beside the book id, an optional `kind` filter, a flag
  controlling whether archived rows are included (default: excluded), and an optional free-text
  needle. The needle matches **case-insensitively** as a substring against **either** `name` **or**
  `body`; a row whose `name` is null is matched on `body` alone. Ordering is **deterministic and
  explicit** — by `name` (nulls last) then by `id` — so a list page and its tests never depend on
  insertion order. Returns detached rows.
- **`update`** — persists an already-mutated `CodexEntry` and returns the stored row. Session-free
  like every other function in the module; no ORM object leaks out.

**`backend/app/db/codex_entry_versions.py`** — keeps `create` and `get_by_id`; one function added,
one widened.

- **`next_generation`** — given an entry id, returns the 1-based generation number the *next* version
  row should carry: `1` when the entry has no version rows, otherwise one more than the highest
  existing generation.
- **`list_by_entry`** — widened to return rows in **ascending `generation`** order (it is unordered
  today), so `019.codex-history` reads a stable history.

**`backend/app/services/authz.py`** — two members added to the existing `Capability` enum and two
rows added to `_CAPABILITY_MATRIX`, per `authorization.md` → "Members-only material":

- **a browse/search capability** — owner ✓, co-author ✓, reader —, none —. Covers UC-071 reads
  (list, get, and later the assistant's codex tools).
- **a create/edit capability** — owner ✓, co-author ✓, reader —, none —. The matrix groups create,
  edit and archive in one row; **archive is `017.codex-archive-restore`'s and is not added here**.
  The `(mode)` qualifier on the co-author cell is *not* expressible in the role matrix — it is a
  collaboration-mode rule applied by the codex service in step 002, exactly as `011` layered chat
  ownership on top of `book_access`.

Nothing else in `authz.py` changes: `BookAccess`, `AccessRole`, `resolve_book_access`, `book_access`
and `require` keep their current shapes.

## Definition of done

1. `[test]` `list_by_book` filtered by a `kind` returns only entries of that kind and never entries
   of another kind or another book. (UC-071 / US-080.AC-1)
2. `[test]` `list_by_book` excludes archived entries by default and includes them when explicitly
   asked. (`domain-codex.md` — archived, never deleted)
3. `[test]` the free-text needle matches case-insensitively as a substring of `name` **or** of
   `body`, and a fact entry (null `name`) is still matched on its body. (US-080.AC-1)
4. `[test]` an empty / absent needle returns the full filtered set — it is not treated as a match on
   the empty string only. (US-080.AC-1)
5. `[test]` two calls with the same arguments return rows in the same order, and that order is by
   name then id with null-named rows last. (US-080.AC-1)
6. `[test]` `update` persists every changed field and the returned row reflects the stored state, not
   the in-memory argument. (UC-070)
7. `[test]` `next_generation` returns `1` for an entry with no version rows. (UC-070 postcondition)
8. `[test]` `next_generation` returns one more than the highest existing generation, including when
   version rows were created out of order. (UC-070 postcondition)
9. `[test]` `list_by_entry` returns rows in ascending `generation` order and only for that entry.
   (UC-073 groundwork)
10. `[test]` the browse capability is granted to `owner` and `co_author` and refused — raising
    `BookAuthorizationError` — for `reader` and `none`. (US-085.AC-1)
11. `[test]` the create/edit capability is granted to `owner` and `co_author` and refused for
    `reader` and `none`. (US-079.AC-1, US-085.AC-1)
12. `[test]` the pre-existing capabilities and their matrix rows are unchanged — every previously
    granted `(capability, role)` pair still resolves the same way. (regression guard)

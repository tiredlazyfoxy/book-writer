# 004 — `services/embedding.py`

## Goal

Build the single point where text becomes vectors — the module `retrieval.md` names and feature `007`
explicitly did not build: designated-server resolution, `$ENV` key resolution, client construction
through the existing path, batch embedding, a dimension probe, a dimension check, and a typed error
taxonomy matching `retrieval.md`'s failure table.

## Interface intent

**`backend/app/services/embedding.py`** — new module. No caller is wired in this step; steps 005, 006
and 009 consume it.

- **a reason enum plus one error class**, following `services/chats.py:ChatErrorReason`'s pairing.
  Three reasons, one per row of `retrieval.md`'s failure table that this module can produce:
  **no provider** (no designated embedding server, or the designated row carries no
  `embedding_model`), **unreachable** (the client raised — transport error, LLM error, or an
  unresolvable `$ENV` key reference), and **dimension mismatch** (a returned vector's length does not
  match an expected one).
- **an availability probe** — reports whether a usable embedding designation exists right now,
  without embedding anything. Callers that must degrade quietly (step 006's best-effort maintenance)
  use it to avoid a raise on the common "not configured yet" path.
- **a batch embed** — takes a sequence of texts, returns one vector per text **in input order**.
  Resolves the designated server, resolves its api key through the `$ENV` indirection, constructs a
  model-bound client, and calls the client's batch-embedding method inside an `async with`. An empty
  input returns an empty result **without** contacting anything.
- **a single-text embed** — the query path (step 009's `codex_search` embeds one string). It may be a
  thin wrapper over the batch call; it must not duplicate the resolution logic.
- **a dimension probe** — embeds a short constant probe string and returns the length of the vector
  the model actually returned. This is what step 005 creates the sidecar table with, per
  `retrieval.md` → "Vector dimension": the dimension is a property of the model and is discovered,
  never declared.
- **a dimension check** — given a batch of vectors and an expected length, raises the mismatch reason
  when any vector's length differs, and returns normally otherwise. It exists as its own callable
  because the comparison happens where the table's dimension is known (steps 005/006) while the error
  taxonomy lives here.

Every failure path raises the module's own error type. No caller should ever have to catch
`aiohttp.ClientError`, `LLMError` or `LlmServerError` to use this module.

## Definition of done

1. `[test]` With **no** designated embedding server, the batch embed raises the no-provider reason
   and never constructs a client. (`retrieval.md` → Failure modes, row 1)
2. `[test]` With a designated server whose `embedding_model` is empty or whitespace, the batch embed
   raises the no-provider reason. (`retrieval.md` → Dependency)
3. `[test]` The availability probe returns false in both of the above cases and true for a fully
   designated server, and never contacts the client. (`retrieval.md` → Failure modes)
4. `[test]` An api key stored as `$SOME_VAR` is resolved from the environment **at use time** and the
   resolved value is what reaches client construction; the raw stored value never is. (`retrieval.md`
   → Dependency; root `CLAUDE.md` → Config & Secrets)
5. `[test]` A `$SOME_VAR` reference whose environment variable is unset surfaces as this module's
   **unreachable** reason, not as a raw `LlmServerError`. (single taxonomy for callers)
6. `[test]` A transport failure or LLM error from the client surfaces as the unreachable reason, not
   as a raw exception. (`retrieval.md` → Failure modes, row 2)
7. `[test]` The batch embed returns one vector per input text, in input order, for a multi-text call.
   (`retrieval.md` → Chunking; a chunk's vector must stay paired with its chunk)
8. `[test]` An empty input list returns an empty result and makes no client call at all.
9. `[test]` The client is entered as an async context manager and exited on **every** path, including
   when the client raises. (`011` finding: `LLMClient` has no standalone `close()`)
10. `[test]` The dimension probe returns the length of the vector the model returned, for two
    different mocked lengths. (`retrieval.md` → Vector dimension)
11. `[test]` The dimension check passes a batch whose vectors all match the expected length, and
    raises the mismatch reason when any one differs. (`retrieval.md` → Failure modes, row 3)
12. `[manual/live]` Against a real configured embedding server, embedding a short text returns a
    non-empty vector and the probe reports that model's dimension.

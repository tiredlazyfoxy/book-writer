# 013 — Subject → chat wiring and canvas application

## Goal

Close the loop: the content pane's current subject reaches the chat turn request, and the assistant's
`canvas` frame reaches the open entry's draft — through a module-level registry beside
`restoreBuffer.ts`, with the restore buffer as the fallback when nothing is registered. Delivers
US-086.AC-1 and US-087.AC-1.

## Interface intent

**`frontend/src/work/contentSubject.ts`** — new module, plain functions at the module tier beside
`restoreBuffer.ts` and `activeChat.ts`. Not a reactive store; not React context; not a hook.

- **register** — a content page declares its `LoadedSubject` (from `frontend/src/work/subject.ts`) and,
  optionally, an apply-draft callback. Returns nothing the caller must thread anywhere.
- **unregister** — clears the registration, guarded so a late unmount cannot clear a newer page's
  registration.
- **read the current subject** — what `ChatPaneState` calls when composing a turn request. Returns the
  registered `LoadedSubject`, or none.
- **dispatch a canvas frame** — takes the book id and the frame's payload. If a target is registered
  **and** its subject kind and id match the frame's, hand the text to its apply-draft callback.
  Otherwise **write the text into the restore buffer** at
  `restoreBufferKey(bookId, "codex-entry", subjectId)`, so returning to the entry surfaces it through
  the path that already exists. A frame for a blank entry (null subject id) with no registered target
  is dropped — there is no key to buffer it under and no row to return to.

**`frontend/src/types/chats.d.ts`** — the turn request body gains the three optional subject fields
(subject kind, subject id, codex kind), and a canvas-frame payload type is added, wire-exact with the
backend's `CanvasFrame`.

**`frontend/src/api/chats.ts`** — `streamChatTurn` carries the subject fields in the POST body, and
`TurnStreamHandlers` gains an `onCanvas` handler. `frontend/src/api/sse.ts` already routes any
non-special event name to its generic handler, so **it needs no change** — the canvas event is routed
through that existing path.

**`frontend/src/work/components/chat/chatPaneState.ts`** — the send and retry functions read the
current subject from `contentSubject.ts` at send time (not from a stored field, so the subject is
always current), pass it into `streamChatTurn`, and wire `onCanvas` to the registry's dispatch. The
pane keeps no subject state of its own.

**`frontend/src/work/pages/codexEntryPageState.ts`** — expose the apply-draft entry point step 012
created as the registry's callback: applying a canvas draft to a field runs the **same** path a
keystroke does (draft set, dirty, buffer written), so the assistant's write and the author's are
indistinguishable downstream.

**`frontend/src/work/pages/CodexEntryPage.tsx`** and **`CodexListPage.tsx`** — each registers its
subject on mount and unregisters on unmount, in its existing page-level `useEffect` (mount/unmount
only, the one sanctioned use). The entry page registers with its apply-draft callback and its
archived flag; the list pages register kind-only subjects with no callback, so a list subject
resolves to no mode and no canvas target.

## Definition of done

1. `[test]` With a codex entry open, sending a chat turn posts a body carrying that entry's subject
   kind, its id, and its codex kind. (US-086.AC-1, US-087.AC-1)
2. `[test]` With a **blank** entry open, the turn body carries a null subject id and the kind chosen
   at the `/codex/new` route. (UC-076)
3. `[test]` With a list page open, the turn body carries that list's subject kind and no id.
   (UC-090 — a list is a subject too)
4. `[test]` With nothing registered, the turn body carries no subject fields at all and the turn
   still runs. (`011`'s shipped behaviour survives)
5. `[test]` A `canvas` frame whose subject matches the registered entry applies its text to that
   field of the page's draft. (US-086.AC-1, US-087.AC-1)
6. `[test]` Applying a canvas draft marks the page dirty and writes the restore buffer exactly as a
   hand edit does, and **no** save call is made. (US-086.AC-2, US-087.AC-2, US-103.AC-1, US-107.AC-1)
7. `[test]` A `canvas` frame arriving when **no** target is registered — the author navigated away
   mid-turn — is written into the restore buffer at
   `bookwriter.restore-buffer:<bookId>:codex-entry:<id>`, and returning to that entry restores it.
   (US-107.AC-1)
8. `[test]` A `canvas` frame whose subject id does not match the registered target falls back to the
   buffer and does **not** overwrite the open entry. (no cross-subject writes)
9. `[test]` A page registers on mount and unregisters on unmount, and a late unmount from a previous
   page does not clear a newer page's registration. (mount/unmount effect only)
10. `[test]` Switching the content-pane subject does not change which chat is active, and switching
    chats does not change the subject. (UC-083 independence; US-105.AC-3)
11. `[test]` The canvas event reaches `onCanvas` through `sse.ts`'s existing generic-event routing,
    with `sse.ts` unmodified. (`011` outcome item 21 — the frame vocabulary was a floor, this widens
    it)

## Dependencies

Steps 010 (the `canvas` frame and the subject fields on the turn request) and 012 (the entry page's
apply-draft entry point).

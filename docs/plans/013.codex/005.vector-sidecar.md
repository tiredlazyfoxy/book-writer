# 005 — Vector sidecar: table, chunker, widened registry, real rebuild

## Goal

Turn `db/vector.py` from feature `007`'s empty shell into the real sidecar: the single discriminated
chunk table created at the model's probed dimension, the upsert / delete / search helpers, the codex
chunker, the **widened** `VECTOR_SOURCE_REGISTRY` entry shape, and a `rebuild_index()` that actually
walks the registry. Cohesion note: the table schema, the helpers that write it and the registry entry
that fills it cannot be frozen independently — a table with no writer and a registry entry with no
table are both untestable halves.

## Interface intent

**`backend/app/db/vector.py`** — the module keeps its existing module globals and `init_vector` /
`rebuild_index` names.

- **`init_vector`** — widened to also receive the **embedding callables it needs** (a batch embedder
  and a dimension probe) from the caller. Reason: `rebuild_index` must embed, `db → services` is
  forbidden by the layer rule, and one of `rebuild_index`'s two callers itself lives in `db/`.
  `app/main.py` is the composition root and passes `services/embedding.py`'s callables in. Both
  existing `rebuild_index()` call sites keep their current zero-argument shape.
- **the chunk table** — one table, one row per chunk, with the columns `retrieval.md` fixes:
  `vector`, `book_id`, `source_kind`, `source_id` (the snowflake **as a string**), `chunk_index`,
  `text`. Created lazily **at the dimension the probe returned**, never at a declared constant.
- **a table-dimension accessor** — reports the dimension the live table was created at, so step 006
  can compare an incoming batch against it.
- **`upsert_chunks`** — given a book id, a source kind, a source id and an ordered list of
  `(text, vector)` pairs, replaces that source's rows: **delete this `source_id`'s chunks, then
  insert the new ones** with `chunk_index` running from zero. Delete-then-reinsert rather than
  update, because the chunk *count* changes when the text does (`retrieval.md`).
- **`delete_by_source`** — removes every chunk of one source id. Used by archive (`017`) and
  internally by the upsert.
- **`delete_by_book`** — removes every chunk of one book. Used by book destroy, later.
- **`search`** — takes a book id, a **query vector**, an optional set of source kinds and a limit;
  returns hits carrying `source_kind`, `source_id`, `chunk_index`, `text` and `score`, nearest
  first. `book_id` is a **hard filter applied inside the query**, never a ranking preference — a hit
  from another book is a permission violation, not a worse result (`retrieval.md`). Note the
  narrowing against `retrieval.md`'s written surface: the doc shows `search(book_id, query_text, …)`,
  but `db/` may not embed, so the db-level function takes an already-embedded vector and a service
  composes the two (step 009).
- **the widened registry entry** — `VECTOR_SOURCE_REGISTRY` stops being
  `(model_class, text_extractor)` tuples and becomes a list of typed entries carrying: the
  **`source_kind` discriminator**, the **model class**, a **row selector** (returns the rows that
  must be indexed, skipping ones that must not be — archived codex entries), and a **chunker**
  (one row → a list of chunk texts) replacing the single `text_extractor`. This is a deliberate
  change to a shipped seam: the old tuple could not express "one row becomes many vectors".
- **the codex chunker** — a pure function over a `CodexEntry`. An entry whose body fits the chunk
  size is **one chunk** with the entry's `name` prepended to the chunk text, so a name-only query
  ("Marek") matches the entry that is about Marek. A `fact` (null name) prepends nothing. Longer
  bodies split on **paragraph boundaries** into overlapping windows; the overlap exists so a sentence
  spanning a boundary is reachable from either side. Chunk size and overlap are **tuning
  parameters**, not architecture — the concrete values are in `005.context.md` and are recorded in
  `outcome.md` as as-built numbers.
- **`rebuild_index`** — keeps its `-> int` shape. Now: probe the dimension, drop and recreate the
  table at that dimension, then for each registry entry walk its row selector, chunk each row, embed
  the chunks in batches, and insert. Returns the **total number of chunks written**.

**`backend/app/db/codex_entries.py`** — add the **row selector** the registry entry needs: every
non-archived codex entry across **all** books, ordered by id so a rebuild is deterministic. This is
the only addition; step 001's functions are untouched.

**`backend/app/db/import_export_queries.py`** — `run_vector_rebuild()` (line 62) keeps its signature
and its position at the tail of `import_all`, and gains a **guard**: a rebuild failure (typically no
embedding provider on a fresh instance) is logged and swallowed, never propagated. It deliberately
bypasses the admin provider gate, so it must tolerate the absence.

**`backend/app/main.py`** — pass the embedding callables into `init_vector` at startup. No other
change.

## Definition of done

1. `[test]` The chunk table is created at the dimension the probe returned, and a different probe
   value produces a differently-dimensioned table. (`retrieval.md` → Vector dimension)
2. `[test]` `upsert_chunks` writes one row per chunk with `book_id`, `source_kind`, `source_id` (as a
   string) and `text` populated and `chunk_index` running from zero in order. (`retrieval.md` →
   Sidecar shape)
3. `[test]` Re-upserting a source with **fewer** chunks than before leaves no orphan rows from the
   longer previous version. (`retrieval.md` → Incremental maintenance)
4. `[test]` `delete_by_source` removes exactly that source's chunks and leaves every other source's
   intact.
5. `[test]` `delete_by_book` removes every chunk of that book and no chunk of another.
6. `[test]` `search` never returns a chunk from another book, even when that chunk is the nearest
   neighbour of the query vector. (`retrieval.md` → hard filter; US-085.AC-1)
7. `[test]` `search` narrows to the requested source kinds, honours the limit, and returns hits
   carrying `source_kind`, `source_id`, `chunk_index`, `text` and `score`. (`retrieval.md` → Query
   surface)
8. `[test]` The chunker yields exactly one chunk for an entry whose body fits the chunk size, and
   that chunk begins with the entry's name. (`retrieval.md` → Chunking)
9. `[test]` The chunker on a `fact` entry (null name) yields the body with no name prefix.
   (US-078.AC-2 consequence)
10. `[test]` The chunker splits a body longer than the chunk size on paragraph boundaries into more
    than one chunk, each within the configured size, with the configured overlap between adjacent
    chunks. (`retrieval.md` → Chunking)
11. `[test]` `VECTOR_SOURCE_REGISTRY` holds exactly one entry, discriminated `codex_entry`, and its
    row selector returns non-archived entries only — an archived entry is never offered to the
    chunker. (`retrieval.md` → "Archived codex entries are removed from the index, not flagged")
12. `[test]` `rebuild_index` drops the existing table, repopulates it from the registry, and returns
    the total chunk count written. (`retrieval.md` → Full rebuild)
13. `[test]` `rebuild_index` with an empty codex returns zero and leaves a usable empty table.
14. `[test]` `run_vector_rebuild` logs and swallows a rebuild failure — an import of a database into
    an instance with **no** embedding provider still completes. (`retrieval.md` → the import path
    bypasses the gate)
15. `[test]` `backend/tests/test_data_domain_codex.py`'s
    `test_codex_not_registered_as_vector_source__DoD5` is **superseded**: the assertion that codex is
    absent from `VECTOR_SOURCE_REGISTRY` is replaced by its inverse, and the rest of that file's
    coverage is unchanged. (feature-008 deferral now discharged)
16. `[manual/live]` With a real configured embedding server, `POST /api/admin/db/vector/rebuild`
    returns a non-zero chunk count for a book with codex entries. (UC-020)

# 002 — Codex schemas + service

## Goal

Add the codex DTO family and the service that owns every codex business rule: kind/name validation,
collaboration-mode enforcement, optimistic concurrency on `modified_at`, and a `CodexEntryVersion`
row carrying the prior content on every edit. Schemas and service land together because the DTOs have
exactly one producer and the mapper that builds them is the service — splitting them would freeze a
contract with no implementation behind it.

## Interface intent

**`backend/app/models/schemas/codex.py`** — new module, Pydantic models only, no logic.

- **a create-request model** — the entry `kind`, an optional `name`, and the `body`.
- **an update-request model** — an optional `name`, the `body`, and the **expected `modified_at`**
  the client loaded the entry at, which drives optimistic concurrency. `kind` is **not** updatable:
  changing an entry's kind would move it between navigator lists and invalidate its name rule, and no
  use case asks for it.
- **an entry-response model** — id, book id, kind, name (nullable), body, archived flag, author id,
  modified-by id (nullable), created-at, modified-at. **Every id is a `str`.**
- **a list-response envelope** — `{ items: [...] }`.

**`backend/app/services/codex.py`** — new module.

- **a reason enum plus one error class**, following `services/chats.py:ChatErrorReason`'s shape. The
  reasons this feature needs: entry not found; a name is required for this kind; a name is not
  allowed for this kind; the entry is archived and read-only; the supplied `modified_at` is stale;
  and a proposal-mode co-author write is unsupported. The last one's message **names FEAT-010 as
  unbuilt** so the author sees why, not just that.
- **create** — takes the access context, the acting user and a create request. Requires the
  create/edit capability, applies the collaboration-mode rule, validates the kind/name rule, writes
  the row with `author_id` set to the acting user, and returns the response DTO. **No version row is
  written on create** — the first version row records the state *before* the first edit, so an entry
  that has never been edited has no history, which is what `019` will read.
- **list** — takes the access context plus the kind, needle and include-archived filters, requires
  the browse capability and returns the list envelope.
- **get** — takes the access context and an entry id, requires the browse capability, and treats an
  entry belonging to a **different book** exactly like a missing one.
- **update** — takes the access context, the acting user, an entry id and an update request.
  Requires the create/edit capability, applies the collaboration-mode rule, refuses an archived
  entry, compares the request's expected `modified_at` against the stored value and raises the stale
  reason when they differ, validates the kind/name rule against the entry's **stored** kind, then, in
  this order: **writes a `CodexEntryVersion` carrying the entry's PRIOR `name` / `body` / `kind`**
  with `author_id` set to the acting user and `generation` from the db layer's next-generation
  lookup, **then** applies the new content, sets `modified_by` to the acting user, bumps
  `modified_at`, and returns the response DTO.
- **the kind/name rule** (US-078.AC-1 / AC-2): `character` and `location` **require** a non-blank
  name; `fact` **refuses** one and stores `name` as null. A whitespace-only name counts as absent.
- **the collaboration-mode rule** (decision 3 in `context.md`): the owner's write always applies. A
  co-author writing to a book whose `collaboration_mode` is `proposal` is refused with the
  proposal-unsupported reason. Free mode applies a co-author's write immediately.
- **a response mapper** — one place that turns a `CodexEntry` row into the response DTO with string
  ids. Nothing else constructs the DTO.

## Definition of done

1. `[test]` Creating a `character` or `location` with a non-blank name stores the entry with that
   name and returns it. (US-078.AC-1)
2. `[test]` Creating a `character` or `location` with a missing or whitespace-only name is refused
   with the name-required reason and writes nothing. (US-078.AC-1)
3. `[test]` Creating a `fact` with no name succeeds and the stored entry's name is null.
   (US-078.AC-2)
4. `[test]` Creating a `fact` with a name is refused with the name-not-allowed reason. (US-078.AC-2)
5. `[test]` In a free-mode book, an owner's create and a co-author's create both apply immediately —
   the entry is readable straight after the call. (US-079.AC-1)
6. `[test]` In a free-mode book, an owner's edit and a co-author's edit both apply immediately.
   (US-079.AC-1)
7. `[test]` In a **proposal**-mode book, a co-author's create is refused with the
   proposal-unsupported reason and nothing is written; the message names FEAT-010. (decision 3;
   US-079.AC-2 knowingly unmet)
8. `[test]` In a **proposal**-mode book, a co-author's edit is refused the same way and the entry is
   unchanged. (decision 3)
9. `[test]` In a proposal-mode book, the **owner's** create and edit still apply. (decision 3)
10. `[test]` An edit writes exactly one `CodexEntryVersion` whose `name`, `body` and `kind` are the
    entry's content **as it stood before** the edit. (UC-070 postcondition; `domain-codex.md`)
11. `[test]` Version generations are 1-based and increment by one per edit, so three edits produce
    generations 1, 2, 3. (UC-070 postcondition)
12. `[test]` An edit sets `modified_by` to the editing user and leaves `author_id` at the original
    creator. (`domain-codex.md`)
13. `[test]` An edit whose expected `modified_at` does not match the stored value is refused with the
    stale reason, no version row is written and the entry is unchanged. (`frontend-workspace.md` →
    stale-buffer / 409)
14. `[test]` An edit of an archived entry is refused with the archived reason. (UC-070 precondition)
15. `[test]` Listing applies the kind, needle and include-archived filters and returns DTOs whose ids
    are strings. (UC-071 / US-080.AC-1)
16. `[test]` Getting an entry that exists but belongs to another book raises the not-found reason —
    it never returns another book's content. (US-085.AC-1)
17. `[test]` A `reader` or non-member access context is refused by `authz.require` on every one of
    create, list, get and update. (US-085.AC-1)

# 011 — Codex API module, DTOs, and the three list pages

## Goal

Give the frontend the codex: hand-written DTOs, the `src/api/codex.ts` module, and one parameterized
list page filling the Characters / Locations / Facts routes that `010.working-page` left as
placeholders — with the search needle living in the URL query string, the repo's first query-param
consumer.

## Interface intent

**`frontend/src/types/codex.d.ts`** — hand-written, wire-exact `snake_case`, **ids typed `string`**,
no `any`, no runtime validation. The kind union as backend enum literals; the entry DTO mirroring the
backend entry response exactly; the create and update request bodies. List envelopes are **not**
modelled — they are unwrapped in the api module.

**`frontend/src/api/codex.ts`** — all HTTP for the codex, following `src/api/chats.ts`'s conventions:
a module-level `/api/books` base, string ids interpolated into the path, a trailing
`signal?: AbortSignal` on every function, `{items: […]}` unwrapped here.

- **list** — book id plus the kind, an optional needle and an optional include-archived flag; returns
  the entries array.
- **get one** — book id and entry id.
- **create** — book id and the create body; returns the created entry.
- **update** — book id, entry id and the update body (carrying the expected `modified_at`); returns
  the updated entry.

**`frontend/src/work/pages/codexListPageState.ts`** — a `CodexListPageState` class plus external
effect functions, per the enforced MobX rules.

- One async trio for the entries (`entries` / `entriesStatus` / `entriesError`).
- The current kind (supplied by the route, not editable), the current search needle, and a draft
  needle the input binds to.
- A `get` computed for the empty-vs-loaded distinction; no derived data stored.
- External functions taking `(state, args, signal)`: a loader that reads the needle from the state and
  fetches, and a search-submit handler that commits the draft needle into state **and** returns the
  new query string for the caller to push. The URL update is performed **in the event handler that
  changed it** — never in a `useEffect` watching the query string (`frontend.md`:192).

**`frontend/src/work/pages/CodexListPage.tsx`** — one `observer` component, parameterized by kind, so
the three routes share it rather than triplicating a table. Renders: a heading for the kind, a search
input with a submit action, a "new entry" action, the entries table (name — or a body excerpt for
facts, which have none — plus modified-at), an empty state, a loading state and an error state.
Row activation navigates to the entry route. `useState` holds the state instance; the single
page-level `useEffect` loads on mount and aborts on unmount.

**`frontend/src/work/routes.tsx`** — replace the three `SubjectPlaceholderPage` elements on
`/characters`, `/locations` and `/facts` with the list page bound to its kind, and add the blank-entry
route `/codex/new` **before** `/codex/:id` (step 012 supplies its element; this step reserves and
routes it). The three navigator entries in
`frontend/src/work/components/shell/navItems.ts` already exist and are **not** touched — this feature
fills their pages, it does not add nav items.

## Definition of done

1. `[test]` The Characters route renders only the book's `character` entries; Locations renders only
   `location`; Facts renders only `fact`. The kind is fixed by the route and is not user-selectable.
   (UC-071 / US-080.AC-1, US-105.AC-1)
2. `[test]` Submitting a search needle writes `q` into the URL query string and re-fetches with it —
   and the write happens in the submit handler, not in an effect reacting to the URL. (UC-071;
   `frontend.md`:192)
3. `[test]` Mounting on a URL that already carries `q` loads filtered on the first fetch, so the
   filtered list is deep-linkable. (US-080.AC-1)
4. `[test]` Clearing the needle and submitting removes `q` from the URL and reloads unfiltered.
5. `[test]` Activating a row navigates to `/work/:bookId/codex/:id` for that entry. (US-105.AC-2,
   UC-083)
6. `[test]` A book with no matching entries renders an empty state, not an error. (UC-071)
7. `[test]` A failed load renders the error state from the async trio and offers a retry that
   re-fetches. (`frontend.md` → async trio)
8. `[test]` The "new entry" action navigates to `/work/:bookId/codex/new` carrying the route's kind
   as a query param. (UC-076 precondition — a blank entry of a chosen kind)
9. `[test]` The api module unwraps the `{items: […]}` envelope, so the state holds a plain array and
   the `.d.ts` models no envelope. (`frontend.md` → api conventions)
10. `[test]` Every id crossing the api boundary is a `string`, including in the create and update
    bodies. (`frontend.md` → ids are strings)

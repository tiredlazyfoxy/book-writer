## Chunking parameters — as-built values, tuning not architecture

`retrieval.md` deliberately pins no numbers ("bounded by the embedding model's input window and
belong with the chunker"). This step sets them, and `outcome.md` records them as as-built:

| Parameter | Value | Why |
|---|---|---|
| chunk size | **1200 characters** | Comfortably inside a 512-token input window (~2000 characters) once the name prefix is added, with room for models with smaller windows |
| overlap | **200 characters** | ~1/6 of a chunk — enough for a sentence spanning a boundary to survive on both sides without inflating the row count |
| single-chunk threshold | chunk size | An entry whose body plus name prefix fits 1200 characters is one chunk, which is the common case for a codex entry |

They belong as named module constants in the chunker so a later tune is a one-line change.

The name prefix format is the chunker's own choice, but it must be **deterministic** — the same entry
always produces byte-identical chunks — because a rebuild must reproduce what incremental
maintenance wrote.

## `source_id` is a string

`retrieval.md` fixes `source_id` as "the source entity's snowflake, **as a string**". Snowflakes
exceed the JS safe-integer range and the id convention is string-at-every-boundary; the sidecar
follows it. Callers pass `int` ids and the module stringifies at the boundary — keep the conversion
in one place.

## The registry entry's row selector

The selector must return rows across **all** books (a rebuild is instance-wide), not per book. It
lives in `backend/app/db/codex_entries.py` because that is the module that owns codex reads —
`db/vector.py` imports it as a namespace module. A `db → db` import is already precedented by
`db/import_export_queries.py`.

Archived rows are excluded **by the selector**, not by a query-time predicate: `retrieval.md` is
explicit that "an 'exclude archived' predicate is a rule every future consumer would have to remember
and one of them would eventually forget".

## The test this step supersedes

`backend/tests/test_data_domain_codex.py:552` currently holds

codex coverage stays untouched. This is the only reason that file appears in this step's Test files.

## Testing without a real embedding server

LanceDB itself runs locally against a temp directory, so the sidecar can be exercised for real — only
the **embedder** is mocked, by injecting deterministic callables through `init_vector` (that is the
injection seam's second benefit). Use fixed short vectors so nearest-neighbour ordering is
predictable, and give the fixture a `tmp_path`-based vector dir so tests do not share an index.

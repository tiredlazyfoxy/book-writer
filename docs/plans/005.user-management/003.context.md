## MobX / api specifics for this page

- The users list is one async trio: `users` / `usersStatus:
  'idle'|'loading'|'ready'|'error'` / `usersError`.
- Effectful ops are external `(state, args, signal)` functions with
  `runInAction`; the page state has **no** `load()`/`save()` methods.
- `useState(() => new UsersPageState())` holds the instance; a single page-level
  `useEffect([])` runs the mount load and unmount abort.
- `disableUserAction` calls `admin.disableUser` then `loadUsers` (the local
  `refresh`) so the list reflects the now-inactive row — the backend is the source
  of truth (no optimistic local edit).
- API module is namespace-imported (`import * as adminApi from '../../api/admin'`);
  `signal?` is always the last arg; all HTTP goes through the shared `request`
  (no `fetch` outside `client.ts`).
- Render `active` directly from the DTO (decision 3) — do not reconstruct the
  reference's `last_login===null && role!=="admin"` heuristic.

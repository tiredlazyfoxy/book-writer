# Step 003 — Admin SPA users list + disable (frontend base)

## Goal

Stand up the Admin SPA's first real page: a users list with role / last-login /
active per row and a per-row action menu, plus the disable action — wired through
a new admin API module and DTO types, with a minimal admin layout that preserves
the 004 mount token-gate.

## Interface intent

- **`src/types/admin.d.ts`** — hand-written DTO `.d.ts` matching the backend wire
  shapes 1:1: an admin-user response shape (`id` **`string`** — per frontend.md,
  entity ids are `string`, not `number`; `username`, `role`, `last_login`,
  `active`), the create / set-password / set-role request shapes, the `role`
  union (`'admin' | 'author'`), and a shared `ROLE_OPTIONS` list for selects. No
  `any`, no zod.
- **`src/api/admin.ts`** — the admin resource module over the shared `request`,
  `signal?` last, imported elsewhere as a namespace: `listUsers`, `createUser`,
  `setUserPassword`, `setUserRole`, `disableUser`. Return types are the
  `types/admin` DTOs; the 204 mutations resolve to void. These functions thread
  the user id as a `string` (the `PUT /{user_id}/…` calls interpolate the
  `string` id into the path).
- **`src/admin/routes.tsx`** — the admin route table mapping `/` (under the
  `/admin` basename) to `UsersPage`.
- **`src/admin/App.tsx`** — grown from its 004 placeholder into: MantineProvider
  (dark) → BrowserRouter `basename="/admin"` → a **minimal** layout (a simple
  header/nav, no shared cross-SPA shell) → the route table. **Keeps the 004
  mount-time token-gate** (redirect to `/login/` when unauthenticated).
- **`src/admin/pages/usersPageState.ts`** — the page state class holding the users
  async trio (`users` / `usersStatus` / `usersError`), plus the external effect
  functions `loadUsers(state, signal)` (fills the trio via `runInAction`) and
  `disableUserAction(state, userId, signal)` (calls the API then re-loads). A
  local `refresh` re-calls `loadUsers` after a mutation. State holds observable
  fields + `get` computeds only — no effectful methods.
- **`src/admin/pages/UsersPage.tsx`** — the `observer` page component: owns a
  stable state instance via `useState(() => new UsersPageState())`, loads on
  mount via a page-level `useEffect` (with abort on unmount), renders the list
  (username, role badge, last-login, active), and a per-row `Menu` whose Disable
  item calls `disableUserAction`. (The Set-Password / Set-Role / Create menu
  entries and modals arrive in step 004.)

## Definition of done

1. `[manual/live]` **US-005.AC-1** — on a configured instance, an authenticated
   admin loading the Admin SPA sees the user list with each account's role,
   last-login, and active state.
2. `[manual/live]` **US-005.AC-3** — an unauthenticated visitor is redirected to
   login by the mount token-gate, and a non-admin token is refused by the backend
   (the list request returns 403 and surfaces as an error state).
3. `[manual/live]` **US-009.AC-1** — disabling a user from the per-row menu
   removes that user's access; the row remains in the list shown as inactive; the
   list refreshes automatically after the action.
4. `[manual/live]` `cd frontend && npm run build` completes clean (typecheck +
   bundle) with the new module, types, and page.

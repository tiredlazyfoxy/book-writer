## Route discipline

- Routes are HTTP-only (`backend.md`): parse → call a `services.admin` function →
  map the typed admin error → return. No business logic, no DB access, no
  password checks in the handler (the reference leaks those into routes — they
  live in the service here, decision 4).
- The caller `User` comes from `Depends(require_role(admin))` (built in step 001).
  The self-guarded endpoints (`role`, `disable`) pass that caller into the service
  so the service compares `caller.id == user_id` (decision 9).
- `require_role` produces the **403** for a non-admin; the handler does not add a
  role check. All other refusals arrive as the step-001 typed admin error and map
  per decision 2: username-taken → 409, not-found → 404, self-target → 400,
  already-disabled → 400, password-invalid → 400.

# Step 002 — Admin user routes (HTTP surface)

## Goal

Expose the admin user service over HTTP: five endpoints under
`/api/admin/users`, each gated by `require_role(admin)`, threading the
authenticated caller into the service and mapping the service's typed error to
the taxonomy status codes.

## Source files

backend/app/routes/admin/__init__.py
backend/app/routes/admin/users.py
backend/app/main.py

## Test files

backend/tests/routes/admin/test_users.py

## Interface intent

- **`app/routes/admin/__init__.py`** — an admin route package marker (may
  aggregate the admin routers for mounting).
- **`app/routes/admin/users.py`** — an `APIRouter` with prefix
  `/api/admin/users`, every endpoint declaring `Depends(require_role(admin))` to
  obtain the caller `User`. Each handler stays HTTP-only: parse the request, call
  the matching `services.admin` function, map the typed admin error to a status
  (decision 2), and return. Endpoints:
  - **`GET ""`** — returns the account list (`list[AdminUserResponse]`), 200.
  - **`POST ""`** — creates an account from `AdminCreateUserRequest`, returns the
    new `AdminUserResponse`, 201.
  - **`PUT "/{user_id}/password"`** — resets the target's password from
    `AdminSetPasswordRequest`, 204.
  - **`PUT "/{user_id}/role"`** — sets the target's role from
    `AdminSetRoleRequest`, threading the caller for the self-guard, 204.
  - **`PUT "/{user_id}/disable"`** — disables the target, threading the caller for
    the self-guard, 204.
  - The **typed-error → status map**: username-taken → 409, not-found → 404,
    self-target → 400, already-disabled → 400, password-invalid → 400.
    (Non-admin → 403 is produced by `require_role` itself.)
- **`app/main.py`** — include the admin users router on the app (composition
  root), alongside the existing auth router.

## Definition of done

1. `[test]` **US-005.AC-3** — `GET /api/admin/users` with an `author`-role token
   returns 403; with an `admin`-role token returns 200.
2. `[test]` **US-005.AC-1** — the `GET` list carries, per account, its `role`,
   `last_login`, and `active`.
3. `[test]` **US-005.AC-2** — no `GET` list item contains a secret field (no
   `pwdhash`, `jwt_signing_key`, or `salt` in the JSON).
4. `[test]` **US-006.AC-1** — `POST /api/admin/users` with an untaken username +
   password + role returns 201 and an `AdminUserResponse` with that role and
   `active` true.
5. `[test]` **US-006.AC-2** — `POST /api/admin/users` with an already-taken
   username returns 409.
6. `[test]` **US-007.AC-1 / US-007.AC-2** — `PUT /api/admin/users/{id}/password`
   returns 204; when the target was disabled, a subsequent `GET` shows it
   `active` true again (re-enabled).
7. `[test]` **US-008.AC-1** — `PUT /api/admin/users/{id}/role` on a non-self
   target returns 204 and a subsequent `GET` shows the updated role.
8. `[test]` **US-008.AC-2** — `PUT /api/admin/users/{id}/role` on the caller's
   own id returns 400.
9. `[test]` **US-009.AC-1** — `PUT /api/admin/users/{id}/disable` on a non-self
   target returns 204 and a subsequent `GET` shows the target `active` false.
10. `[test]` **US-009.AC-3** — `PUT /api/admin/users/{id}/disable` on the
    caller's own id returns 400.
11. `[test]` decision 2 — any of the mutating endpoints called with a
    non-existent `user_id` returns 404.
12. `[test]` decision 2/4 — creating or resetting with a password shorter than 8
    or a mismatched confirm returns 400.

## Gotchas local to this step

- **Capture once, not three reads.** Reading `chat.active_side_chat_id` at each of the three sites
  would let a concurrent finish (another tab) split one turn across the side chat and the main line.
  One local variable at turn start is the whole mechanism (D-D's accepted edge assumes it).
- `start_side_chat` mints the id in the **service** with `generate_id()` — no row exists for a side
  chat, so no model `default_factory` can mint it (`context.md` → "Shared backend facts").
- Existence for finish = `chat.active_side_chat_id == sid` **or** `await
  chat_messages.side_chat_exists(chat.id, sid)`; check the pointer first — an active side chat with
  zero rows must finish cleanly (D-D).
- `409` is `HTTPException` with `detail=err.message`, like every other `ChatError` — no detail object.

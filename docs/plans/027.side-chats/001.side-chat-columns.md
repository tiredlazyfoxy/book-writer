# 001 — Side-chat columns, the additive seam, the `db/` functions and the JSONL codec

## Goal

Add the two nullable side-chat columns (`ChatMessage.side_chat_id`, `Chat.active_side_chat_id`) with
their `ADDITIVE_COLUMNS` entries and JSONL codec fields, and give `db/chat_messages.py` the four
session-free functions the turn filter and the four routes will consume.

## Interface intent

- **`ChatMessage.side_chat_id`** — a new optional integer column, default `None`; `None` means the
  row is on the main line, a value means the row belongs to the side chat with that id. **No FK, no
  index requirement.** Docstring says "finished" is derived, not stored (`context.md` → D-A).
- **`Chat.active_side_chat_id`** — a new optional integer column, default `None`; non-null means a
  side chat is active and every new row is stamped with it.
- **`ADDITIVE_COLUMNS`** in `db/engine.py` — gains `("chat_messages", "side_chat_id")` and
  `("chats", "active_side_chat_id")`, each with a `# feature 027` comment; nothing else in the seam
  changes.
- **`chat_messages.list_transcript`** — takes a chat id and an optional active side-chat id; returns
  that chat's rows whose `side_chat_id` is `NULL` **or** equals the given id, ordered by `position`.
  With `None` it returns main-line rows only. This is what the turn reads (D-C).
- **`chat_messages.side_chat_exists`** — takes a chat id and a side-chat id; returns whether at least
  one row of that chat carries that `side_chat_id`. The row half of D-A's existence rule; the service
  adds the pointer half.
- **`chat_messages.clear_side_chat`** — takes a chat id and a side-chat id; sets `side_chat_id` to
  `NULL` on exactly that chat's rows carrying that id, leaving `position` and every other column
  untouched; returns the number of rows changed. The inject primitive.
- **`chat_messages.delete_by_side_chat`** — takes a chat id and a side-chat id; deletes exactly that
  chat's rows carrying that id; returns the number deleted. The **first delete in `db/chat_messages.py`**
  — the module docstring should say why it is sanctioned (D-D). No renumbering of surviving rows.
- **`_chat_to_dict` / `_dict_to_chat`** — emit `active_side_chat_id` as a string or `null`; restore
  via `data.get(...)`, parsing with `int(...)` when present, so a key-less legacy dict yields `None`.
- **`_chat_message_to_dict` / `_dict_to_chat_message`** — the same for `side_chat_id`.

## Definition of done

1. `[test]` A `ChatMessage` created without `side_chat_id` and a `Chat` created without
   `active_side_chat_id` persist and read back with `None` in both; a `ChatMessage` created with a
   `side_chat_id` reads it back as the same `int`. (D-A)
2. `[test]` `ADDITIVE_COLUMNS` contains both `("chat_messages", "side_chat_id")` and
   `("chats", "active_side_chat_id")`. (`backend/persistence.md` → "The additive-column seam")
3. `[test]` `list_transcript(chat_id, sid)` returns, in `position` order, every main-line row plus
   every row carrying `sid`, and **no** row carrying a different side-chat id; rows of another chat
   never appear. (UC-115 step 1)
4. `[test]` `list_transcript(chat_id, None)` returns main-line rows only, in `position` order, and
   excludes every row that carries any side-chat id. (UC-115 step 2)
5. `[test]` `side_chat_exists` is `True` when at least one row of the chat carries the id and `False`
   when none does, including when a row with that id exists in a **different** chat. (D-A)
6. `[test]` `clear_side_chat(chat_id, sid)` sets `side_chat_id` to `None` on exactly the rows of
   that chat carrying `sid`, returns their count, and leaves their `position`, `content`, `role` and
   every other row (main line, other side chats, other chats) unchanged. (US-139.AC-1 — the storage
   half)
7. `[test]` `delete_by_side_chat(chat_id, sid)` removes exactly the rows of that chat carrying `sid`,
   returns their count, and leaves every other row (main line, other side chats, other chats)
   present with unchanged `position`; `next_position` afterwards is still max+1 over the survivors.
   (US-140.AC-3 — the storage half)
8. `[test]` `clear_side_chat` and `delete_by_side_chat` return `0` and change nothing when no row
   carries the id. (D-A)
9. `[test]` `_chat_to_dict` emits `active_side_chat_id` as the id's decimal string when set and as
   `null` when `None`; `_chat_message_to_dict` does the same for `side_chat_id`; both `_dict_to_*`
   restore the `int`. (root `CLAUDE.md` → DB Import/Export)
10. `[test]` A chat dict and a message dict **without** the new keys — an archive written before this
    feature — restore with `None` in the new fields and every other field intact.
    (`backend/persistence.md` → "A superseded column keeps its codec", read forward)

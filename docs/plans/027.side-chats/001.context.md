## Gotchas local to this step

- The `db/` module's docstring / the `ChatMessage` docstring is the one place to record that
  `delete_by_side_chat` is the chat family's first hard delete and why it is sanctioned (D-D); the
  service that calls it (step 003) links back rather than repeating it.
- `clear_side_chat` and `delete_by_side_chat` filter on **both** `chat_id` and `side_chat_id` — a
  side-chat id is unique in practice (snowflake) but the chat scope is what makes the function safe
  to call from an ownership-checked service without a second lookup.
- Return the changed-row count from both mutators (`result.rowcount`) — step 003's service does not
  need it for correctness but the tests for DoD-6/7/8 assert on it.

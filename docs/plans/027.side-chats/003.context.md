# 003 — step context

Facts only this step needs. The route table, error taxonomy, ownership helper, the hard-delete
sanction and its scope, and the fake-client test technique are in `context.md` (D-D, "Shared backend
facts", "Testing facts"). The side-chat-id parser and the existence check (`pointer == sid or
side_chat_exists`) are step 002's — reuse them, do not re-derive.

## Touch sites

- `backend/app/services/chats.py` — the two new functions sit after step 002's `start_side_chat` /
  `finish_side_chat`. `get_chat` :251-260 (the detail builder over `list_by_chat_ordered`) is what
  `inject_side_chat` returns — call the same mapping rather than a second implementation.
- `backend/app/routes/chats.py` — the two handlers go beside step 002's. **204 precedents in the
  repo:** `DELETE /api/books/{book_id}/chapters/{chapter_id}` in `routes/chapters.py` (the book-family
  one) and `DELETE /api/admin/llm-servers/{server_id}` in `routes/admin/llm_servers.py` (the first
  DELETE pattern) — either shows how a handler declares `status_code=204` and returns no body under
  the "response model is the return annotation" rule.
- `db/` functions consumed here: `chat_messages.clear_side_chat`, `chat_messages.delete_by_side_chat`
  (step 001), `chats.update` (existing).

## Gotchas local to this step

- **Call `chats.update(chat)` even when the pointer did not change** (finished side chat): that is
  the one path that bumps `modified_at`, and D-D says every side-chat mutation bumps it.
- Existence must be checked **before** mutating; `clear_side_chat` / `delete_by_side_chat` returning
  `0` is not a 404 signal — an active side chat with zero rows legitimately returns 0 (DoD-10).
- `delete_side_chat` returns nothing; the route answers 204 with no body — do not return a
  `ChatResponse` "for convenience", the wire contract is fixed (D-D).

## Test shape for this step

- Route tests copy the helpers from `backend/tests/routes/test_chats.py` (named in `context.md`).
  A finished side chat is seeded by creating rows with `side_chat_id=<int>` and a null pointer; an
  active one via `POST …/side-chats` (step 002). For DoD-7, create a codex entry through
  `POST /api/books/{book_id}/codex` (`CreateCodexEntryRequest`, `quick-reference.md`) between start
  and delete, then `GET /api/books/{book_id}/codex/{entry_id}` afterwards.
- The turn tests (DoD-3, DoD-8, DoD-11) use the fake client from
  `backend/tests/services/test_chat_turn.py` exactly as step 002's do, with the injected / deleted
  rows carrying sentinel strings; the inject or delete is performed through the service function
  (no HTTP needed in a service test) before running the turn.

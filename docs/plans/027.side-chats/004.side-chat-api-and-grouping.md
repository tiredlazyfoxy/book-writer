# 004 — The `.d.ts` fields, the four api functions, and the `renderedTranscript` grouping computed

## Goal

Bring the two wire fields into the frontend types, add the four side-chat api functions, and give
`ChatPaneState` the grouping half of the feature — `RenderedMessage.sideChatId`, the
`expandedSideChats` map with its toggle, `activeSideChatId`, and the `renderedTranscript` computed
that turns the flat message array into main-line items and contiguous side-chat groups (D-B).

## Interface intent

- **`ChatResponse.active_side_chat_id`** and **`ChatMessageResponse.side_chat_id`** in
  `types/chats.d.ts` — both **required-nullable** `string | null`, the file's convention.
- **`startSideChat`** — takes book id and chat id (+ optional signal); POSTs to
  `…/chats/{chatId}/side-chats` with no body; resolves the `ChatResponse`.
- **`finishSideChat`** — takes book id, chat id, side-chat id (+ signal); POSTs to
  `…/side-chats/{sideChatId}/finish`; resolves the `ChatResponse`.
- **`injectSideChat`** — same arguments; POSTs to `…/side-chats/{sideChatId}/inject`; resolves the
  `ChatDetailResponse`.
- **`deleteSideChat`** — same arguments; DELETEs `…/side-chats/{sideChatId}`; resolves `void` (204).
- **`RenderedMessage.sideChatId`** — a new `string | null` on the existing rendered-message shape,
  copied from the row's `side_chat_id`; the streaming placeholder pushed at the end of
  `renderedMessages` carries `activeSideChatId` so the in-flight bubble lands inside the active group.
- **`ChatPaneState.expandedSideChats`** — observable `Record<string, boolean>` keyed by side-chat id,
  the `expandedToolCallRows` pattern; **`toggleSideChatGroup(state, sideChatId)`** — an external
  function flipping one key inside `runInAction`, writing a whole new object.
- **`ChatPaneState.activeSideChatId`** — computed; the active chat's `active_side_chat_id`, or
  `null` when there is no active chat.
- **A rendered-transcript item union** — `{ kind: "message", message: RenderedMessage }` for a
  main-line row, `{ kind: "sideChat", sideChatId: string, messages: RenderedMessage[], active:
  boolean, expanded: boolean }` for one contiguous run sharing a non-null `sideChatId`.
- **`ChatPaneState.renderedTranscript`** — computed over `renderedMessages`; walks the array once,
  emitting a `message` item per null-`sideChatId` row and opening a new `sideChat` item whenever the
  `sideChatId` differs from the previous row's; `active` is `sideChatId === activeSideChatId`;
  `expanded` is `true` for the active group and `expandedSideChats[id] ?? false` otherwise. **Never
  checks or repairs contiguity** (D-B).

## Definition of done

1. `[test]` Each of the four api functions issues exactly one request with the method and URL in
   `context.md` → D-D (start: `POST …/chats/{chatId}/side-chats`; finish:
   `POST …/side-chats/{sideChatId}/finish`; inject: `POST …/side-chats/{sideChatId}/inject`; delete:
   `DELETE …/side-chats/{sideChatId}`), forwards the signal, and resolves with what `request`
   returned. (D-F)
2. `[test]` `RenderedMessage.sideChatId` equals the source row's `side_chat_id` for both a null and a
   non-null value. (D-F)
3. `[test]` For a message list `[main, main, A, A, main, B, B, B]` (letters = rows sharing a
   `side_chat_id`), `renderedTranscript` yields exactly `message, message, sideChat(A, 2 messages),
   message, sideChat(B, 3 messages)` in that order, each group's `messages` in position order.
   (US-135.AC-1 — the grouping half; US-139.AC-1 — rows with a null id are ordinary items)
4. `[test]` Two **different** side-chat runs that are adjacent (`A, A, B, B`) produce **two**
   `sideChat` items, not one. (FEAT-022 note D5 — any number of finished side chats)
5. `[test]` A group whose id equals `activeSideChatId` has `active: true` and `expanded: true`
   even when `expandedSideChats[id]` is `false` or absent. (UC-110 step 3)
6. `[test]` A group whose id is not the active one has `active: false` and `expanded: false` by
   default. (US-137.AC-1)
7. `[test]` `toggleSideChatGroup` flips that group's `expanded` to `true`, and a second call flips
   it back to `false`; other groups are unaffected. (US-137.AC-2; UC-111 step 3)
8. `[test]` While `turnStatus === "streaming"` with a side chat active, the streaming placeholder
   appears as the **last message inside the active group**, not as a trailing main-line item; with no
   side chat active it stays a trailing `message` item. (UC-110 step 3)
9. `[test]` `activeSideChatId` is the active chat's `active_side_chat_id`, and `null` when there is
   no active chat or the active chat's field is `null`. (D-F)
10. `[test]` A list with **no** side-chat rows yields only `message` items, one per row, in order —
    the existing transcript is unchanged for chats that never used the feature. (US-095.AC-2 — full
    history, regression)

# 006 — Rendering: `MessageRow` extraction, `SideChatGroup`, and the `MessageList` branch

## Goal

Render `renderedTranscript` — main-line rows through an extracted `MessageRow` component, and each
side-chat run through a new `SideChatGroup` block that is visibly set apart, collapses when finished,
expands on demand, and carries the Inject and Delete controls — without changing how a main-line
message looks.

## Interface intent

- **`MessageRow`** — an `observer` component taking the pane state and one `RenderedMessage`; renders
  exactly the JSX that lives inline in `MessageList` today — the user `Paper` bubble in a
  `data-role="user"` box, or the assistant `Stack` (`data-role="assistant"`) with `ThinkingBlock`
  (when reasoning is present), `ToolCallTrace`, and the `chat-markdown` `Markdown` body — including
  the existing reasoning-expansion lookup. **A pure extraction: no visual or behavioural change.**
- **`SideChatGroup`** — an `observer` component taking the pane state, the book id, and one
  `sideChat` transcript item; renders a bordered `Paper` / `Box` with `role="group"` and
  `aria-label="Side chat"`, whose header `Group` holds: a label `Text` reading `Side chat` for an
  active group and `Side chat · N messages` for a finished one (N = the group's message count; the D7
  placeholder), an expand / collapse control (`ActionIcon` or `UnstyledButton`, `aria-label` `Expand
  side chat` when collapsed / `Collapse side chat` when expanded) **only for a finished group**, and two
  `ActionIcon`s — `aria-label="Inject side chat"` and `aria-label="Delete side chat"` — both
  `disabled` when `sideChatActionsEnabled` is false. Inject calls step 005's `injectSideChat`; Delete
  calls `requestDeleteSideChat` (the confirmation is step 007's). The body renders one `MessageRow`
  per message **only when `expanded`**; collapsed renders header only (conditional rendering — no
  `Collapse`, no `Accordion`).
- **`MessageList`** — maps `state.renderedTranscript` instead of `state.renderedMessages`, branching
  on `kind`: `message` → `MessageRow`, `sideChat` → `SideChatGroup`. Keys: the message key for rows,
  the side-chat id for groups. Everything else in the file (scroll handling, `viewportRef`, the
  loading / empty states) is unchanged. It needs the book id for the group's actions — take it from
  wherever `ChatPane` already has it and pass it down as a prop (no context, no hook).

## Definition of done

1. `[test]` With a side-chat run in the transcript, the list contains an element with
   `role="group"` and accessible name `Side chat`, and every message of that run is rendered
   **inside** it while main-line messages are rendered outside it. (US-135.AC-1)
2. `[test]` An **active** group renders the label `Side chat`, renders its messages (expanded), and
   offers **no** `Expand side chat` / `Collapse side chat` control. (UC-110 step 3)
3. `[test]` A **finished** group renders collapsed by default: the header label `Side chat · N
   messages` with the correct N is present, the control `Expand side chat` is present, and none of
   the group's message contents is in the document. (US-137.AC-1)
4. `[test]` Clicking `Expand side chat` renders the group's messages and swaps the control to
   `Collapse side chat`; clicking that hides the messages again. (US-137.AC-2; UC-111 step 3)
5. `[test]` A group renders `Inject side chat` and `Delete side chat`; both are disabled when
   `sideChatActionsEnabled` is false (e.g. `turnStatus === "streaming"`) and enabled otherwise.
   (UC-112 / UC-113 exception flows — D1)
6. `[test]` Clicking `Inject side chat` on an enabled group calls the inject api once with that
   group's side-chat id; clicking `Delete side chat` sets `sideChatDeleteConfirm` to that id and
   calls **no** api. (US-139.AC-1 — the trigger; US-140.AC-1 — asks first)
7. `[test]` Rows whose `side_chat_id` is `null` — including rows that were injected — render as
   ordinary rows with **no** `Inject side chat` / `Delete side chat` control anywhere near them and
   are not inside any `role="group"` element. (US-139.AC-3)
8. `[test]` A transcript with no side-chat rows renders exactly as before: a user row shows its
   text in a `data-role="user"` box, an assistant row shows rendered markdown in a
   `data-role="assistant"` block, and a row with reasoning shows the `ThinkingBlock` control.
   (US-095.AC-2 — regression)
9. `[test]` While streaming with a side chat active, the in-flight bubble renders **inside** the
   active group. (UC-110 step 3)

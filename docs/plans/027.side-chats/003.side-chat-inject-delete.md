# 003 — Inject and delete a side chat

## Goal

Ship the inject route (a side chat's rows become main-line rows in place, one-way) and the delete
route (the chat family's first hard delete — its rows are removed permanently), each clearing the
active pointer when it targets the active side chat.

## Source files

- `backend/app/services/chats.py`
- `backend/app/routes/chats.py`

## Test files

- `backend/tests/routes/test_chat_side_chats_inject_delete.py`
- `backend/tests/services/test_chat_turn_side_chats_inject.py`

## Interface intent

- **`services/chats.py::inject_side_chat`** — takes access, wire chat id and wire side-chat id;
  resolves the owned chat (404 for missing / other book / other author); parses the id (non-numeric →
  `side_chat_not_found`); refuses `side_chat_not_found` when the id is neither the pointer nor carried
  by any row; otherwise calls `chat_messages.clear_side_chat` for that chat and id, clears the pointer
  **if** it equalled the id, persists the chat through `db/chats.update` (so `modified_at` bumps even
  when the pointer did not move), and returns the `ChatDetailResponse` — the chat plus **all** rows in
  position order, exactly what `get_chat` returns.
- **`services/chats.py::delete_side_chat`** — same resolution and existence check; calls
  `chat_messages.delete_by_side_chat`, clears the pointer if it equalled the id, persists through
  `db/chats.update`, returns nothing. Writes **no table other than `chat_messages`** (and the
  `chats` pointer). No renumbering of surviving rows.
- **`routes/chats.py`** — two handlers: `POST /{chat_id}/side-chats/{side_chat_id}/inject` → 200
  `ChatDetailResponse`, and `DELETE /{chat_id}/side-chats/{side_chat_id}` → **204 with no body**.
  Both under `Depends(authz.book_access)`, HTTP-only, mapping `ChatError` through `_map_chat_error`,
  registered beside step 002's two handlers.

## Definition of done

1. `[test]` Inject of a **finished** side chat answers **200** with a `ChatDetailResponse` in which
   every row that carried the id now has `side_chat_id: null`, the rows keep their original
   `position` values and relative order, and every other row (main line, another finished side chat)
   is unchanged. (US-139.AC-1)
2. `[test]` Inject of the **active** side chat answers **200** with `chat.active_side_chat_id: null`
   and its rows' `side_chat_id: null`. (UC-112 step 2)
3. `[test]` After inject, the next main-line turn receives, in the messages handed to the model, a
   fact stated only in the injected messages. (US-139.AC-2)
4. `[test]` Inject for an id nobody carries, for a non-numeric id, and on another author's chat
   answers **404**; the chat and its rows are unchanged. (D-D; US-061 inherited)
5. `[test]` Delete of a **finished** side chat answers **204** with an empty body; a following `GET`
   detail no longer contains any row that carried the id, and every other row is present with its
   `position` unchanged. (US-140.AC-3)
6. `[test]` Delete of the **active** side chat answers **204**; a following `GET` detail shows
   `active_side_chat_id: null` and none of its rows. (UC-113 step 4; D-D)
7. `[test]` A codex entry created in the same book **while the side chat was active** is still
   present, unchanged, after the side chat is deleted; the chat's main-line rows are also still
   present. (US-140.AC-4)
8. `[test]` After delete, a turn's messages handed to the model contain nothing from the deleted
   rows. (UC-115 step 4)
9. `[test]` Delete for an id nobody carries, for a non-numeric id, and on another author's chat
   answers **404**; nothing is deleted. (D-D; US-061 inherited)
10. `[test]` Inject (**200**) and delete (**204**) of an **active side chat with zero rows** both
    clear the pointer and change no rows. (D-D)
11. `[test]` After a delete leaves a gap in `position`, the next turn's new rows are appended at
    max+1 and the detail response is still in ascending `position` order. (D-D — no renumbering)

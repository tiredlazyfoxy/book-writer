# 005 — Side-chat action state: enablement computeds, the four effect functions, delete confirmation

## Goal

Give `ChatPaneState` the action half of the feature — the busy / error trio for side-chat actions, the
delete-confirmation slot, the `canStartSideChat` / `canFinishSideChat` / `sideChatActionsEnabled`
computeds that enforce product D1 on the client, and the external effect functions that call the four
api functions and re-sync the pane from the server's answer.

## Source files

- `frontend/src/work/components/chat/chatPaneState.ts`

## Test files

- `frontend/tests/work/sideChatActions.test.ts`

## Interface intent

- **`ChatPaneState.sideChatActionStatus`** (`'idle' | 'busy' | 'error'`) and
  **`sideChatActionError`** (`string | null`) — the action trio's status and error; there is no
  `data` member because every action's data lands in `chats` / `messages`.
- **`ChatPaneState.sideChatDeleteConfirm`** — `string | null`; the side-chat id awaiting the author's
  confirmation, or `null` when no confirmation is open.
- **`ChatPaneState.sideChatActionsEnabled`** — computed; `false` when there is no active chat, while
  `turnStatus === "streaming"`, while `closeTurnActive !== null`, or while `sideChatActionStatus ===
  'busy'`; otherwise `true`. The one predicate every side-chat control reads (D1).
- **`ChatPaneState.canStartSideChat`** — computed; `sideChatActionsEnabled && activeSideChatId ===
  null`.
- **`ChatPaneState.canFinishSideChat`** — computed; `sideChatActionsEnabled && activeSideChatId !==
  null`.
- **`startSideChat(state, bookId, signal?)`** — external; guards on `canStartSideChat` and an active
  chat id; sets `busy`; calls the api; on success replaces the matching entry in `state.chats` with
  the returned chat (so `activeSideChatId` flips) and sets `idle`; on `ApiError` sets `error` +
  message; anything else rethrows.
- **`finishSideChat(state, bookId, signal?)`** — external; guards on `canFinishSideChat`; calls the
  api with the current `activeSideChatId`; on success patches `state.chats` with the returned chat
  (messages are untouched — the group becomes "finished" purely through `renderedTranscript`).
- **`injectSideChat(state, bookId, sideChatId, signal?)`** — external; guards on
  `sideChatActionsEnabled`; calls the api; on success replaces `state.messages` **whole** with the
  response's messages and patches `state.chats` with the response's chat.
- **`deleteSideChat(state, bookId, sideChatId, signal?)`** — external; guards on
  `sideChatActionsEnabled`; calls the api (no body comes back), then reloads the chat through the
  existing `getChat` and swaps `state.messages` whole and patches `state.chats` (the `finishTurn`
  reload idiom); clears `sideChatDeleteConfirm` on success **and** on error.
- **`requestDeleteSideChat(state, sideChatId)`** / **`dismissDeleteSideChat(state)`** — external;
  set / clear `sideChatDeleteConfirm` inside `runInAction`; call no api.

## Definition of done

1. `[test]` `canStartSideChat` is `true` with an active chat whose `active_side_chat_id` is `null`,
   `turnStatus` not streaming, no close turn active and status `idle`; it is `false` when the active
   chat's `active_side_chat_id` is set. (UC-110 precondition; US-135.AC-2 — the client refusal)
2. `[test]` `canStartSideChat` is `false` while `turnStatus === "streaming"`. (US-135.AC-3)
3. `[test]` `canFinishSideChat` is `true` only when the active chat's `active_side_chat_id` is set
   and `sideChatActionsEnabled` holds; it is `false` while streaming. (UC-111 precondition and
   exception flow)
4. `[test]` `sideChatActionsEnabled` is `false` while `closeTurnActive !== null`, while
   `sideChatActionStatus === 'busy'`, and when there is no active chat; `true` otherwise. (D1 —
   UC-112 / UC-113 exception flows)
5. `[test]` `startSideChat` calls the start api once with the book id and active chat id, and
   afterwards `activeSideChatId` equals the returned chat's `active_side_chat_id` and
   `sideChatActionStatus` is `'idle'`. (UC-110 steps 1–2)
6. `[test]` `finishSideChat` calls the finish api with the current `activeSideChatId`; afterwards
   `activeSideChatId` is `null`, `state.messages` is the same array content as before, and the
   formerly active group appears in `renderedTranscript` as `active: false, expanded: false`.
   (US-137.AC-1 — the client half)
7. `[test]` `injectSideChat` calls the inject api with the given id; afterwards `state.messages`
   equals the response's messages (every formerly grouped row now `side_chat_id: null`) and
   `renderedTranscript` shows them as `message` items in order. (US-139.AC-1 — the client half)
8. `[test]` `deleteSideChat` calls the delete api once and then `getChat` once; afterwards
   `state.messages` equals the reload's messages, `state.chats` carries the reloaded chat, and
   `sideChatDeleteConfirm` is `null`. (US-140.AC-3 — the client half)
9. `[test]` `requestDeleteSideChat` sets `sideChatDeleteConfirm` to the given id and calls no api;
   `dismissDeleteSideChat` sets it back to `null`, calls no api, and leaves `messages` and `chats`
   unchanged. (US-140.AC-1, US-140.AC-2 — the state half)
10. `[test]` When the api rejects with an `ApiError`, each of the four effect functions sets
    `sideChatActionStatus` to `'error'` and `sideChatActionError` to the error's message, and leaves
    `messages` and `chats` unchanged; a non-`ApiError` rejection propagates. (D-F — backend is the
    source of truth)
11. `[test]` While `sideChatActionStatus === 'busy'`, `canStartSideChat`, `canFinishSideChat` and
    `sideChatActionsEnabled` are all `false`; a second call to any effect function during that window
    calls no api. (D1)

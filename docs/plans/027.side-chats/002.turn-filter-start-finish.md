# 002 — The two DTO fields, the capture-once transcript filter, and the start / finish routes

## Goal

Expose the two side-chat fields on the wire, make the turn stamp its rows with the active side-chat id
and read the filtered transcript (D-C), and ship the start and finish routes with the three new
`ChatErrorReason` members — so a side chat can be opened, receive turns that see the right history,
and be closed.

## Interface intent

- **`ChatResponse.active_side_chat_id`** — a new optional string field, the chat's active side-chat
  id as a decimal string or `null`; filled by `services/chats.py::_to_chat_response`.
- **`ChatMessageResponse.side_chat_id`** — a new optional string field, the row's side-chat id as a
  decimal string or `null`; filled by `_to_message_response`, the single mapper behind the `done`
  frame and the detail reload.
- **`ChatErrorReason`** gains three members — `side_chat_already_active`, `side_chat_not_found`,
  `side_chat_not_active` — and **`routes/chats.py::_CHAT_ERROR_STATUS`** maps them to 409 / 404 / 409.
- **`services/chats.py::start_side_chat`** — takes the access context and the wire chat id; resolves
  the owned chat (404 for missing / other book / other author); refuses with
  `side_chat_already_active` when the pointer is non-null; otherwise mints a new id with
  `generate_id()`, sets `active_side_chat_id`, persists through `db/chats.update`, and returns the
  `ChatResponse`. Allowed when the chat has no messages at all.
- **`services/chats.py::finish_side_chat`** — takes access, wire chat id and wire side-chat id;
  resolves the owned chat; parses the side-chat id (non-numeric → `side_chat_not_found`); if the id is
  neither the pointer nor carried by any row (`chat_messages.side_chat_exists`) → `side_chat_not_found`;
  if it exists but is not the pointer → `side_chat_not_active`; otherwise clears the pointer, persists
  through `db/chats.update`, touches **no message row**, and returns the `ChatResponse`.
- **A module-private side-chat-id parser** in `services/chats.py`, the `_parse_chat_id` twin, raising
  `side_chat_not_found` on a non-numeric string. Step 003 reuses it.
- **`routes/chats.py`** — two handlers: `POST /{chat_id}/side-chats` → 201 `ChatResponse`, and
  `POST /{chat_id}/side-chats/{side_chat_id}/finish` → 200 `ChatResponse`; both under
  `Depends(authz.book_access)`, both HTTP-only, both mapping `ChatError` through `_map_chat_error`.
  Registered alongside `turn` / `title`, after the static `model-options` route.
- **`services/chat_turn.py::run_turn`** — captures `chat.active_side_chat_id` **once**, immediately
  after the chat is resolved and before any further await; passes it as `side_chat_id` on the user-row
  insert and on the assistant-row insert (including the retry path with no user row); and replaces the
  `list_by_chat_ordered(chat.id)` history load with `chat_messages.list_transcript(chat.id,
  <captured id>)`. The `{"role", "content"}` mapping and everything after it are unchanged. **No
  change to `TurnRequest`, frames, composition, tools or delegation.**

## Definition of done

1. `[test]` `GET /chats/{chat_id}` on a chat with no side chat returns `chat.active_side_chat_id:
   null`, and every message has `side_chat_id: null`; after seeding a message row with a side-chat id
   directly, the detail shows that row's `side_chat_id` as the id's decimal string. (D-E; US-135.AC-1
   — the wire half of "set apart")
2. `[test]` `POST …/side-chats` on a chat with messages and no active side chat answers **201** with a
   `ChatResponse` whose `active_side_chat_id` is a non-null decimal string; a following `GET` detail
   shows the same value. (UC-110 steps 1–2; US-141.AC-1 — the server holds the pointer)
3. `[test]` `POST …/side-chats` on a chat with **zero** messages also answers **201** with the pointer
   set. (UC-110 alternate flow)
4. `[test]` A second `POST …/side-chats` while one is active answers **409** and the pointer is
   unchanged. (US-135.AC-2)
5. `[test]` `POST …/side-chats/{sid}/finish` for the active side chat answers **200** with
   `active_side_chat_id: null`; message rows that carried `sid` **still carry it** and are still
   returned by `GET` detail. (US-137.AC-1 — the server half; US-138.AC-2)
6. `[test]` Finish for an id carried by rows but not the pointer (a finished side chat) answers
   **409**; finish for an id nobody carries, and for a non-numeric id, answers **404**. (D-D)
7. `[test]` Start and finish on another author's chat in the same book answer **404**, never 403;
   on a book the caller has no relationship to, **404**. (US-061 inherited; `authorization.md` → chat
   row ownership)
8. `[test]` A turn run while a side chat is active persists **both** the user row and the assistant
   row with `side_chat_id` equal to the pointer; a turn run with no active side chat persists both with
   `None`. (UC-110 step 3)
9. `[test]` A turn inside an active side chat receives, in the messages handed to the model, a fact
   stated only in a main-line message that precedes the side chat. (US-136.AC-1)
10. `[test]` A turn inside an active side chat receives a fact stated only in an earlier message of
    that same side chat. (US-136.AC-2)
11. `[test]` A main-line turn after a side chat is finished (pointer null, rows still carry the id)
    does **not** receive a fact stated only in that side chat, while still receiving the main-line
    messages around it. (US-138.AC-1)
12. `[test]` A turn inside active side chat B does not receive a fact stated only in **finished** side
    chat A, while receiving the main line and B's own earlier messages. (UC-115 steps 1–2)
13. `[test]` A retry turn (no prompt, so no user row) while a side chat is active persists the
    assistant row with `side_chat_id` equal to the pointer. (D-C)
14. `[test]` The turn's `done` frame carries the persisted assistant message with `side_chat_id`
    equal to the pointer as a decimal string. (D-E — the single-mapper rule)

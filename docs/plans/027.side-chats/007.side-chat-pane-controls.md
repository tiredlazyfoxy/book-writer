# 007 — Pane controls: the Start / Finish slot, the delete confirmation, the error banner, the composer hint

## Goal

Put the feature's entry points on the chat pane — one swapping header slot showing `Start side chat`
or `Finish side chat`, a plain `Modal` that asks before a delete, an `Alert` for a failed action, and
a one-line composer hint while a side chat is active.

## Interface intent

- **The header slot** in `ChatPane` — one `ActionIcon` (with `Tooltip`) placed **before** the `New
  chat` icon: when `state.activeSideChatId === null` it is `aria-label="Start side chat"`, disabled
  unless `canStartSideChat`, and calls `startSideChat`; when non-null it is `aria-label="Finish side
  chat"`, disabled unless `canFinishSideChat`, and calls `finishSideChat`. **One slot, swapping** —
  never both rendered.
- **The delete confirmation** in `ChatPane` — a `@mantine/core` `Modal` with `opened={state.
  sideChatDeleteConfirm !== null}`, a title naming the action, body text saying the side chat's
  messages are removed permanently and that anything saved during it (codex entries, chapter edits,
  memos) is kept, and two `Button`s: `Keep it` → `dismissDeleteSideChat`; `Delete side chat` →
  `deleteSideChat` with the pending id. `onClose` also dismisses.
- **The error banner** in `ChatPane` — an `Alert` rendering `state.sideChatActionError` when
  `sideChatActionStatus === 'error'`; absent otherwise.
- **`MessageList` receives the book id** — the one-line change at the existing call site so step
  006's group actions become live (see `006.context.md` → "Book id").
- **The composer hint** in `Composer` — a small `Text` above the input reading `Replying in the side
  chat` while `state.activeSideChatId !== null`; nothing otherwise. **No gate change**: the composer's
  read-only rule and `canSend` are untouched (US-137.AC-3 holds by construction, D-F).

## Definition of done

1. `[test]` With an active chat whose `active_side_chat_id` is `null`, the header shows a control
   named `Start side chat` and **no** control named `Finish side chat`. (UC-110 precondition)
2. `[test]` With an active chat whose `active_side_chat_id` is set — as it is after reload, with no
   client-side memory involved — the header shows `Finish side chat` and **no** `Start side chat`.
   (US-141.AC-1 — the pane reflects the server pointer; UC-114 step 3)
3. `[test]` `Start side chat` is disabled while `turnStatus === "streaming"` and enabled when idle.
   (US-135.AC-3)
4. `[test]` `Finish side chat` is disabled while `turnStatus === "streaming"` and enabled when idle.
   (UC-111 exception flow — D1)
5. `[test]` Clicking `Start side chat` calls the start api once with the active chat id; clicking
   `Finish side chat` calls the finish api once with the active chat id and the active side-chat id.
   (UC-110 step 1; UC-111 step 1)
6. `[test]` When `sideChatDeleteConfirm` is set, a dialog is open whose text says the messages are
   removed permanently and that saved work is kept, with buttons `Keep it` and `Delete side chat`;
   when it is `null` no dialog is rendered. (US-140.AC-1)
7. `[test]` Clicking `Keep it` closes the dialog, calls **no** api, and leaves `messages` and
   `chats` unchanged. (US-140.AC-2)
8. `[test]` Clicking `Delete side chat` in the dialog calls the delete api once with the pending
   side-chat id. (US-140.AC-3 — the trigger)
9. `[test]` When `sideChatActionStatus === 'error'`, an alert containing `sideChatActionError`'s
   text is rendered; when `'idle'`, no such alert exists. (D-F)
10. `[test]` The composer shows the text `Replying in the side chat` when a side chat is active and
    does not show it otherwise; the input and its Send control are present and enabled in both cases
    (the gate is unchanged). (UC-110 step 3; US-137.AC-3 — by construction, no composer exists for a
    finished group)
11. `[manual/live]` End to end against the running app: start a side chat, send two turns, finish
    it, confirm the group collapses in place and the next main-line turn does not reference the side
    chat; inject a finished one and confirm its rows become ordinary; delete one behind the
    confirmation and confirm a codex entry saved meanwhile survives; leave the chat and return with a
    side chat active and confirm the next message lands in it. (UC-110..UC-115, US-141.AC-1)

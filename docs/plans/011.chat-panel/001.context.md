# 001 — step context

Feature-wide facts (layer rules, route/DTO conventions, the chat privacy rule and its 404 choice,
the `llm` option allowlist, test harness, gates) are in `context.md`. Only what this step alone needs
is below.

## The tables as they exist today

`backend/app/models/chat.py`:

- `Chat` (`__tablename__ = "chats"`): `id` (snowflake PK), `book_id` FK `books.id`, `author_id` FK
  `users.id`, `title: str`, `archived: bool = False`, `created_at`, `modified_at`.
- `ChatMessage` (`chat_messages`): `id`, `chat_id` FK `chats.id`, `role: str` (**free string, no
  enum — deliberate**), `content: str`, `position: int`, `created_at`.

## The db modules as they exist today

- `db/chats.py` exports **only** `create(row) -> Chat`, `get_by_id(chat_id) -> Chat | None`,
  `list_by_book(book_id) -> list[Chat]`.
- `db/chat_messages.py` exports **only** `create`, `get_by_id`,
  `list_by_chat(chat_id) -> list[ChatMessage]` — **unordered**.
- There is **no `update`, no delete and no position allocation anywhere** in either module. Step 003
  is the only writer of messages; this step adds the read and allocation primitives it will use.

## The model-pair precedent

`SubAgent` already carries `llm_server_id: int | None = Field(default=None,
foreign_key="llm_servers.id")` and `model_name: str | None`. Mirror it field-for-field —
`assistant-config.md` gives the reasoning (a model only exists on a registered `LlmServer`, and the
`llm` client binds a model at client construction).

## `LlmServer` and its db module

`LlmServer`: `id`, `name`, `backend_type: str` (`"llama-swap"` or `"openai"` — **hyphen**),
`base_url` (includes `/v1`), `api_key: str | None` (raw or `$ENV_VAR`),
`enabled_models: str = "[]"` (**JSON-encoded `list[str]` in TEXT** — the precedent this step copies
for `sampling_params`), `is_active`, `is_embedding`, `embedding_model`, timestamps.

`db/llm_servers.py`: `get_by_id`, `get_all`, `get_active` (ordered by name), `create`, `update`,
`delete`, `clear_all_embedding`, `get_embedding_server`. **There is no query for "which models are
enabled"** — load the servers and `json.loads` the field.

**`services/llm_servers.py:get_server()` masks the api key**, so the model-options path must read
through `db.llm_servers` directly. `probe_models` is the existing precedent for that bypass.

## Authorization surface this step binds to

`services/authz.py` exports `AccessRole(owner|co_author|reader|none)`, `Capability` (7
book-lifecycle values), the frozen dataclass `BookAccess(book_id, user_id, role, book_state,
visibility, collaboration_mode)`, `BookAuthorizationError(capability, role)`,
`resolve_book_access(book_id, user)`, the FastAPI dependency
`book_access(book_id, user=Depends(auth_service.get_current_user))` — which already raises
`HTTPException(404)` for a missing book or `role == none` — and `require(access, capability)`.

`_CAPABILITY_MATRIX: dict[Capability, frozenset[AccessRole]]` has **no chat entries and gains
none**. See `context.md` for why the ownership rule cannot live in it.

Note that `BookAccess` carries `user_id`, so the service has the caller's id without a second
dependency.

## Codecs — where and what shape

`_chat_to_dict` / `_dict_to_chat` / `_chat_message_to_dict` / `_dict_to_chat_message` live in
`services/db_import_export.py` around lines 845–930. `TABLE_REGISTRY` is an 18-entry list of
`RegistryEntry = tuple[str, type[SQLModel], to_dict, from_dict]`; **chats and chat_messages are the
final two entries** and stay where they are.

`backend/tests/test_data_domain_chat.py` **pins the field sets** of both tables and must be amended
in this step. `FULL_CANONICAL_ORDER` in the data-domain tests is registry **ORDER** only — unchanged,
because no table is added.

## Route surface to add

All under one router, `prefix="/api/books"`, mounted bare in `main.py`:

```
GET    /{book_id}/chats/model-options      <- MUST be declared before /chats/{chat_id}
POST   /{book_id}/chats
GET    /{book_id}/chats?archived=false
GET    /{book_id}/chats/{chat_id}
PATCH  /{book_id}/chats/{chat_id}
```

Book-nesting the model-options endpoint is deliberate: the pairs are not book-scoped data, but
gating them on book membership reuses `Depends(authz.book_access)` and avoids inventing a second
authorization story for a picker. Today `/api/admin/llm-servers` is admin-gated, so an author has
**no** data source for a model picker without this endpoint.

Step 003 adds one more route to this same file (`POST /{book_id}/chats/{chat_id}/turn`); leave the
file shaped so that appending it is a local change.

## Error → status map

Mirror `services/llm_servers.py`'s taxonomy shape (`LlmServerErrorReason(invalid_backend_type |
missing_field | not_found | env_not_set | probe_failed)` → 400/400/404/400/502): a reason enum on
the error plus a module-level dict in the route. This step needs chat-not-found → **404**, and every
validation reason → **400**.

## What this step does not do

- No message **writing** — the only writer is step 003's turn endpoint. This step ships the ordered
  read and the position allocation it needs.
- No delete endpoint. Archive is the removal semantic (UC-082), consistent with books, users and
  codex entries.
- No `Capability` additions, no `_CAPABILITY_MATRIX` edit.
- No frontend file, no `types/` or `api/` module — those are step 004.

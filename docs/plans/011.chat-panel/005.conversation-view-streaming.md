# 005 — conversation view, streaming send, collapsible thinking, retry

## Goal

Fill the chat pane's conversation region: render the active chat's messages with `react-markdown`,
send a prompt over the repo's first `streamPost()` call site, append content deltas incrementally,
stream thinking into a collapsible region that auto-collapses when content starts, render persisted
reasoning collapsed on reopen, and show an error banner with a retry that preserves the conversation.
Above the band (~280 lines) by the sizing call in `context.md`: the stream's state, its renderer and
its failure path are one contract.

## Interface intent

- **`api/client.ts`** — export a **reusable token-refresh entry point** wrapping the one-shot silent
  refresh `request<T>` already performs on a 401, reusing the same `isRefreshing` guard and the same
  `logout()`-on-failure behaviour. This is the fix for `streamPost()` bypassing `client.ts` entirely:
  it uses `authHeaders()` + raw `fetch`, so a stale token would fail the stream with no recovery. No
  other behaviour of `request<T>` changes.
- **`api/chats.ts`** — one added function opening the **turn stream**: it awaits the refresh entry
  point above, then calls `streamPost()` against the turn endpoint with the optional prompt in the
  body and handler callbacks for the four frames, returning the `AbortController` that `streamPost`
  owns. Document the seam plainly in the module: **`streamPost` owns and returns its own
  `AbortController` and takes no `signal`**, so this one api function breaks the repo's trailing-
  `signal` shape; the caller stores the returned controller instead of passing one in. The `data`
  payloads arrive as `unknown` and are narrowed here, so no `any` escapes into the state layer.
- **`chatPaneState.ts`** — the conversation half of the pane state.
  - Added observable data: a **messages async trio** for the active chat; the in-flight turn's
    `streamingContent` and `streamingThinking` buffers; a `turnStatus` (idle / streaming / error); a
    turn error message; whether the live thinking region is expanded; the pending prompt text; and the
    live `AbortController` handle.
  - Added pure `get` computeds: whether the composer may submit (non-empty prompt, a chat is active,
    no turn in flight), whether a retry is offered, and the rendered message sequence including the
    in-flight assistant bubble.
  - Added external functions: **load messages** for a chat (`(state, bookId, chatId, signal?)`);
    **send** (`(state, bookId, text)` — appends the user message optimistically, clears the buffers,
    opens the stream, appends `thinking` frames to the thinking buffer and `delta` frames to the
    content buffer through `runInAction`, replaces the in-flight bubble with the persisted message on
    `done`, sets the error state on `error`); **retry** (`(state, bookId)` — opens the same stream
    with **no prompt**, so no user message is re-sent or duplicated); and **stop** (abort the live
    controller). The pick handler from step 004 gains a message load; the shell's unmount cleanup
    calls stop.
  - **The thinking region auto-collapses when the first content delta of a turn arrives** and is
    expandable again by the author; a *persisted* message's reasoning renders **collapsed by
    default** on reopen.
- **`MessageList.tsx`** — an `observer` list rendering each message by role: user messages plain,
  assistant messages through **`react-markdown`** (installed, currently unused repo-wide), each
  assistant message with reasoning preceded by a `ThinkingBlock`, plus the in-flight bubble fed from
  the streaming buffers. Bounded height with its own scroll region; if it auto-scrolls while
  streaming, that is the one sanctioned imperative case and must be a single `autorun` started in the
  mount effect and disposed on cleanup (`frontend.md` → React hook rules) — no `useEffect` in this
  leaf.
- **`ThinkingBlock.tsx`** — an `observer` collapsible region taking the reasoning text, an expanded
  flag and a toggle handler, labelled so an author knows it is the assistant's thinking. Used for both
  the live stream and persisted reasoning; it holds no state of its own.
- **`Composer.tsx`** — an `observer` prompt input (Mantine `Textarea`) with a send control and a stop
  control while streaming, disabled while a turn is in flight, plus the error banner carrying the
  retry action. Submitting clears the input only once the send has been accepted, so a failed send
  never eats the text.
- **`ChatPane.tsx`** — replaces step 004's stub conversation region with `MessageList` + `Composer`,
  passing the same state instance down. No new state, no new effect.

## Definition of done

1. `[test]` Reopening a chat renders its stored messages in position order, user and assistant
   distinguishable, assistant content rendered as markdown (UC-081, US-095.AC-2, US-058.AC-2).
2. `[test]` Sending a prompt shows the author's message immediately and appends `delta` frames
   incrementally to the assistant bubble as they arrive — the bubble grows across frames rather than
   appearing whole at the end (UC-054, US-058.AC-1).
3. `[test]` `thinking` frames stream into a Thinking region that is expanded while thinking, and it
   **auto-collapses when the first content delta arrives** (`context.md` → decisions 7/8).
4. `[test]` A reopened chat renders a stored message's reasoning **collapsed by default**, expandable
   on demand (`context.md` → decision 8).
5. `[test]` `done` replaces the in-flight bubble with the persisted assistant message exactly once —
   no duplicate and no orphaned streaming bubble (US-058.AC-1).
6. `[test]` `error` shows an error banner with a retry action and the conversation up to that point is
   preserved, including the author's just-sent message (UC-056, US-060.AC-1, US-060.AC-2).
7. `[test]` Retry re-opens the turn stream **without a prompt**, so the author's message is neither
   re-sent nor duplicated, and a successful retry appends exactly one assistant message
   (UC-056, US-060.AC-1).
8. `[test]` The composer is disabled while a turn is in flight and re-enabled on both `done` and
   `error`; a second prompt after a completed turn continues the same chat with the prior exchange
   retained (US-058.AC-2).
9. `[test]` The token-refresh entry point is awaited **before** the stream is opened, since
   `streamPost` bypasses `client.ts`'s 401 silent refresh (`frontend.md` → SSE / streaming).
10. `[test]` Switching the active chat mid-stream (or unmounting) aborts the live stream and leaves no
    stray buffer text on the newly opened chat.
11. `[manual/live]` `cd frontend && npm run build` clean, `npm test` green, `npm run test:types`
    clean.
12. `[manual/live]` A live turn against a llama.cpp server started with `--reasoning-format none`
    streams thinking then content into the pane and persists both (`context.md` → deployment
    requirement).

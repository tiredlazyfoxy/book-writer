# 001 — chat CRUD, per-chat model and sampling

## Goal

Ship the chat data surface: `Chat` gains a per-chat `(llm_server_id, model_name)` pair and a
JSON `sampling_params` column, `ChatMessage` gains `reasoning`, and a book-nested chat API delivers
create / list / pick / update / archive plus an author-visible list of selectable models — all of it
private to `Chat.author_id`. Deliberately above the 50–200-line band (~340 lines): schema, codecs,
db, service and routes for one entity pair are a single contract, and the sizing call is the user's
(see `context.md` → "Step sizing").

## Interface intent

- **`models/chat.py`** — three columns, no new table.
  - `Chat` gains the **nullable model pair** `llm_server_id` (FK → `llm_servers.id`) and
    `model_name`, mirroring `SubAgent`'s existing pair exactly, plus `sampling_params`, a
    **non-nullable TEXT column holding a JSON object** whose default is the serialized default
    `ChatSamplingParams`.
  - `ChatMessage` gains a **nullable `reasoning`** text column — the assistant's thinking for that
    message, `None` for user messages and for assistants that produced none.
- **`models/schemas/chats.py`** (new) — DTOs only, no logic.
  - **`ChatSamplingParams`** — the typed gate over the JSON column: the nine params plus
    `enable_thinking`, with the defaults in `context.md` → decision 6, `max_tokens` and `seed`
    optional-and-unset. This model is the *only* way the column is read or written.
  - A **create request** (optional title, the model pair, optional sampling overrides), an **update
    request** whose fields are all optional (title, archived, model pair, sampling) so it doubles as
    the archive/restore and settings-edit body, a **chat response** (ids as strings, the model pair,
    the parsed sampling object, `archived`, both timestamps), a **chat list envelope**, a **message
    response** (id, chat id, role, content, nullable reasoning, position, created-at), a **message
    list envelope**, and a **model-option** response naming an `LlmServer` id + display name and one
    model on it, with its list envelope.
- **`db/chats.py`** — add an **update** (persisting changed columns and bumping `modified_at`) and a
  **per-author listing** for a book, filtered by `archived` and ordered most-recently-modified
  first. The existing `create` / `get_by_id` / `list_by_book` stay.
- **`db/chat_messages.py`** — add an **ordered listing by `position` ascending** for a chat (today's
  `list_by_chat` is unordered) and a **next-position allocation** returning `0` for an empty chat
  and `max(position) + 1` otherwise. Both session-free, like every other function in the module.
- **`services/chats.py`** (new) — the business layer and the single place the privacy rule lives.
  - A typed error with a reason enum covering at least: chat-not-found, invalid model pair,
    unknown-or-inactive server, model-not-enabled, invalid sampling — each mapped to a status by the
    route (404 / 400).
  - An internal **ownership resolver** taking the resolved `BookAccess` and a chat id, returning the
    chat only when it belongs to that book **and** `author_id` equals the caller; otherwise the
    not-found reason. Every other function goes through it. Document that a chat belonging to
    another author answers **404, not 403** (US-061.AC-1; `context.md` → "the chat privacy rule").
  - **create** — validates the model pair (both null or both set; a half-set pair is refused),
    validates that a set pair names an **active** server whose `enabled_models` contains the model,
    serializes the sampling object to JSON, and stores the row with the caller as `author_id`.
  - **list for the caller** — the caller's own chats in the book, filtered by archived.
  - **get with messages** — the chat plus its position-ordered messages.
  - **update** — applies whichever of title / archived / model pair / sampling was sent, under the
    same pair and sampling validation; this is the archive (UC-082), restore (US-096.AC-2) and
    settings-edit path.
  - **list model options** — loads active servers through `db.llm_servers` directly (not
    `services/llm_servers.get_server()`, which masks the api key) and flattens each server's
    `enabled_models` JSON into `(server id, server name, model)` triples. **No api key, masked or
    otherwise, appears in the response.**
  - A response mapper building every DTO by hand, ids stringified, sampling JSON parsed through
    `ChatSamplingParams` (a stored value that no longer parses falls back to defaults rather than
    failing the read).
- **`routes/chats.py`** (new) — one router, prefix `/api/books`, every endpoint taking
  `access: authz.BookAccess = Depends(authz.book_access)`:
  - `GET /{book_id}/chats/model-options` — **declared before** the `chats/{chat_id}` routes, per the
    static-before-param rule.
  - `POST /{book_id}/chats` (create), `GET /{book_id}/chats` (list, `archived` query flag defaulting
    to false), `GET /{book_id}/chats/{chat_id}` (chat + messages), `PATCH /{book_id}/chats/{chat_id}`
    (title / archived / model / sampling).
  - Each maps `authz.BookAuthorizationError` → 403 and the chat service error → its status.
- **`main.py`** — mount the router bare, alongside the existing ones.
- **`services/db_import_export.py`** — extend `_chat_to_dict` / `_dict_to_chat` with the model pair
  (`llm_server_id` as a string or null) and `sampling_params`, and `_chat_message_to_dict` /
  `_dict_to_chat_message` with `reasoning`. Ids emit as `str(...)` and parse via `int(...)`;
  datetimes via `.isoformat()` / `fromisoformat`. **`TABLE_REGISTRY` order is unchanged** — no table
  is added.

## Definition of done

1. `[test]` Creating a chat stores it against the caller as `author_id` and the book, with no
   subject/chapter/codex binding of any kind, and returns it with string ids
   (UC-053, US-056.AC-1).
2. `[test]` Listing returns only the caller's own non-archived chats for that book, most recently
   modified first; another author's chat in the same book never appears in the list, and neither the
   book's owner, a co-author, nor an admin can list or fetch it (US-061.AC-1, US-095.AC-1).
3. `[test]` Fetching, updating or archiving a chat owned by another author answers **404**, not 403 —
   existence is not confirmed (US-061.AC-1; `authorization.md` → "Failure modes").
4. `[test]` A chat fetch returns its messages ordered by `position` ascending, and next-position
   allocation returns `0` on an empty chat and `max + 1` afterwards, so a reopened chat carries its
   full prior history in order (UC-081, US-095.AC-2).
5. `[test]` Archiving a chat removes it from the active list while the row and its messages survive,
   and restoring it returns it to the active list (UC-082, US-096.AC-1, US-096.AC-2).
6. `[test]` The model pair moves together: both-null and both-set are accepted, a half-set pair is
   refused at the service edge with 400, and a pair naming an inactive server or a model absent from
   that server's `enabled_models` is refused (`assistant-config.md` → "Model assignment is nullable,
   and the two model fields move together").
7. `[test]` Sampling params round-trip through the TEXT column via `ChatSamplingParams`: an absent or
   partial object yields the documented defaults, a stored unparseable value reads back as defaults
   rather than raising, and a param the UI never surfaces (e.g. `top_k`) survives an unrelated update
   untouched (`context.md` → decisions 4/5/6).
8. `[test]` The model-options endpoint lists `(server id, server name, model)` triples drawn from
   **active** servers' `enabled_models` only — inactive servers contribute nothing — and no api key,
   raw or masked, appears anywhere in the response (UC-053 precondition; FEAT-004).
9. `[test]` A caller who is not a member of the book gets 404 from every chat route, inheriting
   `book_access`'s existence-hiding (`authorization.md`).
10. `[test]` Import/export round-trips the new columns: a chat with a model pair and non-default
    sampling, and an assistant message with `reasoning`, survive export → import unchanged, and the
    `Chat` / `ChatMessage` field-set pins in `test_data_domain_chat.py` include the new fields while
    the registry `FULL_CANONICAL_ORDER` is unchanged (root `CLAUDE.md` → DB Import/Export).
11. `[manual/live]` `cd backend && .venv/Scripts/python -m pytest` green.

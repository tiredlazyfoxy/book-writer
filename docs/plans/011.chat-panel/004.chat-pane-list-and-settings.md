# 004 — chat pane: list, pick, new, archive, settings

## Goal

Replace `010.working-page`'s empty chat-pane placeholder with the real pane's management surface:
the author's chat list, picking a chat (which sets a device-local per-book pointer, not a route), a
new-chat form carrying the model picker and a temperature control, archive/restore, and editable
settings on the active chat. Above the band (~280 lines) by the sizing call in `context.md`: the
pane, its state, its api module and its DTOs are one contract and splitting them would strand a
half-typed api module.

## Interface intent

- **`types/chats.d.ts`** — hand-written DTOs matching the step-001 wire shapes 1:1: the sampling
  params object, a chat, a chat message (including the nullable reasoning field step 005 renders), a
  model option, and the create / update request bodies. `snake_case` throughout, **every id typed
  `string`**, timestamps `ISODateString`, no `any`, no envelope types (envelopes are unwrapped in the
  api module).
- **`api/chats.ts`** — one function per operation, `signal?: AbortSignal` always trailing, all
  through `request<T>` from `client.ts`: list the caller's chats for a book (with an archived flag),
  create, update (title / archived / model pair / sampling — one call used by archive, restore and
  settings alike), fetch one chat with its messages, and list the author-visible model options.
- **`activeChat.ts`** — module-level plain functions in the same tier as `restoreBuffer.ts`
  (`auth.ts`-style: no class, no MobX, no reactivity, no import from `src/api/`): read, write and
  clear the active chat id **for a book**, over `localStorage`, under this module's own key prefix.
  Never throws — a missing, unparseable or foreign value reads as "no pointer". Document that the
  pointer is device-local and deliberately **not** in the URL and **not** on the server
  (`frontend-workspace.md`).
- **`chatPaneState.ts`** — the pane's state class plus its external effect functions.
  - Observable data: a **chats async trio**, a **model-options async trio**, the active chat id, an
    archived-view flag, the new-chat draft (title, chosen `(server, model)` option key, temperature),
    a settings draft for the active chat, `serverErrors`, and per-action submit statuses. No methods.
  - Pure `get` computeds: the visible list (active vs archived), the active chat object, whether the
    new-chat draft can be submitted (a model option must be chosen and the temperature must be in
    range), and the merged client + server error map.
  - External `(state, args, signal)` functions: **load** (fetch chats and model options, then resolve
    the active chat — the stored pointer when it still names a visible chat, otherwise the most
    recent chat by timestamp, otherwise none); **pick** (set the active id and write the pointer);
    **create from the draft** (create, insert into the list, make it active, write the pointer, reset
    the draft); **set archived** (archive or restore, then re-resolve the active chat if the archived
    one was active); **save settings** (update the active chat's model pair and sampling from the
    settings draft). Each writes through `runInAction`, returns early when the signal aborted, turns
    an `ApiError` into an author-facing message, and rethrows anything else.
  - **Sampling handling:** only `temperature` is editable; every other param is carried through
    from the loaded chat unchanged on every update, so an edit never silently resets a stored value
    (`context.md` → decision 4).
- **`ChatPane.tsx`** — the `observer` component for the right-hand region, taking the book id and the
  pane state as props. Renders a header (the active chat's title, a New-chat control, a control that
  shows the list, and an archived-view toggle), the list, the new-chat form and the settings panel,
  and a placeholder region for the conversation that **step 005 fills**. It creates no state instance
  of its own and runs no effect — the shell owns both.
- **`ChatList.tsx`** — an `observer` list of the visible chats: title, last-modified stamp, the active
  one marked, a per-row archive (or restore, in the archived view) action, and an empty state. Picking
  a row calls the pick handler; **nothing here navigates**.
- **`ChatSettingsPanel.tsx`** — an `observer` form rendering the model picker (options grouped or
  labelled by server name) and a temperature control, plus validation messages. Used twice: inside
  the new-chat form and as the active chat's editable settings. **No other sampling param is
  rendered** — they are persisted and untouched.
- **`ChatPaneSlot.tsx`** — the 010 placeholder is removed; the file either disappears in favour of
  `ChatPane` or becomes a one-line adapter. Whichever the skeleton picks, the shell must no longer
  render a "chat pane is owned by `011.chat-panel`" notice.
- **`WorkspaceShell.tsx`** — owns the `ChatPaneState` instance via `useState`, starts the pane load in
  its **existing** mount `useEffect` (same abort-on-unmount cleanup), passes the state to `ChatPane`
  and the "show the list" handler to `WorkNavigator`. No second effect, no context.
- **`WorkNavigator.tsx`** — the entry whose frozen `paneTarget` is `"chat"` stops rendering a router
  link and renders a control that opens the pane's list instead; the six content-pane entries are
  untouched.
- **`routes.tsx`** — the `/chats` child route stops rendering a content-pane placeholder; it becomes a
  redirect to the book-state route so the documented deep link neither 404s nor puts a chat surface in
  the content pane. Every other route is untouched.

## Definition of done

1. `[test]` The pane lists the author's non-archived chats for the book, most recent first, with an
   empty state when there are none (UC-081, US-095.AC-1).
2. `[test]` Picking a chat makes it the pane's active chat and writes the per-book pointer, and the
   content-pane route is unchanged by the pick — the chat opens in the chat pane, not the content
   pane (US-095.AC-2, US-105.AC-3).
3. `[test]` On load the pane resolves the active chat from the stored pointer; when the pointer is
   missing, unparseable, or names a chat that is not in the list, it falls back to the most recent
   chat by timestamp, and to no active chat when the list is empty
   (`frontend-workspace.md` → "The active-chat pointer lives in the same module tier").
4. `[test]` The pointer is per book and device-local: writing one book's pointer leaves another
   book's untouched, clearing removes only that book's, and a pointer read never throws on garbage.
5. `[test]` The **Chats** navigator entry opens the pane's list without navigating, and
   `/work/:bookId/chats` no longer renders a chats view in the content pane (US-105.AC-3).
6. `[test]` Creating a chat requires a chosen `(server, model)` option and a temperature within
   range; on success the new chat is created through the api module, becomes active and appears in
   the list (UC-053, US-056.AC-1).
7. `[test]` The model picker's options come from the model-options call and show both the server name
   and the model name; with no options available the form says so instead of allowing a create
   (UC-054 exception flow — no enabled model means composing is refused).
8. `[test]` Settings are editable on the **active** chat, not create-time only: changing its model or
   temperature calls update and the pane reflects the new values (`context.md` → decision 2/4).
9. `[test]` Archiving a chat removes it from the active list and the archived view shows it with a
   restore action that returns it to the active list; archiving the active chat re-resolves the
   active chat rather than leaving a dangling pointer (UC-082, US-096.AC-1, US-096.AC-2).
10. `[test]` Only `temperature` is surfaced, and an update round-trips every other stored sampling
    param unchanged (`context.md` → decision 4).
11. `[test]` A failed load or a failed action surfaces an author-facing message in the pane rather
    than crashing or rendering blank.
12. `[manual/live]` `cd frontend && npm run build` clean, `npm test` green, `npm run test:types`
    clean.

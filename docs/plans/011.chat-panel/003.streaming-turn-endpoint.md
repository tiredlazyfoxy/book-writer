# 003 — streaming turn endpoint and the think splitter

## Goal

Run one assistant turn end to end: build a model-bound `llm` client from the chat's `(server,
model)`, compose the system prompt, drive `chat_with_tools` in streaming mode, split `<think>` text
out of the token stream into `thinking` frames, and emit `thinking` / `delta` / `done` / `error` over
SSE with user-message-first persistence so a retry never duplicates the prompt. Above the band
(~280 lines) by the sizing call in `context.md`: the splitter exists only to serve this turn, and the
turn's retry semantics are unverifiable without it.

## Interface intent

- **`services/llm_servers.py`** — a **model-bound client construction path** beside the existing
  `_create_client(server, resolved_key)`, which hardcodes `model=""` because it exists only for
  `list_models()`. Either widen it with an optional model argument or add a thin sibling; either
  way **reuse its `backend_type` branch** rather than re-deriving the `"llama-swap"` / `"openai"`
  mapping, so the translation stays in one place. Keep the existing function's name and behaviour
  intact — it is documented as the monkeypatch seam the LLM-server tests bind to. The returned
  client is used by the caller as an **async context manager**; document that the client exposes
  `__aenter__` / `__aexit__` and **no standalone `close()`**.
- **`services/chat_turn.py`** (new) — the turn, and the splitter it needs.
  - **A think splitter** — a small stateful object fed the raw text chunks from `on_delta` and
    emitting `(channel, text)` segments where the channel is thinking or content, plus a flush at
    end of stream. It must be correct for **tags glued to payload text inside one chunk** and for
    **tags split across chunk boundaries**, which means holding back any trailing text that could
    still become a tag prefix, and it must not lose or duplicate a character. State the end-of-stream
    rules explicitly: an unclosed `<think>` leaves the remaining text on the thinking channel, and a
    held-back partial that turns out not to be a tag is flushed verbatim. A naive per-chunk `split()`
    or substring check is wrong and is what DoD-1 exists to catch.
  - **A sampling-options builder** — takes the chat's `ChatSamplingParams` and the server's
    `backend_type` and returns the options mapping to pass to `chat_with_tools`: **the params only
    for a `llama-swap` server; an `openai` server gets none** (user decision 4). Note in the module
    that the library filters whatever is passed against its own allowlist, so `top_k`,
    `repeat_penalty` and `min_p` are dropped inside the dependency today.
  - **The turn orchestrator** — an async generator (or equivalent frame-yielding callable) taking the
    resolved access context, the chat and an optional prompt, and yielding the four frame kinds:
    1. resolve the chat through the same ownership rule as step 001, and resolve its server + model;
    2. **when a prompt is present, persist the user message first** — allocated position, role
       `"user"` — *before* any assistant work, so a failure leaves it stored;
    3. compose the system prompt from the base constant and the book's `system_prompt` (mode and
       chapter layers null at this feature);
    4. build the tool definitions and callable map from the whole registry (null mode);
    5. construct the model-bound client from the chat's pair with the key resolved via
       `resolve_env_ref`, entered as an async context manager so its session is closed on every
       path including failure;
    6. call `chat_with_tools(..., stream=True, on_delta=...)` with a bounded `max_loops`, feeding
       every delta through the splitter and emitting `thinking` / `delta` frames;
    7. on success persist the assistant message — **content assembled from the streamed content
       deltas, `reasoning` from the thinking deltas**, not from the call's return value, because the
       return value is only the final round's text while `on_delta` sees every round — then emit
       `done` carrying the persisted message DTO;
    8. on failure emit a single `error` frame with an author-facing message, leaving the user
       message stored and writing no assistant message.
  - **Failure taxonomy:** catch `aiohttp.ClientError` (connection/DNS/timeout and streaming
    `raise_for_status`), `llm`'s `LLMError` (non-2xx), `ValueError` (tool-definition/callable
    mismatch) **and** `RuntimeError` (a tool raised, or `max_loops` exhausted); an empty result has no
    dedicated exception and must be treated as a failure too ("the LLM ... returns nothing",
    UC-056). None of these may escape as a 500 once the stream has opened.
  - **Pre-stream refusals**, raised as the step-001 typed service error before anything is persisted
    and therefore before the first frame: chat not found or not the caller's, no model pair set on
    the chat, the server missing or inactive, the key's env var unset (UC-054 exception flow — "no
    LLM server is enabled → composing is refused").
- **`models/schemas/chats.py`** — a **turn request** carrying an **optional** prompt (absent = retry:
  run the assistant over stored history, persisting no new user message) and the small payload models
  for the frames, so nothing is serialized from a free dictionary.
- **`routes/chats.py`** — one added endpoint, `POST /{book_id}/chats/{chat_id}/turn`, declared after
  the existing static route: it resolves `Depends(authz.book_access)`, calls the service for the
  pre-stream checks (mapping the typed error to 404/400 as an ordinary JSON response), and only then
  returns a **streaming SSE response** whose frames are named exactly `thinking`, `delta`, `done`,
  `error` with JSON `data:` payloads — the names `frontend/src/api/sse.ts:streamPost()` already
  special-cases. This is the repo's first SSE endpoint.

## Definition of done

1. `[test]` The splitter routes text correctly under adversarial chunkings, losing and duplicating
   no characters: a tag split across two deltas, a tag glued to payload text on both sides within one
   delta, several think blocks in one stream, no tags at all, and an unclosed tag at end of stream
   (UC-054; `context.md` → deployment requirement).
2. `[test]` A turn with a prompt persists the user message **before** the assistant call, and when the
   assistant fails that user message remains stored exactly once with no assistant message written
   (UC-056, US-060.AC-2).
3. `[test]` A retry — the same endpoint with no prompt — re-runs the assistant over the stored
   history without re-sending or duplicating the user message, and the conversation is unchanged
   apart from the outcome (UC-056, US-060.AC-1, US-060.AC-2).
4. `[test]` A successful turn persists one assistant message whose content is assembled from the
   streamed content deltas and whose `reasoning` is assembled from the thinking deltas, at the next
   position (US-058.AC-1; `context.md` → decision 8).
5. `[test]` The frame stream uses exactly the names `thinking` / `delta` / `done` / `error`, emits
   thinking text on `thinking` and content text on `delta`, terminates a successful turn with a single
   `done` carrying the persisted assistant message, and a failed one with a single `error`
   (US-058.AC-1, US-060.AC-1).
6. `[test]` Sampling options are emitted **only** for a `llama-swap` server; a chat on an `openai`
   server passes none (`context.md` → decision 4).
7. `[test]` The client is constructed bound to the chat's `(server, model)` with the api key resolved
   through `$ENV_VAR` indirection, and is closed on both the success and the failure path
   (`assistant-config.md` → "Model resolution").
8. `[test]` Pre-stream refusals answer as ordinary HTTP errors with **nothing persisted**: a chat with
   no model pair, an inactive or missing server, and an unset key env var (UC-054 exception flow).
9. `[test]` Every library failure surfaces as one `error` frame rather than a 500 or a hung stream:
   a connection error, an `LLMError`, a `ValueError` from the tool pre-flight, a `RuntimeError` from a
   raising tool or exhausted `max_loops`, and an empty response (UC-056, US-060.AC-1).
10. `[test]` A chat belonging to another author, and a caller who is not a member of the book, both
    get 404 before any streaming begins and before anything is persisted (US-061.AC-1).
11. `[test]` The turn composes its system prompt from the base constant plus the book's
    `system_prompt` with the mode and chapter layers absent, and offers the whole `TOOL_REGISTRY`
    because the mode is null (`assistant-config.md`; `context.md` → decision 9).
12. `[manual/live]` `cd backend && .venv/Scripts/python -m pytest` green.
13. `[manual/live]` A live turn against llama.cpp started with `--reasoning-format none` produces
    `thinking` frames ahead of `delta` frames; the same model without that flag produces content only
    (`context.md` → deployment requirement).

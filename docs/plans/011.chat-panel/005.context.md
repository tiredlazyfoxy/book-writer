Feature-wide facts (MobX/observer rules, the api + types conventions, the SSE frame vocabulary, the
deployment requirement, test harness, gates) are in `context.md`. Step 004's context covers the pane's
state class, the shell wiring and the patterns both frontend steps copy. Only what this step alone
needs is below.

## `streamPost()` — the exact seam

`frontend/src/api/sse.ts` exports
`streamPost(url, body, handlers: { onEvent?(event, data: unknown), onError?(message), onDone?() }): AbortController`.

- It uses `authHeaders()` + **raw `fetch`**, so it gets **no 401 silent-refresh** — `client.ts`'s
  one-shot refresh lives inside `request<T>` and never runs here. Hence the refresh entry point this
  step exports from `client.ts` and awaits before opening the stream.
- It splits the body on `\n\n`, parses `event:` / `data:` lines, **JSON-parses `data`**, routes
  `error` → `onError`, `done` → `onDone`, and everything else → `onEvent`. So `thinking` and `delta`
  both arrive via `onEvent` with `data: unknown`, and the api module is where they get narrowed.
- It **swallows `AbortError`**, so aborting a live stream is silent and needs no special handling in
  the state layer.
- It **owns and returns its own `AbortController` and takes no `signal`.** This does not match the
  repo's `(state, args, signal)` effect convention. Resolution, stated in the step file and recorded
  in `outcome.md`: the send/retry functions take no `signal`, store the returned controller on the
  state, and expose an explicit stop; the shell's existing unmount cleanup calls it. Do not invent a
  wrapper that fakes a `signal` parameter.
- **Zero call sites in the repo today.** This step writes the first one.

## `client.ts` as it stands

`class ApiError extends Error { status, message, details }`; `request<T>(url, opts)` attaches
`Authorization: Bearer` from `getToken()`, JSON-stringifies `body`, performs a **one-shot** silent
refresh against `/api/auth/refresh` under an `isRefreshing` guard on a 401 and calls `logout()` if
that fails; plus `authHeaders(): HeadersInit` and `throwApiError(res)`. The refresh entry point this
step exports must reuse that same guard and the same `logout()` fallback — do not write a second
refresh path.

## Mantine surface notes specific to this step

- `Textarea` is used exactly once in the repo (`CreateBookModal.tsx`, direct field assignment from
  JSX, no autosize) and has **no theme defaults**. **There is no Enter-to-send precedent anywhere** —
  if the composer adds one, it is new behaviour and belongs in the interface intent's send control,
  not smuggled in.
- `ScrollArea` is used once (`ModelsModal.tsx`, `ScrollArea.Autosize mah={360}`) with no theme
  default; the message list needs its own explicit height bound.
- Auto-scroll while streaming is the one imperative side-effect `frontend.md` sanctions, and only via
  a single `autorun` started in a mount `useEffect` and disposed on cleanup. Leaf components may not
  hold `useEffect`, so if auto-scroll ships, its `autorun` belongs at the pane level.

## Testing a stream, from nothing

The repo has **no `ReadableStream` fixture, no `IntersectionObserver` stub and no fake-timer setup**.
This step's `tests/support/sseFixture.ts` is the first — a helper that drives the mocked
`api/chats` turn function's handlers with a scripted frame sequence, so a spec can assert
frame-by-frame growth (DoD-2) and the auto-collapse transition (DoD-3) without a real body stream.

Mock the **`api/chats` module**, not `sse.ts` and never `fetch` — the api module is the boundary the
state layer sees, and mocking it keeps the refresh-before-stream assertion (DoD-9) at the module's
own seam. Module-factory form, enumerating every export the subject imports.

`vitest.config.ts` has `globals: false`, so every spec imports `describe/it/expect/vi` from
`"vitest"`; `restoreMocks` / `clearMocks` are true, so handler mocks reset between cases.

## Frame → state mapping (the contract this step consumes)

| Frame | Effect |
|---|---|
| `thinking` | append to the thinking buffer; the live region is expanded |
| `delta` | append to the content buffer; **the first one collapses the thinking region** |
| `done` | replace the in-flight bubble with the persisted message DTO; clear the buffers; re-enable the composer |
| `error` | set the turn error, keep every prior message, offer retry, re-enable the composer |

The user message is already persisted server-side before the assistant runs (step 003), which is why
retry sends **no prompt** and why an `error` never requires the author to retype.

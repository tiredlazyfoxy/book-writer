# 003 — The `/api/books/{book_id}/chapters` route family

## Goal

Expose the chapter skeleton over HTTP as six handlers on a book-scoped router, mapping the service's
typed refusals onto the status taxonomy and inheriting existence hiding from the `book_access`
dependency.

## Source files

```
backend/app/routes/chapters.py
backend/app/main.py
```

## Test files

```
backend/tests/routes/test_chapters.py
```

## Interface intent

**`backend/app/routes/chapters.py`** (new) — HTTP only: parse, call one service entry point, return.
No business logic, no capability check, no database access.

- A router owning the path `/api/books/{book_id}/chapters`, following the existing book-scoped route
  families: the `{book_id}` segment is consumed entirely by `Depends(book_access)` and is **not**
  re-declared by any handler; response models are declared as the **return annotation**, never
  `response_model=`.
- **A list handler** — returns the ordered chapter list envelope, including the `can_reorder` hint.
  `200`.
- **A create handler** — takes the create request body, returns the appended chapter. **`201`**, and
  it is the only handler in this family that is not `200`/`204`.
- **A reorder handler** — `PUT` on the `/order` sub-path, takes the full ordered id list and returns
  the freshly ordered list envelope. `200`. **It is declared before any `/{chapter_id}` route in the
  module** so the literal segment can never be shadowed by the parameterised one.
- **A read handler** — one chapter by id. `200`.
- **A sketch handler** — `PATCH` on the chapter id, takes the sketch body, returns the stored chapter.
  `200`. `PATCH` rather than `PUT` because the body carries one field of a larger resource and the
  rest of that resource is other features' to write.
- **A delete handler** — `DELETE` on the chapter id. **`204`**, no body.
- **A module-level reason → status map plus one mapper function**, following the shape the sibling
  book-scoped routers already use: not-found → `404`, not-planned → **`409`**, invalid reorder set →
  `400`.
- Every handler wraps its single service call in the two-`except` idiom `context.md` fixes: the
  authorization error first, mapped by the existing shared helper; then the chapter error, mapped by
  this module's own helper.

**`backend/app/main.py`** — mount the router alongside the other book-scoped routers, mirroring where
`book_author_prompts` sits in the existing `include_router` sequence. Nothing else in this file
changes.

## Definition of done

1. `[test]` `GET` on the collection returns `200` and the book's chapters ordered by ordinal
   ascending, each carrying its id as a string and no body text.
2. `[test]` `POST` returns **`201`** and a chapter in the `planned` state carrying the submitted
   sketch; a following `GET` on the collection includes it, appended last — **US-032.AC-1**,
   **UC-031**.
3. `[test]` `POST` with a blank title is refused as a validation error (`422`) and nothing is stored;
   `POST` with an empty **sketch** succeeds.
4. `[test]` `PATCH` on a `planned` chapter returns `200` with the updated sketch, and a following
   `GET` on that chapter returns the same value — **US-034.AC-1**.
5. `[test]` `PATCH` on a chapter that is `open` or `closed` returns **`409`** and the stored sketch is
   unchanged — **US-034.AC-2**.
6. `[test]` `DELETE` on a `planned` chapter returns **`204`** and the chapter no longer appears in the
   collection — **US-035.AC-1**.
7. `[test]` `DELETE` on a chapter that is `open` or `closed` returns **`409`** and the chapter is
   still there — **US-035.AC-2**.
8. `[test]` `PUT` on `/order` as the **owner** returns `200`, and the returned list — and a following
   `GET` — reflect the submitted order — **US-033.AC-1**.
9. `[test]` `PUT` on `/order` as a **co-author** returns **`403`** and the order is unchanged —
   **US-033.AC-2**.
10. `[test]` `PUT` on `/order` with a list that omits a chapter, adds an unknown id, repeats an id, or
    names another book's chapter returns **`400`** and changes no ordinal.
11. `[test]` A co-author may `POST`, `PATCH` and `DELETE`; a logged-in non-member of a **public** book
    gets `403` from all three.
12. `[test]` A user with no relationship to a **private** book gets `404` from every route in the
    family — existence hiding, inherited from the dependency, not re-derived.
13. `[test]` A request with no token gets `401` from every route in the family.
14. `[test]` Addressing a chapter id that belongs to **another book** returns `404` — not `403` and
    not `200` — on the read, sketch and delete paths.
15. `[test]` `can_reorder` is `true` in the owner's list response and `false` in a co-author's.
16. `[test]` `PUT /order` reaches the reorder handler rather than a chapter-id route — the literal
    segment is not shadowed by the parameterised one.
17. `[test]` A malformed body on `POST`, `PATCH` or `PUT /order` (missing field, wrong type) is
    refused as a validation error and nothing is stored.

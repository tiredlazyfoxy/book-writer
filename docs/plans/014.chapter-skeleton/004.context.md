# 004 — step context

Feature-wide facts (D1's table shape, D7's deferral, the prompt wire contract, the status taxonomy,
the row-ownership rule, the layer rules, the test harness) are in `context.md` and are not repeated
here.

## The quartet to mirror, file for file

Feature `021` shipped the identical subsystem one level up. Read these four side by side and change
`book` to `chapter` throughout:

- `backend/app/models/schemas/book_author_prompts.py` — `UpdateBookAuthorPromptRequest`,
  `BookAuthorPromptResponse`.
- `backend/app/services/book_author_prompts.py` — `_require_member` (role in `{owner, co_author}`
  else the `not_a_member` reason); `_to_prompt_response`, the **sole** DTO construction site, mapping
  a `None` row to `""` plus `None`; `get_prompt`; `upsert_prompt`, where **create stamps both
  timestamps and update stamps `modified_at` only**.
- `backend/app/routes/book_author_prompts.py` — `GET` / `PUT /api/books/{book_id}/system-prompt`, no
  `user_id` in the response, no `DELETE`, no `POST`, `PUT` answering `200` on both the create and the
  update path, error taxonomy `401` / `404` / `403`.

**The one structural difference** is the chapter resolver: `021`'s service had nothing to look up
before the prompt row, because the book was already resolved by the dependency. Here the chapter id is
an unresolved path parameter, so the service adds the resolve-and-check step and a second reason.

## Why the chapter check is duplicated rather than shared with step 002

Both services need "load the chapter, refuse if it is not this book's". Extracting it would make the
prompt service import the chapter service (a `services → services` edge this codebase does not use) or
put it in `db/` (where it would be business logic). It is two lines and one reason enum member. Keep
them separate; DoD-12 pins the behaviour on this side independently of step 002's DoD-12.

## Empty string is a value, not an absence

Two distinct states must both read as "no prompt" but stay distinguishable in storage:

- **no row** for the pair — before the author ever writes one;
- **a row holding `""`** — after the author clears one.

The response DTO renders both as an empty `system_prompt`; the difference shows only in
`modified_at` (`null` versus a real timestamp). **Do not normalise one into the other in the mapper**
— DoD-2 and DoD-7 assert the two sides of this and would otherwise both pass for the wrong reason.

## Timestamps belong to this layer

Step 001's `db/` module persists the row it is handed and stamps nothing (its docstring says so). This
service sets `created_at` **and** `modified_at` on create, and `modified_at` only on update. DoD-6
asserts exactly that split.

## Collaboration mode does not apply

`BookAccess` carries `collaboration_mode`, and several book-domain capabilities are marked *(mode)* in
`authorization.md`'s matrix — a co-author's write is held as a proposal in `proposal` mode. **That
rule does not reach this table.** A system prompt is the author's own instruction to their own
assistant; it is never seen by a co-author and there is nothing for an owner to review. Do not add a
mode check and do not copy `services/codex.py`'s proposal refusal.

## The chapter state machine does not apply either

Step 002 refuses a sketch edit or a removal on anything but a `planned` chapter, with `409`. **Do not
copy that here.** UC-033 and UC-034 gate *the chapter's content*; a per-author prompt is not chapter
content. DoD-8 exists specifically so a later reader cannot "fix" this by adding the state check.

## `main.py` is touched by step 003 too

Both steps add one `include_router` line. They run in sequence, so there is no conflict — but this
step adds **only** its own line and must not disturb step 003's.

## Testing

Two specs, at two layers, deliberately:

- `backend/tests/services/test_chapter_author_prompts.py` — construct `BookAccess` directly (frozen
  dataclass, no HTTP), seed users / books / memberships / chapters through the sibling `db/` modules
  with the `db` fixture. This is where DoD-4, DoD-5, DoD-6, DoD-7 and DoD-8 are cheapest to assert.
- `backend/tests/routes/test_chapter_author_prompts.py` — real JWTs over `http_client`, following
  `backend/tests/routes/test_book_settings.py`'s per-file seeding helpers. This is where the status
  taxonomy (DoD-9 through DoD-15) lives, and it needs three distinct fixtures: a **public** book with a
  logged-in non-member (`403`), a **private** book with a stranger (`404`), and an unauthenticated
  request (`401`).

DoD-8 needs chapters forced into `open`, `closing` and `closed`; this feature ships no state
transition, so write the state directly through `backend/app/db/chapters.py`.

DoD-14 asserts framework-level method rejection — call `DELETE` and `POST` on the path and expect the
framework's refusal, not a handler's.

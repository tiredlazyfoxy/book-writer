# 001 — The `ChapterAuthorPrompt` table, its `db/` module, registration, codec — and the two missing `db/chapters.py` writes

## Goal

Add the `chapter_author_prompts` table that carries one system prompt per `(chapter, author)` pair —
its model, its session-free `db/` module, its model registration and its JSONL codec — and give
`db/chapters.py` the `update` and `delete` functions the whole skeleton feature needs and it does not
have.

## Interface intent

**`backend/app/models/chapter_author_prompt.py`** (new) — one SQLModel table, no logic.

- **`ChapterAuthorPrompt`**, table name `chapter_author_prompts`. Columns exactly as `context.md` →
  decision D1 lists them: a snowflake primary key generated the way every other table generates one, a
  chapter foreign key, a user foreign key, a **required** prompt text (empty string is a valid value
  meaning "no prompt"), and created/modified timestamps. A **unique constraint on the
  `(chapter_id, user_id)` pair**, declared the way `backend/app/models/book_member.py` declares its
  own — that file is the row-shape precedent, and
  `backend/app/models/book_author_prompt.py` is the direct sibling to mirror field for field.
- The module docstring states **why the table exists rather than a column on `Chapter`**: the prompt
  is per-author, and a single column on the chapter can hold only one author's. It also states that it
  **supersedes `Chapter.system_prompt`**, which is dormant and read by nothing (D1).

**`backend/app/db/chapter_author_prompts.py`** (new) — session-free data access, one module per
entity, following `backend/app/db/book_author_prompts.py` for size and idiom (sessions created
internally, detached rows returned, no ORM type leaking out, **no timestamp policy** — the service
owns timestamps).

- **`create`** — persist a new row it is handed and return the stored row.
- **`get_by_chapter_and_user`** — the single lookup the prompt half is built on: return the row for a
  `(chapter_id, user_id)` pair, or nothing when there is none.
- **`update`** — persist an already-mutated row and return the stored row.

No list function, no delete function, no `get_by_id` — nothing in this feature reads the table any
other way, and `db/` modules are not speculatively widened.

**`backend/app/db/chapters.py`** — two additions beside the existing `create` /
`get_by_id` / `list_by_book`. The existing three are untouched.

- **`update`** — persist an already-mutated chapter row and return nothing, copying
  `backend/app/db/books.py`'s `update` idiom exactly (add, commit, refresh).
- **`delete`** — remove the chapter with the given id and report whether a row was removed, copying
  `backend/app/db/book_members.py`'s delete idiom. Deleting an id that is not there is **not** an
  error; it reports that nothing was removed.

A bulk-ordinal writer is **not** added here — the reorder transaction is step 002's, expressed
through repeated `update` calls inside one service operation. A dedicated bulk function would put the
"rewrite ordinals 1..N" rule in `db/`, which is business logic.

**`backend/app/db/engine.py`** — add the new prompt model to the **MODEL-REGISTRATION SEAM** import
list so `init_db()`'s `SQLModel.metadata.create_all` creates the table. **Nothing else in this file
changes**; in particular the **ADDITIVE MIGRATION SEAM stays `pass`** — a brand-new table needs no
migration statement.

**`backend/app/services/db_import_export.py`** — one codec pair and one registry entry.

- A **to-dict / from-dict pair** for the new table, copied in shape from the existing
  `_book_author_prompt_to_dict` / `_dict_to_book_author_prompt`: snowflake ids emitted as **strings**
  and parsed **string-or-legacy-number**, timestamps handled the way the sibling codecs handle them.
- One `TABLE_REGISTRY` entry, `chapter_author_prompts`, placed **immediately after
  `book_author_prompts`** — `TABLE_REGISTRY` is FK dependency (import) order and the row references
  both `chapters` and `users`, which are already earlier.
- **The existing `chapters` codec pair is not touched.** It round-trips `Chapter.system_prompt` today
  and keeps doing so, so archives written before this feature still import (D1).

## Definition of done

1. `[test]` A prompt row created for a `(chapter, user)` pair is returned intact by
   `get_by_chapter_and_user` — every column, including an empty-string prompt, survives the round
   trip.
2. `[test]` `get_by_chapter_and_user` returns nothing when the pair has no row, and never returns a
   row belonging to a different chapter or a different user.
3. `[test]` A second prompt row for the same `(chapter_id, user_id)` pair is refused by the database —
   the unique constraint is real, not advisory.
4. `[test]` Two different users on the same chapter hold independent prompt rows, and the same user on
   two chapters holds independent prompt rows; writing one never changes the other.
5. `[test]` The prompt `update` persists changed text, and the returned row reflects stored state
   rather than the in-memory argument.
6. `[test]` On a freshly initialised database the `chapter_author_prompts` table exists and is
   queryable — the model-registration seam alone creates it, with no migration statement.
7. `[test]` The prompt codec pair round-trips a row through dict and back with every field preserved;
   ids emit as strings, and a dict carrying a **numeric** id still parses.
8. `[test]` `TABLE_REGISTRY` contains exactly one `chapter_author_prompts` entry and it sits **after**
   the `book_author_prompts` entry.
9. `[test]` `db/chapters.py`'s `update` persists a changed `sketch`, a changed `ordinal` and a changed
   `title`, and a following `get_by_id` returns the stored values.
10. `[test]` `db/chapters.py`'s `delete` removes the row — a following `get_by_id` finds nothing and
    `list_by_book` no longer includes it — and reports that it removed one.
11. `[test]` `db/chapters.py`'s `delete` on an id that does not exist reports that nothing was
    removed and raises nothing.
12. `[test]` The existing `chapters` codec still round-trips `system_prompt` unchanged — the dormant
    column stays exportable and importable (D1).

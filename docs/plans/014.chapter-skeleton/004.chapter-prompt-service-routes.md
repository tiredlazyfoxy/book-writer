# 004 — The per-author chapter system prompt: DTOs, service, route pair

## Goal

Let every member of a book read and write **their own** system prompt for a chapter — DTOs, a service
guarded by row ownership over `BookAccess`, and a `GET`/`PUT` pair at
`/api/books/{book_id}/chapters/{chapter_id}/system-prompt`.

**This step stores and serves the prompt. It does not compose it into anything** (D7).

## Interface intent

**`backend/app/models/schemas/chapter_author_prompts.py`** (new) — two Pydantic DTOs, declarative, no
logic. Field sets are fixed by `context.md` → "The wire contract".

- **An update-request DTO** carrying one field: the prompt text. Empty string is valid input.
- **A prompt-response DTO** carrying the chapter id (as a **string**), the prompt text, and the
  last-modified timestamp (nullable — `null` when the author has no row yet). **No `user_id` field**,
  for the reason `context.md` gives.

**`backend/app/services/chapter_author_prompts.py`** (new) — business logic and the ownership guard.

- **A reason enum plus one exception class**, following `services/chats.py`'s typed-error shape. It
  needs exactly **two** reasons: the caller is not a member of this book; the chapter is not found
  (missing, or belonging to another book). Do not invent more — no token, an invisible book and a
  hidden book state are all produced upstream by the `book_access` dependency and never reach this
  service.
- **A private membership guard** taking the access context: an `owner` or a `co_author` passes;
  anything else (a `reader`, or no relationship) raises the not-a-member reason. It makes **no**
  capability check and adds **no** matrix row — `context.md` → the authorization section.
- **A private chapter resolver** — load the chapter and raise the not-found reason when it is missing
  **or when its `book_id` does not match `access.book_id`**. Same rule as step 002's, expressed here
  rather than shared, because a cross-service helper would make this service depend on the chapter
  service for a two-line invariant and would blur which module owns the refusal.
- **A read entry point** — given the access context and a chapter id: guard membership, resolve the
  chapter, then look up the row for `(chapter_id, access.user_id)` through step 001's `db/` module and
  map it to the response DTO. **No row is not an error**: the response carries an empty prompt and a
  null timestamp.
- **A write entry point** — given the access context, a chapter id and the update request: guard,
  resolve, then **upsert** — create the row when absent (setting both timestamps), update the text and
  the modified timestamp when present. Returns the same response DTO, built from what was stored.
  Empty text is stored as-is; there is no deletion path.
- **A private response mapper** — the single place a row (or its absence) becomes the DTO, so both
  entry points cannot drift.

The service never receives, and cannot be asked for, another user's prompt: the user id comes from the
access context, never from an argument or a path segment.

**A prompt is readable and writable on a chapter in *any* state.** The `planned`-only rule belongs to
the sketch and to removal (UC-033, UC-034); an author's instruction to their own assistant is not book
content and is not gated by the chapter's state machine. Do not copy step 002's not-planned refusal.

**`backend/app/routes/chapter_author_prompts.py`** (new) — HTTP only: parse, call one service entry
point, return. No business logic, no capability check, no database access.

*This is a separate module rather than a route family inside `routes/chapters.py`, for three reasons:
it mirrors `routes/book_author_prompts.py`, which is the sibling a reader will look for; it keeps this
step's source list disjoint from step 003's, so the two can be verified independently; and it has its
own reason set and its own status map, which have nothing to do with the skeleton's.*

- A router owning the path `/api/books/{book_id}/chapters/{chapter_id}/system-prompt`. The
  `{book_id}` segment is consumed entirely by `Depends(book_access)` and is **not** re-declared;
  `{chapter_id}` **is** a handler parameter, because the service needs it. Response models are the
  return annotation, never `response_model=`.
- **A read handler** — returns the caller's own prompt for that chapter. `200` always, for a member;
  the "no row yet" case is an ordinary success carrying an empty prompt.
- **A write handler** — takes the update request body, calls the upsert, returns the stored response.
  **`200`, not `201`**: the resource addressed is "this caller's prompt for this chapter", which
  exists conceptually from the moment the caller is a member of the book, and the same URL answers
  before and after.
- **A module-level reason → status map plus one mapper function**: not-a-member → **`403`**,
  chapter-not-found → **`404`**.
- **No `DELETE` handler and no `POST` handler**, per `context.md` → the wire contract.

**`backend/app/main.py`** — mount the router alongside the other book-scoped routers, beside step
003's. Nothing else in this file changes.

## Out of scope for this step — say it, do not build it

- **Composition.** Nothing in this step is read by `services/prompt_composition.py` or
  `services/chat_turn.py`, and neither file is touched. Wiring the chapter layer in needs an answer to
  "which chapter is this turn about", which is undesigned FEAT-013 context assembly. Deferred to
  `015.chapter-writing-free-mode` (D7).
- **`Chapter.system_prompt`.** The column stays dormant; nothing here reads or writes it (D1).
- **Any `Capability` member or `_CAPABILITY_MATRIX` row.** Row ownership is not expressible in that
  table, and this is the third rule of its kind after `Chat.author_id` and `BookAuthorPrompt`.

## Definition of done

*This half of the feature has no product id — FEAT-019's UC-094 / US-109 describe a superseded model
(`context.md` → "Product situation"). Every item below is self-contained.*

1. `[test]` `GET` returns `200` and the caller's own stored prompt for the chapter.
2. `[test]` `GET` for a chapter where the caller has no row returns `200` with an empty prompt and a
   null modified timestamp — **not** `404`.
3. `[test]` `PUT` stores the body's text, the response echoes what was stored, and a following `GET`
   returns the same value.
4. `[test]` Two members of the same book `PUT` different prompts on the **same chapter**; each one's
   `GET` returns their own text and never the other's — including when one of them is the book's
   owner.
5. `[test]` The same author holds independent prompts on two different chapters of one book; writing
   one leaves the other untouched.
6. `[test]` A second `PUT` updates rather than duplicating: the value changes, the creation timestamp
   is preserved, the modified timestamp advances, and the pair still has exactly one row.
7. `[test]` Writing an empty string is accepted and read back as an empty prompt — clearing a prompt
   needs no delete verb.
8. `[test]` A prompt is readable and writable on a chapter in `open`, `closing` and `closed` state,
   not only on a `planned` one.
9. `[test]` A logged-in non-member of a **public** book gets `403` from both verbs, and nothing is
   stored.
10. `[test]` A user with no relationship to a **private** book gets `404` from both verbs — existence
    hiding, inherited from the dependency.
11. `[test]` A request with no token gets `401` from both verbs.
12. `[test]` A chapter id that does not exist, or that belongs to **another book**, gets `404` from
    both verbs, and the `PUT` stores nothing.
13. `[test]` The response body exposes no user identifier and no field a caller could vary to reach
    another author's prompt.
14. `[test]` The path answers no `DELETE` and no `POST` — both are refused by the framework rather
    than silently accepted.
15. `[test]` A malformed `PUT` body (missing the prompt field) is refused as a validation error and
    nothing is stored.
16. `[manual/live]` The verifier confirms that neither `backend/app/services/chat_turn.py` nor
    `backend/app/services/prompt_composition.py` appears in this step's `## Files Changed` — the
    prompt is stored and served but composed into nothing (D7).
